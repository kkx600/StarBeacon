# 星烽 StarBeacon 持续决策与自动授权

持续决策复用指定模型已完成的本人研判，形成待确认候选或限时自动授权。自动执行模式可单独启用新告警自动研判许可，将索引成功的指定探针告警提交模型队列。模型只输出建议与自报分数，平台依据管理员配置独立决定是否提交任务，采集器访问联动设备。判断、授权、设备配置回读和真实流量效果分别记录。

## 配置与入口

管理员在“模型配置 → 决策策略”配置运行模式，在“评估记录 → 详情”查看持续授权、未授权原因及原任务。两个目录各保持一张业务表格，配置和详情使用独立弹窗；自动授权不提供可编辑的目标 IP。选择器读取启用模型与完整分页的在线探针目录，设备选项来自就绪连接器。

| 配置 | 约束 |
| --- | --- |
| 运行模式 | `shadow` 影子评估；`approval` 持续评估与人工确认；`automatic` 持续评估与自动执行（签名限时任务） |
| 指定模型 | 固定 `provider_id` 与 `provider_revision`；模型停用或修订变化后不再授权 |
| 自动处置 | 仅 `block_source`；评分阈值至少 0.5，且不超过 1 |
| 执行位置 | 固定 `sensor_id`、`registration_id`；仅处理该探针及代次观测的告警 |
| 联动设备 | 固定 `connector_id`、`config_sha256`；设备配置漂移不沿用旧授权 |
| 封禁期限 | 30–3600 秒，同时不得超过设备限制；签发时冻结绝对到期时间 |
| 目标冷却 | 从任务签发时间计，至少等于封禁期限，最多 86400 秒；同设备、同目标跨策略并与人工任务共用 |
| 每小时授权 | 每策略滚动一小时 1–100 项，跨修订累计；另受租户滚动 24 小时 1024 项响应任务额度限制 |
| 自动研判 | 默认关闭；仅自动执行模式可配置 `trigger`，按指定探针和注册代次、告警等级及 UTC 每日登记量触发；每日 1–1000 项，跨修订累计 |
| 数据使用许可 | 开启自动研判须单独确认提交告警白名单字段及可能产生的调用费用；不发送原始载荷或 PCAP，模型和租户共享费用额度继续生效 |
| 评分授权 | 必须明确勾选接受使用未经校准的模型自报分数；模型输出不会代替这项授权 |

自动执行模式只通过持续授权路径提交任务，人工处置接口拒绝为该模式建立第二条授权。

`continuous` 仅用于持续模式。`approval` 配置模型绑定；`automatic` 还必须完整配置 `automatic` 对象。未知字段、重复键、大小写别名、空授权对象及越界期限拒绝保存。切换模型、探针或设备时，页面取消评分及自动研判数据使用许可勾选，要求重新确认。

## 持续处理范围

当前流程处理策略当前修订保存后，由本修订维护者创建并成功完成的指定模型研判。历史已完成研判不补做；不同账号的材料不因管理员角色而合并。策略停用或修订改变后，待提交任务重新核对当前头，不能使用旧配置继续授权。账号或租户停用、角色撤回、研判取消、材料到期均阻止新任务。

平台每秒发起有界轮询，每轮最多访问八个租户、每租户十六项材料，整轮上下文预算十秒。租户游标只越过已访问范围；多实例通过租户事务锁和唯一身份约束共用档案。轮询周期不等于封禁时延承诺，排队、ES 核验、网络与设备耗时需在实际负载下独立测量。

未配置 `trigger` 时，只处理已完成的本人研判，不自动调用模型。配置独立数据使用许可后，索引 Worker 将符合指定探针、注册代次和等级且观测与接收时刻晚于当前许可修订的告警登记到 PostgreSQL；仅保存身份与材料摘要，告警原文仍位于 ES。租户最多启用八个自动研判策略，稳定事件身份和唯一约束防止上报重投重复登记。按需影子评估不创建自动任务。跨账号服务身份、补证任务、批量编排和领域校准仍需独立交付。

平台每轮每租户最多准备十六个自动研判触发，核对 ES 中唯一来源及完整白名单材料摘要，再使用原身份创建队列作业。触发状态、研判队列与审计同事务提交；同策略 UTC 日额度跨修订累计，模型与租户额度仍共享。超过登记额度不提交；费用额度拒绝、材料变化及许可撤回在自动研判记录中明确呈现。登记超过十五分钟或超出材料观测时限后失去执行资格；ES 刷新可见性最多宽限三十秒，宽限期间不向模型发送材料。

队列发送前再核对策略当前修订、维护者、模型和探针注册状态。撤回许可或配置变化阻止尚未发出的模型调用；已经发出的调用不能保证提供方停止或免除计费。队列的单次执行与结果未知处理沿用[告警模型研判](告警模型研判.md)。

## 固定授权门槛

CEL 命中后仍须同时满足下列条件，表达式写成 `true` 也不能绕过：

1. 当前模型、研判、告警身份、原始事件 SHA-256 与冻结白名单材料一致且未超出观测时限。
2. 自报分数达到固定阈值；结论为 `confirmed`、攻击结果为 `attempt`、建议为 `block_source`。
3. 模型实际引用 `source.ip` 与 `rule.id`；白名单字段没有因格式或长度而被截断。
4. 源 IP 是合法目标且不在策略保护网段；观测探针和注册代次等于配置绑定。
5. 当前探针、连接器、签名信任与健康观测就绪；设备身份、配置摘要和原生期限能力符合任务契约。
6. 同一告警在同一设备没有已有自动授权；目标不在冷却期，小时及租户预算未用完，探针没有冲突任务。

模型自报分数未经领域校准，不能称为攻击成功概率。`needs_review=true` 的原模型建议保持不变；自动动作的依据是管理员明确配置的有限范围授权。镜像丢包、完整会话、终端执行、业务结果与实际丢弃报文仍需单独证据，不能由这些门槛推定已具备。

## 幂等、事务与故障

每项持续判断绑定租户、维护者、策略标识、修订和研判作业。评估请求使用确定的原键；重查返回原判断，不重算已经改变的材料。授权档案、签名 `response.block` 任务和审计同事务提交，数据库断连或审计失败时整体回滚。没有完整档案的未知提交由下一轮核对原身份，不按新任务盲目重发。

| 授权档案状态 | 含义 |
| --- | --- |
| `queued` | 策略已授权，签名任务已受理；查看原任务核对设备回执 |
| `awaiting_confirmation` | 当前候选需管理员独立确认；没有自动设备任务 |
| `skipped` | 确定性门槛拒绝，不创建任务；保留未授权原因 |

确定性拒绝包括未命中、材料或设备绑定变化、分数不足、引用缺失、保护范围、目标冷却、原告警已授权、配额及设备未就绪。已留档的拒绝不因设备后来上线而自动重发。依赖暂不可用或数据库事务失败则不提交授权，等待材料仍有效时核对。设备执行未知、重启回读、条件解除与原生 TTL 沿用[HTTP 联动与限时封禁](HTTP联动与限时封禁.md)，不通过重复写入延长期限。

## 留存与接口

`decision_continuous_runs` 按租户强制 RLS；运行账号仅可读取、插入及删除已到期档案，不能 UPDATE 历史。保存判断及授权元数据，不复制凭据、研判原文、载荷或 PCAP。期限按创建时的 `operations` 策略冻结，默认 180 天；配置只影响未来对象。到期档案不可访问，由有界历史清理器回收，原任务仍按自己的期限与保护条件保留。

`decision_triage_triggers` 使用强制 RLS，按创建时 `models` 策略固化期限，默认 180 天；待核对记录独立保护，终态到期后由有界历史清理回收。管理员在当前策略的“自动研判记录”查看本人固定修订的登记、拒绝原因与原作业，单页最多二十条，失败不冒充空数据。接口为 `GET /api/v1/decision-policies/{id}/revisions/{revision}/triggers`。

配置接口沿用 `POST /api/v1/decision-policies`。`GET /api/v1/decision-evaluations/{id}/continuous` 只返回本人未到期的原授权或 `item:null`，不触发判断或设备动作；无授权、尚未处理和档案到期不等于未曾执行。完整字段与响应见[平台 OpenAPI](../api/openapi/platform.json)。浏览器重算档案摘要，核对账号、策略、原评估、配置和任务身份，来源不一致时显示错误，关闭或切换账号后忽略迟到响应。

## 验证边界

测试还包括真实 EVE 标准化、重复索引后的自动登记、实际 HTTPS 模型队列、费用拒绝、策略修订与停用前的许可撤回、触发记录与私有范围。测试包括固定门槛、保护网段、模型与设备变化、并发幂等、重复告警、冷却、小时预算、提交中断、摘要损坏、行级权限和默认留存。进程用例使用实际离线 PCAP 告警、HTTPS 模型协议、持久研判队列、持续任务、mTLS 控制面和采集器，核对独立设备租约及条件解除。受控协议端点不执行真实流量丢弃，结构化模型夹具不证明模型领域质量；实际运行来源见[测试覆盖与验收记录](测试覆盖与验收记录.md)。完整 107 项产品需求、生产容量与正式发布资格仍须分别验收。
