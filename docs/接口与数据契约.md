# 星烽 StarBeacon 接口与数据契约

本文定义完整产品的目标契约，与[架构设计](架构设计.md)配套。代码块是契约示例，不代表所有接口已经实现或通过集成测试。当前 Go 工程的实际路径、参数和响应以 [`api/openapi/`](../api/README.md) 为准；身份、基础告警、探针、规则检查及离线重放已有工程实现，目标契约中的其他能力仍需实施。所有资源引用都必须在认证上下文中再次授权。

## 1. 标识、时间与租户

| 字段 | 约定 |
| --- | --- |
| `tenant_id` | 平台分配的租户 ID；服务端根据身份解析，不接受正文覆盖权限 |
| `organization_id` | 租户内组织／站点；组织层级不替代租户隔离 |
| `sensor_id` | 逻辑探针 ID；证书绑定租户与注册代次 |
| `sensor_registration_id` | 本次注册身份，重新注册创建新值，防止旧数据与新身份混淆 |
| `engine_run_id` | Suricata 本次运行代次，用于限定 `flow_id` |
| `source_generation_id` | EVE 文件逻辑代次；不能只使用文件名或 inode |
| `producer_epoch` | 代理 WAL 序号空间代次，跨普通进程重启保持不变 |
| `stream_id` | `alerts`、`context`、`app_metrics`、`security_logs` 的独立持久序号／配额域；不接受任意新流名 |
| `sequence` | `(sensor_registration_id, stream_id, producer_epoch)` 内单调序号；gRPC 使用 uint64，JSON 输出为字符串 |
| `event_id` | 由不可变源定位计算的哈希；重放、重读时不变 |
| `event_time` | 源事件发生时间；用于调查时间线 |
| `observed_at` | 代理读取源记录的时间；用于识别源日志积压 |
| `received_at` | 平台首次接收记录时间；重试不会成为新的业务发生时间 |
| `indexed_at` | 索引写入时间；与可搜索时间区分 |

事件 ID 的输入为版本前缀、租户、探针注册身份、源代次、源记录起始字节偏移及子记录序号，使用无歧义编码后计算 SHA-256。源代次和字节偏移进入本地持久化状态；日志截断重新分配代次。WAL sequence 服务于确认，不单独作为源记录去重依据。

此定位适用于文件来源。外部 API／Syslog 分别使用独立的 event ID 算法版本，绑定租户、注册数据源、稳定外部 ID/持久来源序号；派生关联检测使用规则版本、关联键、窗口和匹配槽位生成稳定 detection ID，再派生首条告警 ID。证据集合变化只产生检测修订，不改变该告警 ID；具体规则见[关联执行契约](安全运营与数据治理设计.md#62-有界关联执行)。不得把不存在的文件偏移填 0 后混入同一命名空间。Syslog 正文 hash 不足以区分真实重复和重试。数据源身份、传输 stream 与事件身份分别保存，切换网关不改变源 ID。

事件时间 UTC 存储、按租户时区展示；报告使用半开窗口 `[start, end)`。精确包时间采用 RFC 3339 纳秒字符串，epoch 纳秒和原始 tick 也用字符串，不经过 JavaScript Number。IP 统一解析，IPv4-mapped IPv6 的规范化策略固定版本，原始地址可保留。原始 `flow_id` 和其他可能超过 JavaScript 安全整数范围的值，在 JSON/前端统一为字符串。

## 3. gRPC 最小契约

下面是完整的接口骨架。实现时生成 Go 客户端与服务端，并补充状态码、认证中间件、限额和兼容测试。

```proto
syntax = "proto3";

package starbeacon.sensor.v1;
option go_package = "github.com/kkx600/StarBeacon/api/sensor/v1;sensorv1";

import "google/protobuf/timestamp.proto";

service SensorService {
  rpc UploadEvents(stream EventBatch) returns (stream IngestAck);
  rpc Control(stream AgentMessage) returns (stream PlatformCommand);
}

message EventRecord {
  string event_id = 1;
  uint64 sequence = 2;
  string source_generation_id = 3;
  uint64 source_offset = 4;
  uint32 record_ordinal = 5;
  google.protobuf.Timestamp event_time = 6;
  google.protobuf.Timestamp observed_at = 7;
  string event_type = 8;
  reserved 9;
  reserved "eve_json";
  bytes raw_sha256 = 10;
  string engine_run_id = 11;
  bytes payload = 12;
  string payload_schema = 13;
  string content_type = 14;
  bytes payload_sha256 = 15;
}

message EventBatch {
  string batch_id = 1;
  string sensor_id = 2;
  string producer_epoch = 3;
  string schema_version = 4;
  string route_token = 5;
  repeated EventRecord records = 6;
  reserved 7;
  reserved "resume_after_sequence";
  string sensor_registration_id = 8;
  string stream_id = 9;
  bytes batch_sha256 = 10;
}

message SequenceRange {
  uint64 first = 1;
  uint64 last = 2;
}

message IngestAck {
  string batch_id = 1;
  string producer_epoch = 2;
  reserved 3, 5;
  reserved "accepted_through", "missing_ranges";
  repeated SequenceRange accepted_ranges = 4;
  string status = 6;
  uint32 retry_after_ms = 7;
  string error_code = 8;
  string sensor_registration_id = 9;
  string stream_id = 10;
  bytes batch_sha256 = 11;
  repeated SequenceRange quarantined_ranges = 12;
  repeated RejectedRecord rejected_records = 13;
}

message RejectedRecord {
  uint64 sequence = 1;
  string error_code = 2;
  bool retryable = 3;
}

message AgentMessage {
  string sensor_id = 1;
  string message_id = 2;
  string kind = 3;
  string command_id = 4;
  string payload_schema = 5;
  bytes payload_json = 6;
  google.protobuf.Timestamp observed_at = 7;
}

message PlatformCommand {
  string command_id = 1;
  string kind = 2;
  string payload_schema = 3;
  bytes payload_json = 4;
  bytes payload_sha256 = 5;
  bytes signature = 6;
  google.protobuf.Timestamp expires_at = 7;
}
```

`go_package` 对应项目仓库路径。`kind` 和 `status` 在正式 proto 中固化为枚举；不能因 JSON payload 就允许任意命令。payload 必须匹配注册的 schema、大小限制和签名规范。`EventRecord.payload_schema` 标识 EVE、flow summary、app aggregate 或授权安全日志，不能将所有消息称为 `eve_json`；`content_type` 来自允许列表。原始输入摘要与实际传输 payload 摘要分开，流量聚合的 `aggregate_id/revision` 不由 sequence 替代。

服务端从 mTLS 身份得到 tenant 与注册关系，检查 sensor、registration、stream、epoch 一致性。一个 batch 只能使用一个已验证归属的分区令牌，且消息大小、时间字段、序号范围与摘要正确。令牌对新事件的授权到期不改变已固化记录的目标分区；重传必须核对原路由及当前探针权限。

`accepted_ranges` 仅为该 batch 内已取得严格持久 PubAck 的序号集合，范围不得包含未发送记录；不表示跨网关的全局连续前缀。`quarantined_ranges` 是其中已持久保存原文和失败信息的子集，仍计入待修复数据；`rejected_records` 与 accepted 集合互斥。Agent 校验回执身份、batch ID/hash 和集合范围，将 ACK 合并日志 fsync 后才回收该 stream 已全部确认的 WAL 段；崩溃前未持久的 ACK 导致安全重传。新连接不从服务端推测历史前缀，服务端也不信任客户端的 resume 声明跳过写入。告警坏记录若未成功进入持久隔离区就不能回 accepted。允许丢弃的遥测使用本地 gap 记录和独立水位，不能冒充平台已接收。

`batch_id` 由身份、stream、epoch 和 canonical batch 摘要派生，服务器重新计算验证，因此不依赖永久保存每批 PG 收据也能拒绝同 ID 不同内容。batch 摘要采用版本化、长度前缀的固定字段编码，包含路由身份、按序记录及各 payload hash，排除 batch 摘要自身；不把未声明 canonical 规则的 JSON 或跨语言 Protobuf 序列化直接视为稳定签名输入。原批次重试沿用 ID；部分成功后只重发未确认记录时形成新 batch ID，但单条 event ID、sequence 和路由不变。实际索引完成状态走独立健康查询／水位，不用延迟整个 gRPC ACK 直到模型分析完毕。

控制命令目录包括 `publish_ruleset`、`publish_config`、`collect_diagnostics`、`prepare_capture_upload`、`upgrade_agent`；命令都有注册 schema、过期时间和允许的执行身份。回执为收到、验证失败、执行中、生效、失败与回退结果。规则发布成功以引擎实际加载回执为准。

## 4. PostgreSQL 逻辑数据表

以下是建模清单，工程实现还需要迁移 SQL、外键、RLS policy 和容量测试。表中省略统一的租户、时间戳、创建者与版本字段。

| 领域 | 表 | 核心内容／约束 |
| --- | --- | --- |
| 租户 | `tenants`, `organizations`, `tenant_cells`, `quotas` | 状态、区域、组织树、数据单元、额度 |
| 身份 | `users`, `memberships`, `roles`, `role_bindings`, `service_principals` | 角色绑定包含资源范围，服务主体与人分开 |
| 探针 | `sensors`, `sensor_registrations`, `sensor_certificates`, `sensor_configs` | 每个证书属于唯一注册关系 |
| 路由 | `ingest_route_policies`, `ingest_route_tokens` | 逻辑分区策略、有效窗、存储池和迁移版本 |
| 资产 | `assets`, `asset_addresses`, `asset_tags`, `asset_owners`, `asset_groups`, `asset_group_versions`, `asset_relation_history`, `network_segment_versions`, `network_segments`, `network_namespaces` | 地址及组织／标签／责任人／组成员保留有效区间与记录时间，历史缺失不以当前值补齐 |
| 地址与身份关系 | `asset_interfaces`, `identity_bindings`, `address_binding_versions`, `binding_conflicts` | 业务确认与版本在 PG；高频 DHCP/ARP/NAT 原始观察在 ES，不按每包写 PG |
| 数据源与解析 | `data_sources`, `source_credentials`, `parser_profiles`, `parser_revisions`, `source_checkpoints`, `schema_registries` | 身份绑定租户与网络域、解析版本、源游标和隔离策略 |

| 关联与狩猎 | `correlation_rules`, `correlation_revisions`, `detection_releases`, `hunt_queries`, `hunt_runs`, `baseline_profiles` | 规则版本、窗口、依赖字段、授权范围、状态上限、样本与运行水位 |
| 暴露与弱点 | `exposure_sources`, `exposure_cases`, `remediation_tasks`, `risk_acceptances` | 扫描事实在 ES，修复责任、SLA、例外与复测工作流在 PG |
| 剧本与案件 | `playbooks`, `playbook_revisions`, `playbook_runs`, `playbook_steps`, `incident_slas`, `external_ticket_links` | 固定步骤、分支、审批、超时、补偿；动作仍引用独立 actions |

| 规则生成与测试 | `rule_samples`, `rule_generation_jobs`, `rule_test_runs` | 自然语言、PCAP／HTTP Raw 引用，真实／合成、模型与测试版本、资源限额 |
| 事件 | `incidents`, `incident_alert_refs`, `incident_tasks`, `incident_notes` | 同租户逻辑关联，告警引用不要求跨库外键 |
| 人工工作流 | `alert_workflows`, `review_labels` | 稀疏记录人工操作及授权训练标签，不复制所有原始告警 |
| 模型 | `model_providers`, `model_profiles`, `model_capabilities`, `model_price_versions` | endpoint、secret_ref、区域、版本和能力检查 |
| 决策 | `decision_policies`, `policy_versions`, `evaluation_runs`, `calibration_versions` | 规则／模板／模型／数据集版本完整可追溯 |
| 响应 | `response_connectors`, `response_proposals`, `approvals`, `actions`, `action_leases`, `action_attempts` | 目标设备、范围、TTL、幂等、回执与撤销 |
| 连接器 | `connector_runners`, `connector_instances`, `connector_capabilities`, `credential_refs`, `auth_session_metadata` | 租户／站点绑定、版本能力、会话代次与有效期；凭据密文优先保存在客户侧 |
| 通知 | `notification_channels`, `notification_templates`, `notification_routes`, `notification_intents`, `notification_deliveries`, `delivery_attempts`, `delivery_receipts` | 每渠道／接收目标唯一，重试与回执关联，群机器人与应用分适配器 |
| Syslog | `syslog_destinations`, `syslog_routes`, `syslog_checkpoints`, `syslog_replay_jobs` | 批次／序列段水位、持久发送与外部确认分开，不逐原始事件写 PG |
| 审计与登录 | `operation_audits`, `login_audits`, `access_audit_batches` | 分区追加、脱敏、归档和受限检索；不复制全量告警 |
| 报告 | `report_templates`, `report_schedules`, `report_runs`, `report_publications` | 周期唯一键、数据快照、生成与发布状态分开 |
| 对话 | `conversations`, `conversation_messages`, `tool_runs` | 数据权限版本、摘要、引用与工具调用状态 |
| 证据 | `capture_objects`, `evidence_holds`, `evidence_access_grants`, `packet_analysis_jobs`, `evidence_artifacts` | 对象级清单、授权包集合、派生制品、保全、下载授权与到期 |
| 集成 | `mcp_clients`, `api_credentials`, `webhook_subscriptions` | scope、失效、回调目标、限额 |
| 通用 | `jobs`, `outbox`, `usage_ledger`, `schedule_slots`；River 自身迁移表 | 对外任务与业务幂等、周期槽位；后台领取/重试复用 River，业务与入队同事务；不逐告警入队 PG |

唯一键重点：

- `incident_alert_refs(tenant_id, incident_id, event_id)` 防止重复关联。
- `actions(tenant_id, idempotency_key)` 防止重复业务动作，但仍需设备侧对账。
- `report_runs(tenant_id, template_id, period_start, period_end, revision)` 防止重复定时任务。
- `usage_ledger(tenant_id, source_type, source_id, metric)` 防止重复计量。
- `capture_objects(tenant_id, capture_id)` 及对象版本约束防止证据指向漂移。

模型调用结果、原始告警、网络流、每包索引不建立同量级 PG 表。任务与审计历史按时间分区归档，避免长期运行后把控制面数据库变成第二个日志库。

## 5. ES 索引与原始事实

| 逻辑集合 | 组织方式 | 写入与保留 |
| --- | --- | --- |
| `alerts` | 固定时间桶与存储池；`_id=event_id` | create；全部告警原始事实；保留期可配置 |
| `network` / `security-logs` | 稳定事件 ID、固定逻辑分区，与告警复用路由 | flow/DNS/TLS/HTTP 及入站日志；需要唯一明细才能保证调查与频次统计一致 |
| `assessments` | 固定分区；`_id=analysis_id` | 追加，记录每次证据快照和结论 |
| `detection-revisions` | detection ID、稳定修订 ID、固定逻辑分区 | 追加关联证据、撤回及重算修订；首条告警仍为不可变事实，当前状态进入检索投影 |
| `alert-search` | 与事实绑定的稳定时间分区；`_id=event_id` | 完整可筛选字段＋当前状态，不含大原文；分来源版本向量与 OCC 更新 |
| `alert-groups` | 稳定分组键 | 保存选择条件与水位，成员明细按事实索引查询 |
| `evidence-index` | 时间／流／对象目录检索 | 不保存 PCAP 字节 |
| `daily-metrics` | 租户、日、指标定义版本 | 精确重算可替换对应版本，报告引用已冻结版本 |
| `audit-search` / `delivery-search` | 操作／登录与投递查询投影 | 权威来自 PG 业务记录；Syslog 高频尝试按批次记 |
| `flow-intervals` / `flow-classifications` | 计量域／流代次／窗口／分类修订 | 已启用明细默认保存 180 天，支持租户分类配置；原始窗口不因后续分类重复累计 |
| `app-metrics-5s` / 分钟／小时／日汇总 | 稳定 aggregate_id 与修订，含完整应用分布 | 基数与留存单独预算，按统一计量域汇总 |
| `health-metrics-1m` / `health-metrics-1h` | 租户、sensor/cell、窗口、定义版本；固定分区与修订 | 白名单健康汇总，保存样本数／缺测；不复制所有 Prometheus 序列 |
| `intel-observables` / `intel-matches` | 来源版本、规范 IOC／事件 ID、有效窗与撤回状态 | 历史命中保留依据，当前有效命中可重建，不重复累计旧 feed |
| `exposure-findings` / `identity-observations` | 扫描批次／外部ID、源代次与证据 | 弱点、软件与地址身份观察；事实留存和工作流分开 |

例如普通告警索引名 `sb-alerts-v1-p03-2026.09.28`，具体索引由服务端路由解析，外部 API 从不接收索引名。write alias 可用于访问管理，但不能在重试时改写事件所属索引。

原始内容摘要以源定位与原始 EVE 为基础，不把重试时生成的处理时间纳入。重新标准化时生成有版本的派生投影，不利用相同 event ID 的 create 冲突去覆盖原始事实。

生命周期有三个独立期限：告警可检索期限、PCAP 原始证据期限、事件／报告与保全期限。普通 TTL 删除不能绕过 `evidence_holds`。强保全证据复制到具有对应保全策略的专用对象区，避免索引级删除受单条记录约束而长期无法释放容量。

## 6. 研判请求与结果

决策请求传递标准化证据快照与有限任务定义，不把整段无限制原始日志直接拼接到固定 Prompt 后面。Provider 输出先保留原始受限响应，再映射到统一领域对象。

  "evidence_snapshot_id": "esnap_01",

  "model_id": "jev-1.13.0",
  "model_revision": "jev-1.13.0",

| 枚举 | 可选值 |
| --- | --- |
| `detection_validity` | `valid`, `false_positive`, `unknown` |
| `behavior_class` | `malicious`, `authorized`, `benign`, `unknown` |

| `recommended_action` | `observe`, `collect_evidence`, `review`, `propose_block` |

`confirmed_success` 要求引用的结果证据符合对应攻击类型的证据策略。证据不足时可以对“是否可疑”给建议，同时对“是否成功”拒绝下结论，不要求一次分析所有字段都给确定值。

## 7. 响应动作契约

建议、审批与执行分为独立对象。响应请求最小字段：

```json
{
  "proposal_id": "rp_01",
  "subject_id": "incident_01",
  "action_type": "block_ip",
  "connector_id": "firewall_dmz",
  "target": {
    "ip": "198.51.100.20",
    "direction": "ingress",
    "zone": "dmz",
    "destination_asset_ids": ["asset_01"]
  },
  "ttl_seconds": 1800,
  "reason": "依据事件证据申请临时阻断",
  "evidence_snapshot_id": "esnap_02",
  "policy_version": "policy_12",
  "idempotency_key": "incident_01-firewall_dmz-target01-policy12",
  "approval_required": true
}
```

授权服务决定 `approval_required` 的最终值，不能信任调用方写成 false。审批摘要绑定目标、范围、TTL、证据和策略 hash；修改任何影响范围的字段使原审批失效。

有效动作带 `not_before`、`expires_at`、外部设备规则 ID、实际回执、验证状态和撤销计划。对同一设备／方向／目标建立有效租约集合，只有最后一个有效租约退出后才删除设备规则。合并设备规则的原生过期时间为全部有效租约 `expires_at` 的最大值；新增更长租约必须先延长设备 TTL 并回读确认，才能称该租约已生效。缩短、续期和设备重启恢复也需对账；无法可靠更新 TTL 的连接器不合并设备规则，或不授予自动模式。不同租户连接器和设备上下文不能共享动作键。

系统时钟偏差、执行超时或无法回读时显示未知状态，启动 reconcile。TTL 优先使用设备原生过期机制；没有可靠到期撤销能力的连接器不授予自动封禁资格。

```json
{
  "time_range": {
    "start": "2026-09-27T00:00:00Z",
    "end": "2026-09-28T00:00:00Z"
  },
  "filters": [
    { "field": "severity", "op": "in", "value": ["high", "critical"] },
    { "field": "destination.ip", "op": "cidr", "value": "192.0.2.0/24" },
    { "field": "network.transport", "op": "eq", "value": "tcp" },
    { "field": "network.protocol", "op": "eq", "value": "http" },
    { "field": "http.request.method", "op": "eq", "value": "POST" },
    { "field": "url.path", "op": "prefix", "value": "/api/" },
    { "field": "workflow.status", "op": "eq", "value": "open" }
  ],
  "sort": [{ "field": "event_time", "order": "desc" }],
  "page_size": 50,
  "cursor": null
}
```

租户、授权组织和字段权限由服务器注入，不是模型可以删除的 filters。限制最大 AST 深度、条件数、聚合基数和时间窗，不开放 script、任意正则或任意索引访问。

文本高级检索通过字段注册表编译为同一授权 AST；`mode=indexed_events`、`language=starbeacon-ws` 的可支持集合以能力表为准。`mode=packet_native`、`language=wireshark-display` 使用固定 TShark 的受限 PCAP 作业，不能把表达式直接传给 ES query_string，也不能把 PCRE2 matches 换成 Lucene regexp。精确语法、多值与覆盖策略见[高级检索与数据包取证设计](高级检索与数据包取证设计.md)。

## 10. 报告快照与指标定义

报告快照包括 tenant、组织范围、timezone、period_start/end、数据水位、数据缺口、指标定义版本、查询摘要、事件引用、PG 业务状态截止时点、模型／模板版本和统计内容 hash。

| 指标 | 计算口径 |
| --- | --- |
| 原始告警数 | 窗口内唯一 event ID 数；不因误报关闭而减少 |
| 告警组数 | 指定分组算法版本得到的组数，不称为事件数 |
| 真实威胁率 | 已确认真实威胁数／已完成人工研判数；同时展示样本量 |
| 模型自动覆盖率 | 通过验收并无需人工的判定数／候选分析数 |
| 告警误报占比 | 人工确认误报告警／已完成人工有效性标注的告警；不冒称模型假阳性率 |
| 模型假阳性率 | 已知负样本中被模型判为正样本的数量／全部已知负样本；与精确率分开 |
| 处理时长 | 从告警进入待处理队列至首次有效处理，区分工作时间与自然时间 |
| 处置生效率 | 验证生效动作／已执行动作；未知结果单列 |
| 数据覆盖 | 在线采集时长、镜像丢包与数据缺口，不能只看探针心跳 |
| 成本 | usage、固定价格版本、币种和账单对账状态 |

统计任务先保存不可变快照，LLM 仅生成叙述字段；最终图表和数字直接读取该快照。报告重新生成使用 revision 区分内部记录，正式显示标题仍为报告名称与所属周期。

## 11. 规则、模型与接口版本

Protobuf 字段编号不复用，至少支持当前与上一受支持探针版本。规则包记录 Suricata 版本区间、文件清单、SHA-256、签名、测试集和发布审批，模型制品记录代码、权重、tokenizer、校准和能力检查。

接口升级先增加兼容字段，再迁移读写，最后废弃旧字段。输入 schema、规范化 schema 和外部 provider schema 分别版本化。数据迁移不得改写原始事件 ID；重新分析生成新的 analysis ID 与历史引用。

正式开发第一批契约测试覆盖：EVE 大整数、重读 ID、分区稳定性、租户隔离、Bulk 部分失败、任务重复投递、模型 unknown、伪造引用、动作超时和报告重算。测试这些业务不变量比为每个简单 CRUD 写重复实现的测试更有价值。

## 12. 查询投影契约

每个 `alert-search` 文档至少包含：tenant／组织／网络域／资产范围、event_id、原始事实定位、事件时间、探针、SID/rev/发布标识、source/destination、network、HTTP 与 URL 的受控字段、资产快照、当前 workflow、当前选中 assessment、证据可用性、投影 schema 与数据水位。未显式处理的告警使用派生的 `workflow.status=open`，无需为每条原始告警插入 PG 行。

版本向量为 `fact_revision`、`enrichment_revision`、`workflow_revision`、`assessment_revision`、`projection_schema_version`。版本在各自来源单调递增，不用模型完成时间比较新旧：较晚完成的旧证据分析不能覆盖新证据结论。模型候选的选中资格由策略、证据与人工覆盖版本决定；人工撤销覆盖也产生新的工作流版本。

来源变更消息包含 tenant、event_id、稳定分区、domain、revision、不可变内容摘要与可读取来源引用。投影器幂等合并，使用 ES OCC，缺失事实时等待或补齐后才可见。PG outbox 只负责 PG 发起的变更；模型事实的完成消息走持久事件通道。PIT 冻结 ES 读取视图，不构成 ES、PG、对象存储间的分布式快照；严谨报告另外冻结业务状态与证据水位。

列表响应包含 `items`、`next_cursor`、`total.value/relation`、`as_of`、`projection_as_of`、`data_completeness`、`warnings`。同一分页查询不因后台状态变化重新排列已有 PIT 页面；点击详情可以显示比列表更新的状态并提示。不能以客户端合并结果实现精确统计。

## 13. 健康报告与客户侧连接器

`AgentMessage.kind=health_report` 的 payload schema 固定为 `sensor.health.v1`，必填 sensor 注册身份、boot_id、sample_started_at/ended_at、monotonic_elapsed、指标来源和采样错误。字段分组如下：

| 分组 | 字段要点 |
| --- | --- |
| host | CPU 核数／总利用率、内存 total/available、磁盘 total/free/inode、load、uptime |
| processes | agent／suricata 的 PID 代次、RSS、CPU 时间、运行状态 |
| interfaces | 接口 ID、累计 packets/bytes、计数器代次、drop、采样时长 |
| engine | 协议错误、重组缺口、规则数量、加载失败、运行版本 |
| pipeline | EVE 读取、WAL 字节与最老事件、最高连续 ACK、平台反馈索引水位 |
| capture | 环形时间窗、占用、待上传与失败、捕获缺口 |
| deployment | agent/engine 版本、desired/active 配置与规则摘要、发布序号、证书到期 |

累计计数与速率区分，缺失字段不填零。平台最新状态可缓存 Redis，时间序列进入指标存储；需要日志审计的状态变更另发业务事件，不把每 15 秒的全量指标写 PG。

客户连接器使用独立服务和身份，不能以任意 sensor 消息执行设备动作。接口骨架如下，具体动作 payload 必须为已注册 schema：

```proto
syntax = "proto3";
package starbeacon.connector.v1;
option go_package = "starbeacon/api/connector/v1;connectorv1";
import "google/protobuf/timestamp.proto";

service ConnectorService {
  rpc Control(stream RunnerMessage) returns (stream ConnectorCommand);
}

message RunnerMessage {
  string runner_id = 1;
  string registration_id = 2;
  string message_id = 3;
  string command_id = 4;
  string kind = 5;
  string payload_schema = 6;
  bytes payload_json = 7;
  google.protobuf.Timestamp observed_at = 8;
  uint64 journal_sequence = 9;
}

message ConnectorCommand {
  string command_id = 1;
  string action_id = 2;
  string connector_instance_id = 3;
  uint64 fencing_token = 4;
  string kind = 5;
  string payload_schema = 6;
  bytes payload_json = 7;
  bytes payload_sha256 = 8;
  bytes signature = 9;
  google.protobuf.Timestamp not_before = 10;
  google.protobuf.Timestamp expires_at = 11;
}
```

允许命令限于认证任务、能力验证、执行、查询核对、撤销及已批准诊断；类型在正式 proto 中转成枚举。签名覆盖规范编码后的全部命令上下文，防止只签 payload 却能替换目标或期限。Runner 不可根据 payload 自报 tenant 获得授权，租户由证书、注册和连接器归属共同检查。

本地持久日志在执行前落盘；回执包括接受、拒绝、执行中、设备已受理、读回生效、结果未知、失败、撤销中、已撤销和撤销失败。收到平台确认后可以归档 journal，活动租约和撤销计划仍保持。动作过期禁止补执行新的封禁；到期撤销任务不会因原封禁授权过期被取消，而由长期持久的撤销职责与重新核验的受限权限完成。恢复和跨 Runner 接管先读设备状态，再接管外部规则。

## 14. 通知、Syslog 与审计约束

通知唯一键为 `(tenant_id, business_event_id, route_version, channel_id, recipient_key, purpose)`，投递尝试另用 attempt_no。回执通过已验证的提供商消息 ID／签名与租户实例映射关联；没有验证的回调不能随意更新其他投递状态。模板改动、人工重发和业务复发分别有新的业务身份，不能为了避免重复而永久吞掉真正的新告警。

Syslog 记录按 `tenant + destination + route_version + stream_partition + sequence` 建发送水位；`transport_written_through` 与可选 `receiver_confirmed_through` 分开。发送批次可以含多条日志，但重试必须保留原 event ID。向量水位而非一个全局序号表达多分区进度。重放任务包含范围、来源、过滤版本、预计数量、配额、去重约定、缺失范围与状态。

审计事件具有独立 `audit_id`、actor、tenant、授权／委托信息、action、object_ref、变更摘要、结果、request_id、业务任务 ID 和服务端时间。敏感字段用“发生变化”和密钥版本代替内容。登录日志具有认证事务 ID，结果为成功／失败／挑战中／撤销；操作成功与后续异步执行成功分别记录。

具体渠道字段、状态、节流与失败处理见[运营与集成设计](运营与集成设计.md)和[通知渠道调研](research/通知渠道与投递调研.md)。规则契约以[规则管理设计](规则管理设计.md)为对应业务域的详细定义，命名与此处保持一致。

## 15. 应用流量与采集器执行契约

应用目录与规则业务表为 `applications`、`application_categories`、`application_rules`、`application_rule_revisions`、`application_rule_releases`、`metering_domains`、`metering_assignments`。应用规则与 Suricata 规则具有不同身份；共同引用样本、模型、验证和制品服务。主计量点分配保留有效区间，避免两台探针统计相同链路后重复汇总。

流记录包含 `meter_epoch`、`capture_domain`、`flow_epoch`、network namespace、五元组、可选 community_id、开始／结束与序列；字节字段注明 `counter_layer=l3`、方向、窗口增量、累计数、计数器代次、丢包／采样／覆盖质量。分类包含 product/category/service、status、来源规则及引擎版本、证据和 classification_revision；未确认的供应商分数不得显示为准确率。

聚合按保留 accounting_asset_id、但不含应用产品的稳定维度生成 `aggregate_id`，首次固化目标索引／逻辑时间桶／routing，重试和更高修订回原位置并拒绝版本回退，以一个有界的完整应用分布替换版本，明确未知和混合项，总量不因重新归因变化。每个消息具有 schema 与持久序列；默认上报受控聚合和流摘要，全部逐流 5 秒窗口是独立高容量模式，不能暗中开启。计量和应用消息使用独立持久队列预算，不能占用安全告警保底资源。

设备绑定关系至少包含 `tenant_id`、`device_id`、`connector_instance_id`、`executor_sensor_id`、允许的管理地址／安全域、capability_revision、scope_version、认证状态与最近可达性。连接器默认安装在 `executor_sensor_id` 对应采集器主机，独立 Runner 时此字段可空但须有明确站点与审批关系。

每个动作记录 `observation_sensor_id` 与 `executor_sensor_id`，绑定 policy_version、binding_version、scope_version、scope_hash、保护名单版本和实际执行代次；源告警来自 A 探针不代表 A 自动获得所有防火墙写权限。`ConnectorCommand` payload 含上述绑定，并由签名覆盖；执行前本地复核签名、目标、能力、期限与作用域，不通过凭据存在性推断授权。命令与本地授权缓存包含有效期、最大离线执行窗和撤销序号，存在序号缺口、缓存过期或保护范围版本落后时停止新的写动作；已有动作撤销职责仍持久保持。

平台接口补充：

| 接口 | 契约 |
| --- | --- |
| `POST /api/v1/traffic/applications/search` | 应用／类别／资产／网段／方向／时间筛选，返回质量与覆盖 |
| `POST /api/v1/traffic/aggregate` | 指定计量域与口径，禁止混合 L3/NIC/应用正文计数 |
| `GET /api/v1/traffic/flows/{id}` | 会话、分类证据、可用明细和原始取证引用 |
| `POST /api/v1/application-rules/test-runs` | 产品正负样本与性能测试，异步作业 |
| `POST /api/v1/application-rule-releases` | 固定规则包与采集器范围，签名／灰度／回滚 |
| `POST /api/v1/devices/{id}/executor-bindings` | 绑定指定可达采集器与权限，不能自动扫描客户网络 |

## 16. 双端身份、MAC 与数据包时间

| 对象／路径 | 最小字段与规则 |
| --- | --- |
| `starbeacon.source_asset` / `starbeacon.destination_asset` | status、asset_id、snapshot_id、network_namespace_id、候选/来源引用；外部、未知和歧义不填虚构资产 |
| `source` / `destination` 与 `client` / `server` | source/destination 是该事实的方向；client/server 只有协议角色证据成立时填充，不按端口大小推断 |
| `starbeacon.observation_scope_id` | 当前取证访问的观测范围，和历史组织分析维度分开；关联结果不能扩大授权 |
| `source.mac` / `destination.mac` | 只有链路角色可对齐该事件才填；规范化为六字节语义，原值/来源另存 |
| `starbeacon.link_observations[]` | layer_index、src_mac、dst_mac、ethertype、顺序 vlan_stack、source_basis、packet_ref；采用同层对象约束 |
| `observer.ingress.interface` / `observer.egress.interface` | 真实观测接口；单臂镜像无出站观察时 egress 不填 |
| `starbeacon.capture` | capture_id、对象版本、packet_id、section_id、interface_id、packet_ordinal、record_offset、data_offset、captured_length、original_length、linktype |
| `starbeacon.capture.captured_at` / `rx_at` / `tx_at` | 精确时间字符串；附 timestamp_source/resolution、clock_domain、clock_error_ns、unknown 原因；RX/TX 时延需要 rx_tx_correlation_id |
| `starbeacon.flow.inbound` / `outbound` | first_seen_at、last_seen_at、packets、bytes；附 direction_basis、direction_policy_revision、计数层、窗口与覆盖 |
| `starbeacon.nat_observation` | original/translated 源/目的 IP+port、L4、前后网络域、设备/连接ID、有效窗、证据和解析状态 |
| `starbeacon.search_quality` | 受控字段 ID 的完整性/异常原因、schema、覆盖版本；unknown 不等于已确认不存在 |

`packet_id` 由不可变原对象版本、section/接口/原包序号确定；重分析或导出重编号不改变它。PCAPNG 的接口 ID 只在所属 section 有效。微秒值补九位字符串不会得到真实纳秒准确度。`flow_first_packet` 的 Ethernet 字段不冒充告警触发包 MAC，流首末时间也不冒充接口收发时间。

包目录和精细观察不逐条写 PG；原始 PCAP/sidecar/解析产物放 S3，ES 保留有限目录和经批准的可选包摘要（默认 180 天，按类别配置）。字段多值、隧道层和 HTTP/DNS 事务的关系必须保真，不能将独立数组当同对象。详细类型、原始/派生偏移及语法见[高级检索与数据包取证设计](高级检索与数据包取证设计.md)。

## 18. 数据留存、捕获质量与文件分析

所有已启用业务数据类别默认 `retention_days=180`，租户可按类别配置；权威规则见[数据留存与生命周期设计](数据留存与生命周期设计.md)。服务端固化 `retention_anchor_at`、`expires_at`、`retention_policy_revision`、保全范围与删除栅栏。当前有效配置/活动任务不因创建满 180 天被清理；传输缓存与安全 token 的运行 TTL 不替代业务留存。

| 持久对象 | 保存位置与约束 |
| --- | --- |
| `retention_policies`, `retention_policy_revisions`, `retention_jobs`, `deletion_manifests` | PG 控制面；策略发布有预览、版本及审计，删除清单覆盖所有仍可恢复的旧备份 |
| `capture_profiles`, `inspection_profiles`, `capture_archive_jobs`, `evidence_restore_jobs` | PG 配置与稀疏任务；实际探针配置摘要回执，冷热状态、缺口与恢复水位可对账 |
| `file_analysis_profiles`, `sandbox_connectors`, `file_analysis_jobs` | PG 策略、已准入扫描任务及回执；高频 `fileinfo`/每个原包不逐条创建 PG 任务 |
| `file-occurrences`, `file-analysis-results`, `capture-quality` | ES 固定分区；来源/版本/范围与稳定幂等键，默认 180 天；质量指标按有界时间/流窗口记录 |
| PCAP、包/压缩块 sidecar、样本和持久沙箱制品 | 隔离 S3；对象版本/摘要/授权/保留协同，目录不得先于仍被引用的字节删除 |

捕获和检测是两套能力档案：前者包含接口、linktype、snaplen、过滤、卸载与扇出配置、实际观测域；后者包含引擎构建、解析器、重组/正文/文件/解压上限、内存预算、异常策略与规则摘要。保存期和冷热迁移独立配置。`capture_quality` 表示是否观察到并保留原始包，`inspection_coverage` 表示引擎实际检查范围，`evidence_quality` 表示研判引用证据的完整度/关联可信度；均含 `status`、`reason_codes`、版本与证据引用。它们不能与模型输出的置信度合并成一个分数，缺少数据也不能伪装为低风险。

捕获告警不能为每个包产生一条质量事件；计数器、受影响窗口/流与有限样本分层上报，避免磁盘满或重组失败时产生新的告警洪峰。时延字段沿用[响应性能设计](应用识别与响应性能设计.md)，保留源时钟及误差；业务事实/ES 读模型保存关键时间，不为追踪每条告警将全链路节点复制进 PG。

| `POST /api/v1/file-analyses` | 样本不可变引用、策略版本、引擎/规则库版本、静态或动态、出域授权与预算 |
| `GET /api/v1/file-analyses/{id}` | 排队/提交/扫描/报告状态、外部任务 ID、结论、限制、耗时与证据 |
| `POST /api/v1/file-analyses/{id}/cancel` | 取消意图和结果；外部 VM 停止或回收另有确认状态 |

TCP 完整会话导出默认覆盖该代次建连至关闭，要求真实握手、已验证的双向字节连续性和经序列核对的结束证据；仍在通信只允许明确命名的快照。严格请求无法满足时返回缺失项及可选模式，不能自动输出片段冒充完整通信。TCP 以 SYN、SYN-ACK、ACK 及其序列关系验证，不以包数量为三就判定成立；UDP 不适用该条件。文件分析仅对验证过的完整内容给出完整文件摘要，截断/超限/加密不可读与扫描阴性分开。详细状态和配额见[会话完整性设计](PCAP留存与会话完整性设计.md)及[文件分析设计](协议覆盖与文件分析设计.md)。
