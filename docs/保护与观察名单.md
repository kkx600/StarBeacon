# 保护与观察名单

平台「检测与狩猎 → 保护与观察名单」维护带业务有效期、匹配值和探针注册范围的配置。工程入口为 `/detection/watchlists`。名单属于工作流配置，不删除或隐藏原始告警，不将命中直接解释为误报、攻击成功或已完成封禁。

## 类型与生效范围

| 配置 | 当前行为 | 边界 |
| --- | --- | --- |
| 保护名单 `protect` | 当前有效的 IP／CIDR 范围参与新封禁授权；命中时拒绝创建新封禁任务 | 不自动撤销已签名任务或已生效租约；不阻止原租约回读与解除 |
| 观察名单 `observe` | 保存独立配置修订，核对用户提供材料的匹配结果 | 尚未自动关联新告警、推送提醒或执行历史数据回填 |
| IP `ip` | 规范 IPv4／IPv6 的精确匹配 | 拒绝地址区域标识、IPv4 映射形式、未指定和组播地址 |
| 网段 `cidr` | 规范且已掩码的 IPv4／IPv6 前缀匹配 | 没有多级审批能力时，IPv4 前缀长度小于 24、IPv6 小于 120 的配置只能停用保存，不可启用 |
| 域名 `domain` | 规范小写 ASCII／Punycode 域名的精确匹配 | 不接受通配符、URL、路径、IP 或公共后缀；不经 DNS 推断 IP，不扩大为后缀匹配，不参与单 IP 封禁保护 |

每份定义固定 `schema_version=watchlist.v1`、一种名单类型、一种匹配类型、1–64 个不重复的值，以及 1–32 个不重复的探针。范围同时绑定 `sensor_id` 与 `registration_id`；重新注册的同名探针不继承原注册范围。创建、改变定义或启用时核对所选探针当前有效注册；注册失效后仍允许停用原配置。

业务有效期采用 UTC 整秒时间，起点包含、终点不包含，起点不得早于 2000 年，区间不得超过 3,650 天。`active` 表示配置开关；只有启用、已到起点且未到终点的配置才处于业务生效期。名单有效期与历史记录的 180 天留存是两项独立配置，不能用历史记录尚存在推断名单仍有效。

## 目录与交互

页面只展示一份名单目录，支持名称关键词、类型、配置开关筛选和稳定游标翻页；默认每页 20 条，API 每页允许 1–100 条。游标绑定租户与完整筛选条件，不能跨筛选复用。读取失败保留上次读取材料并标识失败，不把错误显示为零条记录。

创建、编辑、启停均通过同一配置表单审阅完整范围。名称为 1–128 个 Unicode 字符，配置依据为 1–1,000 个单行字符；值和范围不得重复。保存依赖当前修订，不静默覆盖他人配置。详情可定位到不可变修订；材料核对使用独立弹窗，表单、详情和核对窗口在同一层切换。选择器和日期控件的 Escape 操作先作用于控件，不误关闭尚未提交的配置。

采集范围选择读取完整的有界分页探针目录，不能将第一批结果假定为全部设备。切换账号、租户或角色取消旧读取，关闭、超时和迟到响应不能覆盖当前材料。浏览器入口当前面向管理员；HTTP 目录和修订只读操作允许当前有效的同租户 admin／viewer，保存与材料核对仅允许管理员。

## 材料核对

`POST /api/v1/watchlists/preview` 接收完整定义、配置开关和最多 128 项显式材料。材料固定探针与注册身份，类型为 IP 或域名，服务端返回每项的匹配结果、核对时间、定义摘要、范围数量、值数量，以及当前是否生效和能否启用。

材料的 `matched` 仅说明匹配值与冻结范围符合定义；停用、未到生效时间或已到期时仍可能在值层面匹配。调用方必须分别核对 `active`、`admissible`、`effective` 和原因，不得把单个匹配标记作为执行许可。预览始终返回 `execution_authorized=false`、`fact_deletion_allowed=false`，不会保存名单、创建设备任务、读取任意网络地址或扫描全部 Elasticsearch 历史。用户未提供材料时，只核对配置及其准入边界。

## 新封禁授权与原任务

人工限时封禁、研判处置确认和持续策略签发新 `response.block` 时，在创建签名任务的同一数据库事务内核对名单。共享事务锁与名单变更互斥，取得锁后读取数据库实际时间，避免等待期间跨越生效点仍使用旧时刻。核对同时使用租户、探针、注册代次和目标 IP；目录损坏、超限或依赖失败时不签发部分结果。

命中有效保护范围时，人工与研判确认接口返回 `409 response_target_protected`；持续策略按确定性 `target_protected` 记录跳过，不把它当作可盲目重试的设备写入失败。此时没有新封禁任务，也没有成功授权证明。

非命中时，平台把 `response.protection.v1` 核对记录、当时的名单状态摘要、核对摘要和原签名命令摘要绑定到原任务，与操作审计原子提交。任务详情独立显示授权时依据，历史没有该记录的任务明确显示缺少记录，不能推断当时已核对保护名单。

相同原请求的精确确认只回读原任务，不在名单改变后重新授权、不延长原任务期限。名单后来启用、变更或到期，不自动撤销已经签名或已经执行的任务。采集器仍核对自身管理地址、保护网段和设备约束；平台授权时的名单记录不表示采集器在设备执行瞬间再次读取当前名单。原租约回读和条件解除保持可用，设备是否实际阻断流量仍须独立验证。

## 并发、审计与留存

保存要求 CSRF、规范的 `Idempotency-Key` 和完整 `expected_revision`，新建修订为 0，成功后递增。同账号、同键、完整相同输入返回原修订；同键改输入或旧修订返回冲突。原回执确认不返回后来的当前版本，也不消耗新的变更额度；已超过原回执留存期时不以旧键续写。

每租户最多 256 份名单，每滚动 24 小时最多 2,048 次实际变更，每份最多 1,000,000 个修订。没有物理删除入口，停用不删除目录，也不释放名单数量额度；大批量导入、归档和目录回收仍需独立设计。达到额度不丢弃历史或省略审计继续保存。

名单配置和材料核对均记录操作审计；当前目录、不可变修订及审计强制租户隔离。运行数据库角色不能改写历史。修订在保存时按 `operations` 策略固化留存，默认 180 天，用户修改策略仅影响后续修订；当前修订始终保护，不因期限早于当前时间而删除或失去正在生效的配置。非当前、已到期修订按有界历史回收处理。

任务的名单核对记录沿用原任务固化的 `operations` 期限，默认 180 天；未结束或未满足回收条件的任务保护其核对记录。回收先处理到期且可终结的子记录，再在后续轮次处理无引用的父任务，不以分类游标顺序绕过外键或未决责任。

## 接口与验收

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/watchlists` | 名称、类型和配置开关筛选；返回当前修订目录与绑定游标 |
| `POST /api/v1/watchlists` | 创建或保存配置修订，启停同样提交完整范围 |
| `GET /api/v1/watchlists/{id}/revisions/{revision}` | 读取有效历史修订或受保护的当前修订 |
| `POST /api/v1/watchlists/preview` | 核对显式材料与配置，不授予设备动作 |

输入错误为 `400 invalid_watchlist`，会话或权限变化为 `401/403`，不可访问或已回收修订为 `404`，旧修订／原键输入／注册冲突为 `409 watchlist_conflict`，数量或变更预算为 `429 watchlist_quota`，依赖或修订完整性故障为 `503 watchlist_unavailable`。接口不接受未登记的查询参数、重复参数、未知或重复 JSON 字段。详细字段见 [平台 OpenAPI](../api/openapi/platform.json)。
