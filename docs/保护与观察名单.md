# 保护与观察名单

平台「检测与狩猎 → 保护与观察名单」维护带业务有效期、匹配值和探针注册范围的配置。工程入口为 `/detection/watchlists`。名单属于工作流配置，不删除或隐藏原始告警，不将命中直接解释为误报、攻击成功或已完成封禁。

## 类型与生效范围

| 配置 | 当前行为 | 边界 |
| --- | --- | --- |
| 保护名单 `protect` | 当前有效的 IP／CIDR 范围参与新封禁授权；命中时拒绝创建新封禁任务 | 不自动撤销已签名任务或已生效租约；不阻止原租约回读与解除 |
| 观察名单 `observe` | 保存独立配置修订，核对用户提供材料的匹配结果；已启用的名单对修订保存后接收的新告警登记命中，并可对指定修订核对已入索引的历史告警 | 命中只是名单与告警的关联记录，尚未推送提醒，也不回填修订保存前的历史数据；不改写告警，不授予设备动作。历史数据只能通过影响预览核对 |
| IP `ip` | 规范 IPv4／IPv6 的精确匹配 | 拒绝地址区域标识、IPv4 映射形式、未指定和组播地址 |
| 网段 `cidr` | 规范且已掩码的 IPv4／IPv6 前缀匹配 | 没有多级审批能力时，IPv4 前缀长度小于 24、IPv6 小于 120 的配置只能停用保存，不可启用 |
| 域名 `domain` | 规范小写 ASCII／Punycode 域名的精确匹配 | 不接受通配符、URL、路径、IP 或公共后缀；不经 DNS 推断 IP，不扩大为后缀匹配，不参与单 IP 封禁保护 |

每份定义固定 `schema_version=watchlist.v1`、一种名单类型、一种匹配类型、1–64 个不重复的值，以及 1–32 个不重复的探针。范围同时绑定 `sensor_id` 与 `registration_id`；重新注册的同名探针不继承原注册范围。创建、改变定义或启用时核对所选探针当前有效注册；注册失效后仍允许停用原配置。

业务有效期采用 UTC 整秒时间，起点包含、终点不包含，起点不得早于 2000 年，区间不得超过 3,650 天。`active` 表示配置开关；只有启用、已到起点且未到终点的配置才处于业务生效期。名单有效期与历史记录的 180 天留存是两项独立配置，不能用历史记录尚存在推断名单仍有效。

## 目录与交互

页面只展示一份名单目录，支持名称关键词、类型、配置开关筛选和稳定游标翻页；默认每页 20 条，API 每页允许 1–100 条。游标绑定租户与完整筛选条件，不能跨筛选复用。读取失败保留上次读取材料并标识失败，不把错误显示为零条记录。

创建、编辑、启停均通过同一配置表单审阅完整范围。名称为 1–128 个 Unicode 字符，配置依据为 1–1,000 个单行字符；值和范围不得重复。保存依赖当前修订，不静默覆盖他人配置。详情可定位到不可变修订；材料核对使用独立弹窗，表单、详情和核对窗口在同一层切换。选择器和日期控件的 Escape 操作先作用于控件，不误关闭尚未提交的配置。

采集范围选择读取完整的有界分页探针目录，不能将第一批结果假定为全部设备。切换账号、租户或角色取消旧读取，关闭、超时和迟到响应不能覆盖当前材料。浏览器入口当前面向管理员；HTTP 目录和修订只读操作允许当前有效的同租户 admin／viewer，保存与材料核对仅允许管理员。

## 材料核对

`POST /api/v1/watchlists/preview` 接收完整定义、配置开关和最多 128 项显式材料。材料固定探针与注册身份，类型为 IP 或域名，服务端返回每项的匹配结果、核对时间、定义摘要、范围数量、值数量，以及当前是否生效和能否启用。

材料的 `matched` 仅说明匹配值与冻结范围符合定义；停用、未到生效时间或已到期时仍可能在值层面匹配。调用方必须分别核对 `active`、`admissible`、`effective` 和原因，不得把单个匹配标记作为执行许可。预览始终返回 `execution_authorized=false`、`fact_deletion_allowed=false`，不会保存名单、创建设备任务、读取任意网络地址或扫描全部 Elasticsearch 历史。用户未提供材料时，只核对配置及其准入边界。

## 命中关联

观察名单命中是名单修订与单条告警之间的关联记录，不代表攻击成立、误报、处置完成或任何设备授权，不改写、隐藏或删除告警；命中后的提醒推送尚未实现。命中只关联告警数据流中成功写入索引的告警，不关联安全日志、网络事件或调查事件。

告警成功写入索引后，平台把同一批次告警的命中在一个数据库事务内按观察名单的当前修订登记。登记与名单保存共享租户事务锁，读取到的始终是已完整保存的当前修订。以下四个条件必须同时满足：名单类型为 `observe` 且配置开关已启用；告警观测时间处于该修订的业务有效期内；告警的平台接收时间不早于该修订的创建时间；告警的 `sensor_id` 与 `registration_id` 位于名单固定的探针范围内。任一条件不满足都不登记，停用、未到起点或已到期的名单不产生新命中。

修订保存之前接收的告警不追溯登记；保存时仍在入索引管道中、接收时间早于该修订创建时间的告警同样不登记，也不补登到上一修订。命中绑定登记时的修订与定义摘要，名单之后改版、停用或到期，不删除已登记命中，也不按新修订重新判定。历史数据只能通过下文的影响预览核对。

匹配字段固定为五个，取值均为告警中实际出现的值：

| 字段 | 取值来源 | 对应匹配类型 |
| --- | --- | --- |
| `source.ip` | 告警源地址 | `ip`、`cidr` |
| `destination.ip` | 告警目的地址 | `ip`、`cidr` |
| `http.hostname` | 告警 HTTP 主机名 | `domain` |
| `tls.sni` | 原始 EVE 中的 TLS SNI | `domain` |
| `dns.rrname` | 原始 EVE 中的 DNS 查询名，每条告警最多取前 8 个 | `domain` |

只有存在已启用的域名类观察名单时才提取后三个字段，其中 TLS SNI 与 DNS 查询名需要解析原始 EVE；只有 IP 与网段名单时不为此解析原始 EVE。域名只做大小写、末尾点和 IDNA 规范化后与名单值精确比较，不经 DNS 解析扩展出 IP，不做后缀或通配匹配，IP 字面量、通配符和公共后缀不作为域名候选。IP 与网段沿用材料核对的精确与前缀匹配规则。一条命中最多记录 16 个互不重复的匹配值。

同一告警重投按稳定标识去重，该标识由租户、名单、修订、事件标识与原始摘要共同计算；重复登记不新增记录，也不重复占用处理日计数。命中冻结登记当时的规则标识、规则名称、严重级别、探针与注册代次、观测时间和接收时间，不复制告警原文；规则标识或规则名称不符合展示约束时记为空，不截断成另一个名称。

登记规模受限：每份名单每个 UTC 处理日最多逐条登记 10,000 条，单个告警批次累计最多新增 2,000 条，覆盖该批次内的所有名单。超出后不再逐条登记，只在该处理日计数上记录首次发生截断的时刻；截断后的命中次数未统计，不能用已登记条数推断实际命中总数。处理日取登记时的 UTC 日期，不是告警观测日期。

命中登记不是告警入索引的前置条件，也不保证完备。数据库超时、锁超时或连接失败等暂时性失败会使整批重投并补登；名单修订不完整、批次内容无效或名单数量超限等确定性失败重投结果不变，只记录日志并计入 `starbeacon_watchlist_hits_skipped_batches_total`，该批命中不再补登，告警索引照常确认。因此命中记录不能当作完备的告警清单，没有命中也不能推断告警未涉及名单值。

命中读取有两个入口，均允许当前有效的同租户 admin／viewer，只返回仍在留存期内的命中。`GET /api/v1/watchlists/{id}/hits` 必须提供 `start` 与 `end`，窗口不超过 31 天，终点不得晚于当前时间（允许 30 秒时钟偏差）；按告警观测时间与命中标识倒序分页，每页默认 20 条、允许 1–100 条，游标绑定租户、名单、窗口和页大小，不能跨条件复用，并同时返回窗口内发生截断的处理日。`GET /api/v1/alerts/{id}/watchlist-hits` 必须提供 `sha256` 原始摘要，只返回事件标识与摘要同时一致的命中，摘要不一致的告警不借用其他告警的关联；一条告警的命中超过 256 条时读取失败并返回 `429 watchlist_quota`，不返回部分结果。

## 历史影响预览

影响预览回答「该修订的定义涉及多少已入索引的历史告警」，是管理员发起的只读核对，不是命中回填。`POST /api/v1/watchlists/{id}/impact` 接收 `revision`、`start` 与 `end`，窗口不超过 31 天，起点不早于 2000 年，终点不得晚于当前时间（允许 30 秒时钟偏差）；仅管理员可用，要求 CSRF，不接受查询参数，也不使用 `Idempotency-Key`，每次请求单独计入额度。已到期且非当前的修订不可读取，返回 `404`。

服务端只在告警数据流内核对该修订的定义，同时限定租户、`event.kind=alert`、窗口、固定探针与注册代次以及名单值。返回命中总数 `total`、每个名单值各自的告警数、最多 20 条样本和 `checked_at` 核对时间，并带有实际查询的字段、`current`（该修订是否为名单当前修订）与 `active`（该修订的配置开关）。样本按 `@timestamp` 倒序、同刻按事件标识升序，每条样本都由服务端按名单值规则复核，不符合的材料使整次预览失败。

预览只查询已索引字段：IP 与网段类名单查 `source.ip`、`destination.ip`，域名类名单只查 `http.hostname`。`tls.sni` 与 `dns.rrname` 没有检索字段，不在预览范围，因此域名类名单的预览计数不包含仅经这两个字段才会命中的告警。域名只做大小写不敏感的精确比较，不转换末尾点或 IDNA 形式，以这些形式入索引的主机名不会被计入。窗口按告警 `@timestamp` 计，命中读取按告警观测时间 `observed_at` 计，两者不是同一个时间字段。

预览不判断配置开关、业务有效期和修订创建时间，只按该修订所含的值与探针范围核对，结果也不与已登记命中互相校验。因此预览总数不等于已登记或将登记的命中数，不能当作实时命中口径。预览不登记命中、不回填历史、不改变命中读取结果、不创建设备任务、不授予设备动作，响应固定 `hits_recorded=false`、`execution_authorized=false`；对保护名单修订同样可核对，结果不改变其封禁保护行为。

检索超时、分片失败或不完整、命中总数非精确、聚合桶与名单值不一一对应，或返回材料与租户、窗口、探针范围、名单值或排序不一致时，整次预览失败，不交付部分计数或样本，告警索引不可用时同样如此，返回 `503 watchlist_impact_incomplete`。

预览有滚动窗口额度：每租户滚动 24 小时最多 200 次，超限返回 `429 watchlist_quota`。额度按操作审计 `watchlist.impact` 计数，审计先于检索提交，检索失败的预览不退还额度；权限不足或修订不可读取的请求不占用额度。

## 新封禁授权与原任务

人工限时封禁、研判处置确认和持续策略签发新 `response.block` 时，在创建签名任务的同一数据库事务内核对名单。共享事务锁与名单变更互斥，取得锁后读取数据库实际时间，避免等待期间跨越生效点仍使用旧时刻。核对同时使用租户、探针、注册代次和目标 IP；目录损坏、超限或依赖失败时不签发部分结果。

命中有效保护范围时，人工与研判确认接口返回 `409 response_target_protected`；持续策略按确定性 `target_protected` 记录跳过，不把它当作可盲目重试的设备写入失败。此时没有新封禁任务，也没有成功授权证明。

非命中时，平台把 `response.protection.v1` 核对记录、当时的名单状态摘要、核对摘要和原签名命令摘要绑定到原任务，与操作审计原子提交。任务详情独立显示授权时依据；封禁任务缺少该记录或记录不完整时详情不予采信并提示刷新核对，不能推断当时已核对保护名单。

相同原请求的精确确认只回读原任务，不在名单改变后重新授权、不延长原任务期限。名单后来启用、变更或到期，不自动撤销已经签名或已经执行的任务。采集器仍核对自身管理地址、保护网段和设备约束；平台授权时的名单记录不表示采集器在设备执行瞬间再次读取当前名单。原租约回读和条件解除保持可用，设备是否实际阻断流量仍须独立验证。

## 并发、审计与留存

保存要求 CSRF、规范的 `Idempotency-Key` 和完整 `expected_revision`，新建修订为 0，成功后递增。同账号、同键、完整相同输入返回原修订；同键改输入或旧修订返回冲突。原回执确认不返回后来的当前版本，也不消耗新的变更额度；已超过原回执留存期时不以旧键续写。

每租户最多 256 份名单，每滚动 24 小时最多 2,048 次实际变更，每份最多 1,000,000 个修订。没有物理删除入口，停用不删除目录，也不释放名单数量额度；大批量导入、归档和目录回收仍需独立设计。达到额度不丢弃历史或省略审计继续保存。

名单配置、材料核对和历史影响预览均记录操作审计；当前目录、不可变修订及审计强制租户隔离。运行数据库角色不能改写历史。修订在保存时按 `operations` 策略固化留存，默认 180 天，用户修改策略仅影响后续修订；当前修订始终保护，不因期限早于当前时间而删除或失去正在生效的配置。非当前、已到期修订按有界历史回收处理。

观察名单命中在登记时按 `alerts` 留存分类固化期限，默认 180 天；处理日计数的期限从该处理日（UTC）结束时起算，使用同一天数。用户修改策略仅影响后续登记，不重算已登记的命中与计数。命中和处理日计数均强制租户隔离，到期前不能删除，到期后按有界历史回收处理；名单停用、改版或到期不触发命中删除。运行数据库角色对命中记录只有读取、写入和删除权限，没有更新权限，已登记的命中不可改写；处理日计数由登记事务更新登记数和截断时刻，该表因此另有更新权限。

非当前修订若仍被未到期的命中引用，到期后也不回收，直到引用它的命中全部到期，使命中能回溯登记时的定义；命中同时保存登记时的 `definition_sha256`。该保护只保证修订继续保存，不放宽修订读取条件：已到期且非当前的修订仍不可通过修订接口或影响预览读取。

任务的名单核对记录沿用原任务固化的 `operations` 期限，默认 180 天；未结束或未满足回收条件的任务保护其核对记录。回收先处理到期且可终结的子记录，再在后续轮次处理无引用的父任务，不以分类游标顺序绕过外键或未决责任。

## 接口与验收

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/watchlists` | 名称、类型和配置开关筛选；返回当前修订目录与绑定游标 |
| `POST /api/v1/watchlists` | 创建或保存配置修订，启停同样提交完整范围 |
| `GET /api/v1/watchlists/{id}/revisions/{revision}` | 读取有效历史修订或受保护的当前修订 |
| `POST /api/v1/watchlists/preview` | 核对显式材料与配置，不授予设备动作 |
| `GET /api/v1/watchlists/{id}/hits` | 按告警观测时间倒序读取单份名单在窗口内的命中，绑定游标；admin 与 viewer 均可 |
| `GET /api/v1/alerts/{id}/watchlist-hits` | 按告警身份与原始摘要读取该告警的全部命中；admin 与 viewer 均可 |
| `POST /api/v1/watchlists/{id}/impact` | 对指定修订在有界窗口内核对已入索引的历史告警，不登记命中、不授予设备动作；仅管理员 |

输入错误为 `400 invalid_watchlist`，会话或权限变化为 `401/403`，不可访问或已回收修订为 `404`，旧修订／原键输入／注册冲突为 `409 watchlist_conflict`，数量、变更或历史影响预览预算为 `429 watchlist_quota`，历史告警检索不完整为 `503 watchlist_impact_incomplete`（本次不交付计数），其余依赖或修订完整性故障为 `503 watchlist_unavailable`。接口不接受未登记的查询参数、重复参数、未知或重复 JSON 字段。详细字段见 [平台 OpenAPI](../api/openapi/platform.json)。
