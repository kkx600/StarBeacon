# 星烽 StarBeacon 连接阻断设计

连接阻断在防火墙或 EDR 的持久封禁生效之前，先暂停或断开当前这条连接。按采集器的部署位置分两种通道：

| 通道 | 适用部署 | 方式 | 状态 |
| --- | --- | --- | --- |
| 受控网关阻断 | 采集器运行在转发路径上的 Linux 网关 | nftables 限时条目，5–60 秒 | 已实现，见第 1–8 节 |
| 旁路 RST 注入 | 镜像口（SPAN／TAP）部署 | 从独立注入网口向连接两端发送 TCP RST，UDP 发 ICMP 不可达 | v1.0.0 规划，见第 9–14 节 |

受控网关方案在 2026-11-26 确认；2026-11-27 决定在 v1.0.0 补回旁路 RST 注入，供镜像口部署使用。两种通道共用策略、保护名单、分钟限额、全局自动化上限和应急停止，记录在同一页面。连接阻断都不能代替设备上的持久封禁。工程能力与验收状态见[功能实现与验收状态](功能实现与验收状态.md)。

## 1. 两种触发方式

| 方式 | 触发依据 | 执行过程 |
| --- | --- | --- |
| 规则即时触发 | 已索引的原生检测告警与已授权的规则编号和修订一致 | 索引器登记候选请求。对应网关的控制流每秒检查一次资格并领取签名任务 |
| 研判后触发 | 管理员针对仍在有效窗口内的告警确认研判结论 | 平台回读原告警与研判修订，再登记同一种阻断请求 |

两种方式都使用原始告警中已观测的 TCP 或 UDP 五元组。规则触发验证最近 20 秒的检测、观测和接收时刻，研判触发的窗口为 2 分钟。策略和平台设置修改之后收到的新观测才有资格。实际时延分别按观测到网关回读、请求登记到网关回读计量。

## 2. 网络前提与本地配置

网关上的采集器使用自己所在的 Linux 转发网络命名空间。运营人员应确认正反向路径都经过此网关，且五元组与观测一致。采集器与平台使用现有双向认证控制流。

管理员先在受控网关核对并加载 [转发链与限时集合模板](../deploy/gateway/nftables.conf)。模板作用于独立的 `inet starbeacon_gateway` 表。采集器运行账户需要能读取该表并创建其限时集合条目。运行账户的网络管理权限限定在受控网关的网络命名空间。

采集器的 `SB_GATEWAY_BLOCK_FILE` 取本机配置的绝对路径。配置须为常规文件，组和其他用户没有写权限。下列地址属于验收用的专属 Docker 子网。

```json
{
  "enabled": true,
  "observe_interface": "eth2",
  "scope": {
    "sources": ["10.203.35.3/32"],
    "destinations": ["10.203.36.3/32"]
  }
}
```

采集器在心跳登记配置摘要和可用状态，在每次执行前重新读取配置，核对项包括开关、作用范围、签名绑定和对应的双向转发规则。未提供本地配置时功能默认关闭。需要观察时，将可选的 `observe_interface` 设置为原告警方向实际转发的同命名空间出侧以太网接口，并授予采集器该命名空间的 `CAP_NET_RAW`。

## 3. 执行边界

网关为该五元组创建一条内核限时记录，匹配正向和反向转发。平台授予 5 至 60 秒的租约，实际条目的到期时刻受授权截止时间约束。其他源端口的连接继续使用正常转发规则。租约由内核计时，到期自动回收。两种发起方式都采用单次条件创建，并独立读回条目、任务归属和剩余期限。[nftables 官方手册](https://netfilter.org/projects/nftables/manpage.html)

独立回读仅确认该防火墙条目。应用是否交付、是否出现新的连接及其影响需要流量观察。规则停用与平台总开关控制后续签发。已签发的执行窗口最长 4 秒，采集器本地停用在执行前生效，已生效条目根据原租约到期。

## 4. 授权和保护

| 层 | 要求 |
| --- | --- |
| 采集器 | 本地开关和两侧 CIDR 授权有效，网关配置摘要已通过心跳登记 |
| 平台开关 | 租户总开关明确启用，两种触发共享一个滚动 60 秒限额 |
| 平台策略 | 绑定采集器及注册代次、明确的检测规则与修订、发起方式、两侧 CIDR 和授权有效期 |
| 执行申请 | 源地址与目的地址都经过当前保护名单核对，原规则或确认研判仍有效，连接有完整观测 |

策略与设置使用预期修订更新。签发、共享限额、活动连接租约、绑定的保护名单摘要和审计同事务登记。相同事件只登记一次。保护名单命中、限额、授权变化和观测失效均可通过请求状态查询。保护名单机制见[保护与观察名单](保护与观察名单.md)。

平台提供 `/api/v1/gateway-block/settings`、`/api/v1/gateway-block/policies` 和 `/api/v1/gateway-block/requests`。管理员通过 `POST /api/v1/alerts/{id}/gateway-blocks` 为当前确认的研判提交请求。关联任务返回网关独立回读结果。

## 5. 效果观察

采集器在独立读回防火墙条目后，开始 5 秒的出侧观察。观察限定在本地指定接口和发送方向，读取判断五元组所需的报头，记录计数及首条重连身份。TCP 按同一对端点和服务上的新源端口起始握手识别重连，UDP 按同样范围内新源端口的数据识别新会话。已建立的对照 TCP 连接可作为观察口有采样的证据。[Linux packet(7)](https://man7.org/linux/man-pages/man7/packet.7.html)

| 结果 | 含义 | 后续 |
| --- | --- | --- |
| 流量暂停 | 完整窗口中有出侧采样，原连接没有新增数据且没有符合条件的重连 | 复核该策略的联动预授权 |
| 仍有流量 | 发现原连接数据或同一服务上的重连 | 通过订阅质量事件的渠道通知值班员，记录页展示相关连接 |
| 结果未知 | 观察口不可用、丢包、同端点报头无法判定、窗口不足、无采样或本地绑定发生变化 | 保留防火墙回读和已取得的证据 |

采用已确认的方案 B。启用自动联动时，策略必须绑定同一采集器上已发布的联动插件、部署代次、设备连接器配置摘要、源或目的地址方向、封禁时长。网关租约应为 8 至 60 秒，联动封禁为 30 秒至设备限额。观察暂停后，平台在 15 秒内使用观察后上报的心跳复核授权。签名、策略修订、研判、双端保护名单、插件部署和设备绑定全部仍有效时，才按预算、滚动限额及目标冷却签发独立的 `response.block` 任务。设备是否受理与独立读回由响应任务记录。

## 6. 记录

每条请求保留事件身份、五元组、绑定采集器、触发方式、策略修订、研判修订、授权人与时间、拒绝原因、命令和原租约截止时间。防火墙回读包含观测窗口、出侧和原连接计数及可能的重连连接。独立的联动任务链接保留签发和设备回执状态。请求留存期限跟随响应动作。

## 7. 页面

“响应中心 → 响应动作 → 连接阻断”（当前名为“网关阻断”，v1.0.0 改名）展示请求与观察记录，支持核对近 24 小时计数、独立回读与关联设备任务。顶部显示平台开关和可用网关数量。租户总开关、限额和策略由管理员通过系统设置中的“网关阻断”分类使用预期修订维护。原型布局参考 `prototype/src/views/BypassView.vue`。

## 8. 验收要点

1. 在 `home_dev` 的独立 Docker 转发路径验证正常流量、默认关闭与准确的本地配置回读。
2. 两种触发各验证选中连接的数据在网关出侧停止，源端口不同的对照连接继续，记录请求到独立回读的时延及两侧抓包数量。
3. 验证双端保护名单、共用分钟限额、同一事件去重、到期恢复以及策略或研判修订变化后拒绝下发。
4. T34 在相同网络验证三种观察结果、重连与后续联动授权。

## 9. 旁路 RST 注入：触发方式

| 方式 | 触发依据 | 执行过程 |
| --- | --- | --- |
| 规则即时触发 | 原生检测命中阻断策略选中的规则编号和修订 | Suricata 对选中的规则使用 `rejectboth` 动作，启动参数 `--reject-dev=<注入网口>` 指定发送网口，命中即由引擎发出 RST 或 ICMP 不可达。只有选中的规则改写动作，其余保持 `alert`；改写随规则发布流程签名下发 |
| 研判后触发 | 管理员确认研判，或自动编排、决策策略按自动化级别签发 | 平台签发任务，采集器的注入器在镜像口等待该连接的下一个报文，用其中的序号向两端各发一个 RST。连接空闲、取不到有效序号时记为“未注入” |

两种触发共用第 4 节的策略字段（采集器与注册代次、规则与修订、两侧 CIDR、授权有效期），策略增加“通道”字段。Suricata 规则动作的官方说明见[规则动作](https://docs.suricata.io/en/suricata-8.0.7/rules/intro.html)和[命令行参数](https://docs.suricata.io/en/suricata-8.0.7/command-line-options.html)。

## 10. 旁路 RST 注入：网络前提与本地配置

上线前逐项确认，任何一项不满足就不启用：

1. 有独立的注入网口，不与镜像口、管理口混用。
2. 注入报文能到达连接至少一端。报文的源地址是伪造的，路径上的反欺骗检查和端口安全策略可能丢弃它。
3. 注入点与镜像点在地址转换的同一侧，否则地址、端口和序号与对端实际使用的不一致。
4. 交换机允许该端口发送这类报文，并取得网络负责人的书面同意。

采集器用本地配置文件声明开关、注入网口和两侧 CIDR，默认关闭；文件要求与第 2 节相同。采集器只对注入网口持有 `CAP_NET_RAW`。心跳登记配置摘要，执行前重新读取。

## 11. 旁路 RST 注入：能力边界

- 不保证断开：伪造的 RST 可能晚于真实报文到达，序号过期的 RST 会被忽略。
- 对 UDP 和 QUIC 效果有限：只能发 ICMP 不可达，很多协议栈和应用不理会。
- 挡不住重连：客户端可以立刻重新建立连接，持久封禁要靠联动插件。
- 撤不回已经送达业务的请求。

页面只显示注入了什么、观察到了什么，不出现“已拦截”“已阻止攻击”这类说法。

## 12. 旁路 RST 注入：授权、限额与效果观察

- 与网关通道共用保护名单核对、租户总开关、滚动 60 秒限额，并受全局自动化上限、暂停自动处置和应急停止约束（见 [AI 自动化处置设计](AI自动化处置设计.md)第 2、10 节）。
- 注入后观察 5 秒：

| 结果 | 含义 | 后续 |
| --- | --- | --- |
| 已终止 | 观察期内该连接没有新的数据报文，也没有符合条件的重连 | 按策略的预授权转联动插件做限时封禁，规则同第 5 节方案 B |
| 仍有流量 | 观察期内还有数据，或对方很快重连 | 发送处置通知，并按预授权转联动插件封禁 |
| 结果未知 | 镜像口在观察期内丢包或离线，无法判断 | 等联动插件确认，不重复注入 |

“未注入”和“保护名单拦截”单独记录。

## 13. 旁路 RST 注入：记录与页面

每条请求在第 6 节字段之外，增加通道、注入报文类型与数量、序号来源和观察窗口。连接阻断页面用“通道”列区分受控网关和 RST 注入，指标按通道分别统计。系统设置的“连接阻断”分类分别配置两种通道的总开关、限额和策略，原型见 `prototype/src/views/BypassView.vue` 与 `prototype/src/views/SystemSettingsView.vue`。

## 14. 旁路 RST 注入：验收要点

1. 默认关闭：没有同时打开采集器开关和平台策略时，不发出任何注入报文。
2. 两种触发在 `home_dev` 的隔离网络各自断开指定连接，测出从命中到发出 RST 的时延分布；对照连接不受影响。
3. 保护名单、分钟限额、暂停自动处置和应急停止生效。
4. 三种观察结果与抓包对照一致，能识别重连。
5. 不影响镜像口收包和检测：开启前后丢包率和告警时延没有明显变化。
6. 实机验收：在真实交换机镜像环境验证注入报文可达，记录可达性和失败原因。
