# 星烽 StarBeacon 运营与集成设计

本文将检索取证、资产、探针、监控、自动响应、通知、Syslog 和审计落实为页面、字段、状态与验收契约。基准日：2026-09-30。所有默认值属于可调整的设计起点；尚未实施或压测。基础架构见[架构设计](架构设计.md)，规则与 AI 生成见[规则管理设计](规则管理设计.md)，完整菜单能力与验收见[功能覆盖与验收矩阵](功能覆盖与验收矩阵.md)。

## 2. 告警检索

### 2.1 可检索字段与语义

| 分组 | 字段 | 运算与约束 |
| --- | --- | --- |
| 时间 | 发生、接收、分析完成、首次处理时间 | 默认发生时间；明确 UTC 存储和租户时区；半开区间 |
| 地址 | `source.ip`、`destination.ip`、源／目的端口 | IP 精确、IP 列表、IPv4/IPv6 CIDR、端口范围；源与攻击者身份分开 |
| 二层与观测 | MAC、VLAN 栈、链路层次、观测接口/网络域 | MAC 规范化精确/集合/字节前缀；多值层次关系不使用扁平 AND 误配 |
| 包与方向时间 | 捕获时间、rx/tx、入站/出站 first/last、clock source/resolution | 只有真实观测到的字段可查；时间含精度/误差/未知原因，不以平台接收时间替代 |
| 协议 | `network.transport`、`network.protocol` | TCP/UDP/ICMP 为传输层，HTTP/DNS/TLS 等为应用层，不能混成一个字段 |
| HTTP | method、host、path、query、状态码、User-Agent、Content-Type | GET/POST 等按规范化枚举；host 规范化；path 保留大小写及原始编码 |
| 检测 | SID、rev、规则源、规则集版本、威胁类型、严重度、标签 | 精确与集合；可按规则消息全文检索 |
| 归属 | 探针、站点、安全域、组织、网段、资产、资产组、责任人 | 默认事件发生时快照；切换当前归属需显式选择 |
| 研判 | 有效性、行为性质、攻击结果、证据充分度、模型／策略版本 | 人工确认与模型结论分别筛选；未知不是否 |
| 处置 | 处理状态、审批状态、封禁状态、执行设备、TTL、验证结果 | 设备接受、配置生效、攻击遏制分别展示 |
| 证据 | PCAP 分层、默认180天可配置期限、归档状态、握手/双向/结束/缺口、检测截断 | 原始捕获、归档和检测覆盖分别显示；无权限不能伪装成没有证据 |

筛选器支持 AND、有限层 OR、排除、存在／缺失；默认最多 50 个条件、5 层、一次 IP/CIDR 条件最多 1,000 项，超出使用有版本的 IP 集合引用。默认查询最近 24 小时，交互查询最长 31 天，跨更长窗口走异步任务或授权汇总。上述上限可按租户调整，服务端仍有硬上限。

文本模式提供 Wireshark 风格比较、逻辑、集合、存在与类型化字段别名；事件索引模式和原生 PCAP 模式显示不同能力。多值的 any/all、`!=` 与逻辑否定、缺失和未知、contains/matches、字节切片及协议层引用都有明确语义，详见[高级检索与数据包取证设计](高级检索与数据包取证设计.md)。普通事件检索不运行任意 PCRE2；需要原生正则/重组/协议字段时显式进入受限报文作业，不能静默更换执行模式或删掉不支持的条件。

事件时间与分区时间独立。默认枚举租户仍保留的授权事实及补录分区，再按事件时间过滤；不能仅按查询日期拼出同名索引。性能裁剪依赖服务端分区目录的完整 min/max event_time 与水位，未封闭或覆盖未知的分区不得被排除。列表返回总数精确性、字段覆盖、迟到和分区失败信息，部分结果不能展示为全量零命中。

Path 提供“精确”“前缀”“包含”三种模式。`/Admin` 与 `/admin` 默认不同；原始 `%2F` 与解码 `/` 分开字段，不能随意替换后当作同一原始证据。查询参数分原文与白名单结构化键，Cookie、Authorization、密码类参数不进入普通全文索引。HTTP/2 的语义字段来自引擎解析，不伪装成原始 HTTP/1 文本。TLS 未解密时方法和路径显示不可见，不返回空字符串来暗示确实不存在。

组合查询、聚合、分页、全选和导出使用相同 Query AST、权限版本和数据快照。全选全部结果生成不可变选择任务，显示命中数、冻结时间及有效期；执行前重新鉴权，并核对工作流版本，避免处理在查询后已被他人修改的对象。

### 2.2 ES 映射、分词与索引成本

| 字段类型 | ES 设计 | 使用原因 |
| --- | --- | --- |
| IP | `ip` | 支持 IPv4/IPv6 与网段条件，禁止中文分词 |
| ID／SID／tenant／状态／method | `keyword` | 精确筛选、聚合和排序；大整数标识统一字符串 |
| 端口／状态码／字节数 | 合适的整数类型 | 约束范围，避免错误类型导致批次失败 |
| 时间 | `date` 或确需时 `date_nanos` | 精度按数据集固定；不为全部指标默认使用纳秒 |
| 规则名／描述／调查摘要 | `text` + `keyword` 子字段 | 全文搜索与精确聚合分开；长值不进入聚合子字段 |
| 中文说明 | 默认内置 `cjk` 分析器，原值另存 | 无外部分词依赖；对专用安全词维护可评测查询词表 |
| host | 规范化 `keyword` + 原始值 | 域名小写、尾点、IDNA 处理策略固定版本 |
| path | 原值 `keyword`；受限派生 `wildcard` 字段 | 精确／前缀与包含查询区分，包含查询只在缩小时间范围后开放 |
| 少量扩展属性 | 字段白名单或 `flattened` | 避免任意 HTTP header／参数制造字段爆炸 |
| 原始 EVE／大正文 | `index:false` 或对象 `enabled:false`，保留 `_source` | 查看原文不等于索引每个字节；完整大载荷按证据对象读取 |

起点为显式模板、根级受控动态字段、字段总数上限 1,000、keyword 聚合子字段长度上限 1,024 个字符；超长值仍可保留原文并标记不可精确索引，不能无声丢弃。严格 schema 不匹配的数据进入隔离与可重放队列，不静默抛掉原始告警。抓到的新字段先映射审核，不在集群运行时无限扩展。

SmartCN 是需要安装到全部相关 ES 节点并重启的官方插件，可作为中文检索评测后选项，版本必须与 ES 9.5.4 一致；不是默认已内置能力。第三方 IK 只在确认版本、词典维护和升级成本后启用，不作为首期必需依赖。分析器或字典变化不自动改写旧倒排索引，需新模板、重建索引、查询验证和别名切换。SID、IP、method、path 仍保留精确字段。[Elastic 分析器](https://www.elastic.co/docs/reference/text-analysis/analysis-lang-analyzer)；[SmartCN](https://www.elastic.co/docs/reference/elasticsearch/plugins/analysis-smartcn)

不用 `query_string` 接收用户原文，也不开放脚本和无界正则。包含查询限制字段、字符数、并发、超时和查询成本；普通列表禁止任意 leading wildcard。高基数 IP、URL 排名限制桶数，长窗改用异步 composite 聚合或汇总。PIT + `search_after` 使用稳定排序 `event_time,event_id`，各页沿用返回的最新 PIT 标识；游标加密或签名，绑定查询和授权，过期后提示重新查询。[PIT 分页](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results)

### 2.3 查询一致性

`alert-search` 同时包含原始可筛选字段、归属快照、当前研判与工作流状态；禁止应用层分页后再跨库过滤。返回 `total.relation`、精确或近似标记、数据水位和投影延迟。默认总数超过统计上限可显示“超过 10,000 条”；需要精确总数时显式发起受限统计，不把截断值当成实际总数。报告的原始告警量从不可变事实索引计算，模型降噪不能减少原始计数。

## 3. HEX、协议与解码工作台

详情分概览、请求响应、包列表、重组流、HEX、原始 EVE、历史研判、处置记录。打开时明确当前对象来自单包、重组方向流、应用层 buffer 或上传 HTTP Raw，不能将几种偏移混用。

HEX 视图默认每行 16 字节，左侧十六进制 offset、中间字节值、右侧可打印 ASCII，支持 8/16/32 字节每行、字节选择、十六进制查找、复制 hex／Base64／文本和跳转偏移。包内偏移、流方向偏移和对象文件偏移分开显示；协议树选中字段时定位可验证的原始字节区间。重组或解码不能一一映射时展示映射不可用，不能编造高亮位置。

UTF-8 使用严格解码报告无效字节位置，用户可切换带替换字符的阅读视图；替换结果是派生显示，不覆盖原始字节。URL percent、Base64、Unicode 转义及允许的压缩解码均由用户明确选择，展示每步输入／输出长度、算法、参数、错误与摘要。递归最多 3 层、单次输出默认 8 MiB、解压比默认不超过 100 倍并限制 CPU／时间，防止解压炸弹或非法样本耗尽资源；超限允许授权异步分析。

大对象通过受控字节范围接口按 64 KiB 读取，每次授权并限制可读取范围；列表与浏览器不一次下载几 GB PCAP。不同层的文本通过转义文本组件展示，禁止执行抓包中的 HTML／JavaScript；本地工作台不自动访问 Host、URL 或解码得到的链接。原文、摘要和派生证据分别记录 SHA-256、解析器版本、截断长度、缺包、加密与时间缺口。

同一捕获切片可能包含多个业务组织的流量。单流读取/下载先确定授权 packet 集合，再生成带原始定位与 hash 的派生制品；只有覆盖全部对象范围的授权才能读取整个原始对象。原始载荷默认要求两个受管端都在授权范围内，外部端按租户取证策略处理；单端摘要权限不能升级为整包权限。要求即时撤权的字节/导出通过网关再次鉴权；已经签发的 S3 URL 在到期前仍可能有效，不能声称改权限后自动失效。

字段脱敏不能伪造原始取证文件：普通角色看脱敏派生视图，授权角色申请原始字节；字节不可见时遮罩偏移并提示，普通复制不能绕过脱敏。下载与保全独立授权，审计记录请求范围和结果，不将完整 payload 写入日志。

## 4. 资产、资产组与网段

资产具有稳定 `asset_id`；IP 不是主键。地址关系由 tenant、site、network namespace（VPC/VLAN/VRF 等）、地址与有效时间共同定义，支持多网卡、多 IP、DHCP、NAT 映射和共享出口。未知源地址是观测对象，经过认领或可信 CMDB 确认后成为管理资产。

资产状态为待确认、在用、维护、退库；退库不删除历史事件。导入采用预校验、冲突清单、幂等导入任务和批次撤销；外部 CMDB ID 带来源命名空间，字段注明可信来源和人工覆盖规则。责任人离职、业务系统删除等情况显示待认领，不把无主资产直接隐藏。

| 对象 | 主要字段 | 核心行为 |
| --- | --- | --- |
| 网段 | CIDR、IPv4/IPv6、站点、网络域、安全域、责任组织、优先级、用途、有效期 | 输入规范化，禁止不明网络域的跨租户匹配 |
| 安全域 | 互联网、办公、生产、DMZ、管理、自定义 | 决定流量方向与保护策略；不是单纯地图分类 |
| 静态资产组 | 明确资产列表、负责人、可见范围 | 人工维护，导入导出与成员变更有审计 |
| 动态资产组 | 受限标签／网段／业务条件 AST、求值版本 | 保存前预览命中数量；定时及变更驱动重算 |
| 业务系统 | 资产关系、重要性、负责人、服务时间、关联组织 | 可影响告警优先级和响应审批要求 |

同一网络域的网段重叠采用最长前缀匹配，再按明确配置的优先级；同前缀同优先级但归属不同则阻止发布并要求解决冲突。跨网络域的相同 CIDR 可以共存。网络观察位置、NAT 前后地址和代理头分别保留；未经可信代理配置不将客户端头当作真实源 IP。

MAC/网卡与 DHCP、ARP、NDP、NAT/PAT 和用户登录关系保存来源及有效窗；MAC 不能单独作为永久资产主键。NAT 映射包含转换前后双方 IP+端口、L4、网络域、设备连接标识和时间区间，歧义显示候选而不自动合并。需要唯一终端的响应策略遇到 ambiguous/unknown 必须停止自动执行。具体工作流见[安全运营与数据治理设计](安全运营与数据治理设计.md)。

动态分组不能因用户权限限制而把无权资产错误移出全局组；服务端按完整授权管理范围求值，前端只见可见成员。分组用于自动封禁时冻结策略版本和影响范围，组变化超过设定比例触发复核或影子模式。组织、标签、责任人和资产组成员关系采用带 valid_from/valid_to 的完整版本记录，并保存 recorded_at 修订时间；地址历史不是唯一需要保留的历史。迟到告警按事件时间重建快照，历史缺失或有效期冲突时标为归属待确认，不用当前值补成已知历史。历史告警保留事件时资产快照；“按当前组织重看历史”作为独立查询模式，日报默认不随组织迁移重写。

## 5. 探针管理与健康数据

探针列表显示名称、站点、组织、角色、IP、代理／Suricata／规则包版本、证书到期、最近心跳、最近流量、最新索引时间、CPU、内存、磁盘、带宽、丢包和维护状态。CPU 与内存显示主机和引擎进程两个视角，不把一个进程的多核百分比混作主机总利用率。

| 数据 | 采样起点 | 字段与处理 |
| --- | --- | --- |
| 心跳 | 15 秒 | 注册代次、boot_id、uptime、观测时间、时钟偏差、任务水位 |
| 主机资源 | 15 秒，60 秒聚合上报 | CPU 核数／利用率、内存 total/available/RSS、swap、load、磁盘容量／inode／IO |
| 采集质量 | 15 秒或引擎原生周期 | 接口 bytes/packets、pps/bps、内核丢包、引擎丢包、流重组缺口、解析错误 |
| 数据链路 | 15 秒 | EVE bytes/s、WAL 字节／最老年龄、接收 ACK 水位、队列／索引／可见延迟 |
| PCAP | 60 秒及状态变化 | 热存与180天归档可用窗、本地缓冲、上传/提升积压、握手缺失率、对象数、校验失败、保全未完成 |
| 版本与配置 | 启动、变化和每日核对 | desired/active 配置与包 hash、实际引擎版本、插件能力、证书状态 |

带宽由累计字节差分计算，考虑计数器复位和单调时间；CPU、丢包分母及计数器来源在详情可见。缺测为未知，不能以 0 补齐。Prometheus 单个 TSDB 默认保留 180 天运行指标；产品健康历史由白名单聚合作业写 ES `health-metrics-1m` 和 `health-metrics-1h`，两者同样默认 180 天，可配置，记录窗口、样本数、缺测、修订、min/max/sum/count，分位数仅在有正确直方图来源时合并。汇总有唯一键与补算水位；不要对各探针 P95 求平均当平台 P95。该设计不依赖 recording rules 提供不同留存，且需另计 ES 汇总容量。[Prometheus 存储](https://prometheus.io/docs/prometheus/latest/storage/)

连续 3 个心跳周期缺失显示连接异常，6 个周期显示离线；检测状态另分正常、无流量、丢包偏高、解析异常、积压、磁盘不足、维护中。阈值按接口速率及站点流量时段配置。探针在线但 Suricata 退出必须单独告警；零告警不等于检测健康。

注册、重新注册、改归属、停用、证书吊销、配置发布、规则发布、升级、诊断均有任务记录。停用不会自动清除本地待上传 WAL；退役流程先决定补传／销毁，再吊销身份。升级分批、检查版本兼容、预留磁盘、保留前版本和失败恢复；二进制签名与配置摘要校验先于执行。诊断包自动去除密钥、会话和业务载荷，敏感扩展采集需明确权限。

采集器同时提供独立本地管理入口，由现场管理员配置管理口、镜像网卡、平台注册与维护。主平台探针详情关联受信入口，控制任务仍由采集器主动连接接收；本地登录与设备证书、平台登录彼此独立。网络变更、规则同步、系统升级及恢复流程见[采集器管理与部署设计](采集器管理与部署设计.md)。

## 6. 平台监控与容量告警

平台运行页展示控制面、数据单元、存储、AI、连接器、通知链路与备份的服务状态，并可下钻受影响租户／探针。就绪检查不因可选 LLM 故障使采集入口整体摘流；关键依赖异常按服务角色影响判断。

| 链路 | 指标 | 需呈现的业务影响 |
| --- | --- | --- |
| 接入／队列 | EPS、bytes/s、ACK P95、积压字节／年龄、副本健康、重投、拒收 | 哪些探针数据还未持久接收、距离本地溢出多久 |
| ES | Bulk 分项失败、429、refresh 延迟、查询 P95、分片、水位、堆／GC、投影滞后 | 最近可查时间，原始事实和读模型的差距 |
| PG／Redis | 连接池等待、锁、事务时延、WAL／复制、缓存命中、内存淘汰、故障转移 | 配置与任务是否可写，缓存是否正在回源 |
| 对象存储 | 请求失败、吞吐、可用容量、上传遗留、保全与生命周期失败 | 哪些证据不可用，保全是否真正生效 |
| 模型 | 并发、等待、超时、schema 失败、拒答、校准漂移、token／费用 | 分析未完成、自动处置资格暂停及预算剩余 |
| 响应／集成 | Runner 心跳、认证期限、待核对动作、到期未解封、设备容量 | 生效未知、可能影响业务的逾期封禁 |
| 通知／Syslog | 最老积压、失败率、限流、transport_written 与确认水位 | 通知延迟与外部日志可能缺失的范围 |
| 备份 | 最近成功时间、校验、恢复演练结果、密钥可恢复状态 | 可恢复点与距约定 RPO 的差距 |

Prometheus 不使用每告警 ID、任意 IP、完整 URL 作为标签。租户维度只在受控数量下开放；详细高基数记录在 ES 检索。SaaS 租户只能看自己用量和健康，平台管理员可看整体资源但不默认获得客户载荷权限。健康事件可进入通知中心，设置恢复通知、持续窗口和抑制，避免一台 ES 故障引起上千条衍生告警。

## 7. 态势大屏

提供综合态势、资产风险、网络威胁、内部异常、响应运营、监测覆盖、应用流量和响应效能模板。应用模板支持百度网盘、爱奇艺等产品的规则归因、带宽与会话，并始终显示未知／混合流量；详见[应用识别与响应性能设计](应用识别与响应性能设计.md)。组件为关键指标、趋势、威胁类型、关键资产、事件时间线、响应漏斗、地图／拓扑与数据健康；地图和攻击线不是主要验收指标。模板可配置布局、时间窗、刷新周期和组织范围，保存后按权限共享。

1440p/1080p 与 4K 屏幕分别验收，支持 16:9 默认布局和容器缩放。综合大屏默认 30 秒刷新，后端汇总缓存 15–60 秒；应用流量大屏默认 5 秒刷新，使用独立的 5 秒聚合，隐藏标签暂停刷新，避免几十个屏幕同时执行全量 ES 聚合。每个数字携带统计定义、数据截止时间与覆盖范围，点击继承筛选；投屏身份只读、最小范围、有有效期，不使用管理员永久 token。

“零事件”“尚无数据”“统计延迟”“仅覆盖部分探针”分别显示。攻击者位置为 IP 推断位置，不能声称定位到实际人员。处置漏斗中建议、授权、设备生效、效果证实分别计数，失败和未知不并入成功。

## 8. 自动响应与置信度策略

策略支持 `shadow`（只评估）、`approval`（按审批执行）、`automatic`（符合条件直接执行），可按威胁类型、资产组、时段和设备设置。自动模式是正式能力，策略一经授权且条件满足，由平台创建持久动作任务、设备执行、读回核对并安排到期撤销。

配置至少包括决策模型／版本、目标任务、校准版本、最小证据、威胁概率阈值、保护名单、动作范围、TTL、设备能力、每分钟／每日上限、最大有效封禁数、冷却窗、失败回退和停用阈值。规则判断与模型判断可单独或串联使用；自动处置不得只依赖 LLM 文本中的“置信度 99%”。

| 判断关卡 | 自动执行条件示例 | 不满足时 |
| --- | --- | --- |
| 模型资格 | 本场景、语言和模型版本经过留出集校准与上线评审 | 影子或人工审批 |
| 证据 | 身份明确、捕获质量达标、关键引用存在、无相互矛盾结果 | 补证／复核 |
| 数值 | 示例 `p_malicious_calibrated ≥ 0.995`，仅作为待评估候选阈值 | 不授权自动封禁 |
| 业务影响 | 不属于管理链路、DNS／认证基础设施、共享出口、允许活动 | 按保护策略拒绝或专门审批 |
| 设备能力 | 支持稳定规则标识、查询确认、可靠 TTL／撤销、配额足够 | 降级审批或停止执行 |
| 系统状态 | 认证有效、Runner 可达、时钟可靠、未超预算或熔断阈值 | 排队限时等待，过期不补执行 |

“恶意概率”“利用成功概率”“适合封禁的风险评估”是不同任务；不能以高恶意概率推定主机已失陷。阻止正在发生的攻击尝试可以不等待成功证据，但须满足对应阻断策略；隔离关键服务器需更高影响级别和单独授权。

初始示例模板可选外部单 IP、明确方向、限定目标服务、10 分钟 TTL、同目标 10 分钟冷却、每设备每分钟 10 次且最多 100 个有效自动动作。它是测试起点，不是通用生产阈值；保存时展示历史回放命中数和业务影响，未完成评测的策略不能切到自动模式。自动判误报支持抽样复核和一键恢复待处理，原告警始终保留。

同目标多个动作的租约合并维护，最后一个合法租约退出才撤销平台拥有的设备规则。设备原生 TTL 的绝对到期时间须等于当前有效租约的最晚到期时间，延长、缩短和续期均需读回确认；更新失败不能把新租约标为生效，无法可靠更新时不合并设备规则。平台不得删除管理员或其他系统创建的规则。更新保护名单要评估已有封禁，并支持按策略撤销。紧急停用分别提供“停止新动作”和“撤销本策略有效动作”，后者逐设备执行并核对，不把停止调度等同于已经解封。

## 9. API 与认证插件连接器

连接器能力清单包含设备类型、产品版本范围、传输方式、目标网络、凭据方式、认证有效期、支持动作、幂等策略、回读、撤销、原生 TTL、最大规则数、API 限速及测试状态。实例生命周期为未配置、待认证、验证中、可用、降级、需重新认证、停用。

连接器默认随采集器同机安装：平台下发任务，采集器访问绑定的设备；独立 Runner 为可选部署。官方 API 优先使用设备服务账号和受限权限。插件模式实现“登录控制台 → 提取当前会话授权 → 调用固定管理接口 → 回读结果”，用于缺少公开 API 的授权设备；可以使用浏览器自动化完成登录，但不能让 LLM 临场探索任意页面并直接发生产写请求。每种设备及固件版本有独立适配包和测试夹具。

认证缓存采用信封加密，记录租户／设备／认证域／账号／凭据版本／Runner 范围／插件版本、创建时间、过期时间、校验状态与加密密钥版本。认证续期与设备变更串行协调；401／403 只允许有限次重新认证，不能无限尝试密码。MFA、验证码、密码失效进入管理员重新认证流程，提供有时间限制的接管通道。会话失效、密码轮换、实例停用立即使旧缓存失效。

浏览器 Worker 非 root、保留沙箱、限制出站、CPU／内存／临时盘／运行时间；每实例独立浏览器上下文，敏感隔离采用独立进程或容器。Cookie、截图、调试端口、HAR 不写普通日志；诊断确需保留时加密、限时和单独授权。控制台操作使用稳定语义定位与接口 schema 检查，版本不匹配时进入不可用，不盲点坐标继续封禁。

插件声明固定目标及允许路径、方法、请求 schema、响应成功条件、错误分类、读回与补偿。禁止任意脚本上传后取得平台管理员网络权限。重试只针对确知安全的阶段；写入请求超时先查询外部规则 ID，有未知结果时保持“待核对”，不重复创建。官方返回成功也要回读配置；EDR 隔离、解除隔离与防火墙封禁分别验收。[响应联动与插件调研](research/响应联动与插件调研.md)

## 10. 办公通知与推送日志

支持邮件、企业微信、钉钉、飞书、通用 Webhook。每类提供群机器人快速配置与可用时的企业应用模式；用户可以选择群、部门、人员或值班组，但平台只使用已配置授权对象，不自动遍历整家企业通讯录。

| 渠道 | 建议模式 | 认证与结果语义 |
| --- | --- | --- |
| 邮件 | SMTP submission + TLS；企业 OAuth 按服务商适配 | SMTP 接受不是最终送达；DSN／退信需验证消息关联 |
| 企业微信 | 群机器人或企业应用 | 机器人 key 保密；应用 token 缓存刷新；返回部分失败须拆收件人记录 |
| 钉钉 | 自定义机器人或企业应用机器人 | 根据配置加签、IP／关键词约束；异步消息按任务标识查询 |
| 飞书 | 自定义机器人或企业应用 | 应用 token／机器人签名；只有接口支持的消息才有后续回执 |
| Webhook | HTTPS POST、版本化 JSON | HMAC 签名、时间戳、事件 ID、重放保护；约定接收确认协议 |

路由条件包括租户、组织、资产组、严重度、事件状态、研判结论、响应结果及运维类型；支持去重、时间窗聚合、摘要、静默时段、值班升级和恢复通知。紧急动作失败可设置不受普通静默约束，需在策略中明确。渠道限速参数来自适配器能力表，可按官方变化更新；不把固定数值散落业务代码。[通知渠道与投递调研](research/通知渠道与投递调研.md)

模板使用允许字段及长度预算，预览展示实际接收端格式。默认包含告警／事件标识、时间、严重度、资产、简短结论、动作状态和需要登录的平台链接；不默认外发完整 HTTP 正文、凭据或 PCAP。报告通知仅在报告发布后触发，下载链接短时且重新鉴权。

投递对象按业务触发、渠道和接收目标生成，状态为待发送、发送中、服务商已受理、已确认送达、部分失败、重试中、失败、结果未知、已抑制、已过期、已取消。提供商不支持回执时终态为“服务商已受理”，不能显示“用户已收到／已读”。网络超时也可能已经送达，优先使用提供方幂等键或查询接口，无法确定则记录潜在重复风险。

投递列表字段：业务对象、模板版本、渠道、接收目标掩码、触发／发送／受理／回执时间、尝试次数、外部消息 ID、HTTP 与业务错误码、耗时、下次重试、失败原因、request_id。每次尝试独立保留脱敏摘要，手动重试关联原记录；渠道停用时已有任务明确取消或等待，不能静默转到其他接收群。

重试采用带抖动退避并尊重 Retry-After，示例最多 6 次且不超过业务有效期；错误凭据和非法接收人先失败等待修复，429/服务错误按政策重试。PG outbox 保障业务触发，通知 Worker 与告警索引队列分离；风暴时聚合摘要、按租户配额限流，抑制数量可追溯。Webhook 禁止访问未授权内网／云元数据，检查 DNS、重定向、目标证书及签名，不仅做 URL 字符串校验。

## 11. Syslog 输出与外部日志归档

Syslog 是正式输出通道，可选择原始告警、标准化告警、事件、操作／登录审计、响应和平台运行日志。默认 RFC 5424 格式、RFC 5425 TLS/TCP，UTF-8、稳定 APP-NAME／MSGID、UTC 时间、结构化字段包含 tenant 标识、event_id、schema_version、sensor_id 和 trace_id；原始内容采用受限 JSON MSG。CEF/LEEF 作为通过目标服务器验收的可选编码，不能把所有格式混为 RFC 5424。[RFC 5424](https://www.rfc-editor.org/rfc/rfc5424)；[RFC 5425](https://www.rfc-editor.org/rfc/rfc5425)

TLS 校验服务端证书与主机名，可选双向认证；TCP 使用 octet-counting 分帧，长度按 UTF-8 字节计算。UDP 仅作为明确接受丢失风险的兼容配置，并限制报文大小；UDP 写成功不代表外部收到。TLS/TCP 本身也没有日志落盘应用级 ACK，平台状态只记 `transport_written`；只有外部接收器提供带事件 ID 的确认扩展时才可记 `receiver_confirmed`，重复转发由接收端按 ID 去重。[RFC 5425 §6.3](https://www.rfc-editor.org/rfc/rfc5425#section-6.3)

输出从可靠事件通道订阅并维护独立持久水位，不能经 LLM 过滤后才称作“全部日志转发”。高频流按批次任务／序列段记录，PG 不为每条 Syslog 存一行投递任务。队列保留时间、字节预算、最大消息和离线补发窗口显式配置；远端故障时不拖住 ES 入库。超过可补发窗口时记录缺失范围并支持从仍在保留期的 ES 受限补发，不能无限保留又声称零成本。

若日志服务器在客户内网，可由采集器同机连接器的持久转发模块发送；其 spool、证书、配额与响应任务分资源隔离。传输中断后重发可能重复，顺序只在指定传感器／流序列内保证，不提供全租户绝对时间排序。接收端限制较小的消息需约定截断标记、摘要和完整对象引用，或协商分片重组；不随意切段导致一条日志被当成多条独立事件。

Syslog 任务页展示目标、数据类别、过滤策略版本、上次发送、最高发送／确认水位、积压、最老年龄、失败码、丢失区间和重放任务。TLS 到期、长时断连、缓冲空间不足有独立运维告警。转发内容不含会话密钥，目标配置与样例发送有审计。

## 12. 登录、操作与集成审计

登录日志记录账号／主体、认证方式、来源 IP、可信代理信息、客户端摘要、开始与完成时间、成功／失败、稳定原因码、MFA 结果、session 标识摘要和注销／撤销事件；密码、OTP、token 不入日志。失败详情对用户保持适度模糊，审计员可见分类原因。

操作日志覆盖创建／修改／删除、权限与成员、租户切换授权、探针与证书、规则生成和发布、模型与阈值、连接器认证、封禁／解封、下载／导出、报告发布、MCP 和 API 服务身份调用。至少包含 tenant、actor、delegation、scope、object、action、before/after 的脱敏摘要与版本、reason、result、request_id、job/action_id、服务端时间。

关键配置和响应事务与审计／outbox 同事务提交，审计无法写入则不得显示写操作成功；高频只读访问可批次持久化，但失败和缺口有计数。操作日志、登录日志、模型任务与投递日志分别查看，跨页以 request_id 或业务对象关联。审计员不能修改审计；支持独立存储归档、签名／哈希校验、保留与导出。操作/登录/访问审计默认 180 天，支持用户自定义；热转冷不得缩短总留存，禁止宣称任何保存期限天然满足所有合规要求。

## 13. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| IP + POST + HTTP + path + 待处理联合查询 | 页内数据、总数、分页和导出一致，无分页后过滤 |
| 同地址存在于两个客户或两个 VPC | 资产、告警、缓存和查询完全按网络域隔离 |
| 非 UTF-8、缺包、压缩炸弹、恶意 HTML | 原字节不变，解码错误可见，作业受限且不执行网页内容 |
| 探针有心跳但引擎停止／镜像断流 | 在线与检测异常同时可见，大屏提示覆盖缺口 |
| 浏览器 Cookie 过期、MFA、页面升级 | 有限重试后需认证或熔断，无盲目写入 |
| 重复封禁、外部 API 超时、Runner 断线 | 动作幂等或待核对，TTL 与撤销机制可验证 |
| 自动阈值命中但目标是保护地址 | 策略拒绝自动执行，并保留判断和拒绝原因 |
| 同 IP 两个有效租约、其中一个到期 | 仍保持封禁，最后租约结束后撤销平台自有规则 |
| 企业应用部分接收人无效 | 投递列表部分失败，成功对象不被无差别重发 |
| Syslog TCP 发送成功而接收服务器未落盘 | 只显示已写入传输，不伪称已存储 |
| 修改组织或撤回权限后查看缓存／导出 | 重新授权，历史快照语义明确，旧权限不能继续生效 |
| Redis、通知或模型故障 | 采集和 ES 留存按各自链路继续，降级状态清晰 |

这些场景需要以授权样本、设备模拟器、实际接口与故障注入验证；当前文档不代表它们已经通过测试。

多源日志接入、漏洞弱点、情报、关联/狩猎、案件 SLA 和剧本的页面状态、来源与验收见[安全运营与数据治理设计](安全运营与数据治理设计.md)。跨页面操作沿用同一身份、数据字典、证据快照与任务中心，不独立复制另一套权限或响应执行器。

## 13. 检测覆盖与内容分析运营

探针详情分别展示原始捕获丢包、截断、检测流量占比、重组缺口、深度到限、协议解析异常、flow/stream/defrag 内存压力、bypass/pass 命中、告警队列溢出与 EVE 输出健康。缺少某计数器时显示不可观测，不能填零；完整性告警与恶意行为告警分别分类。PCAP 归档正常不代表检测完整，检测告警正常也不代表双向原包全部保留。

文件中心提供提取、静态分析、动态沙箱任务与报告；显示排队、扫描范围、引擎/规则版本、完成与失败原因、缺包/加密/压缩限制。沙箱不与设备认证浏览器共享环境。协议目录、旁路质量和文件能力分别见[采集质量设计](旁路采集与检测质量设计.md)、[协议与文件分析设计](协议覆盖与文件分析设计.md)。

告警到通知的度量覆盖符合路由条件、聚合等待、持久投递意图、出队、服务商受理及可信送达回执，受理不等于人已读。平台通知和 Syslog 不等待 PCAP 上传或沙箱完成；规则要求研判后发送时，明确显示等待阶段。详情可按同一 trace 复核，分段与端到端 SLO 见[应用识别与响应性能设计](应用识别与响应性能设计.md)。
