# Syslog 接收与日志检索

主控平台通过已注册采集器接收 Syslog。采集器负责独立监听、设备身份核验、消息分帧与本地持久缓冲；认证后的 gRPC 数据流把消息送入独立队列，工作进程按固定版本解析后写入日志索引。日志与 Suricata 告警使用不同的数据流、配额和映射。

平台入口为“系统管理 → 数据接入 → Syslog 接收”和“系统管理 → 日志检索”；采集器入口为“网络与采集 → Syslog 接收”。来源配置目前由采集器本地私有文件管理，控制台提供状态、目录、检索与原文查看，不提供未执行的远程配置按钮。平台配置审批、下发、来源移交和设备专用语义解析仍属于待实现范围。

## 接入配置

通过采集器专属环境变量 `SB_SYSLOG_SOURCES_FILE` 指定绝对路径。未配置时不打开监听端口，已经持久化的待传日志仍继续上传。文件、证书、私钥和客户端 CA 均须为权限不向组和其他用户开放的普通文件，建议目录 `0700`、文件 `0600`；拒绝最终路径为符号链接的文件。以下为配置结构示例，证书路径及指纹须使用实际设备材料。

```json
{
  "schema_version": "syslog.sources.v1",
  "sources": [
    {
      "id": "firewall_hq",
      "name": "总部边界设备日志",
      "network_domain": "hq_dmz",
      "listen": "0.0.0.0:6514",
      "transport": "tls",
      "format": "rfc5424",
      "timezone": "",
      "year_policy": "",
      "allowed_peers": ["192.0.2.5/32"],
      "accept_unauthenticated": false,
      "accept_datagram_loss": false,
      "max_message_bytes": 65536,
      "max_connections": 8,
      "max_events_per_second": 1000,
      "tls": {
        "certificate_file": "/etc/starbeacon/syslog/server.crt",
        "private_key_file": "/etc/starbeacon/syslog/server.key",
        "client_ca_file": "/etc/starbeacon/syslog/device-ca.crt",
        "client_fingerprints": ["设备叶证书 DER 的 SHA-256，小写 64 位十六进制"]
      }
    }
  ]
}
```

配置中的所有运行限额均要求显式提供。来源 ID 和网络域使用 1–64 位小写字母、数字、下划线或连字符；来源 ID 在该采集器内唯一。网络域是可信来源标签，不自动建立资产网段、实体身份或处置授权。

| 项目 | 约束 |
| --- | --- |
| 来源文件 | 最大 128 KiB，最多 16 个来源；严格字段名，拒绝重复字段、未知字段和尾随内容 |
| 监听 | 显式 IPv4/IPv6 地址和 1024–65535 端口；拒绝域名、组播地址、带 zone 的地址和 IPv4 映射别名；同一传输端点不能重复登记 |
| 来源网段 | 1–32 个规范 CIDR；同时接收 IPv4/IPv6 时分别登记；不支持从正文自动识别租户 |
| 消息 | 每条 256–65536 B 的可配置上限；不截断后继续解析 |
| 连接 | 每来源 1–32 个并发 TCP/TLS 连接；握手 5 秒、读取 15 秒超时 |
| 速率 | 每来源 1–10000 条/秒的令牌桶限额，突发容量等于配置速率；不是吞吐承诺 |
| 内存缓冲 | 共用有界 256 项提交队列；最多 64 条或等待 5 毫秒批量持久化 |
| 磁盘缓冲 | `logs` 独立桶，最多使用总 WAL 计费容量的四分之一；每条预留 64 B 首次路由空间 |

`transport=tls` 要求 TLS 1.3、有效客户端证书链及 1–8 个明确允许的叶证书指纹，两项同时满足才接收。TLS 材料在启动时读取，不在连接失败时降级。来源结构摘要包含规范配置和材料路径，不证明材料文件内容版本；目录不返回路径、监听地址、证书内容或私钥。

TCP 使用 `transport=tcp`、`accept_unauthenticated=true`，TLS 配置留空；UDP 另须 `accept_datagram_loss=true`。此处的授权表示接受未认证的网络来源，不表示已验证日志中声明的设备身份。来源地址仍须满足允许网段。共享 NAT 地址只属于网络线索，不能区分 NAT 后的多个设备；应使用独立证书身份或明确隔离的中继来源。

无效配置或 TLS 材料会拒绝采集器启动，并保留原 WAL；监听端口不可用则单独显示来源不可用并重试，不停止已有 EVE 读取。配置变更须按采集器运行方式受控重启，重启后核对来源状态、接收计数与平台结果。

## 分帧、原文与身份

TCP/TLS 使用 RFC 6587 octet-counting：`消息字节数 + 一个空格 + 消息原始字节`。长度不包含前缀自身，不接受零长度、前导零、符号、按行分帧、超限或不完整帧；失败关闭连接。消息中的换行仍属于同一条原文。UDP 一报文对应一消息，空报文和超限报文整条拒绝，不将截断报文当成完整事件。

RFC 5424/3164 语法复用 `github.com/leodido/go-syslog/v4 v4.6.0`。长度读取使用有界标准库实现，以同时保留完整原始帧；不从解析器的展示字符串重建原文。拒绝宽松自动猜测。RFC 5424 当前接受版本 1，来源时间的小数秒最多 6 位；纳秒长度的非标准时间戳作为解析隔离保留，不截短后冒充成功。[RFC 5424 时间格式](https://www.rfc-editor.org/rfc/rfc5424.html#section-6.2.3.1)。PRI、消息格式或指定解析器不匹配的原文按“解析隔离”存储，仍可审计查看。它不作为成功解析或安全告警。

原文以 Base64 保存并单独计算 SHA-256；传输 JSON 的摘要与原始消息摘要分别校验。接收记录使用固定字段顺序的规范 JSON，原文不做字符替换、去重、换行规范化或租户字段提取。非 UTF-8 文本不能被展示层当成完整文本；HEX 始终对应原始字节。

事件身份绑定认证租户、采集器注册代次、来源 ID、WAL 代次和来源递增序列。同文消息分别编号；上传重试保留原身份。日志不复用 EVE 文件偏移，不伪造文件来源位置。首次发送前把平台路由持久化，重试、断电或跨日后继续使用同一日期索引；确认必须精确对应原批次、摘要、身份和序列范围后才回收 WAL。现有上报路由有效期固定为 180 天；超过路由期限仍保留待传记录并显示上报失败，不自动改写原日期、重新生成身份或丢弃数据。路由期限独立配置与过期缓冲处置尚待实现。

TCP/TLS 传输层应答不是应用级持久确认。采集器没有向设备提供“平台已索引”回执；发送方仍可能因自身重试产生重复原始日志。UDP 无交付确认，无法据采集器计数计算完整上游丢失率。

## 时间与解析质量

| 字段／质量 | 语义 |
| --- | --- |
| `record.observed_at` | 采集器完整取得该消息的 UTC 时间 |
| `received_at` | 平台第一次成功索引的入站观测时间；索引重试不覆盖原事实 |
| `parsed.source_time` | 从原始日志解析出的来源时间，可能为空 |
| `source_timezone` | RFC 5424 原文含可解析时区 |
| `missing_source_time` | 原文未提供时间，不用接收时间冒充设备时间 |
| `inferred_year_timezone` | RFC 3164 按显式时区与接收时间的相邻年份推断 |
| `ambiguous_year`／`ambiguous_local_time` | 年份无法确定、夏令时重复或不存在的本地时刻；来源时间留空 |
| `future_source_time` | 来源时间超前接收时间超过 5 分钟，仍保留原事实与异常标记 |
| `source_time_out_of_range` | 来源时间不在支持范围，保留原文而不伪造有效时间 |

RFC 3164 必须配置 IANA 时区和 `year_policy=nearest_received_year`，不使用运行机器的默认年份或默认时区。来源时间不能作为租户身份、留存起点或自动处置事实。跨年推断超过 183 天及不确定时刻单独标记。

来源目录的计数自本次接收器启动起累计，重启会重新计数；来源序列和待传数据持久保存。拒绝、分帧错误、速率超限或本机持久化失败分别记录。平台目录基于认证心跳，单独标明离线、停用和观测过期；35 秒时效不代表网络可达性或设备日志完整性。监听成功、本地已保存、平台已入站和已索引是不同阶段。

## 索引、留存与检索

独立 JetStream 流为 `SB_LOGS`／`sb.events.logs`，使用文件持久化、独立容量和工作队列确认。上游接收确认仍要求 JetStream 持久确认；索引失败保留消息重试。日志不触发告警推送、模型调用或自动封禁。

严格模板 `sb-logs-v1` 仅覆盖 `sb-logs-*`，禁止自动创建无生命周期的动态索引。索引为 `sb-logs-<tenant>-YYYY.MM.DD`，ID 使用不可变日志身份；重复写入需要读回并核对原事实。模板归属、映射或生命周期不一致时拒绝写入，不覆盖未知对象。

普通字段使用 `keyword`，对端地址使用 `ip`，接收时间使用纳秒日期；正文同时提供内置 CJK 与 standard 分析。结构化 Syslog 数据原样保留，关闭动态索引，避免设备任意键制造字段爆炸。字段上限或解析失败不会自动改写模板。

“数据留存 → 安全日志”默认 180 天，可设置 1–3650 天；新 UTC 日期索引首次创建时固化策略和生命周期起点。既有索引不因策略变更而重算。注册来源配置不按日志留存期删除。本地 WAL 是待传缓冲，不承担 180 天历史存储。

检索以平台接收时间为依据，窗口最多 31 天，支持探针、来源、网络域、传输对端 IP、声明主机／应用、Syslog 严重级别、解析状态与正文关键词。Severity 为 Syslog 的 0–7 级，不直接映射为平台告警等级。关键词不接受任意 Elasticsearch DSL；中文与英文正文均按固定分析器查询。

按 `(received_at,event_id)` 倒序游标续页，每页 1–100 项。游标绑定租户、全部查询条件和页大小；它不是持续写入期间的快照或总量证明。列表排除原文字节与任意结构化字段，正文只返回最多 512 个字符的摘要，截断显式标记；完整原文通过指定分区和事件标识独立读取。

所有日志访问限当前有效管理员。原文读取后再次核对账号、租户及修订，审计写入成功才返回；浏览器核对原文和载荷摘要后展示 HEX、UTF-8 与字节查找。权限撤销、请求取消或切换账号后不能恢复迟到结果。

## 工程验证与未验收范围

单元测试覆盖严格配置、协议解析、时间歧义、原文摘要、长度分帧、来源序列、重复消息、配额、路由预留、确认丢失、重启恢复、速率与来源限制。真实依赖集成测试使用独立 Docker 项目中的 PostgreSQL、NATS、Elasticsearch 与原生 TLS/gRPC，并核对中文查询、隔离记录、冷启动索引、重复投递、原文审计、超过 200 项来源分页及账号停用。标准四进程链路通过实际 Agent 环境加载来源文件，验证 TLS 监听、本地目录、独立上报、中文检索和原文审计；不以库级接收器测试代替进程入口。

最新执行结果与源码来源见[测试覆盖与验收记录](测试覆盖与验收记录.md)。用例存在不表示已经通过当前来源的远程验收。尚未验收的范围包括真实生产设备语义、持续大流量吞吐、上游丢失率、设备日志完整性、平台来源配置生命周期、跨终端／云日志实体关联、日志驱动研判和日志原文通用外发。
