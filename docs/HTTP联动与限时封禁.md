# 星烽 StarBeacon HTTP 联动与限时封禁

平台「响应中心 → 联动设备」提供按执行探针分页读取的设备目录，离线历史与当前执行条件分别呈现；采集器提供固定本地文件与运行绑定的配置核对。详情见[联动设备目录与本地配置核对](联动设备目录与本地配置核对.md)。

## 执行范围

主控平台管理员向指定采集器提交单个 IP 的限时封禁、原租约回读或解除任务；采集器通过本地配置的固定 HTTPS 接口访问设备。旁路探针自身不拦截或转发业务流量。

此流程采用用户确认的通用 HTTP 协议。专属 Docker 端点用于验证认证、签名任务、设备回读、独立租约和绝对到期；真实防火墙、EDR、流量效果和高可用另行验收。当前不包含浏览器登录、Cookie 缓存、MFA、设备品牌适配、EDR 隔离或恢复。

决策策略支持影子评估、持续评估与人工确认、持续评估与自动执行。模型自报分数和判断建议不直接授予设备权限；管理员独立确认，或已显式配置的持续策略核对固定事实、模型、探针与设备绑定、去重、冷却和预算后，才提交签名限时任务。管理员可另行授予数据使用和费用许可，将指定探针、注册代次及等级的新观测告警登记到自动研判队列；未配置该许可时仅处理已完成的本人研判。跨账号服务触发、泛化的全量处理、领域校准、多级审批、应急控制及生产规模仍须交付或独立验收，详见[持续决策与自动授权](持续决策与自动授权.md)。任务受理、执行回执、设备配置状态和真实阻断效果分别记录。

```text
管理员显式提交 → 平台权限 / 注册代次 / 心跳 / 配置核对
              → 当前保护名单核对
              → PostgreSQL 任务、名单依据与审计同事务 → Ed25519 签名
              → mTLS 控制通道 → 指定采集器
              → 目标保护校验 → 本地授权意图落盘
              → 固定 HTTPS 设备接口 → 独立 GET 回读
              → 不可改写的执行回执 → 平台任务记录
```

## 采集器配置

`SB_RESPONSE_CONNECTORS_FILE` 仅用于采集器角色，指向绝对路径的私有 JSON 文件。没有该配置时不声明 `response.block`、`response.read` 和 `response.revoke` 能力。配置文件和 Bearer 文件只允许所有者读取，禁止符号链接、FIFO 和超限内容；部署时保证采集器运行身份可读取文件。配置变化须重启采集器并重新核对设备目录。

私有目录使用 `0700`、文件使用 `0600`，所有者须与容器内实际运行 UID 对应；只读挂载不替代读取权限。裁剪能力后的 UID 0 也不能假定可以读取其他 UID 的私有文件。应为实际运行身份准备字节相同的私有文件，通过只读挂载提供，不扩大组／其他用户权限，也不增加绕过文件权限的能力。未能读取配置时采集器启动失败，应核对运行身份、路径及权限后恢复，不能把失败视为联动设备正常。

```json
{
  "schema_version": "response.connectors.v1",
  "retention_days": 180,
  "connectors": [
    {
      "id": "connector_hq",
      "device_id": "device_hq",
      "device_version": "starbeacon-http/1",
      "origin": "https://198.51.100.5:8443",
      "ca_file": "/run/starbeacon/device-ca.pem",
      "token_file": "/run/starbeacon/device-bearer",
      "allowed_targets": ["10.20.0.0/16"],
      "protected_targets": ["10.20.0.0/24"],
      "max_ttl_seconds": 3600
    }
  ]
}
```

地址为文档示例，须替换为受控设备管理 IP。支持 1–8 个连接器，同一设备只能登记一次。接口原点不接受域名、用户名、路径、查询参数或片段；证书须包含所配置的 IP。目标 CIDR 必须为规范且已掩码的网段，各类最多 32 项。配置摘要覆盖设备身份、接口原点、凭据路径引用和目标约束，不上传凭据内容。

Bearer 文件为 16–4096 字节令牌，可带一个行尾；不接受内部空白或控制字符。每次请求重新读取，允许在同一路径原子替换私有文件撤销或轮换认证；设备再次核验成功前不可提交新任务。CA 在进程启动时加载，CA 或配置变更需重启。HTTP 禁用环境代理、重定向和连接复用；每次请求限 8 秒、JSON 响应限 16 KiB，没有写请求的自动重发。

配置管理 IP、保护网段、本机接口地址和主平台 / 上报端点不得作为封禁目标。主平台及上报地址采用 `host:port`；域名解析受 2 秒期限约束，地址目录或解析失败时拒绝该次封禁，保持采集服务运行。管理域名地址可能变化，独立保护网段仍需覆盖完整管理网络、DNS、认证和基础设施依赖。

## 设备协议

设备应在明确授权范围内提供以下三个固定接口。没有满足协议的设备或适配网关，不可将任意厂商 API 直接填入原点。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /starbeacon/v1/device` | 返回绑定的设备身份、精确接口版本和能力 |
| `GET /starbeacon/v1/leases/{lease_id}` | 独立读取此租约的配置状态与观察时间 |
| `PUT /starbeacon/v1/leases/{lease_id}` | 按固定 IP、所有者和绝对期限创建独立租约 |
| `DELETE /starbeacon/v1/leases/{lease_id}` | 仅在 `If-Match` 所有者摘要匹配时解除此租约 |

所有接口使用本机 Bearer 认证和受信 TLS，JSON 字段区分大小写，不接受重复、别名或未登记字段。设备描述须返回 `response.device.v1`、精确 `device_id` / `version`、`native_ttl=true`、`separate_leases=true`、`conditional_revoke=true`、30–3600 秒内的 `max_ttl_seconds` 和 UTC `observed_at`。缺少任一项不显示就绪。

PUT 请求为签名任务内的 `response.action.v1`：`connector_id`、`config_sha256`、`device_id`、`lease_id`、`owner_sha256`、`target_ip`、`requested_at`、`expires_at`、`reason`。`lease_id` 等于原封禁任务标识；所有者摘要绑定租户、采集器、注册代次与租约，不能代替认证或签名。设备必须拒绝同标识的不同所有者、IP 或期限；相同请求不能续期，已解除或到期的历史租约不能重建。

回读返回 `response.lease.v1`、原 `device_id` / `lease_id` / `owner_sha256` / `target_ip` / `expires_at`、状态 `active` / `revoked` / `expired` 和 UTC 观察时间。客户端逐项核对，允许的时钟观测偏差为 30 秒；已到期租约不能回报为有效，未来到期不能回报为已到期。HTTP 200、202 或空响应均不替代独立回读。

明确不存在仅接受 404 与 `{"schema_version":"response.error.v1","code":"lease_not_found"}`。404 只用于首次创建前确认不存在；回读或解除中的不存在保持结果未知，不能证明配置已经解除。

DELETE 使用 `If-Match: "<owner_sha256>"`，不得按 IP 全局删除、解除他人租约或任意回滚已有设备规则。同 IP 的多个租约分别有效；解除其中一个时，设备必须保持其他未到期租约的效果。原生 TTL 必须由设备独立执行，采集器或主平台停机不能使租约无限延长。设备重启、HA 切换和时钟异常仍需真实设备验收。

## 平台任务

入口为“探针列表 → 查看 → 限时封禁”；“响应中心 → 响应动作”提供独立检索及原任务详情，支持回读与确认解除，见[响应动作与执行追溯](响应动作与执行追溯.md)。采集器的独立“联动设备”工作区（`/response/devices`）只展示目录与本地配置核对，不提供本地设备写入按钮。

`POST /api/v1/sensors/{id}/response-tasks` 要求管理员会话、CSRF 和唯一的 8–64 字符规范 `Idempotency-Key`。单 IP 提交格式如下：

```json
{
  "kind": "response.block",
  "connector_id": "connector_hq",
  "config_sha256": "<当前采集器上报的64位小写SHA-256>",
  "target_ip": "10.20.2.10",
  "ttl_seconds": 300,
  "reason": "人工确认的异常通信"
}
```

占位摘要必须替换为实际目录摘要。TTL 为 30–3600 秒且不超过设备当前上限；理由为 1–500 字符，不接受首尾空白或控制字符。只接受规范单 IPv4 或 IPv6，拒绝 CIDR、回环、组播、链路本地、IPv4 映射和带 zone 的地址。

回读或解除使用 `response.read` / `response.revoke`，填写同一连接器、配置摘要、`original_task_id` 和理由；不得提交目标 IP 或期限。原任务须属于同租户、同采集器、同注册代次，已投递且尚在留存期。平台校验原签名和授权快照，不重新计算原到期时间。

平台事务内重新核对账号和租户状态、凭据修订、探针注册身份、当前签名信任、动作能力以及 35 秒内心跳和设备目录。单租户滚动 24 小时最多 1,024 个联动任务，额度用尽返回 429；相同原提交确认仍返回原任务，不消耗第二次额度。新封禁还核对当前有效 IP／CIDR 保护名单及其冻结探针注册范围；命中返回 `409 response_target_protected`，持续策略按 `target_protected` 记录确定性跳过。名单来源损坏或依赖失败时不签发任务。保护条件变化、额度和审计写失败不会留下部分任务。

同一探针共用串行任务通道；已有排队、投递或运行中的规则、重放、采集配置或联动任务时，创建另一任务返回 409。未知终态保留原回执，允许另行提交回读；回读不重新封禁或续期。现有通道没有紧急响应优先队列，不能承诺在其他任务运行期间的封禁时延。

封禁任务投递期限为提交时刻加 `min(TTL−5,60)` 秒，设备租约到期为提交时刻加 TTL；两个期限分别显示。回读或解除任务的投递期限为 2 分钟，原设备到期时间保持不变。期限包含排队和网络耗时，任务受理不能保证执行前仍有足够时间。

## 授权时的名单依据

新 `response.block` 的平台授权事务取得名单共享锁后读取实际数据库时间，再核对当时有效的保护范围。非命中记录以 `response.protection.v1` 保存核对时间、名单状态 SHA-256、核对 SHA-256 与原命令 SHA-256，与任务和审计原子提交；详情只展示与原任务绑定且结构完整的依据。历史没有此记录的任务明确显示缺少记录，不能据此认定当时核对通过。匹配值、有效期及预览规则见[保护与观察名单](保护与观察名单.md)。

原任务精确确认只回读第一次的授权，不在当前名单变化后重新签发或续期。名单后来启用、停用、变更或到期，不自动撤销原签名任务和设备租约；原租约回读与条件解除不受名单变更拦截。平台授权依据不表示采集器在设备执行瞬间再次读取平台名单，仍须遵循采集器本地保护约束。需要停止已授权任务或撤销全部动作的统一控制仍属于独立能力，不以保存名单替代。

## 未知结果与追溯

采集器在设备副作用之前将原租约意图落入本地 bbolt。首次 PUT 之后仅 GET 核对；响应丢失或 5xx 不能触发第二次 PUT。明确认证、范围或条件拒绝返回失败；无法回读则为结果未知，不能显示封禁或解除成功。

平台提交超时或回执不完整时，界面保留原请求键与输入，提供“核对原提交”；相同提交不会创建第二个任务或重新计时。当前确认内容只保存在本次页面会话，冻结的原输入不会被当前设备配置替换。页面关闭 / 刷新后仍需凭任务目录核对，尚无跨浏览器持久草稿保证。

重启维护仅回读原租约，不补发历史封禁。每轮最多核对两条最久未核对的记录，最多清理 16 条已过留存期且封禁期限已结束的历史。目录损坏、容量不足或身份不符拒绝动作；未知记录不能解释为已解除。此有界维护不构成批量到期核对时延承诺。

任务、任务名单核对记录和操作审计沿用平台 `operations` 分类，默认 180 天，可自定义；核对记录沿用原任务固化的期限。未结束或仍需核对的任务保护名单依据；到期回收先删可回收的子记录，后续轮次再删无引用父任务。本地租约历史默认 180 天，由文件 `retention_days` 配置 1–3650 天；创建时冻结留存期限，修改策略不重写历史。每采集器最多保留 1,024 条历史，达到容量拒绝新动作，需核对留存与容量后处理，不提前删除审计。

成功回执包含 `response.result.v1`、独立配置观测和 `traffic_effect=not_observed`。任务详情显示回读快照与时间；后来到期或配置变化必须重新回读。新核对任务保留原执行回执，不把设备结果、模型建议或 UI 状态改写为真实阻断效果。

## 验证入口与边界

单元测试覆盖协议与 JSON 约束、认证撤回、私有文件、保护范围、同键提交、所有者绑定、写响应丢失、独立租约、重启只读恢复、留存和本地存储故障。集成测试使用真实 PostgreSQL 权限 / 事务 / 限额和真实 HTTPS 协议端点；实际原生程序与 Linux ZIP 链路核对签名任务、指定采集器执行、回读及条件解除，独立到期用例等待实际 30 秒期限结束。

可执行入口为 `internal/response/client_test.go`、`internal/agent/response_test.go`、`tests/integration/response_tasks_test.go`、`tests/integration/processes_test.go` 、`tests/integration/response_protection_test.go`、`web/tests/response.test.ts` 和 `web/tests/response-protection.test.ts`。本轮完整结果以[测试覆盖与验收记录](测试覆盖与验收记录.md)中的同源执行记录为准。协议端点没有操作宿主防火墙、商业设备或真实用户流量；功能覆盖率不等于攻击判断准确率、真实封禁资格或生产时延。
