# 星烽 StarBeacon 开发规范

本文是写代码、写文档和提交改动的唯一规范。怎么验证和发布见[测试与发布流程](测试与发布流程.md)，做什么见[开发任务](开发任务.md)，界面长什么样见[界面设计规范](../DESIGN.md)。

## 1. 通用约定

- **语言**：注释、文档、提交说明和界面文案一律用简体中文；产品名统一写“星烽 StarBeacon”。
- **一次只做一件事**：一个开发任务条目对应一个提交，不夹带无关改动。
- **不留尾巴**：代码里不写 TODO、FIXME 或占位实现。没做完的事写进[开发任务](开发任务.md)的“待排期”。
- **如实呈现**：没有数据、没有验证和失败分别表达，不用成功状态或零值顶替。
- **分工**：主会话负责决策分析、任务拆解、文档和结果复核；代码改动交给子代理完成（模型用 Opus 5.5）。细则见第 8 节。
- **依赖**：新依赖锁定精确版本，同步[依赖版本与部署清单](依赖版本与部署清单.md)和许可清单；现有依赖能解决的不新增。
- **敏感内容**：密钥、令牌、证书私钥和 `.local/` 下的任何文件不入库。

## 2. Go

| 项目 | 规则 |
| --- | --- |
| 格式与静态检查 | `gofmt` 与 `go vet` 必须无输出 |
| 目录 | 入口在 `cmd/`，业务在 `internal/<领域>/`，持久化在 `internal/store/`，HTTP 处理在 `internal/platform/` 与 `internal/agent/` |
| 错误 | 领域包定义哨兵错误，调用方用 `errors.Is` 判断；每个领域用一个映射函数把错误转成状态码和错误码，处理函数里不散写 |
| 事务 | 业务写入和审计记录在同一事务提交 |
| 租户 | 每条查询都带租户条件；隔离由服务端执行，不依赖前端 |
| 并发与幂等 | 修改用修订号做条件更新；写接口支持对原请求的确认，重复提交不产生第二份结果 |
| 接口 | 新增或修改 HTTP 接口时同步 `api/openapi/`，并重新生成[功能实现与验收状态](功能实现与验收状态.md) |
| 迁移 | `migrations/` 只追加新编号，不改已有迁移 |
| 测试 | 新增代码必须带测试。单元测试与源码同目录；真实依赖测试放 `tests/integration/` 并带 `integration` 构建标签。语句覆盖率不低于 90% |

## 3. 前端（主控平台、采集器、原型）

| 项目 | 规则 |
| --- | --- |
| 组件写法 | Vue 3 `<script setup lang="ts">`；事件 ID、`flow_id` 等大整数始终按字符串处理 |
| 一套组件 | 外壳、筛选、表格、分页、状态标签、指标条、状态面板等通用件只在 `web/packages/shared/` 写一份，三个入口都引用它。页面专属组件放 `web/<端>/src/features/<领域>/` |
| 颜色 | 只用主题变量 `var(--*)` 和组件库主题；源码里不出现 `#hex` 或 `rgba()`。取值集中在 `web/packages/shared/src/theme.ts` |
| 字号、字重、圆角 | 只用设计规范的档位：字号 12／13／14／16／20／24，字重 400／500／600，圆角 4／6／8 |
| 状态语义 | 状态的色调由数据显式给出，不从显示文案推断 |
| 列表 | 编号单独成列，不叠在名称下面；一行一条，放不下用省略号；分页只用 `web/packages/shared/src/components/ListPager.vue` 或 `pagination.ts` 的 `tablePagination()`，每页默认 20 条，可选 10、20、50、100，不自己写“上一页／下一页” |
| 页面说明 | 静态说明、使用提示和数据口径收进页面标题旁的“?”；页面内提示条只用于此刻需要用户处理的事 |
| 列表接口 | 分页接口接受 `limit`，只允许 10、20、50、100，默认 20 |
| 配置的位置 | 系统级配置（用户、自动化级别、阻断策略、留存与存储、健康阈值）只放在“系统设置”；业务页面只读显示当前值并链接过去，不放配置面板和配置弹窗。页面上只保留本页的显示类设置 |
| 用语 | 状态用语只用 `web/packages/shared/src/terms.ts` 里登记的标准词，对照表见[界面设计规范](../DESIGN.md)的“用语”一节；新增状态先登记再使用，不写“不可观测”“未获取”“无法判定”这类说法 |
| 时间 | 统一用共享的时间格式函数，输出 `YYYY-MM-DD HH:mm:ss`；不直接调用 `toLocaleString` |
| 数值 | 容量、速率和大整数用 `web/packages/shared/src/utils/format.ts`；没有数据时显示“无数据”或“—”，不显示 0 |
| 请求 | 用 `AbortController` 取消并设 30 秒超时；迟到的响应不覆盖当前内容；切换账号、租户或角色时取消并清空 |
| 接口返回 | 严格校验结构和租户，不符即报错，不接受多余字段 |
| 页面三态 | 加载、空、错误统一用共享的 `StatePanel`；空状态写业务原因和下一步，错误状态带重试 |
| 布局 | 只面向 PC，最小宽度 1024px；不写低于 1024px 的媒体查询，断点只用设计规范表里的取值 |
| 测试 | 组件与交互测试放 `web/tests/`；语句、分支、函数、行四项覆盖率均不低于 90% |

字号档位、时间格式函数、状态语义、列表、页面说明、配置的位置和用语这几条对应的存量代码由开发任务逐项清理；新写的代码现在就按本表执行。

## 4. 格式

- Go 用 `gofmt`。
- 前端与原型用 Prettier，行宽 120，由 CI 检查。工具由[开发任务](开发任务.md) T03 引入并一次性全量格式化；在那之前不要手工重排旧文件，避免格式改动和逻辑改动混在同一个提交里。
- 样式文件按规则分行书写，不提交压缩成一行的 CSS。

## 5. 文档

- **规则和历史分开**：规范类文档只写现行规则。历史记录放 `docs/archive/`，每次发版的结果写 `docs/releases/<版本>.md`。
- **数字只在一处维护**：需求数、接口数以生成的[功能实现与验收状态](功能实现与验收状态.md)为准，工作区和视图数以 `web/packages/shared/src/navigation.json` 为准。其他文档引用它们，不复述具体数字。
- **目标和现状分开**：设计文档写目标契约并在开头注明实现状态的出处；行为变了，对应文档在同一个提交里更新。
- **命令可执行**：文档里的命令必须是仓库里真实存在、可以直接运行的。

## 6. 提交

- 格式：`<类型>: <中文说明>`。类型取 `feat`、`fix`、`refactor`、`style`、`docs`、`test`、`ci`、`chore`。
- 说明用一行写清做了什么；需要时在正文补充原因和验证结果。
- 直接提交到 `main`，一个条目一个提交。推送和打标签须经确认。
- 提交前必须通过关口一，以及该条目要求的关口二（见[测试与发布流程](测试与发布流程.md)）。

## 7. 完成标准

一个条目同时满足以下四条才算完成：

1. 代码、测试和文档在同一个提交里。
2. 关口一、关口二通过，结果写进[开发任务](开发任务.md)的进度记录。
3. 条目已在开发任务里勾选。
4. 没有留下临时文件；验收产物按[验收环境清理](验收环境清理.md)回收。

## 8. 分工

用 Claude 做这个仓库的工作时，按下面的分工执行：

| 角色 | 负责 | 不做 |
| --- | --- | --- |
| 主会话 | 决策分析和需要你拍板的选项；把条目拆成可以交付的说明；写和改全部文档（设计规范、开发规范、测试与发布流程、设计文档、开发任务与进度记录）；复核子代理的结果；发起关口二和提交 | 不直接改代码 |
| 子代理（Opus 5.5） | 按说明改代码和测试，跑关口一，汇报改了什么、验证了什么、没做什么 | 不改文档，不提交，不推送，不运行关口一以外的测试 |

交给子代理的说明必须自成一体，因为它看不到之前的对话：

1. 背景和要达到的效果，用到的决策结论。
2. 范围：要改的文件或目录，以及明确不许碰的文件。
3. 约束：本规范第 3 节的前端规则、测试只在远程执行、不提交。
4. 完成标准和自查方法（两条类型检查，能用浏览器时逐页目视）。
5. 汇报格式：改动的文件、验证结果、没做的事、范围外发现的问题、需要决策的点。

子代理汇报后，主会话要自己核对：重新跑关口一，抽查关键文件，用浏览器看一遍受影响的页面；汇报里说“已完成”不等于已经核实。范围外的问题记到开发任务的“待排期”。

把开发交给 Grok 等其他编码工具时，不套用上面的主会话／子代理分工：它按[开发任务](开发任务.md)逐项完成代码和测试，勾选条目并写进度记录，测试在远程主机执行；规范、流程和设计文档只在条目要求时才改，需要你拍板的事先问。提示词见[开工提示词](开工提示词.md)。
