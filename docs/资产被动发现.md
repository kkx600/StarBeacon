# 星烽 StarBeacon 资产被动发现

资产管理提供独立的“被动发现”视图。管理员选择探针、使用中的网段、标准 CIDR 前缀和时间窗口，查询已进入 Elasticsearch 的 Suricata `flow` 记录。列表展示观测 IP、源方向记录数、目的方向记录数及首末代表记录。该流程不发送扫描报文，不自动登记或合并资产。

## 范围与业务含义

- 查询绑定当前租户、探针注册标识、网段修订与网络域；查询前及结果交付前均核对权限和配置。重新注册的探针不会混入旧注册代次的记录。
- 时间范围采用 `[start,end)`，最大 24 小时，支持 2000—2100 年的时间值。查询前缀必须等于已保存网段或为其同地址族子网，支持 IPv4、IPv6；不接受非标准 CIDR 或 IPv4 映射 IPv6 表示。
- 源、目的方向分别按流文档计数。同一地址可出现在两个方向，一条文档的两端也可同时属于范围；两列相加不等于独立会话数，更不等于设备数。流超时、重启、多个采集点和重复镜像的影响不在该计数中消除。
- 未指定地址、组播和 IPv4 全局广播不列为候选，两个方向分别返回排除数量。定向广播、路由网关、DHCP 地址复用、NAT 和随机 MAC 不据此自动识别。
- 观测时间是实际流记录的事件时间，不是原生逐包入站／出站时刻。首末记录限于本次窗口，不代表设备首次上线。`observed_at` 是采集器读取 EVE 的时刻；平台接收时间使用 `received_at`，当前发现投影不返回该字段。纳秒保留原值；计数、序号和流标识采用十进制字符串，避免浏览器大整数舍入。

旁路位置、采集配置、流日志是否启用、上报积压、索引刷新及留存清理均影响可见范围。流事件的发生时间与 `flow.start`／`flow.end` 含义不同，后者分别记录起始与末包时间；原生流记录还可能携带超时、强制结束或关闭引擎的原因，见 [Suricata 8.0.7 EVE 流事件](https://docs.suricata.io/en/suricata-8.0.7/output/eve/eve-json-format.html#event-type-flow)。本功能据此仅呈现已经生成并索引的记录，不能从查询处理预算推定长连接的发现延迟。没有记录只能表述为“当前范围未观测到地址”，不能表述为“网段没有资产”。探针离线时可查询仍在留存期内的当前注册代次历史记录。

## 查询与性能约束

接口为 `POST /api/v1/inventory/discovery`，采用现有登录会话、管理员权限、同源和 CSRF 校验，拒绝未知或重复 JSON 字段。完整请求和响应结构见 [OpenAPI 契约](../api/openapi/platform.json)。

索引日期取自上传路由，并不等于事件日期。服务使用当前租户的完整索引族，显式排除日期后缀之外仍含连字符的同前缀租户名称，再按实际 `@timestamp` 限定窗口；离线重放与积压事件不会因跨日落入其他分区而漏查。搜索采用 `pre_filter_shard_size=1`，由 ES 根据查询改写和实际分片时间范围预过滤，每节点最多两个并发分片请求；查询预算和租户额度保持固定。两个方向在同一个搜索请求中完成过滤、复合聚合和首末记录提取。聚合请求每方向最多 513 个桶，用于检测 512 个地址的交付上限；两个方向合并后也受同一上限约束。超限返回 `413 discovery_limit`，用户须缩短时间或缩小前缀，不展示截断目录。

ES 搜索期限为 5 秒、接口业务上下文为 10 秒，每节点最大并发分片请求数为 2；这些是处理预算，不能作为大流量响应时间承诺。每租户只允许一个在途查询，每 UTC 自然分钟最多 6 次查询尝试；Redis 额度服务不可用时不绕过限制。限流返回 `429` 和 `Retry-After: 60`。客户端取消、切换条件或离开视图会取消旧请求，过期回执不会覆盖当前页面。

读取严格检查超时标识、分片完整性、桶数与文档计数、证据租户、索引租户与有效日期后缀、探针注册、代次、原始记录摘要及纳秒时间范围。任一异常均不交付部分结果。返回的 `partition_status=available` 只表示当前租户存在流量分区，`absent` 表示当前租户的流量分区不存在；仅在真实搜索返回完整零分片、显式空命中且无聚合时使用该状态，不使用排除模式的 HEAD 404 推断。分区存在不能证明采集完整，缺失分区也不能推定为存储故障。权限不足、索引删除竞争和存储失败分别按接口错误处理。

首末证据通过 `top_hits` 按 `@timestamp`、`event_id` 排序取得，不使用会降低纳秒精度的浮点日期聚合。读取字段采用白名单，不请求或返回 `event.original`、通信载荷或 PCAP。实现复用现有官方 Go ES API；聚合结构参考 [Elasticsearch composite aggregation](https://www.elastic.co/docs/reference/aggregations/search-aggregations-bucket-composite-aggregation) 与 [top hits aggregation](https://www.elastic.co/docs/reference/aggregations/search-aggregations-metrics-top-hits-aggregation)。

## 查看与登记

列表仅包含一个业务表格。证据弹窗展示首末记录的事件时间、采集器读取时间、源和目的 IP／端口／MAC、事件标识、流标识、来源代次、序号和原始 EVE 摘要；IPv6 端点使用方括号避免端口歧义。

“登记资产”打开现有资产表单，只预填观测 IP 和所选网络域。资产名称、责任、接口名称和 MAC 由用户核对，MAC 不自动带入，因为镜像流量中的 MAC 可能属于网关。登记通过现有资产接口与修订机制保存，不以相同 IP 自动覆盖已有资产，也不建立未经确认的设备关联。保存失败保留表单与稳定对象标识；结果不明时应先查询资产目录。

成功交付前写入 `inventory.assets.discover` 操作审计，标识所选网段并冻结适用审计策略的保留截止，默认 180 天。当前地址观测结果不另存 PG；原始流记录继续遵循协议数据留存策略，登记后的资产遵循原有资产修订历史策略。
