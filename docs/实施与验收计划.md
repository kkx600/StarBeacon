| --- | --- | --- |

| 2 | 采集器运维与检测质量 | 注册与证书生命周期、升级回退、管理网络、规则订阅／自动同步；协议能力、复杂 TCP、分片／跨包／大流与密文边界矩阵 |
| 3 | 数据源、资产与应用流量 | 多源接入及质量、被动发现、时段归属／NAT／账号、动态组与关系；应用会话计量、跨点去重、真实产品正负样本及趋势 |

## 依赖与边界

采集器正式同时支持 Linux 主机服务（systemd）和 Linux 容器。两种方式共享采集、规则、任务与证据契约，服务维护、网卡访问、升级回退和管理网络执行器分别实现。容器模式不得默认获得修改宿主机网络、Docker socket 或宿主服务的权限；不把 Docker 验收方式推定为唯一产品部署方式。该范围已由用户确认。现场 Agent 签名切换、失败回退和中断恢复已有 Go CLI、systemd 模板及 Docker 后端，见[采集器程序维护](采集器程序维护.md)；正式安装引导、两类运行环境全场景、平台灰度、检测引擎／系统升级和网络执行器仍需各自完成实际验收。

首个设备联动按已经确定的通用 HTTP 连接器执行专属 Docker 协议验收。具体防火墙／EDR、真实封禁效果与浏览器认证插件分别验收。真实模型、办公渠道、生产对象存储、企业授权方与沙箱需要对应环境与授权样本，未提供条件时保持未验收状态。

旁路捕获不能保证观测连接建立前的数据；缺失握手、重组缺口和加密不可见均需明确呈现。模型自报分数不作为未经校准的攻击概率或自动执行授权。持续大流量、180 天原包留存、生产磁盘水位和真实响应效果须以容量与运行证据判断。

## 状态推进

每一步依次完成对象与接口、权限和幂等、异常恢复、工程页面与原型、测试、远程真实验证和文档。通过后固定来源并提交；后续改动重新核对其受影响范围。正式版仍受[发布与验收流水线](发布与验收流水线.md)约束，不因阶段提交而缩小验收范围。

固定批准修订的单探针规则自动同步具备持久计划与顺序验证／发布流程，见[规则自动同步](规则自动同步.md)。规则渠道订阅、多探针灰度及全场景验收仍属于第 2 步的未完成范围。

原生统计的连续区间、告警抑制与溢出、重组与捕获限制、缺测／复位／断档／过期及双端查看契约见[检测质量观测](检测质量观测.md)。该子流程不替代持久质量告警、完整协议／大包限额矩阵或生产压力验收。
