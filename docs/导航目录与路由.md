# 星烽 StarBeacon 导航目录与路由

主控平台与原型共用 `web/packages/shared/src/navigation.json`，按业务分组、工作区和功能视图组织页面。目录包含 12 个业务分组、43 个工作区；42 个工程功能视图具有明确的组件、权限和规范路径绑定，分属 28 个工作区，15 个工作区明确当前版本未提供。工作区有入口不代表其全部规划功能已经交付，功能状态仍以实现清单和验收记录为准。

## 入口与归属

| 功能 | 侧栏位置 | 主控平台路径 |
| --- | --- | --- |
| 系统设置 | 系统管理 → 系统设置 | `/system/settings` |
| 用户管理 | 系统管理 → 账号与权限 | `/system/accounts/users` |
| 平台运行状态 | 系统管理 → 平台运维 | `/system/operations/health` |
| 数据留存 | 系统管理 → 数据治理 | `/system/governance/retention` |
| 操作／登录日志 | 系统管理 → 审计日志 | `/system/audit/operations`、`/system/audit/logins` |
| 决策策略／评估记录 | 响应中心 → 决策策略 | `/response/policies`、`/response/evaluations` |
| 联动设备 | 响应中心 → 联动设备 | `/response/devices` |
| 响应动作 | 响应中心 → 响应动作 | `/response/actions` |
| 模型提供方 | 智能助手 → 模型与知识 | `/ai/models` |
| 规则生成 | 智能助手 → 规则生成 | `/ai/rule-generation` |
| MCP 服务 | 智能助手 → MCP 服务 | `/ai/mcp` |
| 规则包／单探针计划／分批发布 | 检测与情报 → 检测规则 | `/detection/rules/packages`、`/detection/rules/sync`、`/detection/rules/rollouts` |
| 资产列表／被动发现 | 资产中心 → 资产管理 | `/inventory/list`、`/inventory/discovery` |
| 资产组／网段 | 资产中心 → 资产组与网段 | `/inventory/groups`、`/inventory/networks` |
| 质量事件 | 流量分析 → 流量采集 | `/traffic/capture/quality` |
| 探针任务 | 探针与版本 → 探针管理 | `/sensors/tasks` |

通知管理和安全报告各只有一个工作区，侧栏直接进入，不再叠加同名子菜单。面包屑去除相邻的重复名称；进入深层页面后展开所属分组并选中工作区，折叠侧栏不改变选择。小屏抽屉复用同一菜单组件。

系统设置是现有功能的统一目录，支持名称查找及系统／全域范围切换。可用入口链接现有页面，具体权限和服务启用状态由功能页面继续核对。当前版本未提供的功能明确说明范围，不能保存配置或执行任务。目录不会代替 OIDC、MFA、自定义角色、租户与配额、备份、情报或沙箱等尚未交付的业务实现。

## 层级与兼容

路由采用 history 模式。系统账号、系统审计和检测规则等使用真实父子路由组织公共路径，父级不重复挂载业务视图；访问目录父路径时进入有效默认页。规范路径可直接访问、刷新、复制及使用浏览器前进后退。

| 旧链接示例 | 规范路径 |
| --- | --- |
| `/users` | `/system/accounts/users` |
| `/operations?view=logins` | `/system/audit/logins` |
| `/models?view=policies` | `/response/policies` |
| `/models?view=mcp` | `/ai/mcp` |
| `/rules?view=sync&mode=rollouts` | `/detection/rules/rollouts` |
| `/sensors?view=quality` | `/traffic/capture/quality` |
| `/assets?view=networks` | `/inventory/networks` |

迁移仅消费旧的页面选择参数 `view`、`mode`，保留业务查询条件、固定时间窗口和 hash 定位。默认页面通过明确配置确定，不依赖数组排列。旧 hash 链接继续经过既有迁移入口。

`/assets/` 属于静态资源目录；资产业务使用 `/inventory/`，避免深层访问被静态资源的 404 策略拒绝。旧 `/assets` 入口继续迁移。缺失的 JS、CSS 等静态文件仍返回 404，不能用业务页面兜底掩盖资源错误。

管理员页面保持会话与角色检查。未登录用户返回登录并保留站内目标；查看角色不显示管理员或未提供的工作区，直接访问管理员路径也不能绕过检查。当前管理员权限撤回后离开受限页面；服务端授权与租户隔离继续独立执行。

页签只显示当前工作区的功能。决策策略、MCP 和规则生成不再混在模型提供方或规则包页签中。切换规范路径会卸载旧页面，取消原有请求并清除离开页面的草稿；同一弹窗的关闭／重开仍遵守各自的草稿与重新授权规则。

## 原型对应

原型保留完整规划目录及合成数据标识，已绑定的工程功能使用相同规范路径。旧 `/page/:id` 链接继续兼容，已有的被动发现、质量事件及分批模式链接迁移至对应功能路径。

工程的每个页面绑定都必须具有原型定义，缺少定义时目录检查失败。网段定义、被动发现、分批发布及探针任务记录分别具有对应页面；被动发现和分批发布作为父功能的下一级视图，一级页签数量仍受既有上限约束。采集器与主控平台保持独立入口和数据边界；规划中的采集器连接、维护及升级页面不能冒充当前 HTTP 管理能力，程序维护的实际范围见[采集器程序维护](采集器程序维护.md)。

图库检查同时核对以下内容：

- JPEG 原始字节、尺寸、状态标识、页面横向边界和浏览器来源。
- 全局主题、共享导航、平台与原型布局的源码摘要。
- 原型、主控平台和共享组件源码树，以及所登记的组件输入摘要。
- 全部基础状态图与补充图的完整清单。

主题不变但导航、组件或页面源码发生变化时，旧截图也不能通过刷新清单取得当前资格。图片必须重新从浏览器捕获，不接受转码、拼接或像素修改。

在线图库以禁止缓存的方式读取目录与来源清单，图片链接使用 SHA 版本标识；源码版本不一致时显示待核对状态，不展示旧图作为当前结果。离线打开仍使用随仓库提供的脚本清单。截图表示合成原型的展示状态，不能替代工程端到端测试或生产资格。

## 偏差原因与边界

先前原型按业务分组组织，实际平台则在 `App.vue` 内独立硬编码平级菜单。已有系统管理功能散落在用户、运维、留存等入口，决策及 MCP 被复用到模型页签；原型页面字典与工程路由也没有完整对应检查。图库只核对主题和图像摘要，未要求导航和组件源码同步，固定图片链接还可能保留浏览器缓存。

共享目录、规范路径及原型绑定分别约束这些偏差。保留的未提供页面属于交付范围说明，不计作业务实现；原型中的组织切换、规划页签和合成操作也不授予生产功能资格。完整需求仍通过[功能实现与验收状态](功能实现与验收状态.md)及[测试覆盖与验收记录](测试覆盖与验收记录.md)核对。
