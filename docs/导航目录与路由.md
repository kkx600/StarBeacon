# 星烽 StarBeacon 导航目录与路由

主控平台与原型共用 `web/packages/shared/src/navigation.json`，按业务分组、工作区和功能视图组织页面。具体数量以 `navigation.json` 为准。全流量回溯已接入工程视图，AI 值守、旁路阻断和联动插件当前提供原型。工作区的功能状态见实现清单和验收记录。

## 入口与归属

| 功能 | 侧栏位置 | 主控平台路径 |
| --- | --- | --- |
| 系统设置 | 系统管理 → 系统设置 | `/system/settings` |
| 用户管理 | 系统管理 → 系统设置 → 用户管理 | `/system/settings/users` |
| 功能目录 | 系统管理 → 系统设置 → 功能目录 | `/system/settings?section=features` |
| 全流量存储 | 系统管理 → 系统设置 → 全流量存储 | `/system/settings?section=traffic` |
| 平台运行状态 | 系统管理 → 平台运维 | `/system/operations/health` |
| 数据留存 | 系统管理 → 数据治理 | `/system/governance/retention` |
| 操作／登录日志 | 系统管理 → 审计日志 | `/system/audit/operations`、`/system/audit/logins` |
| 决策策略／评估记录 | 响应中心 → 决策策略 | `/response/policies`、`/response/evaluations` |

分组只有一个可访问的工作区时，侧栏直接显示工作区并进入其默认功能。例如管理员可直接进入事件调查、通知管理、安全报告和探针管理。面包屑去除相邻的重复名称；进入深层页面后展开所属分组并选中工作区，折叠侧栏不改变选择。导航提供展开与折叠两种 PC 形态。

系统设置当前提供用户管理、全流量存储和功能目录三个分类，默认打开用户管理。全流量存储按采集器显示并下发留存策略，采集器本机可从「采集配置」保存策略。创建账号、编辑权限和重置密码从用户管理分类进入。功能目录支持名称查找与系统／全部功能范围切换。

管理员侧栏列出 28 个已提供工程视图的工作区。功能目录列出规划范围，并将 AI 值守、认证与授权等 16 个工作区标为“当前版本未提供”。有权限的用户直接访问这些规范路径时可查看交付范围和返回入口。

## 层级与父级入口

路由采用 history 模式。系统设置、审计和检测规则使用父子路径。规范路径支持直接访问、刷新、复制和浏览器前进后退。原用户管理地址 `/system/accounts` 和 `/system/accounts/users` 跳转到 `/system/settings/users`，保留查询参数和定位标记。

访问目录父路径时进入 `navigation.json` 中该父级排在首位的子页面，例如 `/sensors` 进入 `/sensors/list`、`/traffic` 进入 `/traffic/events`、`/detection` 进入 `/detection/rules/packages`、`/system` 进入 `/system/settings`；业务查询条件、固定时间窗口和 hash 定位随之保留。各父级的默认页由导航测试逐项固定，调整页面顺序须同步核对这些入口。

`/assets/` 属于静态资源目录，不回退为业务页面；资产业务使用 `/inventory/`，避免深层访问被静态资源的 404 策略拒绝。缺失的 JS、CSS 等静态文件仍返回 404，不能用业务页面兜底掩盖资源错误。

管理员页面保持会话与角色检查。未登录用户返回登录并保留站内目标；查看角色不显示管理员或未提供的工作区，直接访问管理员路径也不能绕过检查。当前管理员权限撤回后离开受限页面；服务端授权与租户隔离继续独立执行。

页签只显示当前工作区的功能。检测规则的规则包、应用识别、重放、同步、关联规则及窗口回测共用导航，可跨组件进入并返回；离开回测时清除专属规则标识和修订，保留一般业务时间条件。决策策略、MCP 和规则生成不再混在模型提供方或规则包页签中。切换规范路径会卸载旧页面，取消原有请求并清除离开页面的草稿；同一弹窗的关闭／重开仍遵守各自的草稿与重新授权规则。

## 原型对应

原型保留完整规划目录及合成数据标识，已绑定的工程功能使用相同规范路径。页面目录与内部链接使用 `/page/:id`，已绑定工程功能的页面跳转至相应规范路径；被动发现、质量事件及分批发布入口直接链接各自页面。

工程的每个页面绑定都必须具有原型定义，缺少定义时目录检查失败。网段定义、被动发现、分批发布及探针任务记录分别具有对应页面；被动发现和分批发布作为父功能的下一级视图，一级页签数量仍受既有上限约束。采集器与主控平台保持独立入口和数据边界；规划中的采集器连接、维护及升级页面不能冒充当前 HTTP 管理能力，程序维护的实际范围见[采集器程序维护](采集器程序维护.md)。

图库检查同时核对以下内容：

- JPEG 原始字节、尺寸、状态标识、页面横向边界和浏览器来源。
- 全局主题、共享导航、平台与原型布局的源码摘要。
- 原型、主控平台和共享组件源码树，以及所登记的组件输入摘要。
- 全部基础状态图与补充图的完整清单。

主题不变但导航、组件或页面源码发生变化时，旧截图也不能通过刷新清单取得当前资格。图片必须重新从浏览器捕获，不接受转码、拼接或像素修改。

在线图库以禁止缓存的方式读取目录与来源清单，图片链接使用 SHA 版本标识；源码版本不一致时显示待核对状态，不展示旧图作为当前结果。离线打开仍使用随仓库提供的脚本清单。截图表示合成原型的展示状态，不能替代工程端到端测试或生产资格。

## 偏差原因与边界

先前原型按业务分组组织，实际平台则在 `App.vue` 内独立硬编码平级菜单。已有系统管理功能散落在用户、运维、留存等入口，决策及 MCP 被复用到模型页签；原型页面字典与工程路由也没有完整对应检查。图库只核对主题和图像摘要，未要求导航和组件源码同步，固定图片链接还可能保留浏览器缓存。

共享目录、规范路径及原型绑定分别约束这些偏差。保留的未提供页面属于交付范围说明，不计作业务实现；原型中的组织切换、规划页签和合成操作也不授予生产功能资格。完整需求仍通过[功能实现与验收状态](功能实现与验收状态.md)及[测试覆盖与验收记录](测试覆盖与验收记录.md)核对。
