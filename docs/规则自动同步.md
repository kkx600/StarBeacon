# 星烽 StarBeacon 规则自动同步

规则自动同步位于主控平台“规则管理 → 规则自动同步”。管理员批准具体规则包修订、正反样本和探针注册代次后，平台依次创建独立签名任务，由采集器执行装载检查、两次离线重放和规则发布。任务受理、验证通过与实际生效分别记录。

当前计划面向单台探针，同租户每台探针至多一份计划，最多 10000 份配置。多个探针可以分别配置计划，这不构成多探针灰度、渠道订阅或容量验收。规则包后续保存的修订不会自动取得执行授权；批准其它修订需要保存新的计划修订。

## 配置与授权

| 参数 | 约束 |
| --- | --- |
| 计划名称 | 1–128 字，不含控制字符或首尾空白 |
| 目标探针 | 固定设备主键，不由分组或目录筛选结果动态扩展 |
| 注册代次 | 批准时明确绑定；重注册或迁移后重新授权 |
| 规则包与修订 | 已存在的不可变修订；不自动选择最新版本 |
| 正反样本 | 已导入且内容摘要不同；执行前剩余有效期须超过 31 分钟 |
| 计划状态 | 创建表单默认停用；启用需要任务签名与样本服务可用 |
| 核对周期 | 30–3600 秒，表单默认 60 秒；这是阶段核对周期，不是检测时延承诺 |

仅租户管理员可读取配置；原批准管理员修改该计划。保存和调度都会在事务中核对账号、租户及角色，权限撤销后不再提交后续步骤。保存采用修订比较，精确输入重试回读同一修订；不同输入不能覆盖旧修订。每日最多提交 10000 次配置变更，命中配额返回 429。

浏览器遇到超时或不完整回执时保留原输入，提供“核对原提交”；不能通过更换计划标识重复提交来推测之前是否保存成功。404、409 等明确拒绝保留原因，管理员核对对象与当前修订后再提交。

## 执行与恢复

1. 冻结当前规则文件摘要。探针须启用、近期在线，并上报匹配的平台签名信任和三类任务能力。
2. 对批准的完整规则包执行原生装载检查。其回执与规则修订、检测配置及剖面绑定。
3. 执行正样本和反样本重放。最终发布资格要求正样本产生告警、反样本不产生告警，实际处理包数有效、无截断或异常，并绑定相同检测配置和剖面。
4. 发布事务重新检查三份签名命令及独立成功回执、一天内的验证时效、当前规则摘要、设备注册代次和未决规则事务。条件变化时拒绝发布。
5. 采集器按既有规则安装事务执行；平台只有读到成功回执中的实际规则摘要、原生装载统计和生效时间后，才把本次运行标记为“规则已生效”。实际装载统计必须非空、规则数量大于零且失败数为零。

每次运行保存批准者与完整配置快照，历史运行不借用后来修订的规则或样本说明。每一步最多创建一个任务，任务标识和阶段同一事务保存。平台进程退出、重复调度或多实例重查从持久状态继续，不重复创建同一步骤的任务。调度每轮最多访问八个租户、每租户十六台到期探针；数据库错误整体回滚该步骤，单台错误不阻止同轮其它目标核对。

探针离线时未提交阶段保持等待，恢复后重新核对条件。原任务已投递但缺少终态回执时继续等待，不推测未执行。执行失败、结果未知、样本失效、签名信任变化或当前规则被其它操作改变，均停止后续发布；先查看独立任务和原生核实结果，再重新保存授权修订。系统不对未知副作用自动重试。

## 停用与历史

在途计划仅允许按原配置停用。停用阻止后续步骤，已经签名下发的任务仍须等待独立回执；如果规则发布已经执行，停用不会把实际生效事实改写为取消。需要取消未投递任务或核实未知发布时，使用独立任务入口；规则回退仍走既有历史修订发布资格。

配置中的注册代次、规则修订、样本和核对周期在在途期间不可替换。已有任务结果明确后，管理员可重新配置；不会把旧运行的部分证据自动拼接给另一份授权。

运行档案按“操作日志”分类固化保留期限，默认 180 天，分类策略可自定义。未结束运行受保护；运行尚在处理或其档案未到期时，引用的任务回执不得被清理。运行档案到期清理后，配置保留已处理修订水位，避免把历史记录缺失误认为尚未执行并再次发布。活动配置本身不是历史日志，不随运行档案到期删除。

“规则已生效”反映该次执行回执，不证明此后未被其它授权操作替换，也不证明真实威胁检测率、加密流量可见性或大流量性能。当前不包括外部规则源自动订阅、自动跟随未批准版本、跨探针灰度、自动故障回退编排及正式容量验收。

## 接口与验证入口

- `GET /api/v1/rule-sync-plans`：主键游标分页，每页最多 20 项，并返回当前有效运行档案。
- `POST /api/v1/rule-sync-plans`：保存批准配置及修订；具体字段见 [平台 API](../api/openapi/platform.json)。
- 单元测试：`internal/rulesync/plan_test.go`、`internal/platform/rule_sync_test.go`。
- 实际依赖测试：`tests/integration/rule_sync_persistence_test.go` 验证 PG 权限、事务故障、离线和身份边界；`tests/integration/rule_sync_test.go` 由原生规则发布用例复用真实 Suricata、mTLS、设备任务队列和独立回执。
- 页面测试：`web/tests/rule-sync.test.ts`；原型入口 `/page/rule-sync`，六种状态截图与来源记录位于原型图库。
