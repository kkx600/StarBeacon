# 星烽 StarBeacon PCAP 留存与会话完整性设计

调研基准日：2026-09-30。平台以旁路 TAP／SPAN 部署为主要场景，授权捕获范围内的 **全量原始 PCAP 默认保存 180 天，告警会话证据默认保存 180 天，均支持分类自定义**。冷热分层只改变存储介质与读取等待，不提前删除仍处于保留期的数据。本文规定捕获、会话归档和导出能够证明的范围；配置值、容量算例和性能门槛均需通过目标环境验收，不代表当前已实现或实测。

## 1. 留存范围与时间基准

| 层级 | 默认策略 | 必须表达的边界 |
| --- | --- | --- |
| 全量原始区 | 对已授权接口／网段连续捕获的原始报文默认保存 180 天 | “全量”仅覆盖已配置捕获范围及实际成功捕获的报文；不能覆盖未镜像、捕获前丢失或探针启动前的数据 |
| 告警会话归档区 | 命中归档策略的会话原始报文保存 180 天 | 保存范围以原始包清单为准，不能将只有告警触发包的文件称为完整会话 |
| 原始握手上下文 | 原始 SYN、SYN-ACK、ACK 等建立连接所需报文随依赖证据保留 | 单独保住握手不能补齐已经过期的中间载荷；是否延长上下文保留必须有策略记录 |
| 归档导出与解析结果 | 作为业务证据保存的结果默认 180 天，支持分类自定义 | 下载授权和临时处理文件可采用更短技术 TTL，不能因此提前删除业务证据；用户取得下载文件后平台不能远程撤回副本 |
| 案件保全 | 独立期限与解除流程 | 只有存储侧保护或保全复制成功后才生效，不能只修改 PG 日期 |

原始包及其会话归档复制的留存以可信采集时间为依据，复制/迁移不重置锚点。独立用户导出、分析报告和解析任务结果属于新产生的派生业务制品，默认从制品首次成功提交时保存 180 天；任务重试不得重复起算，任务半成品使用运行 TTL。派生物保留原始捕获时间与来源范围，保留该物不代表原始完整会话仍可用；生成有审计/配额，普通归档复制不得借此自动续期。对象记录每包时间范围、`captured_first_at`、`captured_last_at`、`retention_until` 和策略版本；混合时间对象按最晚应保留时间删除，避免过早删除其中较新的报文。源时间异常时记录原始时间与校正依据，使用固定的可信策略时间，不能因未来时间戳无限续期，也不能因补传旧文件默认获得另一个完整 180 天。

默认 180 天是归档报文的保存窗口，不是任意长连接全部历史永久可用的承诺。超过窗口的完整会话或案件可申请显式延长保全，其容量单列；未延长时，导出必须标记 `retention_boundary`。延长或缩短策略均保存旧策略和新策略，缩短策略先列出受影响会话、保全与运行任务，不能通过普通配置变更删除已有有效保全。

告警、网络上下文、会话目录和原始 PCAP 等业务数据默认均为 180 天，支持分类自定义。**能够定位 PCAP 所需的最小会话／证据目录必须至少跟随对应 PCAP 留存**；分类缩短日志或告警保留期时，不能导致仍保留的 PCAP 无法定位。目录保留不要求把完整告警副本写入 PG。

## 2. 旁路捕获的交付条件

上线验收确认双向镜像、交换机与 TAP 端口带宽、接口与 VLAN／隧道范围、MTU、截断长度、NIC 队列、RSS、NUMA 和时钟来源。两条满载单向链路镜像到一条同速端口可能在到达探针之前丢包；平台资源充足不能修复这类缺失。抓包网卡不承载普通管理业务，管理口与对象上传带宽单独预算。

探针分别报告 NIC／驱动、内核 ring、捕获进程、检测器、归档写入、上传六段的丢包／失败与水位。交换机源端丢包无法从主机计数直接证明为零，需接入镜像源健康数据或以授权探测验证。未取得源端指标时显示“镜像源完整性未验证”，不能将本机 `drop=0` 宣传为链路零丢包。

捕获保留原始报文及 `captured_length`、`original_length`、linktype、原包时间、section／interface、包序号和方向来源。抓包截断、NIC offload、校验和卸载、VLAN 硬件剥离、非对称流、流表淘汰、配置空窗分别标记。默认不以只抓包头或采样实现“完整通信”；缩短 snaplen、BPF 排除或流量采样属于明确改变证据覆盖的策略。

### 2.1 检测与原始归档的独立性

检测深度、协议解析上限、规则动作和模型判断不应决定全量原始区是否保留原始字节。归档路径可以复用经过验证的捕获基础设施，但必须有独立的完整性配置、写入资源和水位；开启检测旁路优化后，原始归档仍应取得授权范围内的报文。

锁定的 Suricata 8.0.7 官方手册在 PCAP 章节描述 depth／加密流排除，而同版本模板显式设置 `use-stream-depth: no`、`honor-pass-rules: no`，源码默认也关闭这两项。不能只凭手册一句话或 `conditional: all` 推断生产完整性。交付保存真实渲染配置、引擎构建和黄金 PCAP 结果，逐项验证 TLS 握手后、超检测深度、pass 规则、捕获侧 bypass、BPF、线程轮转和引擎重启后的原始包覆盖。[PCAP 手册](https://docs.suricata.io/en/suricata-8.0.7/configuration/suricata-yaml.html#packet-log-pcap-log)、[锁版模板](https://github.com/OISF/suricata/blob/suricata-8.0.7/suricata.yaml.in#L427)、[日志实现](https://github.com/OISF/suricata/blob/suricata-8.0.7/src/log-pcap.c#L581)

使用 Suricata 自身作为归档写入器时，显式审查 `conditional: all`、`use-stream-depth: no`、`honor-pass-rules: no` 与全量范围内的 BPF／捕获 bypass；这些配置不能弥补引擎停机或抓包丢失。独立归档写入器则需验证它与 Suricata 收到同一授权流量：不同 fanout group 是复制、同组分发是拆包，不能配置成双方各收一半。不能未经压测同时启动第三个全量抓包器。

Suricata 的 `conditional: alerts` 可以利用流引擎尚存的数据，但不保证取得任意早于告警的握手和正文。因此其产物可作补充证据，不能单独作为 180 天完整告警会话归档的来源。[条件 PCAP](https://docs.suricata.io/en/suricata-8.0.7/configuration/suricata-yaml.html#packet-log-pcap-log)

## 3. 从全量原始数据形成告警会话归档

归档提升从**告警持久接收后**开始，独立于 LLM 研判、人工审批和通知是否成功。告警最终仍全量进入 ES；高峰时不能等待数分钟模型队列才抢救即将轮转的证据。平台正常在线时可下发精确会话归档任务；探针允许按已发布归档策略预留本地告警证据，这只是数据保存，不授予离线封禁权限。

1. 用租户、探针注册身份、捕获域、接口／隧道上下文、双向五元组、会话代次与时间区间定位候选包。Community ID 或五元组不单独作为长期唯一会话键。
2. 为仍在原始区的相关对象取得防删除租约，先保护后读取；对尚未封片的文件取得一致快照／封片水位，不读取持续变化文件后宣称哈希固定。
3. 按授权会话包集合形成稳定 manifest，从连接建立阶段至告警时刻，并按政策继续收集后续双向报文。默认在受保护的原始对象上建立包级引用；需独立保全或不同存储策略时提取到归档区。多条告警关联同一会话归档，不无差别复制多份。
4. 原始对象及所需派生复制上传完成后验证大小、SHA-256、对象版本、原包映射与范围。multipart ETag 不作为通用 SHA-256。
5. 取得存储侧保留保护，提交归档 manifest、保留截止时间和目录状态；只有这些条件全部成立，才把提升状态标为 `protected`。
6. 释放短期读取租约，并由对账任务清理未完成分片／孤立制品。平台崩溃、回执丢失和重复任务按稳定任务及对象身份重试，不改变原始包身份。

状态机为 `requested → locating → protecting → materializing → verifying → protected`；失败分为 `retryable_failed`、`insufficient_capture`、`expired`、`permission_denied`、`quota_exceeded`。`protected` 只表示已物化的范围受保护，其会话完整性另有独立字段。

仅设置 PG 租约不能阻止 S3 生命周期删除。若原始桶存在独立删除规则，必须提前形成存储侧 retention／legal hold 或完成受保护复制，再允许到期清理；在不能协调生命周期的实现中，不提供到期边缘任务的完整性保证。调度保护提前量至少覆盖时钟误差、队列最坏等待、对象读取／复制与重试预算，按实测确定，并展示最早证据到期时间。

超过默认 180 天窗口仍持续的长连接，其最早正文可能已经到期；探针在连接建立后才上线时，也从未取得此前正文。可为活跃流保留原始握手上下文，但告警发生后仍只能归档实际尚存范围。需要这类长连接从建立至关闭全部载荷时，应为明确网络区配置更长全量窗口或预先设置完整会话保全，不能通过回溯算法补出已经删除的字节。

## 4. TCP 建立连接与完整通信

用户所述“AK／CK”在此落实为 **TCP 的 SYN → SYN-ACK → ACK 建立连接过程**。系统验证实际捕获的方向、序列号与确认号，不通过生成虚拟报文补足三次握手。普通三次握手只是一种建立路径，还需处理重传、同时打开、TCP Fast Open 的 SYN 携带数据，以及最终 ACK 同时携带应用数据。[TCP 建连与序列号](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.5)、[TCP Fast Open](https://www.rfc-editor.org/rfc/rfc7413.html)

校验必须按 TCP 32 位序列空间计算 SYN／FIN 消耗及实际载荷长度；不能把所有 ACK 固定当作“对方序列号 +1”。相同五元组的 SYN 先识别同代次重传、TCP Fast Open 重传与同时打开，不能见 SYN 就新建会话。只有结合新 ISN、旧会话关闭/超时和经验证的连接复用证据才能建立新代次；单纯探针重启或序列变化不足以证明新连接，无法关联时保留独立观察记录并标记 ambiguous。不能将两次连接的 SYN 和载荷拼接为一份伪完整会话。

| 维度 | 状态示例 | 含义 |
| --- | --- | --- |
| `handshake_status` | `verified`、`partial`、`not_observed`、`not_applicable`、`ambiguous` | 建立过程有原始包及序列关系验证；UDP 不使用 TCP 三次握手标准 |
| `bidirectional_status` | `observed`、`one_sided`、`unknown` | 两方向是否真实可见，不从 SYN 源地址猜测另一侧已捕获 |
| `payload_coverage` | `contiguous_verified`、`gap_detected`、`truncated`、`unknown` | 连续性和截断情况，不通过能够解密与否判断字节是否保存完整 |
| `payload_visibility` | `plaintext`、`encrypted`、`partially_decrypted`、`unknown` | 明文可见性独立记录；完整密文可能无法恢复应用内容 |
| `termination_status` | `fin_verified`、`rst_observed`、`active_at_cutoff`、`not_observed` | FIN／RST 或导出截止时仍活跃；会话超时不冒充已观察到正常关闭 |
| `capture_quality` | 丢包范围、截断、错序、重复观测、启动中途、超出留存 | 捕获质量独立于是否成功解码应用内容 |
| `export_completeness` | `full_session`、`snapshot`、`partial`、`unavailable` | 导出结果的业务标签，由以上证据和请求范围联合决定 |

`payload_coverage` 的连续性与 `payload_visibility` 的加密状态分开，不能因为 `encrypted` 覆盖掉 `gap_detected`。三次握手已验证不表示应用通信完整；TCP 字节连续也不证明镜像链路从未漏掉重复 ACK／重传包。完整性声明限于该捕获域的已验证观测，不声称还原互联网链路上每一个实际报文。

默认 TCP“完整会话导出”范围固定为该代次建立连接至经序列核对的关闭，要求握手已验证、双向观测、`payload_coverage=contiguous_verified`，且没有未解决的截断/缺口/身份歧义。`unknown` 或 `ambiguous` 不得满足严格完整条件，任意时间子区间也不能标成 full_session。正在通信的连接提供“会话快照”，固定 `cutoff_at`，不无限等待连接结束，也不标为完整关闭会话。RST 终止可以构成所观察会话的结束，但不等于业务交易成功。

UDP、ICMP 等无 TCP 建连过程的协议将握手标记为 not_applicable，默认按明确时间窗口导出快照；只有已验收的应用事务解析器证明事务范围完整时才声明该层事务完整，不套用 TCP 全连接条件。

缺少任一条件时，严格模式返回不可满足项；用户可明确选择部分证据／快照导出，文件和 manifest 同时标记原因，不悄悄把严格请求降为部分文件。单独的“握手＋命中区间”模式有价值，但即使握手齐全，也不能称为全会话载荷。

## 5. 跨切片定位与导出

导出先解析不可变会话身份，再从证据目录查询所有相关切片、包范围及握手上下文，不仅按告警前后固定 60 秒或单个对象取包。输入 manifest 绑定原始对象版本／摘要、原包 ID、授权版本与保留截止时间，作业过程中重新核对权限及存储可用性。

原始包顺序、每个接口时钟与重复观测保持可追溯。多个探针分别看到同一连接时，不默认合并成单一完整流；跨 NAT、负载均衡、隧道和非对称路由的拼接需要可信映射、时间误差界限及方向验证，不能只靠端口相同。无法可靠关联则分别导出并说明关联候选。

导出包括 TCP 重组依赖、相关 IP 分片和封装信息时，仍受请求者的包集合授权约束。上下文涉及未授权业务域时返回范围不足或经过授权的摘要，不能以“补握手”为理由扩大数据权限。共享大切片只提取授权包，不把其他会话原文一并下载。

PCAPNG 输出保留各 section／接口 linktype 与时间分辨率；导出包序号可以重排，但每个导出包都可映射回原始 packet ID。输出附 SHA-256、大小、包数、实际起止时间、选择模式、原始输入引用、缺口及工具版本。只支持单 linktype 的 PCAP 输出不得静默丢弃其他接口报文。[PCAPNG 草案](https://datatracker.ietf.org/doc/draft-ietf-opsawg-pcapng/)

纯字节提取、会话完整性校验和 TShark 协议解析分别限额。大会话导出采用流式读取／写出和分卷 manifest，不要求把整个会话放入内存；跨卷的完整性由包清单证明。现有 TShark 默认 2 GiB 输入限制是深度解析任务预算，不应无意中变成所有合法 PCAP 导出的统一最大值。超预算任务转有配额的专用导出队列，不挤占实时检测和事件入库。

## 6. 数据契约与页面

| 对象 | 关键字段 |
| --- | --- |
| 捕获策略 | `capture_policy_id/version`、范围、接口、过滤摘要、`full_capture_retention_days=180`、`alert_session_retention_days=180`、冷热迁移策略、snaplen、归档准入与配额 |
| 会话身份 | `session_id`、`session_generation`、`capture_domain`、双端身份、L2／隧道上下文、first／last observed、关联来源 |
| 归档 manifest | `manifest_id/version`、源对象 version/hash、包范围、握手 packet IDs、双向字节／包数、可用窗口、保留与保全、缺口 |
| 完整性 | 握手／关闭状态、连续性、加密可见性、捕获／保留原因、校验器版本、证据引用、`assessed_at` |
| 导出请求 | `mode=full_session/snapshot/handshake_and_match/matched_packets`、`require_handshake`、`completeness_required`、时间水位、格式、最大字节与分卷 |
| 导出结果 | `requested_scope`、`materialized_scope`、`cutoff_at`、状态／失败原因、输出摘要、完整性、授权到期、下载方式 |

接口建议为 `GET /api/v1/sessions/{id}/capture-coverage`、`POST /api/v1/sessions/{id}/archive-jobs`、`POST /api/v1/sessions/{id}/export-jobs`；任务结果沿用统一任务中心与证据下载授权。业务鉴权分别覆盖会话摘要、原始包、上下文扩大、归档保全与下载，不暴露任意 S3 key 读取接口。

会话页面展示“可用全量区间”“归档区间”“握手是否齐全”“已观察到关闭／仍在通信”“缺口原因”“最早证据到期时间”。当严格导出不可用时直接说明，例如“连接建立发生在探针启动之前”“前段载荷已超过配置的保留窗口”“仅观察到单向流量”，不只显示通用下载失败。

告警到来后，列表可以先展示“证据归档中”；完整性检查、对象上传与文件沙箱耗时不阻塞原始告警推送。后续证据就绪更新同一事件，保留通知和研判修订，不重复制造相同原始告警。

## 7. 容量、对象数与写入预算

设授权范围实际捕获数据为 `R` 字节/秒，全量原始保留 `D=180` 天。默认全量容量不能乘以告警包比例；冷热分层容量之和仍覆盖完整 180 天。

```text
全量原始字节 = R × 86400 × 180
物理规划容量 = 全量原始字节 × 冗余系数 / 压缩比 / 目标最高磁盘利用率
独立告警归档复制增量 = R × 86400 × p × 180 × 相同物理系数
```

`p` 是**完整选中会话的字节占比**，不是告警条数占比、触发包比例或流量采样率。一次告警可能提升一个巨大长连接；误报不会自动释放已经承诺保存的证据。默认引用原始包的 manifest 不重复保存载荷，但仍有目录及保护开销；独立归档副本、案件保全、延长握手上下文、对象记录头、sidecar、导出、修复和独立灾备另计，不能假定跨桶物理去重。只有确实完成物理复用且生命周期一致的实现，才能扣除重复字节。

以 EC 8+4 冗余系数 1.5、利用率 70%、无压缩为算例，默认全量 180 天的容量如下。流量指被保存字节的持续速率，若输入是链路线速，还要换算协议及捕获文件开销。

| 持续捕获速率 | 每日原始数据 | 180 天原始数据 | EC 数据及校验字节 | 物理规划容量 |
| --- | ---: | ---: | ---: | ---: |
| 100 Mbit/s | 1.08 TB | 0.1944 PB | 0.2916 PB | 0.4166 PB |
| 1 Gbit/s | 10.8 TB | 1.944 PB | 2.916 PB | 4.1657 PB |
| 10 Gbit/s | 108 TB | 19.44 PB | 29.16 PB | 41.6571 PB |
| 40 Gbit/s | 432 TB | 77.76 PB | 116.64 PB | 166.6286 PB |
| 100 Gbit/s | 1.08 PB | 194.4 PB | 291.6 PB | 416.5714 PB |

如另外复制 1% 的完整告警会话并同样保留 180 天，1 Gbit/s 算例额外约 41.657 TB 物理容量；1% 只是算例，不能作为产品承诺。完整容量与负载基准见[实施与容量规划](实施与容量规划.md)。

无压缩时，持续 1／10／40／100 Gbit/s 对应逻辑顺序写入 125 MB/s／1.25 GB/s／5 GB/s／12.5 GB/s；EC 8+4 的纯数据及校验字节分别约为其 1.5 倍。70% 磁盘容量利用率用于容量留白，不代表磁盘或网络已经获得同等吞吐余量。修复、读取导出、索引、multipart、复制和冷层迁移的并发另压测。近端磁盘缓存按断网和上传积压时长独立定容，不能把本地缓存天数当作对象存储保留期限。

128–512 MiB 切片适合起步验证，不能机械用于所有速率。持续 100 Gbit/s、512 MiB 对象约产生 23.3 个对象/秒，180 天约为 3.62 亿对象；1 Gbit/s 同条件也约有 362 万对象。采用更大封装对象、可寻址块与分区 manifest 降低目录压力时，仍保留包级授权和 Range 提取能力。告警会话可通过目录引用封装对象中的包范围，不默认每会话生成一个小型 S3 对象。PG 目录分区／归档和对象清理吞吐必须计入交付，不能只购买足够磁盘。

冷热迁移需同时保存介质层级、可读状态、恢复作业和预计等待；迁移后包引用保持稳定。低频层若要求先恢复整个大对象，应把读取放大、恢复等待和费用纳入导出计划，不能把“保留 180 天”描述为任意历史全量即时下载。

压缩是独立存储策略：低级 Zstandard 独立帧、包/块 sidecar、Range 解压、无损校验及 ZIP 导出边界见[PCAP 压缩与存储布局设计](PCAP压缩与存储布局设计.md)。没有实际流量压测前采用压缩比 1，不以通用文本基准承诺 PCAP 空间收益。

## 8. 验收场景

| 场景 | 必须达到的结果 |
| --- | --- |
| 双向普通连接完整捕获 | 导出含真实 SYN／SYN-ACK／ACK、双向载荷和结束证据，序列校验通过 |
| SYN／SYN-ACK／最终 ACK 重传或携带数据 | 正确保留原始报文，不把重传当新会话，不固定假设 ACK 无载荷 |
| TCP Fast Open、同时打开、32 位序列回绕 | 按协议和实际字节校验，无法判定时返回 ambiguous 而非伪完整 |
| 探针在连接中途启动、单向镜像、镜像源过载 | 缺少握手或双向数据清晰可见，严格完整导出不成功 |
| 告警出现在第 181 天的长连接 | 不声称还原已过期第 1 天正文；握手上下文与完整正文状态分开 |
| 相同五元组端口复用、跨 NAT／多探针 | 不合并不同会话代次；无可信映射时不强行拼接 |
| 归档提升与 180 天到期删除同时发生 | 先存储侧保护再复制；任务失败不虚报 protected，缺失范围可对账 |
| 超 stream depth、TLS 后续密文、pass／bypass | 原始归档与检测可见性分别验证，不因检测停止误标为完整保存 |
| 跨切片、乱序、IP 分片、VLAN／隧道、多 linktype | 依赖包和原始来源映射完整，不能静默丢掉其他接口数据 |
| 跨组织共享切片、作业中撤权 | 只输出授权包，握手补取亦遵守范围；即时撤权走网关验证 |
| 180 天窗口边界、案件保全、策略缩短 | 默认到期和保护优先级可验证，不因普通生命周期删除保全证据 |
| 高流量加告警风暴、上传断网、磁盘满 | 告警、归档、控制资源隔离；缺失／积压明确，不能用静默减少覆盖达标 |
| 大会话分卷与取消、导出 Worker 崩溃 | 内存有界，部分产物不冒充完整，重试不改变原始包身份 |

完整性测试使用有权使用的 PCAP 和可复现的合成正常流量，保存包清单、渲染配置、版本和预期结果；生产流量中的缺包不通过补造数据修复。捕获 PPS、归档字节/s、对象上传延迟、提升最老等待时间、目录水位、严格导出成功率及原因分布共同验收。
