# 星烽 StarBeacon 安全运营与数据治理设计

设计基准日：2026-09-30。本文定义多源数据、资产身份、情报、暴露面、关联检测、狩猎、案件和自动化剧本的产品与工程契约。功能范围以[功能覆盖与验收矩阵](功能覆盖与验收矩阵.md)为验收目录，本文不代表能力已经实现。原始告警和安全日志仍入 ES，控制配置与人工业务流程入 PG，大制品入 S3。

## 1. 数据来源与能力就绪

每项能力显示“未配置、验证中、可用、部分覆盖、数据延迟、异常、停用”，同时显示来源、最近成功、水位、有效范围、字段覆盖和版本。连接器显示在线不等于已取得所需数据；试用许可或仅有连接器代码也不等于功能已验收。

| 信号 | 接入方式 | 可支持的分析 | 证据边界 |
| --- | --- | --- | --- |
| Suricata、Flow Meter、PCAP | 注册探针 gRPC／对象上传 | 网络检测、协议、会话、应用和包取证 | 受镜像位置、加密、丢包和保留限制 |
| NetFlow/IPFIX/sFlow | 客户侧授权 exporter 接收器 | 无全包环境的通信/带宽观察 | 模板、采样和计数口径明确，不产生不存在的 PCAP 或请求正文 |
| 防火墙、WAF、DNS、代理 | Syslog、受限 API、文件增量连接器 | 放行/阻断、地址转换、解析和服务访问 | 设备时钟、日志开启项与字段版本必须验证 |
| EDR、主机审计、身份系统 | 客户已有系统 API／授权日志 | 进程、用户登录、终端隔离和身份异常 | 不由网络流量假造进程树、文件或登录用户 |
| 云与容器 | 已授权账户、区域和服务连接器 | 云审计、对象访问、控制面和工作负载事件 | 分页、水位、服务限流及可用区域单独验收 |
| CMDB、漏洞扫描、软件清单 | 导入、API、授权扫描任务联动 | 资产归属、漏洞/配置弱点和修复追踪 | Banner 匹配仅为疑似，扫描失败不等于无漏洞 |
| 威胁情报与知识 | feed/API、STIX/TAXII、离线签名包 | IOC、上下文、检测映射与追溯匹配 | 来源权限、分享限制、有效性和撤回独立记录 |

基础生产能力包含上述数据源的通用框架、已声明首批连接器和导入契约，不能以“支持全部设备”替代具体版本验收。产品清单与测试夹具登记在连接器能力目录，离线环境可使用相同 schema 的导入路径。

## 2. 多源安全日志接入

### 2.1 注册与运输

数据源配置包含 `source_id`、所属租户/组织/网络域、类型、设备版本、传输方式、证书或 credential_ref、解析器版本、期望速率、时间策略、数据分级、留存和责任人。接入流程为注册 → 认证/样本验证 → 字段覆盖预览 → 小流量观察 → 启用 → 健康监控；仅保存配置不自动扫描设备或读取全租户日志。

Syslog 入站与已有 Syslog 输出是独立能力。默认采用 RFC 5424 + TLS 的注册发送方；TCP 按约定的 octet counting 分帧，兼容 RFC 3164 需要显式时区和缺少年份处理规则。UDP 仅用于明确接受丢失风险的受控采集区；它不能返回持久 ACK。TLS/TCP 流控也不等于设备端已支持应用确认或重发，页面分别记录输入、持久接收、隔离与缺口。[RFC 5424](https://www.rfc-editor.org/rfc/rfc5424)、[RFC 5425](https://www.rfc-editor.org/rfc/rfc5425)、[RFC 6587](https://www.rfc-editor.org/rfc/rfc6587)

租户由证书、注册 API 身份或客户连接器固定绑定；不信任 Syslog 正文中的 HOSTNAME/tenant、可伪造来源 IP 或任意 HTTP header。无法提供强身份的 UDP 设备应接入专属客户收集器/隔离监听域，再由收集器 mTLS 上报；共享 NAT 后的多个客户不能靠公网 IP 分租户。API 连接器使用外部稳定 ID 和游标分页，提交本地 WAL 后再推进游标；失效游标进入有界重扫并去重。

### 2.2 解析、身份与质量

1. 接收端先限制单条与解压后大小、字符集、速率和连接数；原始字节与传输元数据进入来源绑定的持久域，再运行隔离的解析器。
2. 每条记录有稳定源身份：文件代次/偏移、外部事件 ID，或收集器持久 `source_epoch/sequence`。设备真实重复发送的两条相同文本，若没有上游 ID，就不能靠正文 hash 合并成一条；正文 hash 只用于完整性校验和辅助重复标记。
3. 保存源时间、时区、接收时间、时间可信度、解析版本、原始类型和质量状态。RFC 3164 缺少年份时保留推断依据；未来时间、DST 歧义和严重漂移标记异常，不修改原始文本掩盖问题。
4. 按版本化映射输出 ECS 核心和 `starbeacon.*` 扩展。新字段进入映射审核；不因某设备产生任意键就创建数万 ES 字段。
5. 解析失败进入持久隔离区，提供样本、原因、受影响数量、修复版本和受限重放任务；隔离不是数据已正常可查。重解析产生新的派生修订，不制造第二条原始事实。

接入健康包括期望/实际 EPS、源序列缺口、格式错误、时间偏移、重复重试、字段覆盖、WAL、队列年龄及可查水位。告警与安全日志使用不同队列配额，日志风暴不能耗尽告警保底空间。脱敏在普通检索视图执行，原始敏感内容按证据权限和短留存保存；不声称文本遮罩会改变已经捕获的 PCAP。

### 2.3 网络流记录接入

NetFlow v5/v9、IPFIX 和 sFlow 接收优先复用 GoFlow2 2.2.7 的协议解码与模板组件，不重新编写这些二进制协议。仅选用必要解码组件与平台持久发送适配，不因上游有 Kafka 输出模块就强制部署 Kafka。采集器绑定 exporter 和网络域；UDP exporter 使用隔离接收域及允许列表，不从可伪造字段获得其他租户权限。[GoFlow2 固定版本](https://github.com/netsampler/goflow2/tree/v2.2.7)

IPFIX/NetFlow v9 模板缓存键至少含来源绑定、传输会话、observation domain/source ID、template ID 与 exporter 代次。模板重用、超时、重启和乱序需要可见状态，未知模板记录不能猜字段解码；设置模板数量、生命周期与单消息限额。原始 export sequence 按协议解释，不能把“计数单位是记录”的序号误当包序号判断丢失。

保存 flow start/end、export/receive 时间、来源时间基准、采样类型/比例、字节/包数、入口/出口 ifIndex 和方向质量；若缺少绝对时间或设备重启导致 uptime 回绕，输出 unknown/推断标记。抽样放大值与原样本值分开，跨镜像与 exporter 通过计量域指定唯一汇总源，避免双计数。流记录无报文字节时只提供事件/流检索，不显示原生包过滤可用。模板容量、乱序、采样变化和高 PPS 接收需要独立夹具与实测。

## 3. 资产、地址与身份解析

资产具有稳定 ID、多网卡、地址/服务/软件版本、业务/组织/责任人以及有效时间。未纳管地址首先是观察对象，允许认领、合并建议、拆分、冲突处理、维护和退役；合并不可抹掉来源和历史 ID。

| 关系 | 必需内容 | 解析规则 |
| --- | --- | --- |
| IP—接口—MAC | 租户、网络域、站点、接口、IP、MAC、VLAN/VRF、有效窗、来源、信任等级 | 路由后的 MAC 往往是网关；随机化/克隆 MAC 不是永久主机身份 |
| DHCP/ARP/NDP | 地址、租约/观察窗口、server/客户端标识、消息类型、来源包/日志 | DHCP release/expiry 和冲突分别处理；单次 ARP 可伪造，不覆盖可信 CMDB |
| NAT/PAT | 原始与转换后的源/目的 IP+端口、L4、原/后网络域、有效窗口、设备/规则/连接 ID | 仅公网 IP 不足以映射终端；端口复用、时间重叠或缺失时返回 ambiguous |
| 用户—终端—会话 | 身份系统命名空间、稳定用户 ID、设备 ID、登录/注销、有效窗、认证来源 | HTTP 用户名、邮箱文本不是已认证登录身份；同名跨域不合并 |
| 服务/云/容器 | 来源账户、区域、实例/工作负载 ID、生命周期、服务端口、证据 | 短生命周期 IP 回收后不把旧风险转给新实例 |

业务确认关系在 PG 保存版本及 `valid_from/valid_to/recorded_at`，高频观察在 ES；不可为每个包更新 PG。解析结果包含 `resolved/ambiguous/unknown/external`、候选数、来源和置信依据。人工覆盖需理由、到期时间和前后版本；新观察冲突不会静默抹掉覆盖。

告警同时保存 source/destination 的资产快照与网络域；client/server 另按协议握手与角色证据判断，不因端口较小就认定服务器。自动动作需要唯一目标时，必须验证映射在事件时间及执行时间均适用；NAT 映射不确定、资产迁移或共享出口不能自动转成终端隔离或大范围 IP 封禁。

入站/出站流统计以已版本化的安全域边界为准；真实接收/发出包时间依赖观测点与采集接口，双向 first/last 时间不能代替网卡 rx/tx。MAC、接口、包时钟和未知原因统一见[高级检索与数据包取证设计](高级检索与数据包取证设计.md)。

## 4. 漏洞、弱点与暴露面

平台提供资产暴露总览、端口/服务变化、漏洞弱点列表、修复任务、风险接受与复测。主动扫描通过经过授权的外部扫描器连接器执行，记录目标集合快照、网络域、时间窗、最大速率、凭据引用和停止条件；平台不实现另一套扫描引擎。

漏洞记录包含来源/外部 finding ID、扫描批次、资产/服务/软件实例、CVE/CWE 或配置规则 ID、版本、CVSS 版本及向量、首次/最近观察、证据等级、修复建议、补丁和复测时间。无 CVE 的弱配置也可建项；同一 CVE 在不同端口、软件实例上的发现不能无条件合并。软件名/CPE 匹配保存候选和方法，不能把不确定版本强判受影响。

风险排序综合资产重要性、实际暴露、可利用性资料、已观察攻击和修复状态，保留评分版本。KEV、EPSS 等外部信号有快照日期和来源；EPSS 是未来一段时间利用活动预测，不是某资产失陷概率。[CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)、[FIRST EPSS](https://www.first.org/epss/)

状态为待核实、确认存在、修复中、待复测、已修复、风险接受、误报、重新打开。人工标记修复不自动成为复测通过；只有范围和权限完整的成功复测可关闭，扫描器离线/权限下降/资产未扫描均保留未知。风险接受包含理由、审批、补偿措施、责任人和期限，到期重新进入待处理。首个生产档须交付导入与至少一个扫描来源的闭环，连接器未授权时界面显示未配置。

## 5. 威胁情报生命周期

来源登记所有者、连接器、授权与共享限制、数据驻留、类型、更新方式、质量评估、优先级、有效期和停止条件。支持 IP/CIDR、域名、URL、文件 hash 等声明类型；每种类型有独立规范化和匹配方法，不把域名后缀简单字符串包含当子域匹配，也不丢弃 URL 大小写与编码语义。

同步为游标/版本化快照，支持增量、全量、离线包、撤回和失败恢复。事实唯一键含来源、上游标识和版本；跨源可聚合规范 IOC，但保留来源分歧与各自信任等级。原始情报在 ES/制品，PG 保存配置和同步任务；匹配热点以只读版本制品下发 Worker，Redis 不是唯一情报库。

情报状态包括有效、待核验、已过期、已撤回、被抑制。命中记录保存事件 ID、IOC 版本、匹配字段/值、时间和资产证据。撤回/过期不会删除历史命中依据，但会更新当前风险投影、评估有效动作并按策略撤销；不能仅刷新缓存却让旧 IOC 持续触发封禁。

追溯匹配是有范围、时间、字段覆盖和最大扫描量的异步狩猎任务，稳定匹配 ID 防止重跑重复建案。完成报告区分已扫描、有缺口、过期不可查、失败分区。情报分享和导出继承原始分享限制，MCP/LLM 不得绕过；恶意样本不能自动上传第三方服务。[MISP 数据格式](https://www.misp-project.org/datamodels.html)、[STIX 2.1](https://docs.oasis-open.org/cti/stix/v2.1/os/stix-v2.1-os.html)

## 6. 检测工程、关联与威胁狩猎

### 6.1 检测规则家族

Suricata 网络签名、应用识别、IOC 匹配和日志关联是不同规则类型，共用版本、样本、审批、灰度、回滚、负责人、例外和效果评估。导入 Sigma 时保留原始 UUID、logsource、版本、许可证和字段管线；只接受编译器已声明支持的规则/关联子集，不将 Sigma YAML 原样执行或承诺任意转成 Suricata SID。规范与官方转换组件可复用，平台只编写目标字段映射和经过验收的适配层。[Sigma 规范](https://github.com/SigmaHQ/sigma-specification)、[pySigma](https://github.com/SigmaHQ/pySigma)

### 6.2 有界关联执行

支持计数、不同值计数、有序序列、存在/缺失事件及时间窗组合，按租户、网络域、资产/身份等显式键关联。规则定义输入数据集、必需字段、窗口、允许迟到、去重键、最小覆盖、基数上限、输出严重度、例外、版本及冷却。基础密码喷洒、横向访问、外连、DNS异常、异常外传等是需验收的数据驱动模板，不是仅靠名字判定攻击。

事件时间与处理时间分开；stream watermark、已暂停来源与最大乱序共同决定窗口状态。未到达水位的“没有事件”不能当确定缺失；采集断流或未知字段不能触发“未发生正常认证”等否定规则。超迟到事件进入补算队列并标注修订，不重复生成历史自动封禁。

首个实现复用 JetStream 有界消费与 ES 固定分区事实，窗口状态由可恢复检查点和源水位重建；每键内存、全局活跃键、窗口宽度及回查次数有限额。规则分片以单一有效执行代次处理同键，计数窗口使用稳定 `detection_id = hash(tenant, rule_revision, key, window_id, match_slot)`：普通阈值窗口只有一个固定槽位；有序序列的多个独立匹配按规则声明的锚点事件 ID 区分。证据集合 hash 存在输出修订中，迟到补证据更新同一检测实例，不能改变 ID 后再触发一次动作。滑动窗口的步长、槽位及跨窗抑制键必须在规则中固定；源事件按稳定 ID 去重，消息重投不能简单累加。输出使用固定存储路由和递增修订，旧修订不得覆盖新结论；动作按检测实例与策略代次幂等。Redis 可加速状态，丢失后必须重放/重建且暂停受影响自动结论，不能以空缓存判为无风险。

每个检测实例首次形成告警时写入不可变 `alerts` 事实，后续证据、撤回或重算追加到 `detection-revisions`，再按版本更新 `alert-search` 的当前投影；不能对原始告警执行覆盖写。分片持久输出包含检测 ID、证据集合摘要、输入水位、执行代次与稳定修订键；输出持久化后才推进检查点，重放先核对相同修订键及内容，旧执行代次不得覆盖新状态。告警数量按检测实例计数，修订次数单列。

若实际关联规模超出有界窗口与恢复预算，按 ADR 引入专用流处理引擎；当前不声称 Go Worker 能无状态完成任意 CEP。关联告警进入统一 ES 告警与响应门控，规则变更、迟到和重建中的结果标记 provisional，不能直接自动处置。

### 6.3 狩猎、基线与覆盖

狩猎提供保存/共享查询、参数化模板、跨网络/终端/身份的授权关联、历史任务、结果固定、笔记、证据和转事件。结果必须携带查询版本、数据集、水位、权限范围、数量语义、扫描成本和覆盖。图关系包括类型、时间区间、来源与置信依据；LLM 推断的边与观察事实分层显示，不补造完整攻击链。

基础基线按资产角色/用户/时间段分别建立，保存训练窗、最小样本、排除维护/已知攻击的策略、季节性、阈值和模型版本。冷启动/样本不足/数据源缺失时不产出异常确定结论。管理员能解释一次异常相对哪个基线偏离、反馈正常并回放阈值；不默认让普通用户行为自我学习为白名单。

ATT&CK 固定知识版本并关联 technique/sub-technique、Detection Strategy、Analytic、必需数据条件及测试样本。覆盖分为已映射、数据就绪、回放通过、生产验证和失效；规则数量或映射标签不等于检测覆盖率，分母与版本在大屏展示。[ATT&CK 检测策略](https://attack.mitre.org/detectionstrategies/)

## 7. 案件、工单与受限剧本

事件包含严重度、状态、业务影响、资产/身份范围、责任组与值班人、SLA、告警、证据、调查任务、协作笔记、响应、根因、修复和复核。分派/升级/移交保留历史；SLA 计时规则定义工作日历、时区、暂停原因和重开行为。MTTA/MTTR 需说明起止点及未完成样本，不能只统计已关闭事件得到偏低均值。

外部工单同步记录租户、外部系统/ID、版本、方向、字段映射和最后同步 hash。Webhook 验签、去重和循环来源标识避免相互更新形成风暴；状态冲突需明确权威字段和人工处理，外部关闭不能自动撤销仍需保全的证据。

剧本采用有限 DAG，节点限于检索、富化、条件、创建/更新事件、通知、等待审批、调用已登记响应动作和核对。每个节点有输入/输出 schema、授权范围、超时、最大尝试、错误分支、补偿和幂等键；不提供任意 Shell/Python/浏览器脚本节点作为默认能力。保存校验无环、最多步骤、最长持续时间和影响范围，测试模式禁止生产设备写入。

运行绑定不可变剧本版本、证据快照与发起人授权。人工审批绑定动作内容 hash，修改目标或扩大范围必须生成新的审批。取消停止未开始节点并传播中断；已经发生的外部副作用进入对账和补偿，不能显示成“取消即回滚”。重试的每次尝试独立留痕，重启后恢复等待审批和到期节点。设备动作仍走策略门控、动作租约和采集器连接器，剧本不能另开一条绕过授权的封禁路径。

控制面后台任务复用 River 社区核心库。剧本状态机与 DAG 校验由领域层持久化，不把免费队列库称为自带持久工作流引擎。周期报告/feed/狩猎在 PG 保存 `next_due_at`、时区、错过执行策略与唯一 `schedule_slot`，补偿扫描器在一个事务中创建槽位和 River 任务；普通内存 cron tick 只触发扫描，不承担唯一调度事实。长停机后选择补最近一期、逐期有界补跑或标记错过，防止恢复风暴。

## 8. 身份、权限与数据治理

用户可通过 OIDC 接入企业身份，验证 issuer、audience、nonce/state/PKCE、密钥轮换和账号状态；本地应急管理员单独管理。敏感角色支持 MFA/Passkey 或已有 IdP 的相应认证强度，依赖成熟认证库；平台不自研密码学协议。邀请、离职、禁用、角色收紧、服务 token 轮换和租户切换都更新授权版本并撤销会话。

权限对象包含租户、组织、资产端点、观测范围、证据字节、导出、保全、模型出域、规则发布、响应申请/审批/执行和审计。两端资产不同时属于可见范围时，告警摘要与原始载荷分别裁剪；共享捕获对象下载须先提取授权包集合。当前权限决定访问，历史归属仅用于分析，不能借历史角色绕过已撤权。

数据目录登记数据集/字段级别、来源、用途、驻留、责任人、留存、可导出角色和脱敏策略。删除任务展示 PG、ES、对象、缓存、共享导出、模型上下文与备份到期的清理范围，遇到有效保全冲突保留理由和到期复查；软删除配置不等于历史数据被物理清除。

导出支持 CSV/JSON/PCAP 及报告制品：冻结查询与数据版本，重新鉴权，限制行数/字节/有效期，敏感字段裁剪，表格文本防公式注入。包/日志原始证据只读，派生解码和脱敏有独立摘要/方法。供应商日志、LLM 会话和通知模板不得带出不被允许的载荷。

## 9. 功能与数据验收

| 场景 | 验收结果 |
| --- | --- |
| 两条相同 Syslog 正文；一条上传重试 | 真实两条保留，已知源身份的重试去重；无ID不假装无损去重 |
| 解析器升级、字段改名、回放旧日志 | 原始事实不变，派生修订可查，检测依赖和覆盖状态变化可见 |
| DHCP 重新分配、MAC 随机化、NAT端口复用 | 事件时间匹配正确；冲突返回 ambiguous，不转嫁历史风险 |
| 扫描失败或扫描凭据权限下降 | 不自动把原漏洞关闭，覆盖缺口可见 |
| IOC 到期/撤回、feed重放 | 当前风险收敛，历史依据保留，无重复告警/案件，既有动作按策略评估 |
| 关联消费者重启、迟到、缓存清空 | 窗口可重建，告警不重复，重建中自动处置暂停 |
| 无身份日志却运行否定关联规则 | 显示数据不满足，不凭“查询零结果”认定攻击 |
| 剧本取消但设备已接单 | 未执行步骤终止，已发生动作对账/撤销，状态不伪称原子回滚 |
| 跨组织流与共享PCAP、授权中途撤回 | 必要摘要与原始证据权限分开，导出不包含未授权包 |
| 服务恢复时积压多期报告和feed任务 | 按槽位去重与错过策略有界补跑，不产生无界任务风暴 |

以上验收需要实现后的模拟器、授权样本、真实连接器和故障注入。用户选定首批数据源/设备/行业协议后，在矩阵登记具体覆盖及例外，不能用“主流功能齐全”替代可复核的输入条件和测试结果。
