# 星烽 StarBeacon 检测质量观测

检测质量位于平台“探针管理 → 探针详情 → 检测质量”和采集器“网络与采集 → 检测质量”。两端复用一个只读弹窗和一张指标表，展示捕获质量、检查覆盖、告警输出及策略影响。进程存活、没有告警和计数为零均不代表检测完整或流量安全。

## 来源与运行边界

质量观测只接收当前托管 Suricata 进程产生、且已经持久写入本机 WAL 的 EVE `stats` 记录。外部 EVE 读取模式不推定其生产进程与配置，离线重放也不更新实时质量。每次进程启动生成独立 `engine_run_id`，绑定实际检测配置摘要；启动前的旧记录、重复、乱序、无效及超过允许时间偏差的记录不刷新观测。

原生统计配置为五秒采样。回执分别保留原生 `sampled_at`、采集器 `received_at`、连续区间 `interval_started_at` 和读取快照的 `evaluated_at`，不以运行时长冒充采样新鲜度。Unix 控制接口的计数仍保留在捕获状态中，但不用于建立质量区间：其统计表可能来自上一次同步，输出运行时长是在调用时计算。[原生控制接口](https://github.com/OISF/suricata/blob/suricata-8.0.7/src/counters.c#L827)、[统计 JSON 输出](https://github.com/OISF/suricata/blob/suricata-8.0.7/src/output-json-stats.c#L211)

统计只来自原生总量，不累加线程副本。25 项白名单指标不包含业务载荷、私有路径或凭据。全部计数以十进制 `uint64` 字符串传输，累计值和区间增量独立显示，字节使用自动单位；活跃流属于瞬时值，不作相邻差分。缺失、无效、超范围及暂未注册的字段保持“未提供”，不能补零。

## 状态与计算

| 状态 | 判定与展示 |
| --- | --- |
| 尚未观测 | 当前运行身份尚无可核对的统计；各类质量未知 |
| 等待连续样本 | 首次有效样本只建立累计基线，不产生增量 |
| 区间观测 | 同一运行身份下两次有效统计递增，采样及接收间隔不超过 20 秒；只为两端均有值的累计指标计算增量 |
| 计数发生复位 | 任一累计指标下降，整个区间停止差分，列明复位指标；瞬时量下降不触发复位 |
| 采样存在间隔 | 采样或接收间隔超过 20 秒，或接收时间回退；不把跨缺口差值作为连续区间，当前样本成为后续基线 |
| 观测已过期 | 样本或读取时间超过 20 秒，或当前时间发生无法核对的回退；累计值保留为历史，隐藏增量与活动质量结论 |
| 引擎运行未确认 | 引擎不处于已核对运行状态；已有数字仅作为历史观测，不能推断进程一定已停止 |
| 探针离线 | 平台无法确认设备当前引擎状态，保留最后观测，不把失联推定为引擎停止 |

20 秒是当前工程的连续性与新鲜度边界，不是检测或上报 SLA。平台心跳还存在传输与数据库等待；页面每秒检查已展示快照的时间，不能用打开页面时的时间刷新原生统计。只读页面不执行检测、重放、改配置或设备动作。

采集器刷新失败时在弹窗内展示错误与重试入口，明确保留原采样时间、累计值和区间，旧记录仍受过期检查。切换到原包、重放或任务页签后打开检测质量，也使用相同错误反馈。

## 质量分类

| 分类 | 原生指标与业务含义 |
| --- | --- |
| 捕获质量 | `capture.kernel_packets`、`capture.kernel_drops`、`capture.errors`；内核丢包与捕获错误增量说明本区间存在捕获限制，不计算未经验证分母的丢包率 |
| 检查覆盖 | TCP 会话／分段内存、重组深度、重组缺口、错误线程、确认未见数据、重叠字节冲突、校验和与中途接管；分片跟踪／数量额度与超时、流表内存及应急模式 |
| 告警输出 | `detect.alert_queue_overflow`；队列溢出说明引擎匹配的告警可能没有进入输出 |
| 策略影响 | `detect.alerts_suppressed`、`flow_bypassed.local_pkts`、`flow_bypassed.local_capture_pkts`；有意抑制与旁路单独呈现，不与队列容量损失合并 |

分类有实际非零增量时分别显示限制或策略影响；没有增量且所需指标齐备时仅显示“未报告增量”，不显示安全或完整。存在缺测时显示“质量未知”。`detect.alert`、解码包数／字节和活跃流用于辅助观察，不用来推断攻击成功或自动封禁授权。[捕获指标](https://github.com/OISF/suricata/blob/suricata-8.0.7/src/source-af-packet.c#L2467)、[TCP 指标](https://github.com/OISF/suricata/blob/suricata-8.0.7/src/stream-tcp.c#L6128)、[告警指标](https://github.com/OISF/suricata/blob/suricata-8.0.7/src/detect-engine.c#L3267)、[旁路指标](https://github.com/OISF/suricata/blob/suricata-8.0.7/src/flow-worker.c#L254)

## 留存、权限与未完成范围

平台质量快照沿用指定探针当前健康记录与租户权限，采集器沿用本机管理认证。快照不构成质量历史目录；原始 EVE 统计继续进入现有事件链路，按对应事件分类默认保留 180 天，可配置。当前不创建额外的逐采样 PG 历史表或逐指标投递任务。

本功能不提供单流、单事务或单包覆盖归因，不把区间丢包断言为每条会话丢包；没有覆盖所有 pass／threshold 策略、驱动截断、解析器事件和异常策略。质量事件的持久目录、质量告警与办公通知、原包记录器及事件交付质量的统一关联、多网卡和持续大流量资格仍需独立交付。采样窗口内短暂发生又恢复的异常仍可显示在累计／增量中，观察丢失及重启前未记录的窗口不能恢复。

测试包含整数精度、缺测、复位、时钟与采样缺口、快照隔离、WAL 写入失败和页面过期状态；原生离线样本分别检查普通告警、`noalert` 抑制及同包多规则造成的队列溢出；真实 AF_PACKET 链路核对质量经持久读取和心跳到达平台。实际结果与来源见[测试覆盖与验收记录](测试覆盖与验收记录.md)，工程用例不代替生产吞吐或完整检测质量矩阵。
