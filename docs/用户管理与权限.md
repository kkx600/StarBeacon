# 星烽 StarBeacon 用户管理与权限

管理员通过主控平台的“用户管理”维护当前租户的登录账号。页面采用一张用户列表，创建、详情和权限编辑使用独立弹窗；密码不出现在列表、详情、审计或幂等回执中。

## 账号与权限

| 对象 | 当前行为 |
| --- | --- |
| 账号名称 | 合法 UTF-8，3–64 字节，不含控制字符、格式控制字符或首尾空白；平台内唯一，创建后不可改名 |
| 初始密码 | 创建时必填，12–72 个 UTF-8 字节，不含控制字符；使用 bcrypt 保存摘要，API 只写不读 |
| 管理员 | 可以管理本租户用户并访问管理功能；每次用户管理操作重新核对账号和租户的有效状态 |
| 只读用户 | 保留现有查看范围，不能访问用户目录、创建用户或变更权限 |
| 使用状态 | 明确选择启用或停用；停用后拒绝登录，重新启用不会恢复旧会话 |
| 身份边界 | 用户详情和分页游标必须属于当前租户；跨租户请求返回 404 |

账号名称的唯一性服务于现有平台登录入口。当前未提供同名账号在不同租户登录、OIDC、MFA、自定义角色、字段级授权或母子组织委托。采集器继续使用自己的本机身份与会话，不使用平台用户目录作为本机登录库。

## 页面操作

列表支持角色和使用状态筛选，按稳定账号标识倒序分页，每页 20 条。修改筛选时回到第一页；详情只返回公开身份、修订和建立／更新时间。

创建表单默认选择只读用户和启用状态，管理员必须输入初始密码。字段按 UTF-8 字节长度检查，中文字符不按一个字节计算；后端执行相同边界检查。创建成功后重新查询当前账号状态，不能将历史创建回执当作该账号当前权限。

编辑表单只调整角色与使用状态。账号名称只读，不显示或接收密码。当前登录管理员不可停用自身或降低自身权限；没有实际变化的提交会被拒绝。校验失败保留草稿并将焦点移至错误说明；Escape 收起下拉选项时不关闭弹窗。提交期间禁止重复点击，结果不确定时提供原请求确认入口。

平台顶栏提供“修改密码”，管理员和只读用户均可修改自身密码。用户详情提供独立“重置密码”弹窗，管理员只能重置其他本租户成员。两种操作均需输入当前操作者密码、新密码与确认密码；重置不要求目标成员的原密码。新密码按 UTF-8 字节检查，不能与当前操作者密码或目标账号原密码相同。弹窗提交期间禁止重复操作，错误信息使用中文并取得焦点。

密码变更保持账号名称、角色和启用状态，原子撤销目标账号全部既有会话。修改自身密码的成功响应清除平台 Cookie，并返回登录入口；重置停用账号不会自动启用。结果未知时冻结原输入和幂等键，不能自动重复执行。成员重置可人工确认原请求；自身修改若原会话已撤销，需使用新密码重新登录核对。密码仅在当前弹窗内存中暂存，关闭、页面卸载或身份改变时清理。

## 修订、会话与事务

每个账号具有递增修订。编辑必须提交 `expected_revision`，并使用 `Idempotency-Key`。版本冲突返回 409，不能用当前页面的旧修订覆盖他人变更。账号修订上限为 1,000,000。

角色或使用状态变更、目标账号全部旧会话撤销、操作审计和公开请求回执在同一 PostgreSQL 事务内提交。任何一项持久化失败都会回滚整个操作；重新启用不会让被撤销的 Cookie 恢复。租户内用户写入采用事务级互斥，并在取得锁后重新核对操作者，防止两名管理员并发降权使管理能力丢失。

登录读取的内部账号修订必须与会话创建时的实际修订一致。受控 `create_tenant_session` 函数在租户身份锁内核对账号、租户、角色与修订后创建会话；密码或权限变化后，旧登录验证结果不能再产生会话。内部修订不出现在浏览器身份响应中。`change_tenant_password` 在相同锁内重新核对操作者修订和凭据、目标修订，提交密码、会话撤销和审计；运行角色不取得身份表写权限，固定函数撤销 PUBLIC 执行权限。

密码摘要的生成与比较在事务资源锁之外完成，保持 bcrypt 的既定工作因子。服务先读取原回执与目标修订；已有请求仅核对原密码摘要，不重新生成，过期或修订冲突不进入新密码提交。管理员重置他人密码时并行完成两项独立计算；修改自身密码复用已经验证的新旧密码不同这一条件。取得锁后再次核对操作者、目标摘要与修订及原回执，计算期间的撤权不能继续提交；并发原键改变快照最多重读三次，仍只提交一次密码、审计与回执。该机制不保存明文或快速密码指纹，不降低加密强度，不承诺高负载下固定响应时限。API 与字节长度边界参见 [Go bcrypt 文档](https://pkg.go.dev/golang.org/x/crypto/bcrypt)。

运行数据库角色不能直接对 `users` 执行 INSERT／UPDATE／DELETE。身份维护通过固定签名的 `save_tenant_user` 函数完成；函数撤销 PUBLIC 的执行权限，使用受控搜索路径和明确的租户、操作者、目标、修订、凭据摘要及审计参数。用户请求回执采用 FORCE RLS；既有登录身份表属于专门身份读取边界，不能声称所有用户表读取已经采用 FORCE RLS。

## 重试与保留

同一操作者使用同一幂等键与原始输入确认时，服务端返回原公开结果，不重复创建用户或执行权限变更。改变账号配置、预期修订或初始密码会返回 409。创建回执通过既有 bcrypt 摘要核对原密码，不保存密码原文或可快速穷举的密码指纹。

请求尚未确认时，前端只在当前页面内存中保留原输入和幂等键，并冻结表单；不会保存到 localStorage 或 sessionStorage。确认必须使用原请求，不能因超时生成新键再次创建。页面卸载或登录身份改变时清理密码与待确认材料。

操作审计和幂等回执默认保留 180 天，使用租户“操作数据”分类策略确定新记录的期限；支持用户自定义。到期回执返回 410，后台仅回收已到期回执；登录账号本身不会因操作历史到期而自动删除。

单租户最多 500 个账号；用户创建、权限变更和密码变更合计最多 1,000 次／UTC 日。超过额度返回 429，已有同键请求确认不消耗新日额度。密码验证按操作者账号每 60 秒最多 10 次，跨实例共享；错误密码、结果确认和后续事务失败均计入次数。验证预算先独立提交，不随密码事务回滚，窗口到期重新计算；超过时返回 429 与 `Retry-After: 60`。计数仅保留每账号一行预算状态，不保存请求正文。当前没有账号删除、重命名或身份提供方同步流程。离线恢复属于独立的管理入口，不通过浏览器身份授权。

## 接口与验证边界

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/users` | 本租户用户分页与筛选 |
| `POST /api/v1/users` | 创建用户，密码只写 |
| `GET /api/v1/users/{id}` | 查看公开身份和当前修订 |
| `PATCH /api/v1/users/{id}` | 按修订变更角色与使用状态 |
| `GET /api/v1/auth/account` | 当前有效账号的公开记录与修订 |
| `POST /api/v1/auth/password` | 验证当前密码并修改自身密码 |
| `POST /api/v1/users/{id}/password` | 管理员验证自身密码并重置其他成员密码 |

管理写接口要求有效管理员会话、同源 CSRF 校验和幂等键；自身密码修改允许当前有效管理员或只读用户，使用相同的写入保护。错误当前密码返回 403，不清除仍有效的会话；修订或幂等输入冲突返回 409。完整字段、类型及状态码以[平台 OpenAPI](../api/openapi/platform.json)为准。

远程专属 PostgreSQL 数据库已验证实际 HTTP 登录、角色变更和会话撤销、跨租户拒绝、审计及回执失败回滚、并发管理员保护、分页、默认／自定义期限、额度与损坏回执拒绝；连接中断测试核对了身份、会话、回执和审计的实际事务回滚。本地前端组件测试覆盖表单、未知提交确认、修订、身份变化和单列表交互。完整同源码全量、七档 PC 与正式发行包验收以[测试覆盖与验收记录](测试覆盖与验收记录.md)为准，不能把上述子流程测试视作全产品发布资格。

## 离线管理员恢复

管理员遗失密码时，使用发行包中的 `starbeaconctl`，通过 `SB_MIGRATION_DATABASE_URL` 连接当前部署的管理数据库。先执行只读核对：

```sh
starbeaconctl inspect-admin --tenant tenant_local --username admin
```

输出只包含指定有效管理员的公开身份和修订；不返回密码摘要。按核对结果填写账号 ID、修订和恢复请求标识：

```sh
export SB_RECOVERY_PASSWORD_FILE=/run/secrets/starbeacon-recovery-password
starbeaconctl recover-admin --tenant tenant_local \
  --user-id user_example --expected-revision 1 \
  --request-id recovery_ticket_001 --reason '值班管理员凭据遗失'
```

密码文件须为 0400 或 0600 的普通文件，最多 72 个 UTF-8 密码字节，可带一组末尾换行；拒绝符号链接、目录和公开可读文件。也可单独设置 `SB_RECOVERY_PASSWORD`，两种来源不能同时提供。密码不作为 CLI 参数，不回显，原因不得包含新密码。凭据文件的创建与保管由部署运维负责，发行包不附带默认恢复密码。

恢复权限同时核对实际连接身份与有效数据库角色对身份表所有者的授权；`starbeacon_app` 不能执行，即使受控身份函数可用。仅修改指定租户中有效管理员的密码，不创建账号、提升角色或启用停用对象。不同租户、只读用户和停用租户／管理员都会拒绝。停用对象的重新授权需要独立治理流程，不能用恢复入口绕过。

密码、账号修订递增、全部旧会话撤销、恢复原因审计和公开回执在同一事务提交。已验证的旧登录修订也不能创建新会话。恢复记录标记实际数据库操作者为 `database:<数据库角色>`，在平台操作日志中可查看、按操作筛选并读取原因。审计与回执默认保留 180 天，遵循操作数据分类的自定义期限；不保存密码或凭据摘要。离线恢复不受浏览器密码验证预算和当日管理额度阻断，但仍需要数据库所有者权限与修订核对。

结果未知时保持同一租户、账号、原修订、请求标识、原因和新密码，再次执行原请求确认。原密码恢复已提交且当前账号仍与回执一致时，返回 `confirmed=true`，不重复改密或撤销新会话。输入变化、账号随后变更或旧修订返回冲突；过期回执不能确认。可再次执行 `inspect-admin` 读取公开修订，并使用新密码登录核对；不得自动生成新请求重复覆盖。
