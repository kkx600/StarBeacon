# 事件调查与结案

事件调查把检测事实和人工处置记录分开保存。告警原文保留在 Elasticsearch；PostgreSQL 保存事件对象、来源身份与摘要、责任分派、调查修订和操作审计。调查材料不自动改写检测结论，不证明攻击成功或设备已经封禁。

## 页面与流程

平台导航及页面统一为「事件调查」，工程地址为 `/incidents`，采用 History 路由。页面只有一份安全事件列表，按调查状态和严重度在数据库筛选，每页 20 条，使用稳定的创建时间与事件标识续点。

「建立事件」弹窗登记人工线索，也可关联实际告警。管理员在告警详情点击「建立事件调查」，携带当前事件标识及原始 SHA-256 摘要进入表单。关联前核验当前租户 ES 中唯一的告警来源，冻结来源探针、事件发生时间和代理观测时间。人工线索允许空告警数组，不生成不存在的检测记录。同一告警在一个租户内只对应一份调查，重复升级提供既有调查入口。

「查看」弹窗展示当前调查概览、责任人、修订时间、来源身份与摘要，以及独立的调查时间线。记录调查时关闭查看弹窗，再打开表单，避免叠加多个操作层。历史材料以时间线和折叠内容展示，不在同页放置第二份业务列表。

未确认的网络提交冻结请求键与输入。用户可关闭弹窗后通过「核对原提交」恢复原请求；连接中断不会被解释为保存失败，也不会自动创建另一份调查。确认回执必须匹配事件、修订、实际操作人、提交材料及告警来源。确定的参数、权限、修订和额度拒绝解除冻结，允许核对输入后提交。

## 状态与结案材料

| 状态 | 行为与约束 |
| --- | --- |
| 待调查 `open` | 创建入口的唯一初始状态，可先登记再分派责任人。 |
| 调查中 `investigating` | 保留每次调查说明、责任人和材料的独立修订。 |
| 已结案 `closed` | 需责任人、结案原因、根因说明、影响范围、修复措施及复测说明。 |

结案原因包括「确认处置完成」和「确认误报」；前者至少提供一条可复核的复测证据引用，后者仍须填写四项复核材料。证据引用最多八条，每条最多 256 字符，不重复。引用是定位信息，平台不据此声明附件存在、测试通过或外部设备执行完成。

关闭事件只允许重开为「调查中」，不能直接退回「待调查」。重开清空当前结案材料，历史修订继续保存原结论；每次记录使用完整材料快照，不覆盖旧修订。到期关闭事件不可编辑或重开。

## 协作任务

事件详情的「协作任务」入口关闭调查详情，在同一层弹窗中切换任务列表、任务详情与任务表单。任务状态在数据库筛选，每页20条；独立历史按修订续点，每页20条。列表、表单和历史不同时展示第二份业务表格。

每项任务保存标题、说明、优先级、负责人、可选截止时间和独立修订。截止按用户本地时间输入，接口以RFC3339传输，未修改的精确时间不因表单分钟显示而丢失；截止仅用于人工工作安排，不自动执行设备动作或触发SLA。状态包括「待处理」「处理中」「已完成」「已取消」。开始处理和完成需指定有效管理员；完成必须填写依据，取消必须填写原因。取消既有任务可保留已失效的历史负责人；重新分派或继续处理须使用有效负责人。重开清空当前终态说明，原依据继续保留在历史修订。

任务写入同时冻结事件修订和任务修订，原请求键、输入、回执及审计在一个事务保存。结案与任务写入共用租户事务锁：存在待处理或处理中任务时拒绝结案；已结案事件的任务只读，需要继续工作时先重开调查。未知提交锁定原输入，关闭弹窗后可从页面「核对任务提交」恢复；不能换一个请求键假定原操作失败。身份变更、事件切换和弹窗详情切换取消旧读取，迟到响应不能显示为当前材料。

每事件最多128项任务，租户最多10,000项，每UTC日最多4,096次任务变更，单任务最多1,000次修订。预算独立于事件调查修订；原回执确认不占用新额度。

## 调查笔记

事件详情的「调查笔记」入口与协作任务保持相同的单层弹窗交互：在列表、详情、修订历史和表单之间切换，不叠加第二份业务表。笔记列表可按有效／已撤回筛选，以创建时间和笔记标识稳定续页，每页 20 条；修订历史按修订号倒序续页，每页 20 条。读取失败、没有记录和已过期分开提示；旧请求在事件切换、身份变更、关闭或超时后不能覆盖当前材料。

笔记只保存纯文本，不执行 HTML、脚本或 Markdown，不把文本中的链接当作已验收证据。标题为 1–120 个 Unicode 字符，正文为 1–8,192 个字符；正文允许正常换行与制表符，拒绝非法编码、空白正文和其他控制字符。创建必须为「有效」状态，作者及作者名称由服务端固定，客户端不能指定或转让。

当前仍具备调查权限的原作者可编辑、撤回和恢复自己的笔记；同租户其他管理员只能查阅，笔记作者被停用或降权不会使其他账号获得代写权限。撤回需填写 1–2,048 字符的原因，保留原正文和全部历史；恢复清空当前撤回说明，历史仍可查阅。每次变更另需填写变更依据，笔记修订不会改写事件调查或原始告警结论。

新写入同时核对父事件的 `incident_revision` 和笔记的 `expected_revision`，并与结案使用相同租户事务边界；父事件变化、旧笔记修订或同请求键不同输入返回冲突，不静默覆盖。结案后禁止新建、编辑、撤回和恢复；需要继续记录时先重开事件。仍在留存期的原提交精确确认只返回当时回执，不重复写入、不续期，也不因后续笔记修订而返回新的内容。未知提交保留原输入和请求键，关闭弹窗后从「核对笔记提交」恢复确认。

每事件最多 128 条笔记，每租户最多 10,000 条，每 UTC 日最多 4,096 次笔记变更，每条笔记最多 1,000 次修订；额度独立于事件及协作任务。确认原回执不占新额度。超过上限不删除历史或省略审计换取继续接收。

## 权限、并发与预算

当前实现面向本地管理员。责任人列表仅包含当前租户仍有效的管理员，最多 100 人；只读账号无调查读写入口。平台身份、当前责任人和租户有效性在事务内重新核对。PG 表强制 RLS，客户端不提交租户标识；跨租户事件及续点按不可访问处理。

写入使用 `expected_revision` 乐观并发；旧修订返回 409，不自动覆盖他人调查。管理员、操作类型和 `Idempotency-Key` 共同标识原提交；相同键改变输入返回冲突，精确重试返回第一次提交时固化的回执与期限。确认持久回执不依赖 ES 再次在线或原始告警仍在保留期。新关联仍须核对真实来源。

每个租户最多 10,000 个事件，每个 UTC 日最多 4,096 次调查变更，每事件最多 1,000 次修订。接口每次最多关联八条，单事件累计最多 16 条；页面每次关联一条。达到预算返回 429；不以忽略审计或丢弃旧材料继续接收。创建、关联占位、历史修订和审计在同一事务提交，中断不能留下半份事件或占用告警关联。

## 留存与回收

`incidents` 属于分类留存策略，默认 180 天，管理员可自定义未来记录的期限。每次实际调查修订在提交时固化到期时间；精确重试不续期，已有修订不随策略变化重新起算。

未关闭事件、协作任务、调查笔记及其独立历史受保护，不因创建时间较早而删除。笔记与笔记历史同样采用 `incidents` 分类，实际写入时固化默认 180 天或当时自定义期限。关闭后按每份修订的固化期限回收；当前关闭记录到期、没有保留中的调查历史、任务或笔记后，才回收事件及告警关联。任务和笔记历史先于各自当前记录回收；已完成或已取消任务、已到期笔记只有在事件关闭后方可回收。分类预算不足时在后续清理轮次继续，不绕过父子引用。清理分类追加在已有持久游标之后，保持既有分类顺序。运行数据库角色没有改写调查历史的权限，删除同时受 RLS 到期谓词限制。

## 接口与验收边界

事件调查六个、协作任务五个、调查笔记五个 HTTP 操作及输入、错误、权限、分页和幂等契约见 [平台 OpenAPI](../api/openapi/platform.json)。笔记接口为 `GET/POST /api/v1/incidents/{id}/notes`、`GET/POST /api/v1/incidents/{id}/notes/{note}` 与 `GET /api/v1/incidents/{id}/notes/{note}/history`。迁移为 `00026_incidents.sql`、`00044_incident_tasks.sql` 与 `00051_incident_notes.sql`；Go 领域与 HTTP 输入测试、前端交互测试以及远程真实 PG／ES 集成测试分别验证契约、生命周期、跨租户、修订、来源摘要、事务失败、配额和回收。实际通过状态及源码摘要见 [测试覆盖与验收记录](测试覆盖与验收记录.md)，用例文件存在不等同执行通过。

调查笔记的 [Go 领域](../internal/incident/notes_test.go)、[存储契约](../internal/store/incident_notes_test.go)、[HTTP 输入](../internal/platform/incident_notes_test.go)、[前端交互](../web/tests/incident-notes.test.ts) 与 [真实依赖集成](../tests/integration/incident_notes_test.go) 分别提供可执行入口；本批次定向通过不等于全部远程或浏览器验收通过。

完整目标还包括附件、更多可观测对象、自动分派、SLA、合并拆分、私密共享、外部工单和复盘知识审核。这些能力仍按 [功能实现与验收状态](功能实现与验收状态.md) 记录，不使用当前人工调查流程冒充完整协作产品。
