# 星烽 StarBeacon 依赖版本与部署清单

核定日期：2026-09-30。本文是项目选型基线；完整应用构建、集成与性能验收尚未进行。Go 按项目要求使用 **1.26.x**，核验日该系列最新修订为 **1.26.8**，开发与 CI 必须锁定同一补丁。本机默认仍为 `go1.25.6 darwin/arm64`；仓库外隔离的官方 Go 1.26.8 已完成代表性导入组合的模块图与校验和验证，未更改系统工具链。Linux ARM64 编译尝试超时，不能认定构建通过。PostgreSQL 使用 18 系列；Redis、Elasticsearch 在本次官方 latest release 复核中仍为下表版本。其他依赖保留已核定的兼容基线，后续维护通过受控升级，不追随浮动 `latest`。

### 2.1 文件分析组件的交付边界

YARA-X 与 ClamAV 的固定正式发布分别为 [1.21.0](https://github.com/VirusTotal/yara-x/releases/tag/v1.21.0)、[1.5.4](https://github.com/Cisco-Talos/clamav/releases/tag/clamav-1.5.4)。YARA-X CLI 或官方 Go binding 均在独立静态分析制品中运行；使用 Go binding 时需要同版 C API、cgo、C 工具链、pkg-config 与相应系统库。原生库、构建特性、系统包、规则包和镜像 digest 在该制品的实际构建中冻结，不把这些依赖加入已验证的纯 Go 模块组合，也不把已有 `CGO_ENABLED=0` 检查称为它们的构建结果。[Go binding 固定模块](https://github.com/VirusTotal/yara-x/blob/go/v1.21.0/go/go.mod)、[原生链接声明](https://github.com/VirusTotal/yara-x/blob/go/v1.21.0/go/main.go)

ClamAV 优先通过本地 Unix socket 的 clamd 扫描；需要一次性 CLI 时使用受限 clamscan 进程。`clamscan --alert-exceeds-max=yes` 是本地扫描配置；采用 clamd／clamdscan 时，在服务端 `clamd.conf` 配置 `AlertExceedsMax yes` 及实际文件、解包、递归、输入流和线程限额，不能依赖 clamdscan 参数修改远端引擎。超限、加密、错误及只扫描部分内容均保留独立状态；客户端超时不证明服务端已停止计算，还需监控、进程／容器级预算与回收。病毒库由受控更新流程维护，记录版本、更新时间、校验与回滚，禁止每个扫描任务联网自行下载。[扫描客户端边界](https://docs.clamav.net/manual/Usage/Scanning.html)、[1.5.4 服务端配置](https://github.com/Cisco-Talos/clamav/blob/clamav-1.5.4/etc/clamd.conf.sample)

CAPE 首期交付范围是对已有受控实例的 API 适配；文档标题“2.5”不能用作已核实发行包版本。自建实例另行锁定 Ubuntu 镜像及系统包、Python 与依赖、QEMU/libvirt、guest agent、guest OS 和分析软件、快照、任务数据库、报告存储及可选网络仿真工具，并验收隔离与恢复。CAPE 的这些运行依赖不自动成为平台核心必装项，也不能据当前 PG／ES 版本推断 CAPE 与其兼容。独立沙箱禁止访问平台管理网和生产业务网；动态分析异步运行，不参与实时规则告警的同步等待。[锁定源码及部署说明](https://github.com/kevoreilly/CAPEv2/tree/334e3ad22fbb4be6681f7404751bb6b3531bb8b5)、[当前 API 说明](https://capev2.readthedocs.io/en/latest/usage/api.html)

样本、文件分析报告、持久化行为、沙箱 PCAP、截图及其他已生成业务证据默认保留 **180 天**，按分类可配置。仅临时解包目录、未入库的 VM 运行缓存和凭据使用独立短 TTL；扫描器清理策略不得提前删除已入库证据。完整流程、资源起点、权限和测试见[协议覆盖与文件分析设计](协议覆盖与文件分析设计.md)。各组件单独登记许可证、原生依赖与第三方通知，独立进程部署不免除二进制再分发时的许可义务。

### 2.2 PCAP 压缩组件的交付边界

可选 PCAP 压缩复用 `github.com/klauspost/compress/zstd` **v1.20.1** 的纯 Go 编解码器，不重复实现压缩算法。该 tag 声明 Go 1.25；根许可证主体为 BSD-3-Clause，另有目录级许可，按实际选用文件和制品保留第三方通知。压缩块边界、包定位 sidecar、原始／压缩偏移映射、S3 Range 读取、摘要和解压预算由平台负责；codec 本身不提供本系统的对象存储随机读取协议。[固定发布](https://github.com/klauspost/compress/releases/tag/v1.20.1)、[模块定义](https://github.com/klauspost/compress/blob/v1.20.1/go.mod)、[LICENSE](https://github.com/klauspost/compress/blob/v1.20.1/LICENSE)、[zstd 能力说明](https://github.com/klauspost/compress/blob/v1.20.1/zstd/README.md)

压缩是可配置存储策略；未完成实际流量、CPU、写入及随机取证压测前，容量压缩比按 **1** 计算，不靠预估压缩收益削减 180 天保留容量。可用 [Zstandard 1.5.7](https://github.com/facebook/zstd/releases/tag/v1.5.7) 做格式互操作验证，但不强制生产引入 C 运行依赖。上轮代表性 Go 图包含间接 `compress v1.20.0`，本次选择的 `v1.20.1` 与 `zstd` 直接使用场景尚未加入该验证；升级后的真实目标包仍须重新验收。

### 3.2 后台任务与协议工具的交付边界

River 的开源核心为 MPL-2.0，不引入 River Pro 私有模块。业务写入与 `InsertTx` 在同一个 pgx 事务提交；通用任务复用其领取、重试和恢复。业务层仍保存报告周期唯一键、动作授权、设备互斥／fencing、人工审批与外部副作用幂等。免费周期调度状态在内存中，不能承诺故障期间不漏调度：PG 保存 `next_due_at` 与周期槽，定时扫描和重启补偿以唯一键将到期任务入队，River tick 只负责唤醒。全局租户配额、公平调度、设备租约由业务层保证，不能把 Pro 的持久周期／工作流／全局并发能力写成开源功能。[事务入队](https://riverqueue.com/docs/transactional-enqueueing)、[周期调度边界](https://riverqueue.com/docs/periodic-jobs)、[功能划分](https://riverqueue.com/pro)

TShark 的 GPL 分发要求随制品登记；使用独立进程不免除附带二进制、修改源码与许可证的履行责任。Go 通过固定参数、受限管道及只读 PCAP 文件通信，不链接 Wireshark 内部库。按 4.6.9 实际运行结果冻结字段字典、配置与语法兼容样本，不用网站 current 文档中 5.0 的功能推断 4.6.9 支持。作业不授予抓包权限，不启用 extcap、外部插件、用户 Lua 或实时 DNS。系统包的版本与构建特性单独锁定；Ubuntu 默认源中的版本不能未经核实就标作 4.6.9。

Sigma / STIX 的完整解析与转换优先采用官方 Python 组件的隔离适配作业，分别核验为 `pySigma 1.5.1`、`stix2 3.0.2`；它们不是 Go 控制面的运行依赖，也不把 Sigma 规则直接当作 Suricata 规则。启用完整适配时另外固定 Python、转换 backend、数据映射与 wheels/hash；未完成这份可选制品清单前不宣称已支持任意 Sigma backend 或所有 STIX Pattern。

标准 PG 主备可以采用明确 fencing 的受控人工切换或企业现有托管 HA；若交付要求自动数据库故障转移，必须另选并锁定受支持的 HA 组件，不将“主备已建好”当成自动切换已实现。密钥默认来自受控挂载及信封加密，可接现有 KMS；OIDC、SMTP、设备 API、外部 Syslog 是客户服务依赖，需要端点、证书、账户权限与契约验收，不为它们虚构统一软件版本。

## 6. 拓扑、端口与资源隔离

| 连接 | 建议端口／方向 | 网络边界 |
| --- | --- | --- |
| 用户／Agent → 平台 | HTTPS 443，含 MCP／SSE | 公开或客户内网入口，统一身份及限流 |
| 探针／Runner → 平台 | mTLS gRPC 7443，可经已有代理汇聚 | 主动出站，按证书及租户注册授权 |
| 服务 → PG | 5432 | 仅业务／备份网段，非公网 |
| 服务 → ES | HTTPS 9200；集群内部 9300 | 外部用户不直接访问 ES |
| 服务 → Redis | 6379；Sentinel 26379 | TLS/ACL，按环境配置端口，非公网 |
| 服务 → NATS | 4222；集群路由 6222；监控 8222 | mTLS、subject 权限，监控仅运维网络 |
| 服务／探针 → S3 | HTTPS 443 或配置的 API 9000 | 管理控制台独立且不公开给普通租户 |
| 运维 → 指标 | Prometheus 9090、可选 Grafana 3000 | 单独运维身份；探针健康经平台汇聚 |
| 平台／Runner → Syslog | TLS 6514；兼容 TCP/UDP 514 | 客户配置目标，明确确认语义 |
| 通知／模型出站 | HTTPS 443；邮件 587/465 按服务商 | 允许列表、限流、证书和密钥轮换 |
| 文件分析 worker → clamd | 优先本地 Unix socket；远程协议端口 3310 不直接开放 | clamd 裸 TCP 无认证／加密；如需远程使用受控认证代理，固定输入和扫描权限 |
| 文件分析适配器 → 外部沙箱 | HTTPS 443 或已配置服务端口，CAPE `/apiv2/` | 仅提交服务可访问；guest 网络与平台管理网隔离，任务级出站策略单独授权 |

端口是部署起点，可因企业标准调整；内网端口表不代表应向互联网开放。抓包、浏览器、规则回放、模型推理、实时索引各有独立资源上限。报告浏览器和设备认证浏览器不得共享登录上下文。

## 7. 固定版本后的验收与升级

1. 工程形成后固定 `go.mod/go.sum`、`pnpm-lock.yaml`、生成器清单、容器 tag 与各架构 digest、OS 包清单及 SBOM；当前方案阶段尚无这些实际构建产物。
2. 确认本机具备已选定补丁的 Go 1.26.x 后，以 `GOTOOLCHAIN=local` 进行依赖图解析及目标 Linux 架构完整构建，执行 Proto 兼容和关键契约测试；前端执行冻结安装、vue-tsc、生产构建与关键操作验证。
3. 验证 ES 9.5.4 映射／分析器、PG 18.6 RLS／迁移、Redis 故障退化、JetStream 严格持久化和重放；服务版本一致不等于配置已正确。
4. 模型、规则、连接器分别执行自己的兼容与回滚验收；同一浏览器版本也不能证明所有设备控制台可自动登录。
5. 用真实 EPS、包速、载荷、规则集、查询并发、保留期和故障场景验证三档部署。性能数据写入独立基准报告，未测试前不填写吞吐实测值。
6. 文件分析分别验证 YARA-X 原生制品、ClamAV 引擎与病毒库、CAPE API／guest 镜像及隔离恢复；扫描超限、部分结果、超时、重复提交与取消必须保留可区分状态。样本与报告 180 天默认留存和容量单列核算。
7. 升级先在兼容矩阵中试验，再灰度。Go 保持 1.26.x 系列，在受支持补丁内完成兼容验证后升级；数据迁移和应用回滚分开，ES 不依赖直接降级二进制恢复旧数据。

许可证登记区分组件源码、发行二进制和可选商业功能。Redis 8 不是旧 BSD 许可，ES 默认发行物与部分源码许可不同，MinIO HA 需许可，Grafana OSS 有对应开源条件；选定交付方式后保留实际条款与第三方通知，不能将上述组合统一标成“全部 Apache／免费商用”。详情与官方链接见[依赖版本核验](research/依赖版本核验.md)和[采集链路与存储调研](research/采集链路与存储调研.md)。
