# 星烽 StarBeacon 检测引擎运行观测

采集器通过已登记的原生进程和 UNIX 控制接口读取运行状态。平台探针详情与采集器运行页面展示同一观测，分批规则发布使用该观测作为后续批次门禁。

## 观测内容

后台每 5 秒尝试一次核对，单次控制调用共用 2 秒期限。心跳、本机健康接口和诊断只读取内存快照，不等待原生控制接口。缓存超过 15 秒时返回“等待原生观测”，不会继续呈现旧成功。观测不执行规则重载、进程启动、停止或文件写入，不引入额外服务依赖。

| 内容 | 核对方式 |
| --- | --- |
| 进程身份 | PID 文件、登记可执行文件、明确的配置路径与命令行；PID 与以毫秒单位记录的进程启动时间在观测前后保持一致 |
| 完整规则来源 | 原生 `conf-get` 返回登记的规则文件，拒绝其他并行规则文件或命令行覆盖 |
| 托管启动记录 | 复用采集管理器核对主配置与辅助文件的启动摘要和实际子进程 |
| 登记文件 | 最多 900 KiB 的普通完整规则文件；前后字节摘要一致 |
| 装载数量 | 原生 `ruleset-stats` 只有一份完整规则集，明确报告装载数和失败数；装载数等于文件有效规则行数且失败数为零 |
| 变更与互斥 | 规则或采集配置事务执行中返回等待；存在未核实恢复材料时返回不可用；观测期间身份、配置、规则变化均拒绝成功 |

原生观测支持托管采集进程和已登记的外部进程。仅提供 EVE 文件、缺少 PID、规则或控制接口的设备仍可上报事件，但不能取得原生运行观测资格。外部进程的配置文件摘要只表示观测时的磁盘内容，不证明所有参数仍与进程启动时一致。

原生进程实际退出、停止后续批次及恢复后不自动续发的隔离测试见[测试覆盖与验收记录](测试覆盖与验收记录.md)和[检测引擎运行观测证据](验收证据/2026-10-18-检测引擎运行观测.json)。离散运行观测不代表该需求已完成生产验收。

## 分批发布门禁

每个已发布目标，包括前序批次，须同时满足：

1. 当前身份、启用状态、登记文件摘要及独立任务仍通过核对。
2. 原生观测时间不早于该目标同步运行完成时间，距平台核对不超过 90 秒，未来偏差不超过 5 秒。
3. 原生报告格式、进程身份、规则文件摘要及装载计数有效，文件摘要等于批准规则包摘要。
4. 观察窗口结束后，平台接收心跳、宿主机观测和原生观测三条水位均越过窗口结束时间。

缺报、旧设备未提供此字段、未配置、过期或事务忙时显示“等待发布后的有效原生观测”，清除观察起点并等待恢复。收到发布后的明确核对失败时停止后续提交，显示“原生进程或规则装载核对未通过”。停止不撤销已经下发的签名任务，不自动回滚生效规则；在途回执仍独立核对。

观察是离散采样，不能证明两次采样之间从未停机、丢包或重载。`ruleset-stats` 不提供内存规则内容摘要；相同规则数和文件摘要不排除其他本机写入者曾装载不同但等量的内容。完整的效果、质量、性能门禁、外部写入者治理及自动故障回退仍须单独交付与验收。

## 接口与页面

`HostHealth.engine_health` 为可选扩展，包含 `schema_version`、`state`、`source`、`observed_at`、结构化原因码，以及成功观测时的进程、配置、登记规则摘要和规则计数。它沿现有 mTLS 心跳持久化至本租户探针记录，不改变注册权限或执行授权。

页面使用组件默认状态色，并明确区分“最近观测通过”“等待原生观测”“未配置原生观测”“原生观测未通过”和格式错误。失败或缺报不展示旧的成功计数；离线探针保持原有历史快照提示。长摘要可换行，不扩大弹窗宽度。原型中的观测均标注合成示例，不能作为真实设备资格。

协议依据：[Suricata 控制接口](https://docs.suricata.io/en/suricata-8.0.7/unix-socket.html)、[官方控制命令](https://github.com/OISF/suricata/blob/suricata-8.0.7/doc/userguide/manpages/suricatasc.rst)。工程测试入口为 `internal/enginehealth/health_test.go`、`internal/agent/engine_health_test.go`、`tests/integration/rule_rollouts_test.go`、`tests/integration/rule_rollouts_native_test.go` 和 `web/tests/engine-health.test.ts`；具体远程执行结果须以同一源码快照的验收记录为准。
