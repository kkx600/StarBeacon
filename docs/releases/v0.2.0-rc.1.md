# StarBeacon v0.2.0-rc.1

本次预发布面向隔离环境中的主控平台与采集器安装、交互评审和功能核验。

## 本版内容

- 全流量回溯支持按会话查找和取回已经保留的流量分段。平台系统设置提供全流量存储配置，采集器保留本地策略配置与同步入口。
- 联动插件支持模板配置、试运行、签名下发，并可从接口文档生成待核对草稿。受控 Linux 网关支持限时连接阻断，分别记录设备回读与流量观察。
- AI 值守提供待确认方案与处置流水。全局助手可按页面上下文生成草稿。已发布的编排从原告警启动，由操作员逐步推进，已授权的动作引用原签名任务、设备回执和租约。
- 主控、采集器及原型采用共享的表格、分页、页面说明和状态标签。12 个代表页已通过评审，原型图库包含 195 张 1440×900 截图。

## 检查结果

发布候选在 `home_dev` 运行后端、前端与原型及契约三组验收。远程报告和发布核验结果登记于主线的任务记录。GitHub Actions 在本页「构建与核验」部分列出实际来源提交、运行链接及 ZIP 摘要。[开发任务](https://github.com/kkx600/StarBeacon/blob/main/docs/开发任务.md)

## 安装包

主控平台和采集器各提供一个 Linux amd64 ZIP。包内含 UPX 压缩的 Go 程序、对应前端、Nginx 配置示例、版本清单、依赖许可及 CycloneDX SBOM。部署方按现场拓扑配置依赖服务、TLS、运行身份与凭据。[工程实现与开发](../工程实现与开发.md)

## 已知问题与边界

- 当前功能验证使用隔离 Docker 网络与受控测试依赖。生产环境容量、TLS／HA、备份与恢复、外部通知送达及实际防火墙／EDR 的效果仍待现场验收。
- AI 草稿及人工审批链路已有受控模型验证。商业模型的输出质量及场景校准仍待实测。
- 原型使用合成数据。完整需求的实现与验证范围见状态文档。[功能实现与验收状态](../功能实现与验收状态.md)
