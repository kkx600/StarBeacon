# 星烽 StarBeacon 协议能力与检测验证

## 功能与入口

主平台在“探针管理 → 探针详情 → 协议能力”查看指定探针最后上报的观测；采集器在“网络与采集 → 协议能力”查看本机观测。平台数据仍受租户和注册代次约束，站点、探针分组与设备身份由管理目录维护，不由证书或协议名称推断。

目录分别展示识别、事务与日志、在线规则、文件提取、报文取证和外部补充。列表支持协议名称或标识筛选，协议配置、来源摘要通过独立弹窗查看，检测限额按需展开。未上报、核对中、核对失败、无筛选结果和明确禁用分别呈现；旧采集器缺少此字段时不补造能力。

## 观测来源

采集器使用现有原生执行隔离器，冻结检测引擎文件和单份配置，在私有作业目录执行 `-V` 与 `--list-app-layer-protos`。记录固定版本 8.0.7、引擎文件 SHA-256、配置 SHA-256 和观测时间；命令不取得设备凭据、状态目录或网络访问。命令输出最多 32 KiB，配置最多 1 MiB，引擎快照最多 256 MiB；沿用原生执行器的内存、输出和进程限制，两个查询共用 8 秒执行上下文。

检查在独立后台任务中运行，不在心跳、任务回执或健康 HTTP 请求中执行原生命令。后台每五秒核对文件与采集状态，成功观测缓存最多 30 秒、失败缓存最多五秒；配置、文件摘要或运行状态变化使缓存身份失效。健康读取只取已有观测；托管配置摘要变化时先显示等待核对，不把旧观测描述为当前配置。

模板含未核验的 include、includes 或插件时返回明确的未知状态；不读取引用路径后假定为完整配置。检测配置正文、文件路径和原生命令错误正文不进入上报材料。

`managed_configuration` 表示核对托管检测配置；`capture_active` 单独记录核对时是否确认采集进程就绪。`offline_template` 只说明所配置的离线模板，不能证明外部 EVE 生产进程使用了同一配置。引擎文件摘要不是运行进程证明，也不代替软件供应链资格。

原生目录可能受配置与构建影响。目录列出不单独证明事务解析启用；未列出也不能直接断言未编译。`yes`、`no`、`detection-only`、未显式配置与 TCP/UDP 差异分别保存；只在明确启用解析并配置对应 EVE 类型时显示“已配置”事务日志。

## 六层能力边界

| 能力 | 当前含义 | 不授予的结论 |
| --- | --- | --- |
| 识别 | 原生目录与显式解析器配置 | 所有端口、版本和异常流量均识别准确 |
| 事务与日志 | 解析配置与 EVE 日志配置 | 当前会话实际存在、完整或可解密 |
| 在线规则 | 明确禁用，或仍需独立规则样本验证 | 安装引擎即具有有效规则或检测效果 |
| 文件提取 | 当前平台文件流水线尚未提供 | 配置 file-store 就等同完成文件分析 |
| 报文取证 | 已启用独立归档时，登记现有 L2/L3/L4 有界包头解析 | 全部 TShark 字段、应用流重组或完整协议资格 |
| 外部补充 | 业务审计等连接器尚未提供 | 仅按端口或协议名称推断终端、账号及攻击结果 |

所有条目当前保持 `not_qualified`。目录不授予设备动作、模型费用、文件下载或正式发布资格。服务端及界面拒绝由探针自报为已验收的结构；该数据不用于扩大响应授权。

TLS、QUIC 和加密应用仅能使用实际可见元数据。握手、SNI 或 QUIC Initial 可见不表示已解密正文；ECH、缺包、分片、检查深度及资源预算仍可能形成盲区。

## 显式检测限额

仅返回以下配置路径的有界数值与单位：`flow.memcap`、`stream.memcap`、`stream.reassembly.memcap`、`stream.reassembly.depth`、`defrag.memcap`、HTTP libhtp 默认请求正文深度和默认响应正文深度。缺失值显示未显式配置，不把引擎默认值猜成 0。HTTP 站点专用配置可能覆盖默认正文限制；零值的含义依配置项而定，不代表没有其他资源预算。

目录是配置观测，不修改采集参数、全量包保留范围或用户留存策略。全量 PCAP、告警、操作与登录等业务类别仍默认保留 180 天，支持既有分类配置。

## 真实验证与限制

原生离线样本保留完整普通 TCP 握手、正确序号和校验和，在 18088 非标准端口分别验证：七字节 TCP 分段、TCP 乱序、IPv4 三十二字节分片、IPv4 分片乱序。每类同时包含目标 URI 与无匹配 URI，核对正样本一条告警、负样本零告警，并沿用实际包处理数量检查和隔离重放。

该八组样本于 2026-10-14 在远程独立 Docker 环境的 Suricata 8.0.7 完整工程回归通过；同源 415 个单元、106 个集成和真实网卡用例通过，双端实际目录与来源已核对。覆盖率及页面范围见[测试覆盖与验收记录](测试覆盖与验收记录.md)。这不是 jumbo、重叠分片、IPv6 分片、隧道、深度上限、大流量或全部协议的绕过验收，不构成吞吐或告警时延承诺。

后续仍需逐协议的正常、异常、非标准端口、版本与加密样本矩阵，以及 TShark、外部连接器、跨站点聚合、历史资格记录和生产容量验收。完整状态见[功能实现与验收状态](功能实现与验收状态.md)。

原生命令与配置含义依据 [Suricata 8.0.7 命令说明](https://docs.suricata.io/en/suricata-8.0.7/command-line-options.html)、[固定配置](https://github.com/OISF/suricata/blob/suricata-8.0.7/suricata.yaml.in)及[协议与文件设计](协议覆盖与文件分析设计.md)核对。
