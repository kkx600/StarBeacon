# 星烽 StarBeacon 验收环境清理

每轮验收结束后执行工程文件清理。通过、失败和取消都保留独立的本轮结果；清理结果不改变测试结果，也不授予发布资格。

## 保留规则

- 平台和采集器各保留当前版本与一个上一版本。例如当前版本 `0.5.1`，保留 `0.5.1`、`0.5.0`，回收更早版本。同版本只保留一份候选制品，优先选择两个 ZIP 均通过大小及 SHA-256 核对的完整制品。
- 按语义化版本排序，不按文件名或时间推测版本；`rc.10` 在 `rc.2` 之后。正式版本只选择上一正式版本，不用同一版本的 RC 候选替代回退制品；预览版本可保留上一个预览版本。默认当前版本来自本仓库最新版本标签，也可显式指定。浅检出没有版本标签时仅清理无版本工程材料，发行包保留并等待显式版本输入；高于当前版本的待验收制品不当作旧版本删除。
- 各类工程报告保留最近两份不同源码的已完成结果；显式指定的本轮目录受到保护。旧日志、原始覆盖文件、重复快照、截图副本和临时包允许删除，不要求永久归档。
- 无版本临时材料设 48 小时保护窗口，避免清理并行任务；已识别的过期、重复版本包不额外延长保留。保留正在执行任务的材料，执行清理时可通过 `--keep` 明确绑定。
- 部署定位状态、设备身份、凭据、证书、数据库、WAL、对象存储、正式原型图库、源码及未提交改动受保护。本规则不调整告警、PCAP、操作与登录审计等业务数据的默认 180 天留存策略。

旧文档中的“历史失败或全部原始日志始终保留”指验收执行期间不得覆盖、混入其他来源；验收结束后的磁盘保留以本规则为准。旧日志删除后，历史文档仍记录当时结论，不表示对应原始文件永久可下载。

## 本机文件

清理限定在本仓库 `.local/acceptance/`，清单与结果保存在 `.local/cleanup/`，文件权限为 `0600`。路径越界、符号链接、已跟踪文件、执行前身份或修改时间变化的文件均不删除。

```sh
# 仅生成清单。
make acceptance-cleanup-plan

# 生成并保存清单后执行，输出删除数量、逻辑大小与磁盘可用空间。
make acceptance-cleanup

# 显式绑定版本和正在执行的目录。
python3 scripts/cleanup_acceptance.py local --apply --current-version v0.5.1 \
  --keep .local/acceptance/current-run
```

`qualify_frontend.py` 的命令行入口在本轮结果落盘后执行文件清理，并保护当前输出目录；清理失败单独报告，不将测试失败改为通过。`remote_acceptance.py fetch` 在报告解包、来源核对和完整替换后执行本机清理，再检查对应远程 Docker 资源。

持久远程项目还在报告回传后清理其专属 `go-build-cache`、`capture-go-build-cache`。执行前核对 `owner.json`、项目路径和 Go 工具进程，保留原目录属主与权限；只回收可重建的编译缓存，不删除已安装工具链、依赖服务和系统 Docker 构建缓存。存在 Go 工具进程时保留缓存并记录 `busy`，避免影响并行编译。

## Docker 资源

```sh
# 本机 Docker。
make acceptance-cleanup-docker

# 已配置 SSH 主机上的 Docker；不启动或重启服务。
python3 scripts/cleanup_acceptance.py docker --host home_dev --apply
```

仅处理 `starbeacon/`、`starbeacon-` 命名空间及带本项目来源标签的无标签镜像；带其他项目别名的镜像不回收。组件和系统架构分别保留版本，所有运行、停止容器的镜像引用及父镜像受保护。48 小时内创建的镜像和时间无法核对的镜像暂不回收。

远程执行从本地该 SSH 主机的最新持久验收状态确定项目，也可成对提供 `--project`、`--directory`。远端先核对路径及 `owner.json`，归属无法核对时不调用 Docker；SSH 别名改变、目录消失或其他实例同名均不能触发自动接管。

已退出超过 48 小时、Compose 项目标识为本项目且 `oneoff=true` 的一次性容器，可使用不带强制选项及卷删除选项的命令回收。删除前再次检查状态；镜像删除前再次核对容器引用和标签身份。只调用 `docker image rm --no-prune`，不强删容器引用，不回收共享父层。

普通服务容器、持久卷、数据库与证书目录、共享构建缓存和非本项目资源不在自动回收范围内。禁止使用全局 `system prune`、全局 `builder prune` 或直接删除 `/var/lib/docker`。Docker 不可用时，清理记录明确标记 `unavailable`，命令返回 `2`；服务恢复后再次执行上述入口，不能把待执行项记为已释放空间。

## 结果记录

清理记录包含删除计划、实际删除数量与逻辑字节数、跳过原因及前后磁盘可用空间。共享层、压缩文件系统、硬链接和后台磁盘活动会影响实际空间，不能将逻辑字节数当作磁盘净释放值。原始清单包含内部文件路径，仅保存在私有工程目录。
