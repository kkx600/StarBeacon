# 星烽 StarBeacon 应用识别规则与采集器分类

本文描述当前工程入口、数据边界和验证行为。完整应用流量产品目标见[应用识别与响应性能设计](应用识别与响应性能设计.md)，工程状态见[功能实现与验收状态](功能实现与验收状态.md)。输入验证不能代替真实产品样本、采集器分发、流量归因或字节计量验收。

## 业务范围

规则管理的“应用识别规则”页签维护当前租户的产品名称规则，使用单表列表、创建／编辑表单、修订详情与输入验证弹窗。管理员可创建、修订、停用和重新启用；只读用户可查看并验证，不可维护规则。每个弹窗独立展示，详情和验证使用字段列表，不叠加第二张业务表。

产品标识与名称独立于 HTTP、TLS、QUIC、DNS 协议。应用类别为云存储、在线视频、即时通信、办公协作、研发工具、远程访问、业务系统和其他应用。产品名称可调整；稳定标识用于关联规则，不能用“HTTP”作为已经识别到某个网盘或视频产品的证明。

输入验证入口验证用户提供的可见元数据，回执固定标注 `user_supplied_metadata`。目录保存和材料验证不发布到探针；独立的部署入口通过签名任务下发完整启用规则快照。编辑或停用目录规则后，须部署该快照才会影响探针后续事件。历史网络事件保持原分类，普通业务活动不转换成攻击告警，应用规则不授权网络动作。工程未预置未经产品正负样本核验的互联网品牌识别库；`.example` 名称仅用于合成示例和受控验证。

## 规则与证据

定义版本为 `application-rule.v1`。一个规则声明 1–4 个受支持协议，最多 32 个非递归条件；不接收任意表达式、正则、脚本、文件路径或网络请求。

| 条件组 | 执行语义 | 边界 |
| --- | --- | --- |
| 候选域名 `any` | 1–16 条，至少一项命中 | 只允许 HTTP Host、可见 SNI、DNS 查询名称 |
| 同时满足 `all` | 每项均须命中 | 缺测不按空值命中，不跨材料协议填补 |
| 排除 `exclude` | 任一命中即排除该规则 | 不变更其他产品规则或原始材料 |

| 字段 | 运算符 | 约束 |
| --- | --- | --- |
| `http.host`、`tls.sni`、`dns.name` | 精确匹配、域名及子域 | IDNA 规范化，小写与单个根尾点处理，按 label 边界比较 |
| `http.method` | 精确匹配 | 受支持的大写 HTTP 方法 |
| `http.path` | 精确匹配、前缀 | 原材料中的可见路径，从 `/` 开始；不做解密或跨请求重组 |
| `http.user_agent` | 精确匹配、包含文本 | 区分大小写，UA 本身可伪造，不能作为单独产品依据 |
| `tls.alpn` | 精确匹配 | 仅可见的协议名称，不能据此推断 TLS 正文 |

域名规则拒绝 IP、公共后缀、URL、用户信息、通配符和非法标签。`files.example.attacker.example` 不能命中 `files.example`；`myfiles.example` 也不能命中。HTTP Host 材料可包含 1–65535 的规范十进制端口；端口不是识别依据。规则定义最多 16 KiB，HTTP 请求正文最多 32 KiB，避免多字节名称绕过字符数预算。

HTTP 材料与 TLS／QUIC、DNS 材料互斥。DNS 最多 32 个查询名称，ALPN 最多 8 个值；缺测使用空字符串和空数组。DNS 验证只表明查询名称符合候选规则，未建立客户端、回答 TTL、地址和连接的关联，不能给其他传输会话分配产品。

| 结果 | 含义 |
| --- | --- |
| 未知 `unknown` | 没有命中，或没有可用的可见元数据 |
| 规则候选 `candidate` | 一个产品的名称与附加条件符合材料；多个同产品规则可同时命中 |
| 证据冲突 `conflict` | 多个不同产品同时命中，不以优先级或最大得分隐藏冲突 |

验证不输出“已确认”或准确率百分比。所有命中均参与结果判断，最多展示前 16 条规则、每条前 8 条依据，明确展示截断状态。共享域名、CDN、ECH、代理复用、隧道和加密正文需要独立产品验证与关联，不能在此入口补造分类事实。

## 修订、权限与留存

每租户最多 128 条当前配置，停用配置仍占目录额度；最近 24 小时最多 2048 次维护。规则表引用一个不可变修订，配置、修订、原请求回执与操作审计在同一事务提交。API 不提供硬删除，停用可由后续授权修订恢复。

创建要求 `expected_revision=0` 且启用；编辑要求最新期望修订，并包含实际变更。并发维护只能一方成功，另一方返回 409，不覆盖他人的内容。`Idempotency-Key` 绑定操作者、完整输入和原修订；同键同输入返回原回执，变更输入返回冲突。网络失败或超时后，界面保留并锁定原输入与请求键，通过“核对原提交”确认，不能自动生成新键重试。

数据库运行账号受租户 RLS 约束，不能更新修订表。目录、历史、验证与维护均复核账号及租户有效状态，写入要求管理员；账号停用、降权或凭据修订后不得沿用旧身份完成操作。验证与维护审计只保存动作、对象和请求元数据，不复制测试域名、路径、UA 或整个验证材料。

修订历史按创建时的操作数据留存策略固定到期时间，默认 180 天，可按现有留存策略自定义后续对象期限。当前引用修订受保护，包括停用的当前配置；已过期且无当前引用的历史不可读取，并由有界维护任务清理。策略变更不倒改既有期限，当前有效配置不按历史期限回收。

## 接口与一致性

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/application-rules` | 当前目录；名称／状态筛选，按 ID 升序游标分页，最多 100 条／页 |
| `GET /api/v1/application-rules/{id}/revisions/{revision}` | 精确不可变修订；规范十进制序号，拒绝查询参数 |
| `POST /api/v1/application-rules` | 管理员维护；CSRF、幂等键、CAS、原子审计 |
| `POST /api/v1/application-rules/preview` | 用户定义副本与材料验证；`candidate_rule/1` 为合成测试身份 |
| `POST /api/v1/application-rules/test` | 当前租户全部启用规则的完整快照验证，不按列表分页截断 |
| `GET /api/v1/application-rules/snapshot` | 完整启用快照及摘要，无分页、不接受查询参数 |
| `POST /api/v1/sensors/{id}/application-rules` | 管理员冻结目录摘要、注册代次和探针状态，创建签名部署任务 |

请求拒绝重复键、大小写别名、未知字段和额外 JSON。审计失败不返回正常验证回执，存储不可用不以空目录或“未知产品”掩盖错误。

`application-test.v1` 分别绑定原测试材料摘要和按规则 ID 排序的完整版本快照摘要。浏览器独立核对定义、输入与候选快照 SHA-256，保留 Go JSON 的字符转义语义；目录、修订、状态、计数与限制不一致时不展示结果。验证材料变更立即清除旧结论；关闭、切换账号或卸载页面会取消请求，迟到响应不得覆盖当前视图。

## 规则部署与实际协议分类

部署参数绑定 `expected_registration_id`、`expected_state_sha256`、`rules_sha256`。平台在同一事务回核当前管理员、在线观测、注册身份、任务信任、完整目录和每日预算；每租户最近 24 小时最多 2048 次部署。快照 `application-package.v1` 上限 900 KiB，不接收用户自报租户、规则全文或任意脚本。目录变更后仍可用原幂等键与原输入核对已受理任务，不能改键盲目重试。

采集器执行 `applications.apply`，再次核对签名身份和本地状态摘要，先同步提交 bbolt，再切换唯一不可变匹配器。重启恢复同一任务、快照和安装时间。空快照是显式清空当前规则；部署受理、安装回执与实际协议分类分别展示。应用状态损坏时不继续分类、不报告空规则已生效，基础 EVE 采集继续运行，并报告能力异常。

真实分类来源固定为 `suricata_visible_metadata`，与输入验证的 `user_supplied_metadata` 分开。HTTP 使用实际 Host、方法、可见路径和 UA；TLS 使用 SNI 及 `client_alpns`／`server_alpns` 的可见名称；QUIC 使用 SNI 和类型为 16 的可见 ALPN 扩展；DNS v3 使用查询数组，v2 只使用 query 名称，不将 answer 的顶层名称补成查询。ALPN 名称可以来自客户端声明，不等同于服务端已选定协议。告警 `tx_guessed=true` 为估计关联，保持未知，不给产品归因。[固定版本字段](https://docs.suricata.io/en/suricata-8.0.7/_generated/eve-index.html)

匹配按协议与反向域名桶筛选，不逐包调用 LLM，也不在每条记录重新验证全部定义。规则快照保持原摘要，比较域名按 IDNA 规范值；不同产品命中保留冲突。最多展示 16 条规则、每条最多 8 项依据，并按字节预算进一步省略后续依据；保留正向域名、全部命中计数及明确截断标识。该预算不改变分类结论，也不能阻塞基础告警。

分类以 `application-attribution.v1` 独立附加在 Protobuf 记录中，绑定原 EVE 摘要、观察时间、部署任务、规则快照和状态。原始 EVE 字节、载荷摘要及来源身份不改写；附加 JSON 与其 SHA-256 同步进入 WAL 和批次摘要。已持久的记录不因后续规则变更或重启重新归因。无附加分类的旧批次保持原摘要算法；启用分类前须确保事件接入与索引进程支持该契约。

平台按原已投递的部署命令复算分类，按探针与注册身份隔离，不能用当前目录替换历史依据。存储故障保留重试；分类语义或依据失效仅隔离附加分类，原告警仍入库并进入原通知策略。操作留存默认 180 天；可能生效且未被后续成功部署替代的配置任务保留复算依据，已到期历史读取仍遵守操作留存期限。旧规则修订或旧任务被回收后，迟到附加分类可能失去可核验依据，不伪装成已经确认的产品。

ES 使用独立 `sb-events-v2` 模板和严格的可选字段映射，保留原 v1 模板供既有程序读取。已有事件索引仅添加应用字段，不改变分片、ILM 或历史文档。产品、类别、状态、任务和快照使用 keyword；有界依据只存储、不进行全文或嵌套索引。检索支持 `app.product == "owned_files"`、`app.category == "cloud_storage"`、`app.status == "candidate"` 及完整字段名；缺失分类保持缺失，不能当作未知或零流量。

工程页使用独立部署弹窗，选择具备有效观测和能力的探针，展示完整快照摘要。提交结果未知时保留原目标、参数与键；关闭弹窗可在同一工作区重新核对。告警、协议记录和探针详情展示对应分类及部署状态，均不输出应用准确率、应用字节或真实产品覆盖率。

## 仍需交付

活跃流计量、计量域和跨探针重叠处理、历史会话归因修正、真实互联网产品样本矩阵、应用流量排行／趋势／未知流量／大屏及生产吞吐仍须实现并独立验收。协议事件分类不能代替连接字节计量；DNS 查询名称匹配不会给其回答地址或其他连接分配产品。当前版本采用显式单探针部署，多探针灰度和自动订阅尚未交付。
