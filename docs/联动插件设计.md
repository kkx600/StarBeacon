# 星烽 StarBeacon 联动插件设计

本文定义联动插件的功能和交付契约。模板运行器和草稿版本目录见第 3 节，脚本运行器和发布流程见第 4–6 节。现有固定接口的配置与任务契约见[HTTP 联动与限时封禁](HTTP联动与限时封禁.md)。各项工程进度和验收依据见[功能实现与验收状态](功能实现与验收状态.md)。

决策日期：2026-11-20。防火墙、EDR、WAF 都在客户内网，每家的接口都不一样。平台不去逐家内置适配，而是让采集器运行**用户自己写的插件**：采集器在内网访问设备，拉取设备告警，执行封禁、解封、隔离。

## 1. 两种写法

| 写法 | 内容 | 适用 | 能做什么 |
| --- | --- | --- | --- |
| **模板** | 一份声明式配置：请求地址、参数、认证方式、成功条件 | 接口规整的设备，占大多数 | 固定的请求与字段映射，不能写逻辑 |
| **脚本** | 一段类 Python 的脚本（Starlark），调用平台提供的函数 | 要多步登录、签名、翻页或特殊判断的设备 | 条件、循环、函数、数据转换；不能访问文件、进程和任意网络 |

先用模板，模板表达不了再用脚本。两种写法共用同一套入口、试运行、签名和下发流程，在平台上是同一种对象。

也可以把设备接口文档里登录、黑名单、告警查询这几段贴进来，让 AI 生成草稿（第 7 节）。

## 2. 插件要实现的入口

一个插件按设备能力实现其中几项，没实现的能力在页面上不可选。

| 入口 | 作用 | 输入 | 返回 |
| --- | --- | --- | --- |
| `health` | 检查设备可达、凭据有效 | — | 是否正常及原因 |
| `pull_alerts` | 拉取设备上的新告警 | 上次拉到的位置 | 含 `cursor` 和 `items` 的一页归一化告警 |
| `block` | 封禁地址 | 目标地址、时长 | 设备是否接受；可附带设备规则标识等信息 |
| `unblock` | 解除封禁 | 目标地址、封禁时保存的信息 | 设备是否接受 |
| `verify` | 回读设备，确认规则在不在 | 目标地址、封禁时保存的信息 | 存在、不存在或无法确认 |
| `isolate`、`release` | 隔离主机、解除隔离（EDR） | 主机标识 | 设备是否接受 |

`block` 和 `isolate` 必须同时实现对应的解除入口和 `verify`，否则不能签名：平台的限时封禁、到期解除和结果核对都依赖它们。`block` 返回的附加信息（例如设备给出的规则标识）随这次封禁的租约保存，解除和回读时通过 `lease` 取回。

拉取到的设备告警统一成这些字段后进入平台，与网络告警走同一条研判和关联流程，来源标记为“设备告警 · 插件名”：

| 字段 | 说明 |
| --- | --- |
| `id` | 设备侧的告警标识，用于去重 |
| `time` | 发生时间 |
| `severity` | 严重、高危、中危、低危 |
| `name` | 告警名称 |
| `source_ip`、`destination_ip` | 源和目的地址，可缺省 |
| `host` | 终端名称或标识（EDR） |
| `raw` | 设备原始记录，原样保留 |

## 3. 模板写法

```yaml
id: fw-vendor-b
device: 防火墙 · 厂商 B v5
allow_hosts: [192.0.2.20]           # 只允许访问这些地址
auth:
  login: {method: POST, path: /api/login, body: {user: "{{secret.username}}", pass: "{{secret.password}}"}}
  token: "{{response.json.token}}"   # 过期后自动重新登录
  header: "Authorization: Bearer {{token}}"
actions:
  block:
    request: {method: POST, path: /api/blacklist, body: {ip: "{{target.ip}}", ttl: "{{duration_seconds}}", comment: "{{task_id}}"}}
    success: "{{response.status == 200 and response.json.code == 0}}"
    save: {rule_id: "{{response.json.id}}"}   # 随租约保存，解除和回读时用
  unblock:
    request: {method: DELETE, path: "/api/blacklist/{{lease.rule_id}}"}
    success: "{{response.status in [200, 404]}}"
  verify:
    request: {method: GET, path: "/api/blacklist/{{lease.rule_id}}"}
    present: "{{response.status == 200}}"
```

模板里只有取值和布尔判断，没有循环和自定义函数。

### 模板契约与草稿版本

工程接口使用 `response.template.v1` 的 JSON 声明。每个步骤的 `accept.status` 列出可接受的状态码，`field` 和 `equals` 可选填一个平面 JSON 字段及对应的字符串、整数或布尔值。绑定、输出字段和相对路径用法见[验收设备模板](../internal/response/testdata/owned_acl_template.json)。

- 设备运行绑定包括固定管理 IP、受信 CA、目标及保护网段和租约上限。登录配置指定用户、密码和令牌字段名。采集器从私有文件读取凭据，令牌在内存中按 `ttl_seconds` 缓存。设备返回 401 时重新认证一次只读请求。写请求按任务标识进行独立核对。
- 封禁提交任务标识、目标、所有者和绝对到期。回读按任务标识匹配设备、所有者、目标、期限和规则标识。采集器把确认过的规则标识保存到本地租约，解除时同时使用规则标识和所有者条件。明确不存在仅用于创建前核对，解除结果需要设备回读确认。
- 管理员通过 `GET /api/v1/response-plugins` 读取当前草稿，使用 `after` 续页。`POST` 需要 `expected_version` 和 `Idempotency-Key`，初版的 `expected_version` 为 0。`GET /api/v1/response-plugins/{id}/versions/{version}` 读取具体历史版本。当前为 `draft`，被新版本替代后显示 `superseded`，版本内容及摘要保持固定。每租户最多 64 个模板，每个最多 32 个版本。
- 只读模板可以单独声明 `health` 或 `pull_alerts`。分页模板的 `cursor_param` 指定查询参数名，`items_field` 和 `cursor_field` 指定响应字段，`fields` 将设备字段映射到告警契约。每条告警随附原始设备记录。

## 4. 脚本写法

```python
def _headers(ctx):
    if state.get("token") == None:
        resp = http.post(ctx.base_url + "/login", json = {"user": secret.get("username"), "pwd": secret.get("password")})
        if resp.status != 200:
            fail("登录失败：%d" % resp.status)
        state.set("token", resp.json()["token"], ttl = 1500)
    return {"X-Auth-Token": state.get("token")}

def pull_alerts(ctx, since):
    resp = http.get(ctx.base_url + "/alerts", params = {"from": since or "", "limit": 200}, headers = _headers(ctx))
    page = resp.json()
    levels = {"critical": "严重", "high": "高危", "medium": "中危"}
    return {"cursor": page["next_cursor"], "items": [{
        "id": item["uuid"],
        "time": item["occurred_at"],
        "severity": levels.get(item["level"], "低危"),
        "name": item["title"],
        "source_ip": item["src"],
        "destination_ip": item["dst"],
        "raw": item,
    } for item in page["items"]]}

def block(ctx, target, duration):
    resp = http.post(ctx.base_url + "/blacklist", json = {"ip": target["ip"], "expires_at": ctx.expires_at, "memo": ctx.task_id, "owner": ctx.owner_sha256}, headers = _headers(ctx))
    if resp.status != 200:
        fail("设备拒绝：%d" % resp.status)
    return {"ok": resp.json()["code"] == 0, "rule_id": resp.json()["id"]}

def unblock(ctx, target, lease):
    resp = http.delete(ctx.base_url + "/blacklist/" + lease["rule_id"], headers = _headers(ctx))
    return resp.status in [200, 404]

def verify(ctx, target, lease):
    resp = http.get(ctx.base_url + "/blacklist/by-task/" + lease["lease_id"], headers = _headers(ctx))
    return resp.status == 200 and resp.json()["state"] == "active"
```

脚本只能用平台提供的这些函数：

| 函数 | 作用 |
| --- | --- |
| `http.get`、`http.post`、`http.put`、`http.delete` | 访问插件登记过的设备地址 |
| `secret.get` | 按名称取不透明凭据引用，只能交给登记的登录字段、设备请求头或专用 HMAC 函数 |
| `state.get`、`state.set` | 采集器内存中每个运行绑定最多 32 个键。支持普通 JSON 和凭据引用，过期后读取为空。调用成功才提交变更 |
| `json.encode/decode`、`base64.encode/decode`、`hash.sha256`、`hash.hmac_sha256` | JSON、标准 Base64 和十六进制摘要。HMAC 使用本地单独登记的 32 字节随机密钥 |
| `time.now`、`log.info`、`log.warn`、`fail` | 本次执行的 UTC 时间、单行日志和失败中止。`log.fail` 与 `fail` 等价 |

采集器的本地运行绑定固定源码、HTTPS 原点、CA、管理 IP 及各入口的接口清单。请求的相对路径或完整地址必须匹配登记路径。末段 `{rule_id}` 仅接收任务提供的设备规则标识。查询键、请求头和脚本可见的顶层响应字段按接口登记；登录只返回不透明令牌引用。每个设备写入还需由任务端提供一次性的精确授权，锁定 HTTP 方法、路径和 JSON 正文。脚本可缓存令牌引用，令牌最长有效 30 分钟。拉取位置的持久化和告警去重随第 6 节的启用流程接入。

## 5. 运行与隔离

脚本语言选 Starlark：语法接近 Python，学习成本低；语言本身没有文件、进程和网络能力，所有对外访问只能通过平台给的函数。解释器用 Go 实现，直接编进采集器，不需要另装 Python 运行环境。

| 限制 | 做法 |
| --- | --- |
| 能访问哪里 | 工作进程无网络，只能让采集器访问登记的 HTTPS 原点、接口与方法。域名的全部解析结果都须匹配同一管理 IP。代理和 HTTP 跳转关闭 |
| 跑多久 | 每次调用共享 100,000 个解释器步骤、5 秒实际耗时和 3 秒 CPU 时间 |
| 用多少内存 | Linux 的 bubblewrap 工作进程只挂载采集器可执行文件和本进程命名空间的 `/proc`。虚拟地址空间硬上限 1.5 GiB，Go 内存目标 64 MiB。禁止常规文件写入和 core dump |
| 并发与速率 | 每个插件绑定同时最多 1 次调用，整个采集器最多 4 个工作进程。每次执行最多发出 8 次设备请求，每分钟最多 30 次 |
| 数据大小 | 脚本最多 32 KiB，设备响应、调用输入和返回值最多 16 KiB。单条日志最多 512 字节 |
| 凭据 | 明文留在采集器父进程。打印、编码、返回凭据引用和设备回显已知凭据会被拒绝。执行记录保存结果码、登记的接口、状态码与安全日志 |
| 传输 | 由采集器使用本地登记的 CA 正常校验证书，设备请求与脚本工作进程分离 |

步数上限和中止使用解释器的 `Thread.SetMaxExecutionSteps` 和 `Thread.Cancel`。父进程在取消或超时时关闭进程管道并回收工作进程。Linux 隔离启动失败时拒绝执行。递归和 `load` 均被禁用，时间由平台函数提供。见 [Starlark 语言规范](https://github.com/google/starlark-go/blob/4f4267fb140d1e8b91c9bce55cee2f809e8840dd/doc/spec.md)、[Go 实现的接口文档](https://pkg.go.dev/go.starlark.net/starlark)及[依赖版本与部署清单](依赖版本与部署清单.md)。

需要浏览器登录的设备不在本设计范围内，仍按[响应联动与插件调研](research/响应联动与插件调研.md)里的独立进程方案另行评估。

## 6. 从草稿到启用

```mermaid
flowchart LR
    A[草稿] --> B[试运行]
    B -->|通过| C[签名]
    B -->|失败| A
    C --> D[下发到采集器]
    D --> E[启用]
    E --> F[停用或回退上一版本]
```

1. **模拟设备**在采集器父进程按次序匹配冻结的样例请求和响应。样例传输在内存中运行，使用合成凭据。模板执行器或 Starlark 工作进程实际调用接口，样例必须恰好全部消费。
2. **真实设备只读**执行该版本声明的 `health`、`pull_alerts`、`verify`。回读使用专属试运行标识，告警只核验映射和游标。
3. **按能力验收**。只读版本核对写入受限。封禁版本对采集器本地登记的保留测试 IP 执行 60 秒租约的封禁、回读、解封和复核。EDR 版本在本地登记的测试终端上完成对应的隔离、回读、解除和复核。两种能力均声明时各自验证。变更回读由采集器父进程核对实际 HTTPS 响应的设备、目标、租约、所有者和绝对到期。
4. **签名并下发**在同一租户和采集器注册代次内，依次核对最近 24 小时同一版本与同一本地绑定的三个成功回执。平台使用 Ed25519 对版本摘要、设备绑定、采集器身份和三档回执摘要签名，再用现有控制流投递任务。采集器同时校验外层任务和版本签名。
5. **停用与回退**按预期部署代次更新。回退复用上一版保存的签名。采集器在同一 WAL 事务保存启用状态和成功回执，平台收到绑定回执后才更新目录。存在仍在期限内的未撤销租约时，采集器保护其运行版本。

### 采集器本地绑定

设置 `SB_RESPONSE_PLUGIN_BINDINGS_FILE` 指向采集器可读的私有 JSON 文件。根对象为 `{"schema_version":"response.plugin-bindings.v1","profiles":[...]}`。最多登记八项，每项的 `plugin_id`、`device.id` 和 `device.device_id` 各自唯一。设备字段沿用[联动连接器配置](HTTP联动与限时封禁.md)。包含封禁能力的配置另外设置 `test_address`，允许文档保留网段内的地址，并须落在设备授权范围内且避开保护名单和管理地址。包含 EDR 隔离能力的脚本配置 `test_host`，值为预留测试终端的本地标识。

脚本配置的 `script.routes` 登记 `entry`、`method`、相对 `path`、查询键、认证请求头和脚本可见的 JSON 字段。脚本可通过 `login` 和 `secrets` 引用本地凭据，允许省略设备的 `token_file`。每个变更入口由 `script.actions` 冻结方法、路径与正文字段。新增动作包含 `{{lease_id}}`、`{{owner_sha256}}`、`{{expires_at}}` 和对应的 `{{target_ip}}` 或 `{{host_id}}`。解除动作使用带 `{rule_id}` 的路径，由采集器附带所有者条件。设备级回读由 `script.verify.block` 或 `script.verify.isolate` 绑定到任务标识路径，并映射设备、目标、租约、所有者、到期、状态、规则标识和观测时间。脚本接收 `ctx.owner_sha256`、`ctx.expires_at` 和 `ctx.duration_seconds`，由采集器填充。

签名模板可进入现有联动设备目录。脚本启用现有生产 IP 处置入口时，通过 `script.device_health` 映射实际设备标识、原生到期、独立租约、条件解除和最大时限，沿用原有人工授权、保护名单及租约。EDR 第三档验收使用受控测试终端协议。本地文件只通过控制流登记设备与绑定摘要。

### 样例与平台操作

草稿的 `examples` 按调用顺序保存 `method`、相对 `path`、可选 `query`、`status`、可选 `request` 及 `response`。正文以 JSON 字符串保存。模拟租约标识为 `fixture-lease`。正文的字符串占位符可使用 `lease_id`、`owner_sha256`、`expires_at`、`observed_at`、`target_ip`、`host_id`、`device_id` 和 `device_version`。

管理员使用 `GET /api/v1/response-plugins/{id}/operations?sensor_id=...` 查看当前和上一版、试运行及最近回执。向同一路径提交 `POST` 时，提供 `sensor_id`、`version`、`action`、`expected_generation` 和 `Idempotency-Key`。三档操作依次为 `simulate`、`read`、`capability`，发布、回退和停用分别为 `publish`、`rollback`、`disable`。

试运行回执保存各入口的结果、耗时和脱敏请求摘要，请求摘要仅含 HTTP 方法和状态码。列表显示最近一项任务的更新时间，启用的采集器报告拉取失败时显示设备异常。

## 7. AI 生成插件

1. 用户选择设备类型和需要的能力，贴入接口文档的相关段落。
2. AI 给出草稿：能用模板表达就生成模板，否则生成脚本；同时生成一组样例请求和响应，供模拟设备试运行使用。
3. 用户审阅、修改，按第 6 节试运行。

约束：AI 只看到用户贴的文档文本，接触不到凭据和真实设备；生成的内容与手写的一样，要经过人工审阅、试运行和签名才能下发，没有捷径。生成记录保留所用模型和输入摘要。

## 8. 执行可靠性

插件只负责“怎么调设备”。授权、限时、幂等、到期解除和结果核对仍由平台和采集器的任务机制负责，规则不变：

- 每个动作带任务标识，设备支持时写进规则备注，重复下发不重复生效。
- 封禁都有期限，到期由采集器调用 `unblock` 并用 `verify` 确认。
- 设备没有明确答复时记为“结果未知”，先 `verify` 再决定重试，不直接重发。
- 保护名单内的地址在下发前就被拦下，插件不会被调用。

`pull_alerts` 默认每 60 秒执行一次，每页最多 200 条。采集器以本地绑定的插件、设备和告警标识去重，告警、已见标识和游标在同一 WAL 事务提交。设备中断、WAL 空间不足或标识预算用尽时保留原游标并退避重试。一个 WAL 最多登记一百万个已见标识。重启及回退复用原游标，原有告警队列继续按路由和稳定事件身份交付。检索和研判统一使用“设备告警 · 插件名”来源，告警原始 JSON 保留在原始记录里。

## 9. 页面

“响应中心 → 联动设备 → 联动插件”：一张插件表（编号、名称、写法、适配设备、能力、运行采集器、状态、最近执行），新建与编辑用弹窗，弹窗内包含源码、配置项、试运行日志和“签名并下发”。AI 生成是同一页上的另一个入口。插件和联动设备一样是按条目管理的对象，留在响应中心，不放进系统设置。原型见 `prototype/src/views/PluginsView.vue`。

## 10. 验收要点

1. 模板和脚本各完成一个真实设备的封禁、回读、解封全流程。
2. 隔离有效：访问未登记地址、超步数、超时、超大响应、读取凭据明文，全部被拒绝并有记录。
3. 未签名、签名不匹配、指定给其他采集器的版本不会被加载。
4. 设备超时或返回不明确时进入“结果未知”，不会重复封禁。
5. 拉取告警不重复、不遗漏，设备中断恢复后从上次位置继续。
6. AI 生成的草稿不经试运行和签名无法下发。
