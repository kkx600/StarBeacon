# 星烽 StarBeacon 高级检索与数据包取证设计

基准日：2026-09-30。本文定义检索语言、字段语义、数据包工作台和离线分析任务的工程契约。目标是覆盖安全运营中常用的地址、协议、请求响应、报文字节和会话条件，同时使复杂协议取证能够复用 Wireshark。功能属于待实现和验收的设计，不表示兼容性、准确率或性能已经实测。基础数据权威和持久化规则沿用[架构设计](架构设计.md)，通用页面与日志规范沿用[运营与集成设计](运营与集成设计.md)。

## 1. 两种检索模式与查询对象

| 模式 | 页面名称与对象 | 执行方式 | 边界 |
| --- | --- | --- | --- |
| `indexed_events` | 事件检索；告警、应用事务、会话摘要、资产和响应状态 | 服务端类型化 AST 编译为 ES 查询；采用 `starbeacon-ws` 语言和版本化字段注册表 | 查询已经采集、规范化且可检索的事实；不是对 PCAP 中每个包运行 Wireshark |
| `packet_native` | 数据包检索；授权 PCAP/PCAPNG 范围 | 隔离作业运行固定版本 TShark，使用 `wireshark-display` 语言 | 依赖原始字节、解析配置、重组上下文和取证权限；不能凭事件摘要恢复未捕获内容 |

原生引擎锁定 **TShark 4.6.9**，版本、制品摘要、编译选项、PCRE2 版本、字段字典、启用解析器、Decode As、重组和解密配置共同组成 `parser_profile_id`。在线文档可能含后续版本行为，生产兼容表必须由锁定制品生成并通过固定样本验收。[发布说明](https://www.wireshark.org/docs/relnotes/wireshark-4.6.9.html)、[锁版显示过滤器说明](https://github.com/wireshark/wireshark/blob/v4.6.9/doc/man_pages/wireshark-filter.adoc)

输入框固定显示模式、数据集、时间范围、可见字段覆盖和解析器版本。保存查询同时保存这些信息；切换模式先重新校验，并说明查询对象由事件变为数据包，不能在后台悄悄切换后沿用原总数。`frame.number`、`tcp.stream` 是特定分析输入及配置下的编号，不能当作全平台永久主键。告警总数、会话数、数据包数分别计数，跨对象关联使用独立取证任务。

Wireshark 显示过滤语法和 BPF 捕获过滤语法分开入口。例如 `tcp.port == 443` 属于显示条件，不能原样作为捕获过滤器。捕获策略影响将来能保留的证据，修改它需探针配置权限、预览和发布记录，不由一次历史检索自动触发。[Wireshark 过滤器分类](https://wiki.wireshark.org/DisplayFilters)

## 2. 检索语法支持矩阵

下表是交付与验收范围。“事件支持”以字段注册表标记的数据集、类型、完整性和权限为前提；表内未声明支持的表达式必须返回错误位置、原因与可用模式，不能静默降级成全文搜索或忽略某个条件。

| 语法或能力 | 事件检索 | 数据包检索 | 约束与示例 |
| --- | --- | --- | --- |
| 字段／协议存在 | 支持注册字段与协议别名 | 使用原生引擎 | `http.request.method`；布尔字段存在不等于值为真 |
| `and/&&`、`or/\|\|`、`not/!`、`xor/^^`、括号 | 支持；AST 统一优先级和预算 | 原生 | 可视化编辑器不能把嵌套 OR 展平成 AND |
| `==/eq/any_eq`、`!=/ne/all_ne` | 支持现代多值语义 | 原生 | `ip.addr == 192.0.2.8`；`!=` 不是“任意值不等” |
| `===/all_eq`、`!==/any_ne`、比较前 `any/all` | 支持注册的多值字段 | 原生 | `all tcp.port > 1024`；显示实际量词 |
| `< <= > >=` 及英文别名 | 数字、地址、时间；字符串排序仅白名单字段 | 原生类型规则 | 端口按数值，IP 按地址族内二进制顺序，禁止字符串比较 IP |
| IPv4/IPv6 精确、CIDR | 支持 | 原生 | `ipv6.addr == 2001:db8::/32`；混用地址族报错 |
| `in {…}`、包含范围的集合 | 支持常量集合；同类型、逗号分隔 | 原生允许范围按配置验收 | `tcp.port in {80,443,8000..8100}` |
| MAC 精确与集合 | 有可靠来源的链路字段支持 | 原生 | `eth.src == 02:00:00:00:00:01`；规范化前保留原值 |
| `contains` 字符串 | 仅完整可检索的白名单字符串，区分大小写 | 原生 | `http.request.uri contains "/login"`；不是分词全文搜索 |
| `contains` 原始字节／协议 | 返回需要数据包模式 | 原生 | `tcp.payload contains 47:45:54`；不扫描 ES Base64 原文 |
| `matches/~` | 不转换为 ES 正则；提示原生作业 | 原生 PCRE2，受任务资源限制 | `http.request.uri matches r"(?-i)^/api/"` |
| 字节与字符串切片、负偏移、组合切片 | 返回需要数据包模式；仅 OUI 专用筛选可映射已派生字段 | 原生 | `eth.src[0:3] == 02:00:00`、`frame[-4:] == de:ad:be:ef` |
| 协议层选择 `#` | 仅显式的平台注册层字段，不冒充任意层选择 | 原生 | `ip.src#2 == 192.0.2.8` |
| 原始字段 `@` | 返回需要数据包模式 | 原生 | 区分解析后文本与原始编码字节 |
| `lower/upper`、`len` | 仅预计算并注册的字段，ASCII 大小写及字节长度契约固定 | 原生 | 不为任意用户表达式开放 ES script |
| `count` | 仅保存真实 occurrence 数的字段 | 原生 | ES 去重后的 doc values 数量不能冒充原字段出现次数 |
| `string/vals/dec/hex`、算术、字段间比较 | 返回需要数据包模式；平台自身派生指标另列字段 | 原生支持范围 | 不能用自定义脚本隐式执行任意表达式 |
| TCP 位标志／bitwise AND | 已注册标志字段支持；小范围掩码可编译为枚举项 | 原生 | 会话“曾见 SYN”不命名为某包的 `tcp.flags.syn` |
| 宏、当前选中包字段引用 | 不执行用户文本宏 | 默认拒绝；工作台“以此字段筛选”生成冻结常量 | 不读取宿主机宏文件或用户配置 |
| 主机名作为 IP 字面值、外部名称解析 | 拒绝；改用域名字段或固定 IP 集合 | 默认拒绝，作业无出站网络 | 同一查询不能随 DNS 变化而改变结果 |
| Lua、自定义 dissector、任意 CLI 选项 | 不提供 | 不向普通查询开放 | 管理员维护的解析器制品走发布与兼容性验收 |

上述核心比较及量词语义以锁版手册和官方测试为参照；切片、层选择等复杂能力保留原生执行，以减少自行维护协议语义的成本。[锁版手册](https://github.com/wireshark/wireshark/blob/v4.6.9/doc/man_pages/wireshark-filter.adoc)、[官方过滤器测试](https://github.com/wireshark/wireshark/blob/v4.6.9/test/suite_dfilter/group_syntax.py)

### 2.1 词法、类型与单位

事件语言接受小写英文运算符和相应符号；字段名区分大小写。整数字面值支持十进制、`0x` 十六进制、`0b` 二进制和前导零八进制，编辑器提示 `010` 的数值为 8，避免误读为 10。字符串需双引号，接受受控转义与 `r"…"` 原始字符串；保存原始输入和规范化 AST，非法 UTF-8、未闭合引号、溢出及越界端口在执行前报错。

事件时间字面值要求包含时区的 RFC 3339；时间选择器按租户时区转换。原生任务固定 `TZ=UTC`，无时区的原生时间表达式明确按 UTC 解释，避免不同 Runner 结果变化。持续时间字段有明确单位；`frame.time_delta` 是秒，平台 `event.duration` 遵循自身字段注册表的纳秒单位。UI 可输入“5 毫秒”，转换后展示提交值，DSL 不把 `5ms` 默认为 Wireshark 原生字面值。流量区分 B、bit、B/s、bit/s，包长区分捕获长度与原长度。

### 2.2 多值、缺失与未知

对具有完整观测的字段，设值序列为 V。`==` 要求至少一个值相等；`!=` 要求字段存在且全部值不等；`===` 要求字段存在且全部值相等；`!==` 要求至少一个值不等。普通大小比较默认 any，显式量词覆盖默认值。空序列的比较结果为 false；`not (f == x)` 可匹配已确认缺失的字段，`f != x` 不匹配它。布尔字段值为 false 时，其存在测试仍为 true。

| 完整观测的 V | `f == x` | `f != x` | `f === x` | `f !== x` | `not (f == x)` |
| --- | --- | --- | --- | --- | --- |
| `[x]` | true | false | true | false | false |
| `[x,y]`，y 与 x 不同 | true | false | false | true | false |
| `[y]` | false | true | false | true | true |
| `[]`，已确认没有字段 | false | false | false | false | true |

事件索引还存在原生单个协议树没有表达的平台问题：未启用日志、加密不可见、旧 schema、截断、未索引、脱敏和字段权限不足。这些情况不能统称为“字段不存在”。注册表和 `starbeacon.search_quality` 保存字段覆盖与异常原因；不能只用 ES `exists` 判断原始字段是否存在，因为 `ignore_above`、禁用索引、null 和空数组都会影响索引存在性。[ES exists](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-exists-query)

事件模式默认采用 `coverage_policy=strict`：已确认存在／不存在的完整字段按上表计算；无法判定的谓词为 unknown，NOT unknown 仍为 unknown，AND／OR 按三值逻辑组合，只有最终为 true 的记录进入命中集。这是平台质量扩展，必须在语法帮助中明确，不宣传与任意原生数据包过滤完全等价。完整观测集合上的结果须与对应原生语义一致。实现中编译每个节点的 true、false 集合，unknown 为剩余部分；不使用 `must_not match` 将所有不可见值变为确定否定。字段异常集合为受控字段 ID，不按任意 header 动态建 mapping。

未知字段、当前数据集不支持的字段和无权限字段在编译期返回适当的 `unknown_field`、`field_not_available`、`field_forbidden`，避免以零命中掩盖配置错误。结果给出覆盖摘要和是否排除不确定记录；精确的 unknown 数量作为受预算约束的统计，未计算就标为未统计。机器研判不得把“没有检索到”当作不存在攻击的证明。

### 2.3 同一值、同一对象与同一事务

`tcp.port in {8000..8100}` 要求同一个端口落在区间。不能改写成两个独立 any 比较，否则源端口 50000 与目的端口 80 会分别满足上下界而误命中。量词作用于该字段的所有真实出现值；不能把重复值去重后用于 `count`。

DNS answer 的 `name/type/data/ttl`、HTTP header 的 `name/value`、证书条目和隧道层字段需要同元素约束，使用有限 nested 结构或独立事务记录。多个 HTTP 事务不能展平成会话的 method 数组与 path 数组后执行组合条件，否则 GET `/a` 和 POST `/b` 会被误当作 GET `/b`。别名仅指向当前文档定义的事务；需要跨事务序列时使用关联分析任务。[ES nested 对象关系](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/nested)、[Wireshark 范围集合说明](https://www.wireshark.org/docs/wsug_html_chunked/ChWorkBuildDisplayFilterSection.html)

### 2.4 正则与包含查询

Wireshark 的 `matches` 采用 PCRE2，不能改用 Go RE2 或 ES Lucene 正则后仍沿用同一兼容承诺。事件模式保留 `contains` 对已注册字符串的精确子串语义；通配字符必须按字面量转义。确需在已索引字段使用 Lucene 正则时，由单独的“索引正则”高级控件生成带 `engine=lucene` 的 AST，显示语法和成本，不使用 Wireshark 的 `matches` 标记。[Lucene 正则限制](https://www.elastic.co/docs/reference/query-languages/query-dsl/regexp-syntax)

原生正则受整个进程 CPU、内存、时限及输出配额约束；回溯超时、解析器错误和被取消显示失败或部分结果，不显示“无匹配”。不能仅限制结果数量而允许无限扫描。字符串正规化、域名小写、路径大小写、原始百分号编码和派生解码字段分别注册，不以全文分词替代 URI 比较。

## 3. 常用字段与协议覆盖

### 3.1 主流检索字段

| 分组 | 常用入口／字段 | 事件模式的来源约束 | 原生模式 |
| --- | --- | --- | --- |
| 地址 | `ip.src/dst/addr`、`ipv6.src/dst/addr`；ECS `source.ip/destination.ip` | 对应事件所选网络层；地址族守卫；保存 `selected_network_layer` | 按所有实际协议层出现值求值，可用 `#` 指定层 |
| MAC | `source.mac/destination.mac`；`eth.src/dst/addr` | 后一组别名仅在可证明为该包链路头的记录启用；流首包 MAC 不伪装成当前包 | Ethernet 解析器字段；非 Ethernet 捕获不编造 MAC |
| VLAN／隧道 | 外／内层 VLAN、VNI、GRE、外／内层端点 | 规范化为带层序号的 `starbeacon.link_observations` 与 `starbeacon.encapsulation` | 原生解析器及层选择；并非每种 linktype 都有 VLAN |
| TCP／UDP | srcport、dstport、port；TCP flags、窗口、seq/ack、重传、RTT | 端口由协议守卫映射；包级旗标只在包证据存在时支持；流计数另列 | 原生字段与分析标记；重传等是解析推断，受捕获缺口影响 |
| IP／ICMP | TTL/Hop Limit、DSCP/ECN、分片、ICMP type/code | 仅已采集字段；非首片端口可未知 | 原生 IPv4/IPv6/ICMP/ICMPv6；扩展头及内嵌错误报文保留层级 |
| HTTP | request method、host、URI、状态码、UA、content type、request/response 时间 | Suricata 对应事务；HTTP/2 另有 stream ID；方法和路径不可从加密 TLS 猜测 | HTTP/1、HTTP/2 等已启用解析器；请求响应配对注明完整性 |
| DNS | query name/type、rcode、answers、TTL | DNS 事务及 nested answers；响应与请求关联有来源 | 原生 DNS；DoH/DoT 未解密时不等价于明文 DNS |
| TLS／QUIC | SNI、版本、ALPN、证书摘要、指纹、QUIC 元数据 | 仅可见握手／实际输出字段；ECH 隐藏值标不可见 | 原生可见部分；明文需要已授权的解密条件 |
| 文件／远程服务 | 文件名、类型、大小、hash；SSH、SMB、RDP、FTP、SMTP 等协议元数据 | 按实际启用的 EVE 输出和解析覆盖登记，秘密字段不默认索引 | 固定制品所带协议解析器及字段；不保证每协议每版本解密 |
| 帧／时间 | `frame.len/cap_len/time/time_epoch`、接口、方向、抓包位置 | 仅精确包记录提供 frame 别名；告警发生时间使用 `event_time` | 原生捕获元数据；原时间分辨率单独展示 |
| 平台业务 | 严重度、SID、规则包、研判、处置、组织、资产组、证据状态 | 平台权威与 `alert-search` 投影 | 不直接加入原生过滤器；先确定授权证据范围再提交报文条件 |

协议支持按“元数据解析、全文可见、会话重组、对象提取、字段可检索”分别显示，不能只列一个支持协议名称。HTTP/3、工业协议、数据库协议等以锁定 TShark 字段目录扩展原生取证；需要长期事件检索时先定义规范化 schema 和容量，再启用索引。字段自动补全来自版本化注册表，不能让前端硬编码一个永不过期的协议名单。[Wireshark 字段目录](https://www.wireshark.org/docs/dfref/)、[Frame 字段](https://www.wireshark.org/docs/dfref/f/frame.html)

### 3.2 字段注册表

每个条目至少包括 `field_id`、canonical path、显示名、类型、地址族／单位、单值或多值、occurrence 语义、可用数据集、映射来源、权限级别、支持运算符、索引方式、最大可索引长度、完整性条件、别名、引擎版本区间和废弃状态。协议别名包含协议守卫；例如 `tcp.port` 不能命中 UDP 的 443 端口。

原生目录由构建时 `tshark -G fields`／`-G protocols` 获取并附摘要，与发布制品一起签名。它表示解析器认识字段，不证明客户捕获到了字段。事件注册表由平台维护并映射到经过验证的原生交集；别名变更不能静默修改保存查询的含义，升级时给出兼容性诊断。

## 4. MAC、VLAN、隧道与资产关联

Suricata 使用 `eve-log.ethernet: yes` 输出可用的 Ethernet 信息。必须核对实际发布配置；默认配置未启用不能承诺历史 EVE 自带 MAC。对于 `pkt_src=stream (flow timeout)`，官方说明输出可能来自流中首个具有 Ethernet 头的包；平台记录 `source_basis=flow_first_packet`，不得当成当前告警触发帧的地址。[Suricata Ethernet 输出边界](https://docs.suricata.io/en/suricata-8.0.7/output/eve/eve-json-output.html)

ECS `source.mac`、`destination.mac` 按字节规范化，可使用大写连字符形式；输入支持常见冒号、连字符和点分形式，比较基于六个字节。EUI-64 单独类型，不截成六字节。原字符串和标准化版本保留。只有能对齐事件 source/destination 角色时才填这两个扁平字段；否则保存链路观测数组并显示来源，不猜测角色。[ECS MAC 字段](https://www.elastic.co/docs/reference/ecs/ecs-source)

`starbeacon.link_observations[]` 包含 `layer_index`、`src_mac`、`dst_mac`、`ethertype`、`vlan_stack[]`、`source_basis`、`packet_ref`；VLAN 元素含层序号、VID、PCP、DEI 和来源。QinQ 保留顺序，不能只留下一个无顺序的 VLAN ID 集合。VLAN offload 元数据与帧内标签注明来源；如为展示构造恢复 VLAN 头，它属于派生帧，原始捕获字节保持不变。

MAC 只说明观测链路的发方／收方，跨路由器通常是下一跳；虚拟化、随机化、代理 ARP、MAC 漂移及重复地址会破坏“一个 MAC 等于一台终端”的假设。关联键包含租户、站点、网络命名空间、VLAN/VNI/VRF、接口与有效时间；ARP/NDP/DHCP、CMDB 和终端数据形成带来源与置信度的关系。MAC/OUI 不是资产唯一主键，也不证明产品、操作系统或人员身份。

外层隧道五元组、内层业务五元组、NAT 前后元组分别保存；IPv6 link-local 地址附接口／zone scope。同一地址在不同网络域不能合并。原生 `ip.addr` 可匹配多个内外层，而事件 `source.ip` 仅表示所选业务层，界面必须标识这一差异。大规模跨探针关联仍需时间窗、观测位置及 NAT 证据，不以 Community ID 或包内容 hash 独自确认同一会话。

## 5. 时间、入站与出站语义

### 5.1 时间字段

| 字段 | 含义 | 无法取得时的处理 |
| --- | --- | --- |
| `starbeacon.capture.captured_at` | 此捕获点记录该包的时间 | null + 原因；不能以文件修改时间补值 |
| `starbeacon.capture.rx_at` | 在明确接收观测点得到的 RX 时间 | 普通文件没有额外 RX 证据时不补造 |
| `starbeacon.capture.tx_at` | 在明确发送观测点得到的 TX 时间 | 单臂旁路通常不可知 |
| `starbeacon.capture.rx_tx_correlation_id` | 证明同一报文或受定义的转换报文在 RX/TX 两点关联的引用 | 没有对应关系则不能计算穿越时延 |
| `event_time` | Suricata／源记录定义的事件发生时间 | 保留源语义和时钟质量 |
| `observed_at/received_at/indexed_at` | 代理读取、平台接收、索引写入时间 | 沿用[接口契约](接口与数据契约.md)，不改名为入站／出站 |
| `starbeacon.flow.inbound.first_seen_at/last_seen_at` | 以指定保护域为参照，入站方向首／末次实际观测 | 没见到该方向为未知，不能套整条流的 start/end |
| `starbeacon.flow.outbound.first_seen_at/last_seen_at` | 同一参照下出站方向首／末次实际观测 | 不代表源主机真实发出和目的主机收到时间 |
| 请求开始、请求完成、响应开始、响应完成 | 对指定事务的可观察时刻 | 缺请求／响应／重组上下文分别标明 |

入站／出站流字段还包含 `packets`、`bytes`，并与 `direction_basis`、`direction_policy_revision`、统计窗口和计数层一起保存。to-server/to-client、client/server、source/destination、网络域入站/出站、探针 RX/TX 是五套不同概念。内部到内部标为 lateral，无法确定域关系标 unknown；不要强行二分。

单臂 SPAN 探针只知道它接收到镜像副本的接口。ECS 对这种观测点要求使用 `observer.ingress`，不能借目的安全域伪造 `observer.egress.interface`。实际串联设备、带可信方向元数据的捕获或有验证关联的双点观测才能填 egress/RX/TX；应保存观察点、采集方式和证据引用。[ECS observer 定义](https://www.elastic.co/docs/reference/ecs/ecs-observer)

Linux 可区分软件 RX、软件 TX、硬件时间戳等来源，设备与驱动能力不同；TX completion 也不必然等同实际线上发送时刻。平台默认提供观测时间和方向时间线，只有经过采集能力验证才显示收发时延。[Linux timestamping](https://www.kernel.org/doc/html/latest/networking/timestamping.html)

### 5.2 精度与时钟误差

每个捕获时间附 `timestamp_source`、`timestamp_resolution`、`clock_domain`、`clock_error_ns`、同步状态和可选校正信息。分辨率表示可表达的最小刻度，不表示准确率；微秒捕获值补九位小数仍不是纳秒测量。原始时间不可被平台校时直接覆盖，校正时间作为可重建派生视图。跨探针排序在误差重叠时显示“先后无法确定”，不生成负网络时延或伪精确因果链。[Wireshark 时间戳说明](https://www.wireshark.org/docs/wsug_html_chunked/ChAdvTimestamps.html)

API 时间以 RFC 3339 纳秒字符串或 `seconds` 十进制字符串 + `nanos` 整数传输，epoch 纳秒和大文件 offset 不使用 JavaScript Number。PCAPNG 还保留原始 ticks、基数／指数分辨率、接口 offset；二进制刻度转换出现舍入时记录，不丢掉原文件。ES `date_nanos` 只用于需要此精度且处于可表示范围的索引字段；异常历史时间留原值并进入质量提示，不静默归零。普通告警毫秒索引不能用于证明两包纳秒级先后。

协议识别、日志、在线规则、文件提取及加密可见性的生产矩阵见[协议覆盖与文件分析设计](协议覆盖与文件分析设计.md)；采集丢包、重组与检测限额见[旁路采集与检测质量设计](旁路采集与检测质量设计.md)。

## 6. 捕获文件与数据包证据契约

授权监测范围的全量原包、告警会话归档及持久派生结果默认均保留 180 天，支持用户分类设置；冷热分层不提前删除未命中流量。详细期限锚点、目录、跨片提升与握手验收见[PCAP 留存与会话完整性设计](PCAP留存与会话完整性设计.md)。

### 6.1 标识和定位

单包稳定 ID 由原捕获对象 ID、对象版本、section、接口与原包序号生成，不以任务中的 `frame.number` 或报文字节 hash 单独生成。重复包是可能真实发生的观测，不能因 hash 一样就从证据文件删除。

`starbeacon.capture` 最少提供 `capture_id`、`packet_id`、`section_id`、`interface_id`、`packet_ordinal`、`record_offset`、`data_offset`、`captured_length`、`original_length`、`linktype`、`captured_at`、时间质量和捕获质量。offset 的单位是字节，并标明相对于原始未压缩文件还是独立压缩块；大整数在 JSON 中用字符串。目录的 SHA-256、对象版本、块校验和和保留状态决定证据可用性。

原始 PCAP/PCAPNG、包 offset sidecar 和派生解析结果放对象存储；PG 只保存任务、对象清单、授权与保全关系，ES 保存有限证据目录和可选包摘要（默认 180 天，按类别配置）。不能为支持任意原生过滤器而默认把所有包、所有协议树字段永久写入 ES。包摘要索引是单独的容量档，按捕获 PPS、平均元数据大小、留存和副本核算。

### 6.2 PCAPNG 和捕获异常

PCAPNG 可以含多个 section、多个接口、不同 linktype、不同时间分辨率及无时间戳记录。接口 ID 只在对应 section 有效。读取器必须显式支持混合 linktype，遇到不支持的类型或块版本产生可见错误／跳过计数，不能采用静默丢弃不同链路类型的配置。[PCAPNG 格式草案](https://datatracker.ietf.org/doc/draft-ietf-opsawg-pcapng/)、[gopacket pcapgo 选项](https://pkg.go.dev/github.com/gopacket/gopacket/pcapgo)

捕获长度小于原长度标 snaplen 截断；FCS 是否存在、以太网 padding、VLAN offload、GRO/LRO/TSO、checksum offload 和镜像重复分别记录。读取到“校验和错误”不能自动解释为线上报文损坏。接口丢包计数、环形覆盖、文件损坏、重组缺口、采样和解码失败是不同质量项；缺少丢包统计不等于零丢包。[gopacket CaptureInfo](https://pkg.go.dev/github.com/gopacket/gopacket#CaptureInfo)

## 7. 原生分析作业

### 7.1 创建与执行

1. 用户选择告警关联证据、案件证据、捕获时间／网络域或上传文件，并取得文件级及字段级取证授权。冻结对象 ID、版本、摘要、实际时间范围和捕获缺口；客户端不提交任意文件路径或 S3 key。共享对象先提取授权包集合形成受控输入，再交给原生解析器；不能读取所有隐藏流后仅在输出时过滤。
2. 校验过滤表达式、字段字典、解析器配置和预算，估算需要读取的对象字节、暂存空间与排队时间。无 PCAP、已过期、无权限、待上传和上传不完整分别展示。
3. 获取作业期对象读取租约或保留保护，防止分析中途生命周期删除。普通读取租约不自动变成长期案件保全；法律保全仍走存储侧确认流程。租户超额或无法获得保护时不开始读取。
4. Worker 在租户隔离的作业目录中下载并校验输入，准备可 seek 的只读文件。保留原文件，并建立分析输入帧号到原包 ID 的映射；合并文件的接口、时间精度与顺序变化可追溯。
5. 按服务端固定参数运行 TShark 的两遍解析 `-2`，然后使用 `-Y` 应用显示过滤；`-n` 关闭名称解析。不能把需要前后文的输入直接改为不可 seek 的管道，也不能在首遍用仅保留命中包的过滤丢弃重组依赖。[TShark 两遍分析](https://www.wireshark.org/docs/man-pages/tshark.html)
6. 输出形成受限包列表、协议树、会话及对象制品；重复字段和协议层顺序必须保留。协议树优先采用流式 PDML 适配，不将重复 JSON key 读入普通 map 后覆盖。产物附输入摘要、引擎和 profile、表达式摘要、输出完整性、截止水位及错误。
7. 结果写入对象存储并按任务分页返回，默认结果留存 180 天，可配置延期或案件保全。到期删除派生结果不代表删除原始证据；原始证据到期后，结果仍展示原始引用不可用的状态。

作业状态为 `queued → preparing → running → completed`，分支为 `partial`、`failed`、`cancelled`、`expired`。作业中断后不会把已经输出的部分包当完整命中集合；续跑需要能证明输入和 profile 不变，否则生成新任务。

原始字节采用独立业务权限：同租户流量中，两个受管端都必须处于请求者授权范围，外部端按显式外联证据策略处理。只满足单端范围时默认仅提供允许的摘要／脱敏视图；完整载荷可能包含另一端的数据，不能因一条告警可见就自动放行。包集合授权 grant 绑定对象 version/hash、原包范围、授权版本和到期时间；重组上下文和对象提取亦不得越过这个集合。

按流授权的下载应生成只含授权包的派生 PCAP，并附原包映射及裁剪完整性。仅当原对象包含的所有数据范围都已授权时，才允许下载整个原始切片。需要即时撤权的字节读取、流式下载和导出均经网关逐次验证；已签发的直达 S3 URL 在过期前通常仍可能可用，不能宣传其会随着平台权限修改即时失效。短时签名 URL 只用于明确接受这一有效期边界且已经完整授权的对象。

### 7.2 范围完整性与重组

时间窗或文件切片只是调查范围，不自动包含完整会话。任务分别声明 `scope_requested`、`scope_materialized`、`context_before/after` 和 `reassembly_coverage`。遇到跨切片 TCP、乱序、重传、IPv4/IPv6 分片、协议升级、HTTP/2 多路复用等情况，按证据目录补取授权上下文；无法补齐时保留部分结果与原因。不能先按五元组／端口过度裁剪，导致隧道、ICMP 引用或重组数据丢失，再宣称过滤完整。

TCP stream ID、相对 sequence number、请求响应 frame 引用只对当前 profile 与输入集合有效。工作台同时提供原始序号（如原生 `tcp.seq_raw`）、相对序号及其解释；以流视图重组出的字节不是原始帧，重复发送的原始包仍可单独查看。任务范围变化或 Decode As 变化需要重新分析。

导出默认采用完整会话模式，对 TCP 校验实际 SYN、SYN-ACK、ACK 及后续通信范围，具体例外按会话完整性契约；未完成或有缺口不降级后仍称完整。用户可另选匹配包、匹配包及受验证的重组依赖、完整授权范围三类取证范围，这些范围名本身不证明会话完整。每个导出清单说明选择规则、包数、上下文和是否可独立重组；不能给仅匹配包的裁剪文件贴“完整会话”标签。TShark 输出是否自动包含某种依赖，以锁版实测结果为准，不能仅凭参数名称作保证。

### 7.3 隔离、解密与配额

原生解析器以非 root 身份、只读根文件系统、独立临时目录和无出站网络运行；限制进程数、CPU、内存、输入解压、写盘与输出。使用 Go `exec.CommandContext` 和固定参数数组，不经 shell；表达式作为一个参数传递，不允许用户注入其他选项。禁止继承宿主机 Wireshark 配置、Lua、外部捕获器、个人插件及无关密钥。取消必须终止子进程组并清理租约和暂存空间。

HTTPS 解密只接受客户明确授权的离线 keylog／密钥引用或已授权解密设备产生的证据。秘密按租户、案件、输入范围和有效期隔离，作业期注入、任务后销毁暂存；访问和解密产物有独立审计与权限。秘密不进入检索、模型、普通诊断包和通用缓存。持有证书私钥不保证能解密现代 TLS，会话缺包或密钥不匹配显示无法解密，不假装得到 HTTP 请求。

| 资源 | 默认工程起点 | 超限处理 |
| --- | --- | --- |
| 原生任务并发 | 每租户 2 个，全局按独立 Worker 池控制 | 公平排队，不能抢占告警索引保底资源 |
| 单任务物化输入 | 2 GiB、1,000 万包、1 小时时窗，三项分别限制 | 提交前展示拆分／授权大作业选项；拆分可能损失重组须提示 |
| 原生任务资源 | 2 vCPU、4 GiB 内存、10 分钟运行时限 | 终止并标 partial/failed，附具体原因 |
| 临时磁盘 | 按输入、解压、两遍解析及导出预留，默认上限 8 GiB | 无预留不启动，不争满节点磁盘 |
| 结果 | 默认最多 100 万包摘要、100 MiB 协议树／其他文本产物 | 保留水位和截断状态；详情按包再解析或取缓存 |
| 表达式 | 默认 8 KiB，正则模式最长 256 字符 | 超限编译拒绝；引擎资源限制仍必须保留 |

上述值用于隔离和容量压测，不表示 2 GiB 必在 10 分钟内完成。任务成本取决于协议、压缩、重组、正则与硬件。配额可按租户档位调整，但有全局硬上限；限额变化记录审计和 profile 版本。

## 8. 数据包工作台

页面提供包列表、会话、协议树、双向流、请求响应、对象提取、HEX／文本和时间线，所有视图共享选中包与证据引用。包列表默认列：包序号、捕获时间、相对时间、接口、方向、源／目的 MAC、源／目的 IP、端口、协议、捕获长度／原长度、摘要、解析／捕获异常；按需要显示 VLAN、隧道层、TCP flags、RTT 和攻击关联。

时间线可切换绝对时间、相对首包时间、相邻包间隔、同方向间隔。排序固定时间及原始定位作为 tie-breaker；相同时间戳不等于同时到达。方向时间线显示入站／出站的首末包、请求响应阶段、捕获空窗和时钟误差。没有 TX 证据的包，“出站时间”显示未采集，并解释当前是旁路观测。

HEX 保留[运营与集成设计](运营与集成设计.md)规定的行宽、字节窗口、严格 UTF-8 与派生解码链。协议树节点返回 `data_source_id`、`data_source_kind`、`byte_ranges` 与 `range_status`；原帧、重组数据、解密数据和解压数据各自有偏移空间。计算字段可能没有原始字节，重组字段可能对应多个范围，不能仅依靠 PDML 的 pos/size 就为所有字段生成原帧高亮。

原生字符串切片按解析后字符位置，原始字节切片按字节位置；HEX 面板永远按字节，必须分别标注。整数查看器允许显式选择 16/32/64 位、signed/unsigned、大端／小端；它是派生解释，不修改字段值。多字节整数不能靠省略字节序自动转换成原始 byte array。偏移越界、跨 UTF-8 字符及跨包映射均显示错误／边界，复制时注明复制的是原字节还是派生文本。

文件／对象提取显示协议、原始名称、实际提取长度、声明长度、MIME 推断来源、SHA-256、重组完整性与关联包。输出名称由平台生成，原文件名只作转义元数据；文件不执行、不自动渲染 HTML、不自动联机取内容。解密、对象提取、批量导出和原始字节下载分别授权，不能因拥有告警列表权限就获得整个共享捕获对象。

| `GET /api/v1/packet-analysis/jobs/{id}/packets` | 不可变结果分页，返回覆盖、截断、包 ID 和任务水位 |
| `GET /api/v1/packet-analysis/jobs/{id}/packets/{packet_id}` | 取得协议树、字节来源及原包映射；再次检查授权 |
| `POST /api/v1/packet-analysis/jobs/{id}/cancel` | 取消执行、停止子进程、撤销临时读取租约 |
| `POST /api/v1/packet-analysis/jobs/{id}/exports` | 导出模式、对象范围、依赖策略和保留期；生成独立受审计任务 |

请求包含 `mode`、`language`、`language_version`、`dataset`、`field_registry_version`、表达式或 AST、时间范围和 `coverage_policy`。原生请求另含 `evidence_refs`、`parser_profile_id`、上下文范围及预算档；tenant、权限版本和实际硬配额由服务端注入。用户不能通过表达式选择任意 ES 索引或覆盖权限过滤。

事件查询保持 PIT + `search_after`，总数、聚合、导出和列表使用同一 AST 与投影代次。原生任务结果使用不可变任务产物游标，绑定任务、产物摘要、权限版本与有效期，不伪装成 ES PIT。授权收紧使旧游标和下载失效；缓存键覆盖租户、主体范围、查询、profile、输入摘要与数据代次。

保存查询支持个人／组织共享、名称、用途、所有者、版本、默认窗口与参数 schema；参数是类型化值，不做字符串宏替换。共享不授予数据权限。自然语言转查询只生成可解释草案，执行前经过相同字段、成本和权限检查；模型不能直接提交原始 ES DSL、TShark 命令或任意脚本。

## 10. 组件复用与验收

平台 Go 层使用维护中的 `github.com/gopacket/gopacket` 读取基础包元数据与 PCAP/PCAPNG，复用 `pcapgo`；复杂应用协议、重组与完整显示过滤器交给独立 TShark，不在 Go 中重复实现全套 dissector。事件语言可使用 `github.com/alecthomas/participle/v2` 构造受限语法与类型化 AST；该库只解决语法解析，字段映射、多值语义、权限和成本仍由平台显式实现。标准库 `net/netip`、`net.ParseMAC`、`encoding/binary`、`encoding/hex`、`unicode/utf8`、`encoding/xml` 和 `os/exec` 分别承担地址、字节、文本、PDML 和受限进程调用。依赖版本与许可纳入[依赖版本与部署清单](依赖版本与部署清单.md)，不用无人维护的旧 fork 仅为减少少量适配工作。

必需验收集：

1. 单值、多值、重复值、空序列、部分字段、unknown、布尔 false 的存在测试，以及所有比较／否定真值表；覆盖范围集合的跨端口误命中反例。
2. IPv4/IPv6、IPv4-mapped IPv6、link-local scope、MAC 多格式、QinQ、多层隧道、NAT、相同私网地址跨网络域；所有别名有原字段和协议守卫。
3. GET/POST、URI 大小写／编码、同会话多个事务、HTTP/2 多流、DNS 多 answer 同元素条件；TLS/ECH/加密 DNS 不产生虚假明文。
4. 普通字符串、Unicode、无效 UTF-8、raw string、原生 PCRE2、切片、负偏移、层选择、大小端；事件模式对不支持语法给出稳定错误。
5. 固定 TShark 4.6.9 黄金 PCAP 与平台完整观测交集逐条比对；官方测试只作为参考，不能写成已通过本平台验证。版本升级执行字段字典差异和固定样本回归。
6. 混合 linktype、多 section、不同时间分辨率、无时间戳、snaplen、VLAN offload、FCS、checksum offload、损坏块、超大包和压缩炸弹；任何跳过均有计数。
7. 跨切片、乱序／重传、分片、单向捕获、镜像重复、丢包、时钟回拨／漂移；原始证据与派生重组有可追溯定位。
8. 运行中保留期到期、对象缺失、输入校验失败、Worker 退出、取消、输出满和重组超内存；恢复结果不冒充完整扫描。
9. 跨租户 evidence ID、MAC／网段、缓存、游标、导出与 keylog 越权；路径／参数／HTML 注入均不得绕过边界。
10. 单探针与 200+ 探针输入下同时执行告警检索、原生解析、导出和报告，测量吞吐、P95/P99、排队、临时盘和索引放大；按实测调整配额，不能让取证任务拖慢告警接收与自动响应。

单独核算 `包目录 PPS × 平均目录字节 × 留存`、`原生并发 × 峰值重组内存`、输入下载与临时盘、解析树输出、派生结果留存和跨对象上下文读取放大。日常检索使用结构化索引，大规模原始字节分析使用可解释、可取消的异步任务；两者共同覆盖运营和深度取证需求。
