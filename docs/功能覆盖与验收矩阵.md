# 星烽 StarBeacon 功能覆盖与验收矩阵

核对日期：2026-09-30。本文将 107 项网络检测、资产与风险、威胁运营、响应和平台治理需求转换为可分配、可测试的验收条目。这里的“已有落点”指文档设计覆盖，不代表代码已经实现、设备已经适配或性能已经通过验证。

## 1. 使用范围与交付约束

“完整态势感知”以能力目录、数据来源、部署范围和验收结果共同定义。平台应具备主流安全运营的完整工作路径；终端、身份、漏洞、云与工业协议等信息仍依赖相应数据源和权限，不能通过网络旁路采集推断出没有观察到的事实。

| 标记 | 含义 | 交付要求 |
| --- | --- | --- |
| 内置 | StarBeacon 自有页面、业务模型、查询与工作流 | 默认交付；没有数据时显示接入条件和覆盖缺口 |
| 连接器 | 借助外部系统获得数据或执行动作 | 声明产品／接口版本、许可、权限、速率、幂等和维护责任；逐项验收 |
| 条件能力 | 需要特定观测位置、明文、完整抓包、训练样本或设备功能 | 界面显示当前是否具备条件；不具备时不输出确定结论 |
| P0 | 试点所需基础闭环 | 网络告警、可用证据、基础资产、调查、响应与审计可贯通 |
| P1 | 完整生产交付 | 多源接入、基础关联与狩猎、情报生命周期、弱点治理、案件协作、剧本、多租户、文件静态分析与至少一个动态沙箱连接器均有验收记录 |
| P2 | 可独立评估的专业扩展 | 复杂自学习模型、专用行业内容、深层知识图谱；不代替 P1 基础能力 |

P1 的“完整”不要求每个客户购买全部外部产品，但要求平台具备对应对象、接入与使用流程，能区分未接入、无权限、过期、不支持与确实没有发现。采购和验收范围按本矩阵逐项标明“适用／条件不具备／明确排除”，不能把所有条件能力都算成默认已具备。

详细契约分工：产品入口见[产品设计](产品设计.md)，检索与证据见[运营与集成设计](运营与集成设计.md)，检测签名见[规则管理设计](规则管理设计.md)，计量与联动见[应用识别与响应性能设计](应用识别与响应性能设计.md)，多源接入和业务治理见[安全运营与数据治理设计](安全运营与数据治理设计.md)，存储和服务职责见[架构设计](架构设计.md)与[接口与数据契约](接口与数据契约.md)。具体查询语法与数据包字段以对应详细设计为准。

## 2. 数据接入与质量

网络、主机、设备日志的统一调查具有明确的数据依赖。Security Onion 官方设计把网络元数据、PCAP、主机和外部日志连接到告警、狩猎与案件流程；这说明“可以输出 Syslog”不足以覆盖多源安全运营。[Security Onion 数据与调查路径](https://docs.securityonion.net/en/3/main/introduction/)

| 需求 ID | 页面与用户流程 | 输入及字段依赖 | 已有落点与具体契约要求 | 能力／阶段 | 验收与容量边界／责任 |
| --- | --- | --- | --- | --- | --- |
| SB-DAT-001 | 数据源中心：创建、验证、启停、移交数据源 | source_id、tenant_id、站点、网络域、来源类型、认证身份、责任人、schema | 架构有 gRPC 探针接入；多源注册要与探针区分，正文中的 tenant 不可覆盖认证归属 | 内置／P0–P1 | 伪造租户字段仍进入注册租户或被拒收；启停可审计；每源有字节与 EPS 配额／数据、平台 |
| SB-DAT-002 | 数据源中心：接收 Syslog 与设备事件 | RFC 5424／3164、TLS/TCP、可选 UDP、peer 身份、设备时间／时区、received_at | 运营已有出站 Syslog；入站需独立监听、客户侧中继、来源绑定、分帧及持久缓冲 | 内置＋连接器／P1 | UDP 明示可能丢失；共享 NAT 源 IP 不能唯一确定租户；无时区日期保留推定标记／数据、集成 |
| SB-DAT-003 | 数据源中心：API、文件、对象和批次导入 | cursor、etag／version、分页、文件代次与偏移、source_sequence、batch_id | 复用 WAL、队列与隔离重放；源游标仅在持久接收后推进，导入失败可继续 | 内置＋连接器／P1 | API 翻页变化、文件轮转、断点续传不跳行；无上游 ID 的相同正文不能直接 hash 去重／数据 |
| SB-DAT-004 | 日志工作台：跨终端、身份、云和应用调查 | 终端资产 ID、用户／会话 ID、进程、文件、登录结果、云账号／资源／审计事件 | 产品已有后续信号边界；需提供标准化字段、受控来源目录和字段覆盖页 | 连接器／P1 | 每类至少一份授权样本与解析契约；缺终端信号不显示“主机未失陷”；数据源版本单独验收／集成、检测 |
| SB-DAT-005 | 流量接入：无 PCAP 网络的流量概览 | NetFlow／IPFIX／sFlow、exporter、observation_domain、template、采样率与采样方式 | 应用分析已有计量域；流记录必须保留计数口径，不与全包流量直接叠加 | 连接器＋条件／P1 | 模板过期、计数器复位、采样变化可见；抽样估算不显示精确流量／数据、采集 |
| SB-DAT-006 | 解析器管理：样例、字段映射、测试、灰度、回退 | parser_id/version、原文引用、字段类型、时间解析、异常样本、脱敏规则 | ES 已有严格映射和隔离；补齐解析器版本与失败原因、回放任务和受影响源范围 | 内置／P1 | 坏字段隔离且能重放；升级重解析产生修订，不覆盖原始事实；不能动态执行任意上传代码／数据 |
| SB-DAT-007 | 数据质量：缺失、迟到、重复、乱序、漂移 | 序列水位、源时间、接收时间、解析成功率、丢包、必需字段覆盖 | 健康页已有链路水位；增加每数据源字段缺失率与时钟可信等级 | 内置／P0–P1 | 注入乱序、重传与时钟偏移后，统计可解释；存在缺口时“无事件”不等于“无风险”／数据、质量 |
| SB-DAT-008 | 重放与回溯：选源、时段、解析／规则版本后预览 | 不可变源定位、重放 run_id、schema、检测版本、资源预算 | 已有消息重放与索引幂等；业务重分析与传输重试应分离 | 内置／P1 | 重放不重复封禁、不重复通知、不改原始告警 ID；默认影子结果，授权后才能变更业务状态／数据、检测 |

入站接收与出站转发必须有不同配置对象、权限、队列和页面状态。通用日志的流量不能无限占用原始安全告警的保底接收能力；无法继续持久接收时暴露拒收、暂停或丢失区间，不能默默按内容丢弃。

## 4. 漏洞、弱点与暴露治理

Wazuh 的漏洞能力依赖终端软件清单与漏洞信息的匹配，安全配置评估依赖端点检查；这类事实不能由一次网络告警代替。[漏洞检测机制](https://documentation.wazuh.com/current/user-manual/capabilities/vulnerability-detection/index.html)、[安全配置评估](https://documentation.wazuh.com/current/user-manual/capabilities/sec-config-assessment/index.html)

| 需求 ID | 页面与用户流程 | 输入及字段依赖 | 已有落点与具体契约要求 | 能力／阶段 | 验收与容量边界／责任 |
| --- | --- | --- | --- | --- | --- |
| SB-EXP-001 | 风险中心：接入扫描结果与软件清单 | scanner/source、scan_id、asset/service、组件／版本、finding ID、证据、扫描时间 | 产品计划接入扫描器；要求资产匹配、同源幂等、跨源并存及过期状态 | 内置＋连接器／P1 | 同 CVE 不跨资产合并；banner 推测、版本匹配和验证证据分级；扫描覆盖不足单列／集成、平台 |
| SB-EXP-002 | 扫描任务：申请、范围预览、调度、取消与结果回收 | 授权网段／资产快照、扫描策略、时窗、速率、外部任务 ID、禁止范围 | 使用外部扫描器；平台不自研扫描引擎，不默认开启主动扫描 | 连接器＋条件／P1 | 扫描器确认范围和授权后启动；工控、关键业务有禁扫约束；取消与设备实际停止分开／集成、响应 |
| SB-EXP-003 | 漏洞优先级：按业务影响与利用证据排序 | CVE/CWE、CVSS 版本／向量、KEV、EPSS 日期／概率、暴露、资产重要性 | 资产风险有可解释评分；漏洞页补齐评分来源、版本、缺失与过期 | 内置＋连接器／P1 | EPSS 与百分位分列；不把 EPSS 当本资产被攻陷概率；每分量可解释、未知不填零／检测、平台 |
| SB-EXP-004 | 整改闭环：分派、期限、豁免、复测、关闭、重开 | finding status、owner、due_at、exception expiry、修复证据、retest_run | 已有事件任务可复用；弱点需独立生命周期，不把工单关闭视为漏洞消失 | 内置／P1 | 外部复测成功后才验证修复；扫描失败／资产失联不关闭漏洞；豁免到期回到待处理／平台、质量 |
| SB-EXP-005 | 配置与弱口令风险：查看、认领、修复 | 外部基线检查、policy/check ID、expected/actual 摘要、授权弱口令检测结果 | 属外部检查结果管理；不保留明文密码，不从登录失败推断弱口令存在 | 连接器＋条件／P1 | 结果保留标准／策略版本和设备范围；生产试密必须由授权扫描器执行，告警不隐式触发／集成、平台 |
| SB-EXP-006 | 外部暴露与变更：认领公网资产、外连审批 | 授权域名／IP、外部测绘／扫描结果、DNS、证书、CMDB 与边界映射 | 资产和网段已有入口；补齐新暴露服务、未知外连和过期域名任务 | 内置＋连接器／P1 | 共享云 IP、CDN 和域名历史不直接等于企业所有权；接入数据来源和采样时间可见／资产、集成 |
| SB-EXP-007 | 风险态势：漏洞与攻击证据关联 | finding 资产／服务时间范围、CVE、规则元数据、攻击证据快照 | 已有资产告警画像；风险关联保留匹配方式和冲突，不修改原始事实 | 内置／P1 | 同名 CVE 告警不能证明漏洞存在或利用成功；列表显示“存在风险＋观察到尝试”的独立证据／检测 |

EPSS 描述漏洞在未来 30 天出现外部利用活动的预测，并不是环境完整风险评分；StarBeacon 使用它作为优先级输入之一。[FIRST EPSS 说明](https://www.first.org/epss/faq)

## 15. 生产验收的共同要求

功能负责人为每个适用需求维护 `requirement_id`、实现入口、支持版本、样例来源、正常／异常用例、资源配置、结果与证据链接。阶段验收不能只检查菜单存在。

1. **可观察性验收**：准备双向／单向、缺包、加密、地址复用、重叠网段、时钟偏差、来源身份冲突等样本；系统应正确给出未知与条件不足，而不是补造内容。
2. **跨域一致性验收**：从一个告警依次进入资产、情报、漏洞、会话、包、案件、动作和报告，租户、时间窗、身份、证据与状态语义保持一致。无法关联时展示具体原因。
3. **真实性验收**：来源事实、规则匹配、模型推断、人工确认、设备回执、效果验证具有独立类别；重放、补录、迟到和修订都有可追溯身份。
4. **隔离与恢复验收**：断网重传、队列积压、PG／ES／对象局部故障、Worker 重启和执行器失联，不得造成跨租户泄漏、原始事实静默丢失或重复封禁。已授权撤销任务独立恢复。
5. **效果验收**：检测内容和 AI 使用代表性正负样本、实际数据源及业务场景。披露精确率、召回率、拒答率、样本量和数据缺口；不使用第三方宣传值作为本平台实测。
6. **容量验收**：按全量告警、协议日志、外部日志、全量 PCAP 与目录、应用聚合、关联状态、弱点快照、审计、文件样本／分析制品和备份分别计算流量、180 天默认留存及副本成本。1–200 个探针只是管理数量，不能替代 bps、pps、EPS、活跃会话与查询并发的约束。
7. **体验验收**：中文名称一致、权限提示不泄漏对象存在性、空缺不显示为零、异步作业可取消、部分成功有明细、状态能下钻依据；无须复制 IP 和时间在多个互不相干的页面中调查。

性能门槛沿用[实施与容量规划](实施与容量规划.md)及[应用识别与响应性能设计](应用识别与响应性能设计.md)的适用条件。增加日志源、包解析、关联规则或外部连接器时必须重算资源预算；文档中已有的吞吐和时延目标不自动覆盖所有扩展组合。
