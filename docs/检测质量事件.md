# 星烽 StarBeacon 检测质量事件

质量事件记录探针在某个统计区间观察到的检测限制、策略影响或观测中断。事件不代表逐条会话的检测覆盖，不能直接作为攻击成功或自动封禁的授权。实时快照的指标白名单、采样和缺测规则见[检测质量观测](检测质量观测.md)。

## 记录条件

平台只接收托管捕获进程的质量报告。报告须绑定引擎运行标识与实际配置 SHA-256，包含固定顺序的 25 项指标、合法的 uint64 十进制字符串、采样与读取时间，以及可按指标重新计算的四类区间结论。平台校验报告评估时间与接收时间；无效报告拒绝整次心跳，不更新健康状态或创建质量待办。外部 EVE、未提供原生样本的报告不创建质量事件。

| 事件类型 | 记录规则 | 业务含义 |
| --- | --- | --- |
| 检测区间存在限制 | 捕获损失、检查限制或告警溢出出现非零区间增量 | 列出的原生指标反映该区间存在限制 |
| 检测策略产生影响 | 仅策略层出现非零区间增量 | 规则抑制或旁路策略产生影响，不计为资源丢包 |
| 检测区间无法核对 | 计数复位、采样断档、样本过期或引擎非运行 | 无法继续使用原区间判断检测质量 |
| 原限制未再报告增量 | 同引擎的后续连续区间中，先前原因指标均明确报告零增量 | 只说明这些指标在该区间没有继续增长，不等于完整恢复 |
| 连续区间重新可观测 | 观测中断或运行代次变化后取得连续区间 | 可以继续核对统计，不证明补回丢包或恢复全部检测能力 |

平台以同一引擎、同一配置的相邻已接收原生快照累计值计算区间，并核对每项计数的原生观测复位水位；默认十秒心跳可能跨越多个五秒原生采样，不能仅采用最新五秒增量。比较以实际采样和读取时间为准；超过二十秒、读取时钟回退或计数下降不计算连续增量，缺测不补零。首次接收尚无平台水位时保留探针提供的有效区间，不能恢复此前未上报的窗口。重复同一原生样本不建立零增量区间，也不清除先前限制。复位水位随原生累计下降保持，不因后续五秒恢复增长而清除；即使接收端累计值已超过复位前，也不能把该区间算为连续增量。同一运行身份下水位回退拒绝整次心跳。旧报告缺少完整水位时只使用报告原生区间，不授予跨心跳连续性。PG 仅保存每个注册代次的最后原生快照作为水位。

相同引擎、配置、事件类型与原因集合采用同一信号指纹去重。重复心跳不重复创建事件；同一非静默信号持续至少 15 分钟时可创建持续状态提醒。提醒依赖有效心跳，不保证离线探针仍能定时产生事件。新的非零原因会形成新信号；仅首次样本或缺少原限制指标时不创建清除结论。当前游标保存最后发出的事件关联与当前观测水位，两者的引擎身份独立保存，避免重启后的基线覆盖先前事件身份。

## 存储与重试

心跳更新、信号游标和事件待办在 PostgreSQL 同一租户事务内提交，避免已更新健康状态却丢失待办。PostgreSQL 保存去重状态和待索引材料；不可变历史事件以 Elasticsearch 的 `sb-context` 网络事件日分区为主存储，数据集为 `starbeacon.sensor_quality`。平台生成的派生区间记录与 Suricata 原始 EVE 使用独立数据集，派生内容不能冒充原始 EVE。

工作进程以 30 秒租约领取待办；任务最长处理 20 秒，同时最多执行 8 项。失败采用有上限的指数退避，丢失确认时使用相同不可变事件键重试。ES 确认写入或验证重复来源后，才向持久通知流发布摘要；摘要消息采用独立内部去重命名空间。通知队列受理后清除 PG 待办正文，保留有界状态；ES 成功、通知流尚未确认时继续重试。正文解码失败也保留已领取租约并进入退避，不通过回滚反复阻塞后续待办。

并发上限是整个质量调度器的上限。当前每轮对每个已列出的租户最多领取一项，轮间至少等待 200 毫秒；单租户突发积压需要多轮处理，不能由八项并发推定该租户的吞吐或时延。依赖中断时正文仍占用 PG 空间，直到成功或到期；专属积压容量限制与大规模故障恢复尚未验收。原生采样、心跳、索引和渠道受理属于不同等待阶段，质量事件的耗时不等同于普通攻击告警耗时。

历史事件沿用网络事件的保留策略，默认 180 天，由租户自定义。ES 保留期限按既有 UTC 日分区固化，不是每行精确到秒删除；修改策略不会改写既有分区期限。待办到期后不再补写历史，并清除暂存正文。当前注册的去重游标作为活动运行状态保留，历史注册游标到期后回收。质量事件关联的先前事件可能已过保留期，不因此修改当前事件或补造原始材料。

## 查询与页面

平台「探针管理 → 质量事件」提供时间、探针标识、注册代次和事件类型筛选，管理员与只读用户均只能读取当前会话租户数据。支持查询历史注册代次；探针名称修改不改写历史标识。接口为 `GET /api/v1/sensors/quality-events`，不接受自报租户、重复参数或未知参数。

时间范围为 2000—2100 年，开始包含、结束不包含，单次窗口不超过 31 天。每页固定 20 条，最多检索前 10,000 条；更早历史通过调整窗口查询。排序为平台记录时间倒序，同时间按事件标识升序；这属于固定时间窗口内的有界实时分页，不承诺 PIT 一致快照。索引超时、分片不完整、来源或精确数量不一致时返回错误，不展示部分结果。精确命中总数、原生累计值与增量均以字符串保留精度。

列表与详情分别呈现。详情保留当时的报告状态、采样时间、区间、运行身份、注册代次、原因和关联事件。历史详情不套用当前时钟的实时过期判断；实时质量弹窗仍按当前在线和运行状态判断。改变查询条件或登录身份会取消旧请求并清除结果，迟到结果不能进入另一租户会话。

事件异步索引；空列表不表示没有待办、没有检测限制或完整采集。该流程只保存平台实际收到的信号变化与持续提醒，不是逐采样历史，不恢复断连期间未上报的统计区间。

## 通知与回执

邮件、企业微信、钉钉、飞书、Webhook 和 Syslog 可显式订阅「检测质量事件」。历史渠道默认仍只订阅原有内容；质量订阅不按告警级别过滤。仅 Syslog 支持操作与登录审计日志，生产环境仍使用 Syslog TLS。

通知只包含事件标识、探针标识、平台记录时间、事件类型、正式标题与持续提醒标志，不外发原生计数、配置摘要、报文、IP 或原始 EVE。通知沿用既有加密连接配置、不可变渠道修订、静默、停用抑制、幂等投递和人工核实流程。推送日志以「检测质量事件」显示，记录数为 1、告警数为 0。渠道已受理不代表接收人已读；Syslog 传输已写入不代表日志服务器已落盘。

## 验收范围

协议测试覆盖并发心跳去重、身份与时间校验、同事务提交、租户隔离、租约和退避、重复索引与消息去重、冻结详情、明确订阅、投递计数及渠道回执。原生捕获用例使用独立 Docker 网卡的实际 HTTP 流量与 `noalert` 规则，核对原生统计经心跳、持久待办、ES 和通知渠道的闭环。执行结果与同源码证明见[测试覆盖与验收记录](测试覆盖与验收记录.md)。

仍需独立交付全部 pass／threshold 策略、驱动与解析错误映射、原包记录器和事件交付质量的统一关联、多网卡与持续大流量资格。协议夹具和一次原生链路测试不替代这些验收。
