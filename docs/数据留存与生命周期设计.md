# 星烽 StarBeacon 数据留存与生命周期设计

设计基准日：2026-09-30。**所有业务数据类别默认保留 180 天，支持用户按类别自定义时长。** 默认值不是只针对告警证据，也不是仅保存汇总；已经启用并形成的原始业务明细同样适用。冷热分层、采集范围、是否生成某类数据、保留时长和查询预算是不同配置，不能通过分层或降采样暗中缩短用户选择的留存。

## 1. 默认策略与配置入口

设置中心提供“数据留存”页面，按租户和数据类别显示继承来源、生效版本、保留天数、容量估算、当前最早可用时间、冷数据恢复状态、保全例外及清理水位。单用户部署使用同一模型，默认租户自动初始化为 180 天；集团管理只能在被授权的租户范围内修改。

| 数据类别 | 默认留存 | 权威存储与依赖 |
| --- | ---: | --- |
| 原始告警、标准化事实、当前检索投影、检测修订、研判 | 180 天 | ES；当前投影不得先于所服务事实过期 |
| 网络/协议/流量明细、外部安全日志、身份观察 | 180 天 | ES；只保存已启用的类别，未采集不能伪装为到期 |
| 原始 PCAP/PCAPNG、告警会话归档、包定位 sidecar | 180 天 | S3；最小证据目录至少随被引用对象保留 |
| 提取文件、静态/动态分析报告、文件行为证据 | 180 天 | 隔离 S3 + ES；同样受样本访问权限约束 |
| 操作、登录、访问、规则发布、权限及响应审计 | 180 天 | PG 权威/审计归档、ES 查询投影；归档仍须可检索或可恢复 |
| 通知投递/回执、Syslog 发送记录、接口调用业务日志 | 180 天 | PG/ES；高频 Syslog 用批次记录，不复制全部消息到 PG |
| 对话、工具记录、报告、调查笔记、导出与原生解析结果 | 180 天 | PG + S3/ES；权限收紧立即影响在线读取，不等待数据到期 |
| 已完成任务、动作与尝试、模型评测/调用业务记录 | 180 天 | PG + ES/S3；原文出域策略独立，不默认记录密钥/秘密 |
| 5 秒/分钟/小时/日产品统计、探针及平台运行历史 | 180 天 | ES 汇总、Prometheus 运维指标；汇总不替代仍在留存期的已启用明细 |
| 已失效情报、历史弱点/资产关系、配置与规则历史 | 180 天 | ES/PG/S3；仍被有效业务证据引用的版本必须保全或保存快照 |
| 恢复所需备份集、恢复目录与业务归档 | 180 天 | 独立故障域；备份容量、恢复速度和删除例外单独核算 |

未结束的案件、活动动作/撤销 journal、当前资产/用户/规则/租户配置是仍在使用的业务对象，不能因为创建满 180 天自动删除。结束/停用后才进入相应历史生命周期；有引用、保全或运行任务时记录延迟清理原因。恢复密钥、当前凭据和信任根按安全生命周期轮换，不随历史日志到期销毁仍需解密的密钥。

传输缓冲和短期安全机制不属于业务历史留存：NATS 重放窗口、本地 WAL/上传缓存、未完成 multipart、Redis 缓存、下载 token、登录 session、解密密钥注入、沙箱临时目录和 VM 快照复位各有运行 TTL。它们可以短于 180 天，但必须在业务持久副本可用后才按各自契约回收；不能依靠 72 小时消息队列冒充 180 天原始数据存储。

## 2. 策略契约

`retention_policy` 包含 `tenant_id`、`data_class`、`retention_days`（正整数，默认 180）、`anchor_kind`、`storage_class_plan`、`policy_revision`、`effective_at`、`history_apply_mode`、审批/操作者、容量估算版本与硬额度。`0` 不隐式表示永久保存或立即删除；关闭采集使用独立开关，永久保全使用具备范围和审查流程的 hold。

每条事实/对象在首次持久化时固化 `retention_anchor_at`、`expires_at` 与策略版本；重试、复制、重建索引、冷热迁移不重新起算。事件索引使用可信接收/原固定逻辑分区时钟，PCAP 使用可信捕获窗口（混合对象按最晚应保留的包计算），服务端审计使用记录时间，已完成任务使用完成时间；独立导出、分析报告和解析结果以该制品首次成功提交时间起算，保留原始来源时间，重试与普通归档复制不据此续期。异常源时钟保留原值和质量原因，以版本化策略确定可信锚点；不得使用未经验证的源时间无限续期。普通补传沿用既有锚点；已超期的历史导入通过显式导入策略重新定义允许保存期限。

在线访问目标按对象自身期限判断；物理分区清理可以因为桶边界、保全或备份粒度而晚于单条到期，但不得提前。界面区分已到期不可访问、待物理清理、受保护、冷存储待恢复、已销毁和销毁失败。用户查询 180 天并不意味着允许无预算同步扫描 180 天全部原包，长范围仍走可取消异步任务。

## 3. 变更与清理

策略继承顺序为平台默认 → 租户类别策略 → 经授权的专属数据范围策略；当前有效保全优先阻止删除。禁止普通请求正文任意覆盖 retention_days。修改时先计算存量对象、未来写入、预计成本、最早可用时间变化、活动任务及保全冲突；用户明确选择仅未来数据或重算存量。延长不能恢复已经删除的数据，缩短不能跳过影响预览。

ES 同池内不同期限不能仅套一个会误删长留存租户的索引策略。优先按少量留存档和隔离级别建池；记录级期限与整索引删除之间通过分区目录、保全迁移和受控清理作业协调，不能为每租户每天创建大量小分片。迟到/重放沿用稳定路由；删除栅栏和 tombstone 阻止历史重放重建已销毁事实。

PG 历史表按时间分区；删除前核对当前配置、活动任务、审计完整性与引用依赖。S3 清理包含对象版本、派生副本、sidecar 和未完成上传；仅删除可见 key 不等于所有版本已销毁。存储侧 Object Lock 与平台业务保全状态须一致；目录先失效、存储删除失败时保留可追踪结果，不能错误显示销毁成功。

冷热迁移只改变介质/存储级别，不更改 `expires_at`。恢复请求显示预计等待、费用和可用期；恢复缓存到期不删除冷存储权威对象。恢复备份前应用删除/授权变更清单，防止已销毁数据或已撤回权限复活；删除清单保留到所有可能包含旧数据的备份均不可恢复为止。

## 4. API 与验收

| API | 契约 |
| --- | --- |
| `GET /api/v1/retention-policies` | 返回授权范围的类别、继承、有效期、状态与版本 |
| `POST /api/v1/retention-policies/preview` | 按候选时长和存量处理方式估算影响、成本、保全冲突与不可恢复范围 |
| `PUT /api/v1/retention-policies/{id}` | 带 If-Match、预览摘要和幂等键；审计与策略发布同事务 |
| `GET /api/v1/retention-jobs/{id}` | 各存储清理/迁移结果、失败、重试与保护原因 |
| `POST /api/v1/evidence-restore-jobs` | 授权对象和范围、预算、恢复目的与结果有效期；不开放任意 bucket/key |

验收覆盖初始全部类别均为 180 天、分类自定义、缩短/延长与历史适用范围、过期边界、时钟异常、跨租户策略隔离、对象版本和保全冲突、重放复活、失败重试、目录一致性及备份恢复。容量按当前策略逐类估算；配置页面必须说明无法维持期限的容量/许可问题，不自动把 180 改为 7 或只保留汇总。具体容量见[实施与容量规划](实施与容量规划.md)。
