# 星烽 StarBeacon Go 依赖与发行交付

本文定义两个 Linux ZIP 中 Go 程序的依赖交付与校验范围。它不替代完整产品功能验收、真实设备联动、生产部署、性能测试或第三方商业组件的交付授权。实际执行记录见 [测试覆盖与验收记录](测试覆盖与验收记录.md)。

## 交付内容

平台包包含 `starbeacon`、`starbeacon-ingest`、`starbeacon-worker` 和 `starbeaconctl`；采集器包包含 `starbeacon-agent`。每个程序分别使用实际 Linux 架构的编译条件核对依赖，不直接把整个 `go.mod` 当作发行 SBOM。

| 路径 | 内容 |
| --- | --- |
| `bin/<程序>.buildinfo.txt` | 压缩前从实际程序读取的 Go 版本、模块版本、Go 校验和及构建条件；程序名称不包含临时目录 |
| `dependencies/<程序>.cdx.json` | CycloneDX 1.6 应用 SBOM，绑定发行版本、提交、实际压缩程序摘要、压缩前摘要、目标架构和 Go 运行时 |
| `dependencies/go.json` | 各程序的实际模块、已编译包及输入摘要、许可标识与原文摘要、SBOM 摘要及全部交付文件目录 |
| `dependencies/notices/` | 上游许可原文、版权通知，以及相应许可要求附带的依赖源码；保持上游原文语言 |
| `dependencies/go-runtime/` | 所用 Go 发行物的 `LICENSE` 和 `PATENTS` |
| `manifest.json` | 绑定项目、前端许可目录和 Go 依赖目录的摘要，以及程序、架构、工具链和 UPX 核验记录 |

实际依赖由 `go version -m`、相同目标条件下的 `go list -deps -json` 和应用 SBOM 三方核对。模块集合、版本、Go 校验和、程序身份或架构不一致即终止构建；依赖替换不在当前发行范围内。编译输入包含 Go、汇编、对象和嵌入文件的摘要。采集器目前通过共用角色组装包引用部分平台依赖，SBOM 如实保留这些实际依赖，不按产品名称删减。

## 工具与识别范围

构建使用 Go 1.26.8、[go-licenses v2.0.1](https://github.com/google/go-licenses/tree/v2.0.1) 和 [cyclonedx-gomod v1.12.0](https://github.com/CycloneDX/cyclonedx-gomod/tree/v1.12.0)。工具模块版本与 Go 校验和在执行前核对。`go-licenses` 负责识别、原文和需要附带的源码导出；CycloneDX 使用 `app` 模式和实际编译条件，包含 Go 标准运行时，保留自动识别的许可证据，不把自动检测改写成法律批准。

构建工具的 `GOROOT` 取自本次 `go env`，并与实际程序的工具链版本核对，避免跨编译工具携带的默认路径误判标准库。应用 SBOM 的上游工具要求能够识别 Git 提交；`--source-commit-file` 接收 `git cat-file commit <提交>` 的原始对象，先按 Git 对象规则核对提交摘要，再在独立临时源码副本中提供该真实对象。不会创建合成提交、修改工作区或用基础提交证明未提交内容。候选源码、实际构建输入和业务测试仍使用独立摘要绑定；正式发布须满足干净候选提交门禁。

当前许可核对集合为 Apache-2.0、BSD-2-Clause、BSD-3-Clause、ISC、MIT、MIT-0 和 MPL-2.0。未知标识、不在集合中的许可、缺少原文、缺少需要交付的编译源码或摘要变化会阻止构建。扩大集合需要核对实际条款、源文件和交付义务，不提供跳过未知许可的发行参数。

固定的 `github.com/segmentio/asm v1.2.1` 原文为 [MIT No Attribution](https://raw.githubusercontent.com/segmentio/asm/v1.2.1/LICENSE)，对应 [SPDX MIT-0](https://spdx.org/licenses/MIT-0.html)。该文本尚不能由当前分类器识别；[例外目录](../licenses/go/exceptions.json) 仅对模块路径、版本、Go 校验和和原文 SHA-256 全部相符的依赖使用 MIT-0。模块内其它未知原文不能继承该例外。构建不修改模块缓存、替换许可文本或关闭 Go 校验和验证。

MPL-2.0 依赖除许可文件外附带原始源码；交付目录中对应已编译包的 Go、汇编和嵌入文件必须与实际输入摘要一致。工具的标准输出、标准错误、超时前输出、许可检测警告和导出失败原文留在独立构建诊断中，不进入产品 ZIP，也不作为业务数据。自动识别仍有工具能力边界，目录记录和程序绑定不代替对新增依赖、原生外部代码与实际交付方式的审查。

## 可复现构建与拒绝发布

依赖预先按固定版本下载并校验，发行构建运行时关闭网络。两个 ZIP 固定文件顺序、权限和时间；构建信息使用程序名称，SBOM 不包含随机序列、生成时间或工具自身因编译路径变化产生的哈希。原始工具信息和有时间／进程标识的诊断保存在构建证据中，避免改变同一输入的 ZIP 摘要。

ZIP 校验器重新核对程序构建信息、全部模块、SBOM 组件与依赖图、压缩程序摘要、运行时许可、原文和需要交付的源码，不只相信清单里的通过标记。未声明文件、重复路径、越界、链接、遗漏、来源不符和解压体积超限均拒绝。项目许可与前端实际打包许可也独立核对。

Linux ZIP 内的压缩程序还须在远程同架构 Docker 环境完成实际启动、UPX 完整性、解压还原摘要和端到端业务测试。交付目录通过不表示原包生产存储、设备封禁、完整功能或性能已通过验收。系统依赖、Suricata、对象存储及其它未随 ZIP 分发的组件分别按 [依赖版本与部署清单](依赖版本与部署清单.md) 核对，不包含在本文件的 Go 模块交付结论中。

## 候选运行环境

`scripts/remote_candidate_review.py` 只操作已登记的专属 Docker 工程实例。部署前核对当前源码、实际完整后端执行状态与嵌套证据摘要、离线和真实网卡子流程、两端前端及两个 ZIP 的字节；失败结果不能用于替换。实际程序在远程从已经核验的 ZIP 解包，不以开发镜像中带覆盖插桩的程序代替交付程序。

替换使用只读的单程序挂载，保留原有数据库、WAL、对象身份、配置、证书、运行隔离和网络。平台与网关同时重建，采集器随后重建；核对五个在线程序的实际字节和版本，并回读采集配置修订、生效状态、健康和 History 网关。核对失败自动恢复先前 Compose 定义；不会重新初始化租户或重置采集游标。此过程重启采集器，存在捕获缺口，不能宣称无损升级。

运行证据独立记录源码、ZIP、在线字节、采集前后状态和部署时间。来源为未提交工作区时仅允许工程验收，不产生正式 Release。已部署候选实例也拒绝被普通开发环境更新静默覆盖；生产升级、数据迁移与跨版本回退需按各自契约单独完成。
