# 星烽 StarBeacon 原包归档与会话导出

## 捕获与持久确认

Linux 托管采集器使用独立 AF_PACKET 流保存实际网卡报文，和 Suricata → EVE 事件链分别运行。PCAPNG 包含实际网卡名称、MAC、BPF、纳秒报文时间、原始长度和捕获长度；内核丢包计数未获取时标记未获取，不能视为零。VLAN 卸载使原始标签不可见时保留缺口，不凭空补造标签。镜像源、NIC、主机和采集进程的丢包不能用单个内核计数证明全部不存在。

切片先保存原字节，再编码为独立 Zstandard 帧，每帧记录原始／存储偏移、长度和 SHA-256。编码默认每帧 256 KiB，使用低压缩级别、一个编码线程与 1 MiB 窗口；也支持不压缩。TLS、已压缩文件及其他高熵数据的压缩收益可能很小，不按固定压缩率配置容量。

切片经 mTLS `UploadPacketArchive` 上报，首块为严格目录，后续每块最多 128 KiB、偏移连续。当前原包接收服务运行在主平台 gRPC，采集器使用独立连接，与事件接入和控制连接分开；最多四个原包传输，不是已验证的 200 探针吞吐承诺。接收端校验证书身份、注册代次、原包容器、编码和摘要，写入带版本的对象并提交租户目录后才返回确认。采集器必须核对同一原包、目录／原始／存储摘要、长度、对象版本和期限，才回收本地已确认载荷。

未确认原件、捕获中断与损坏现场不会自动淘汰。容量不足时停止产生新的切片并记录健康错误；捕获与告警链路的状态分别显示。隔离记录保留在历史目录和容量账目中，上传轮询使用独立 FIFO，仅取可处理记录。重启重建派生索引，恢复过程中发现身份或顺序损坏时拒绝继续上传。

## 配置与留存

| 配置 | 默认与限制 |
| --- | --- |
| `SB_PACKET_CAPTURE` | 托管模式默认开启；外部 EVE 模式不提供独立原包捕获 |
| `SB_PACKET_DIR` | 私有本地目录，与 WAL 和重放样本目录隔离；不能为符号链接或向其他用户开放 |
| `SB_PACKET_BACKEND` | 平台默认沿用重放存储；开发可用 `filesystem`，生产使用 `s3` 及已配置的 S3 凭据 |
| `SB_PACKET_CODEC` | `zstd`；可选 `none` |
| `SB_PACKET_SPOOL_BYTES` | 1 GiB；至少 100 MiB，并能容纳三份最大切片及目录预留 |
| `SB_PACKET_SEGMENT_BYTES` | 16 MiB；1–64 MiB |
| `SB_PACKET_ROTATE_SECONDS` | 30 秒；1–3600 秒 |
| `SB_PACKET_STORAGE_BYTES` | 每租户 1 TiB 对象容量预算；至少 100 MiB |

具体环境变量以 `internal/config` 校验为准。生产对象存储需要 TLS、版本能力及最小权限凭据；对象密钥只在接入／平台注入，不传给采集器。远程工程测试使用受控版本对象服务，不能代替实际对象存储产品、证书和故障恢复验收。

PCAP 业务策略默认 180 天，可配置 1–3650 天；新对象首次提交时固定期限。平台清理按到期目录及指定版本回收对象，未完成删除仍占额度。活动读租约保护应用内回收；对象存储自行配置的生命周期删除不受数据库锁保护。新配置不重算存量期限。不能把本地已确认重试缓存数量、工作队列 TTL 或编码临时文件期限作为证据留存期限。

持续 1 Gbit/s 原包约为 10.8 TB／天、180 天约 1.944 PB，未计副本、目录及备份。租户容量预算不是 180 天容量承诺；达到预算时显式背压。实际镜像吞吐、压缩率、丢包、索引速度和端到端时延需要相应硬件负载测试。

## 目录与下载

平台「流量检索 → 原包归档」使用稳定游标与探针筛选，采集器「网络与采集 → 原包归档」展示最多 200 条近期暂存及确认记录。列表只含轻量摘要；详情读取完整目录。两端均限管理员访问，平台由当前租户 RLS 限定范围。

本机正在捕获的目录只持久保存开始时的身份、网卡、配置、开始时间及暂存预留。包数、首尾包时间、结束时间和完整性计数须等封存后冻结，页面显示「待封存／尚未冻结」，不把开始记录中的空值当作零流量或零丢包。进程中断且未完整封存的原件同样保留未知状态和核查说明；不能下载，也不能参与完整会话导出。该状态的校验仅允许本机专属开始记录的固定空字段，不放宽平台目录、可下载原件或摘要核验。

下载按指定对象版本重建真实 PCAPNG，核对各帧和整文件摘要及捕获元数据。准备完成后再次核验账号、对象及有效期，记录审计后发送；认证、损坏或缺失不返回伪造的空文件。浏览器再核验完整长度和 SHA-256，成功后才触发保存。采集器已确认并回收载荷的目录记录不允许再次本地下载，原件需从平台获取。

## 逐包协议查看

两端在原包归档列表中使用「协议查看」打开单个弹窗，按当前切片的实际捕获顺序选择包序号，支持上一包、下一包和序号跳转。未封存、不可核验或已回收本机原件的记录不能查看；本机已确认上传的原件从平台读取。该视图不建立第二张业务列表。

接口分别为 `GET /api/v1/packet-archives/{id}/packets/{number}` 和 `GET /api/local/v1/packet-archives/{id}/packets/{number}`。序号为 1–1,048,576 的规范十进制整数，不能带前导零、符号或查询参数；归档内不存在该序号返回 404。每次先读取指定版本并核验整个不超过 64 MiB 的归档、编码摘要和捕获目录，再读取一个包。与下载共享读取额度，平台并发 4／90 秒，本机并发 2／30 秒；超额返回 429。当前没有随机访问包索引，不能据此承诺海量逐包检索性能。

协议层由社区维护的 gopacket 解码，预算最多 16 层。展示 Ethernet 源／目的 MAC、VLAN、IPv4／IPv6、TCP／UDP、ARP、ICMP 和 IPv6 分片等实际可解析字段；协议层的偏移只有在其字节与原帧匹配时才显示。截断包保留截断状态，解析失败前登记的空层不显示默认字段；达到层数限制时显示独立状态。VLAN 卸载注释不作为原帧标签，也不向原字节补写链路头。

协议树的显示字段不等于告警或流量数据集的索引字段。高级筛选以各数据集实际字段目录为准；尚未建立原包字段索引的字段不能用于海量原包查询。

回执绑定归档及目录摘要、归档原始摘要、所选帧摘要、捕获纳秒时间和长度。浏览器核对身份、序号、捕获时间范围及所选帧 SHA-256 后才显示 HEX／UTF-8；旧包内容在切换或失败时清除，关闭取消请求，迟到响应不能恢复内容。MAC 是所见链路帧地址，不推断远端物理主机；捕获时间不等于双向入站／出站时间。应用正文未重组、报文校验和未独立确认、TLS 未解密，载荷层名称不表示相应应用已识别。

两端仅允许当前管理员访问，发送原字节前再次复核会话和目录状态。平台按租户隔离并检查冻结对象版本、目录摘要和留存期限；本机重新核对待确认制品状态。`pcap.inspect.request` 保存归档级独立访问审计，审计失败不返回通信内容；请求标识用于关联读取过程，不表示客户端已完整阅读内容。响应使用 `Cache-Control: no-store`，校验暂存不纳入证据目录，完成或失败后回收。

## TCP 会话导出

平台从当页选择 1–16 个切片，通过弹窗固定双方 IP、端口、MAC 与有序 VLAN 栈。IPv4、IPv6、单层和双层 VLAN 使用相同身份校验；跨租户、跨探针、注册代次、捕获运行、网卡、网卡 MAC 或配置摘要不自动合并，NAT 候选亦不自动拼接。

| 模式 | 返回条件与标识 |
| --- | --- |
| 完整 TCP 会话 | 必须观察到 SYN、正确 SYN/ACK 和第三次 ACK；双向序号覆盖连续、重传重叠字节一致、两端 FIN 及确认齐全，且没有已知捕获质量缺口 |
| 通信快照 | 用户明确选择；导出实际匹配报文，始终标为 `snapshot`，保留完整性缺口 |

严格模式条件不足返回 HTTP 422 和实际原因，不生成文件，也不自动降级。无匹配报文时两种模式都拒绝。序号回绕、相同重传和载荷乱序可核对；不同初始序号的连接复用、冲突重传、序号缺口、未观察连接开始或关闭、内核丢包／计数未知、截断和不可见 VLAN 都不能得到完整会话标识。

TCP Fast Open、RST 接收有效性、IP 分片与隧道尚无完整性资格，不能称为完整 TCP 会话。快照不会拼造握手、重组生成报文或解密 TLS。输出中的载荷可见性保持 `unknown`，端到端校验和保持 `not_checked`；字节连续不代表应用攻击成功、明文可见或接收端确实采用这些字节。

| 处理预算 | 限制 |
| --- | --- |
| 同源切片 | 最多 16 个 |
| 原始输入 | 合计最多 256 MiB |
| 捕获窗口 | 最多 1 小时 |
| 扫描报文 | 最多 1,048,576 个 |
| 输出 PCAPNG | 最多 64 MiB |
| 单方向序号跨度 | 最多 32 MiB |
| 全局并发／执行预算 | 两个导出／90 秒 |

成功文件的节注释保存请求、来源 ID、指定对象版本、原始与目录摘要和完整性报告；每个报文保留原始字节、纳秒时间和长度，并附来源切片 ID 与原包序号。输出节内序号重新编号用于定位，不替代来源序号。

导出创建审计后读取并验证源文件；同一数据库事务按稳定顺序锁定目录及当前账号，防止应用清理或停用在准备过程中改变授权。成功制品发送前再次核验来源。取消、失败和完成后均回收派生暂存，捕获原件与对象期限保持原有规则。

## 验证与剩余边界

已完成的本机测试核对实际原始帧、跨切片握手与 FIN、SHA-256、PCAPNG 元数据、IPv6／VLAN 身份、相同和冲突重传、序号回绕、缺口、源文件损坏、输出失败、取消及严格／快照区别。已有远程快照验证真实网卡独立原包捕获、mTLS 版本上传、目录、下载与回收；会话导出须在对应源码上完成远程验证，见[测试覆盖与验收记录](测试覆盖与验收记录.md)。

当前实现不是海量逐包检索器。大规模会话索引、跨日长连接、异步导出作业、分卷、完整协议树、TFO／RST／分片资格、生产对象存储、海量吞吐与压缩性能均未完整验收。受限会话导出不能用来宣称全部取证需求已交付。

本机处于平台确认状态的目录只保留捕获元数据和确认摘要，原件已从暂存回收。详情展示确认摘要中的实际存储大小；原始大小与压缩清单缺失时说明应在主平台查看，不推断尚未编码。确认摘要的身份、摘要、对象版本和大小须与已提供的目录、清单一致；字段冲突不能作为成功目录呈现。
