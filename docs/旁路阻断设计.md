# 星烽 StarBeacon 旁路阻断设计

本文定义目标功能、架构或交付契约；当前代码、接口、工程页面、测试依据及未完成项统一见[功能实现与验收状态](功能实现与验收状态.md)。本文内容尚未实现。

决策日期：2026-11-20。探针是旁路部署，不在转发路径上，本身拦不住报文。旁路阻断指探针通过一个独立的注入网口，向命中的连接两端发送伪造的 TCP RST（对 UDP 发 ICMP 不可达），让连接中断。

**它是尽力而为的手段，默认关闭。** 作用是在防火墙规则生效之前先把当前连接断掉、争取时间；持久封禁仍由[联动插件](联动插件设计.md)在防火墙上完成。此前文档中“不依靠发送 TCP RST 作为可靠封禁机制”的立场不变：旁路阻断不是可靠封禁，只是可选的补充。

## 1. 两种触发方式

| 方式 | 谁来发 | 时延 | 适用 |
| --- | --- | --- | --- |
| **规则即时阻断** | Suricata：把选定规则的动作设为 `reject`，命中即由引擎发出 | 毫秒级 | 确定性很高的规则，例如已知漏洞利用特征 |
| **研判后阻断** | 采集器的注入器：平台按策略下发“断开这条连接”的任务 | 秒级 | 需要先经过 AI 研判、关联规则或人工确认的场景 |

规则即时阻断使用 Suricata 的 `reject`、`rejectsrc`、`rejectdst`、`rejectboth` 动作，并用启动参数 `--reject-dev=<网口>` 指定发送网口，官方说明为“用该设备发出 reject 关键字产生的 RST 或 ICMP 错误报文”。见 [规则动作](https://docs.suricata.io/en/suricata-8.0.7/rules/intro.html)、[命令行参数](https://docs.suricata.io/en/suricata-8.0.7/command-line-options.html)。只有阻断策略明确选中的规则才会被改成 `reject`，其余规则保持 `alert`，规则动作的授权要求见[规则管理设计](规则管理设计.md)。

研判后阻断由采集器自己发包：收到任务后在捕获口等待该连接的下一个报文，取其中的序号向两端各发一个 RST。连接已经空闲、没有后续报文时无法取得有效序号，记为“未注入”。

## 2. 网络前提

上线前逐项确认，任何一项不满足就不启用：

1. **有独立的注入网口**，不与镜像口、管理口混用。
2. **注入的报文能到达连接两端**（至少一端）。报文的源地址是伪造的，路径上的反欺骗检查、端口安全策略会把它丢掉。
3. **注入点与镜像点在地址转换的同一侧**，否则探针看到的地址、端口和序号与对端实际使用的不一致。
4. 交换机允许该端口发送这类报文，且已得到网络负责人的书面同意。

## 3. 它做不到什么

- **不保证断开**：伪造的 RST 可能比真实报文晚到，对端已经收下数据；序号过期的 RST 会被忽略。
- **对 UDP 和 QUIC 效果有限**：只能发 ICMP 不可达，很多协议栈和应用不理会。
- **挡不住重连**：客户端可以立刻重新建立连接，所以要配合防火墙封禁。
- **撤不回已经发生的事**：已经送达业务的请求不会因为连接被断开而失效。

页面上不出现“已拦截”“已阻止攻击”这类说法，只显示注入了什么、观察到了什么。

## 4. 授权与保护

功能要同时满足下面几层才会生效：

| 层 | 要求 |
| --- | --- |
| 采集器 | 本地配置里打开旁路阻断并指定注入网口；默认关闭 |
| 平台开关 | “系统设置 → 旁路阻断”里的总开关；默认关闭 |
| 平台策略 | 每条阻断策略单独授权：触发条件、目标范围、方式、有效期、授权人；在同一处维护 |
| 每次执行 | 来源和目标都不在保护名单内；没有超过每分钟注入上限 |

- 策略只作用于**命中的那条连接**，不做网段级阻断。
- 策略有有效期，到期自动停用，需要重新授权。
- 在[AI 值守](AI自动化处置设计.md)的“暂停自动处置”打开时，研判后阻断立即停止；规则即时阻断由策略单独停用。
- 保护名单的含义和维护方式见[保护与观察名单](保护与观察名单.md)。

## 5. 效果观察

每次注入后继续观察该连接一段时间（默认 5 秒），给出三种结果之一：

| 结果 | 含义 | 后续 |
| --- | --- | --- |
| 已终止 | 观察期内该连接没有新的数据报文 | 按策略转联动插件做限时封禁 |
| 仍有流量 | 观察期内还有数据，或对方很快重连 | 提示值班员，并转联动插件封禁 |
| 结果未知 | 探针在观察期内丢包或离线，无法判断 | 等联动插件确认，不重复注入 |

另有两种没有注入的情况单独记录：保护名单拦截、未注入（连接已空闲）。

## 6. 记录

每次阻断保存：编号、时间、连接五元组、协议、命中的策略及修订、触发的告警、注入的报文类型和数量、效果观察结果、后续动作、授权人。记录与告警、响应动作互相可跳转，保留期限跟随响应动作。

## 7. 页面

“响应中心 → 响应动作 → 旁路阻断”只放阻断记录：顶部只读显示是否开启和注入网口状态（带“修改”链接到系统设置）；一行指标（今日阻断连接、确认终止、仍有流量、结果未知、保护名单拦截）；一张阻断记录表。

总开关、每分钟注入上限和阻断策略属于系统级配置，放在“系统设置 → 旁路阻断”；新建策略时必须勾选“我了解旁路阻断不保证断开连接，也不能代替防火墙封禁”。原型见 `prototype/src/views/BypassView.vue` 和 `prototype/src/views/SystemSettingsView.vue`。

## 8. 验收要点

1. 默认关闭：没有同时打开采集器开关和平台策略时，不发出任何注入报文。
2. 两种触发方式各自在实验网络里断开指定连接，并测出从命中到发出 RST 的时延分布。
3. 保护名单内的地址不被注入；超过每分钟上限后停止注入并告警。
4. 效果观察的三种结果与抓包对照一致；重连能被识别。
5. 注入网口断开、策略到期、暂停自动处置后立即停止。
6. 不影响镜像口收包和检测：开启前后丢包率、告警时延无明显变化。
