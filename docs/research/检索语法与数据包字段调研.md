# 星烽 StarBeacon 检索语法与数据包字段调研

调研日：2026-09-30。范围包括官方 Wireshark/TShark 资料、Suricata EVE、ECS、Linux 时间戳、PCAPNG 和 Go 包解析库。下文区分官方能力与 StarBeacon 设计决定；本机 TShark 4.4.7 完成 12 条基础语义实验，尚未执行目标 4.6.9 的平台兼容性与性能测试。配额均为设计输入。落地契约见[高级检索与数据包取证设计](../高级检索与数据包取证设计.md)。

资料获取先尝试 Context7 的 Wireshark library resolve；服务返回当月配额耗尽，未取得可用 library ID，因此没有绕过解析步骤调用 query。随后直接读取官方手册、锁版源码、字段参考与维护仓库。公开 current 文档会随开发分支演进；生产采用 **TShark 4.6.9** 的发布资料和锁版手册，并要求制品级回归验证。[Wireshark 下载](https://www.wireshark.org/download.html)、[4.6.9 发布说明](https://www.wireshark.org/docs/relnotes/wireshark-4.6.9.html)

## 1. Wireshark 风格语法的兼容边界

Wireshark 的过滤器作用于解析后的数据包协议树，可以有同名字段的多个出现值。当前网页手册与锁版手册都提供量词、集合、切片、层选择、原始字段和 PCRE2 匹配。只有复制界面输入框和部分运算符，无法获得这套协议语义。[锁版手册](https://github.com/wireshark/wireshark/blob/v4.6.9/doc/man_pages/wireshark-filter.adoc)

设计决定：平台提供事件索引检索和原生数据包作业两个入口。事件检索支持高频业务条件，原生模式复用 TShark 深度解析；保存查询必须保存模式和数据粒度。拒绝把字段未采集、表达式不支持和确实无命中合并成空列表。

| 核验点 | 依据与风险 | 对应设计 |
| --- | --- | --- |
| 比较量词 | 官方测试区分 any equality、all inequality、all equality、any inequality | 保留 `==`、`!=`、`===`、`!==` 和显式量词，建立真值表 |
| 存在与布尔值 | 布尔字段存在时可能值为 false | 裸 `tcp.flags.syn` 与 `tcp.flags.syn == true` 不混用 |
| 区间集合 | 同一多值字段的两个独立比较可由不同值满足 | 范围集合须由同一元素满足上下界 |
| MAC／IP／端口 | 类型和地址族决定比较意义 | 字段注册表与类型检查，不使用字符串词典序比较 IP |
| 字段层级 | 隧道和内嵌报文会出现多个网络层 | 事件选定业务层；完整 `#` 语义留给原生引擎 |
| 正则 | Wireshark 使用 PCRE2，ES 使用 Lucene | 不能将 `matches` 偷换成 Lucene regexp 或 Go regexp |

比较与存在性参照[官方测试](https://github.com/wireshark/wireshark/blob/v4.6.9/test/suite_dfilter/group_syntax.py)，范围集合与字段类型参照[用户指南](https://www.wireshark.org/docs/wsug_html_chunked/ChWorkBuildDisplayFilterSection.html)。这些源码与文档只证明上游定义，不构成 StarBeacon 已通过兼容验收的证据。

ES 的正则面向 term，语法与 PCRE2 不同；允许该高级能力必须独立标识引擎。ES 的索引存在性还会受 null、空数组、`ignore_above`、`index` 和 `doc_values` 配置影响，不能直接映射为原始流量是否存在该字段。[正则语法](https://www.elastic.co/docs/reference/query-languages/query-dsl/regexp-syntax)、[exists 查询](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-exists-query)

平台据此引入字段覆盖状态与严格未知语义：未采集、截断、字段无权或不可索引不能因 NOT 运算变成确定“不存在”。这属于索引数据质量约束，应明确区别于对完整原生协议树的普通布尔测试。

## 2. 数据包、会话和事务不能混为一条记录

Wireshark 的 Frame 字段包括捕获长度、原长度、文件偏移、接口、方向和时间等元数据。它们与一条 Suricata 告警、一条结束流记录不是同一个对象。`frame.number` 和 `tcp.stream` 只在相应输入及解析上下文中有意义。[Frame 字段目录](https://www.wireshark.org/docs/dfref/f/frame.html)、[TCP 字段目录](https://www.wireshark.org/docs/dfref/t/tcp.html)

设计决定：事件列表保留原始事实身份，包列表使用对象版本与原始包位置生成稳定 packet ID。HTTP 和 DNS 按事务保留关联，数组对象采用受限 nested 或独立事务；禁止把所有请求方法、路径展平成两个数组后交叉匹配。ES 官方说明普通 object 数组会失去元素之间的关系，这是选择 nested 的直接依据。[ES nested](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/nested)

包目录和 sidecar 不默认无限写 ES。完整解析树及派生重组结果属于可过期的对象制品；查询需要宽协议覆盖时运行异步原生作业。采集 PPS 与业务告警 EPS 是独立容量项，不能沿用告警存储预算覆盖全量包索引。

## 3. MAC 的来源与资产身份

Suricata 的 EVE Ethernet 输出需要启用 `ethernet`，且仅在可用时输出。对流超时产生的伪包事件，相关值可能取自流的首个 Ethernet 报文。这说明“EVE 中有 MAC”不能推导为“知道触发告警包的 MAC”。[Suricata EVE 配置](https://docs.suricata.io/en/suricata-8.0.7/output/eve/eve-json-output.html)

ECS 定义了 source/destination MAC，建议统一规范格式；它是事件端点字段，不是跨路由观测下的终端身份证明。[ECS source](https://www.elastic.co/docs/reference/ecs/ecs-source)、[ECS destination](https://www.elastic.co/docs/reference/ecs/ecs-destination)

设计决定：对每组链路地址保存来源依据、层序号和包引用；流首包、当前帧、解封装内层和接口自身地址分开。VLAN 栈顺序保留，未知不能填 0。资产关联同时依赖站点、网络域、时间和可信 ARP/NDP/DHCP／CMDB 关系；共享网关 MAC、随机化 MAC、同租户重复地址和多租户相同私网段都不能直接合并资产。

## 4. 入站／出站与时间戳

ECS 对单臂镜像探针明确只使用 observer.ingress，egress 对应真实的出站观察信息。目的地址属于外网并不表示探针实际观察到了报文从防火墙发出。[ECS observer](https://www.elastic.co/docs/reference/ecs/ecs-observer)

Linux 支持多种 RX/TX 时间戳，并区分软件、硬件和完成通知。其产生时机、驱动支持及关联方式不同。普通旁路包捕获不能自动获得同一报文穿过另一设备的出站时间。[Linux 时间戳](https://www.kernel.org/doc/html/latest/networking/timestamping.html)

Wireshark 显示的是捕获来源提供的时间；捕获格式和设备决定分辨率与准确度。PCAPNG 可以按接口保留不同分辨率，转换到较低精度格式可能丢信息。[Wireshark 时间戳](https://www.wireshark.org/docs/wsug_html_chunked/ChAdvTimestamps.html)

设计决定：拆分捕获时间、真实 RX/TX、源事件时间、平台接收时间，以及按安全域分类的入站／出站首末观测时间。JSON 传递纳秒 epoch 和大 offset 时使用字符串或整数拆分。原时间、时钟来源、误差和校正视图共存；没有对应收发证据就不计算精确穿越时延。

## 5. PCAPNG 与 Go 包解析库

PCAPNG 规范当前仍是 IETF 草案，包含 section、接口描述、时间分辨率与偏移、原长度与捕获长度、可选方向等信息。平台需记录其实际文件特性，不能只保存一个全文件 linktype 和一个时间精度。[PCAPNG 草案](https://datatracker.ietf.org/doc/draft-ietf-opsawg-pcapng/)

维护中的 gopacket 提供 `CaptureInfo` 和 PCAPNG 读取能力。`CaptureInfo` 区分时间、捕获长度、原长度、接口及 ancillary data；`pcapgo.NgReaderOptions` 可控制混合 linktype，其错误配置可能忽略不匹配的包。[CaptureInfo](https://pkg.go.dev/github.com/gopacket/gopacket#CaptureInfo)、[pcapgo](https://pkg.go.dev/github.com/gopacket/gopacket/pcapgo)

设计决定：基础元数据和有界读取复用 Go 库；遇到不支持块／linktype 必须出具缺口，不静默丢包。VLAN offload、网卡 checksum offload、GRO/LRO、FCS 和 snaplen 都影响解析解释，要作为捕获质量展示。复杂协议与显示过滤器不再重复实现，交由 TShark 独立进程。自定义索引语言的词法和 AST 可复用维护中的 Participle，不能把解析库的存在当成自动获得 Wireshark 兼容。[Participle](https://github.com/alecthomas/participle)

## 6. TShark 作业的可靠边界

TShark `-2` 两遍分析需要可回读输入，支持某些依赖未来数据的字段与重组关系；`-Y` 是显示过滤器；PDML 保留协议树形式。作业参数及输出格式必须按锁定版本检验，不把实时管道和离线双遍处理当成等价输入。[TShark 手册](https://www.wireshark.org/docs/man-pages/tshark.html)、[锁版手册源码](https://github.com/wireshark/wireshark/blob/v4.6.9/doc/man_pages/tshark.adoc)

设计决定：授权输入集合先物化为 seekable 文件，冻结 parser profile，在无外部网络的受限 Worker 中解析。输入窗口、额外上下文和实际完整性必须返回。派生 PCAP 保留到原始包的映射，按匹配包导出不能承诺完整会话。重组上限、恶意样本、解析器崩溃、输出爆量和任务取消都采用同一资源治理；不允许影响在线告警入库。

共享捕获对象必须先按授权包范围裁剪。同租户双端受管资产都在授权范围才默认提供原始字节；单端权限只提供策略允许的摘要／脱敏信息。仅凭一条流的访问权给出整个 512 MiB 对象下载链接会泄漏其他流。需要即时撤权的内容通过网关验证，不能宣称已签出的 S3 URL 随平台权限即时失效。

授权 TLS keylog 属于限域、限时秘密；离线解密结果是额外敏感制品。没有密钥、握手缺失或协议不支持时保持加密状态，不生成虚假的 HTTP 明文。原始帧、解密字节、重组流和解压正文使用独立偏移空间，协议树只能高亮有证据映射的范围。

## 7. 文档审查得到的具体缺口

| 缺口 | 实施影响 | 契约要求 |
| --- | --- | --- |
| 高级输入只有通用 AST，没有语言版本和能力表 | 用户误以为任意 Wireshark 语句都能直接查 ES | 两模式、字段注册表、语法矩阵、稳定错误和兼容测试 |
| 缺失与未采集混淆 | NOT 条件和误报判断可被不可见数据误导 | 字段覆盖、unknown 语义、结果质量与证据边界 |
| 多值区间和事务关联未明确 | IP/端口／HTTP 参数出现交叉误匹配 | 元素一致性、协议守卫、事务和层级边界 |
| MAC 未定义来源和角色 | 网关／流首包地址被当作受害终端 | EVE 配置、source_basis、层级及资产关系历史 |
| 入站／出站时间没有采集条件 | 用接收时间、流结束时间伪造发送或防火墙穿越时间 | RX/TX 证据、方向首末时间、时钟质量分开 |
| 包位置、纳秒和 PCAPNG 边界不足 | 下载错误包、混合接口丢包或 JS 精度损失 | 原对象版本、section/interface、包 ID、offset 和精度 |
| 共享对象下载授权过粗 | 一条流授权暴露其他资产流量 | 授权包集合、派生文件、网关撤权和独立取证权限 |
| 原生深度解析资源未独立核算 | 重组／正则／导出拖慢在线检测链路 | 独立队列、配额、临时盘、取消、部分结果和留存 |

## 8. 验收证据要求

本机可执行 TShark 为 4.4.7（`v4.4.7-0-g7980339b1630`），不是目标 4.6.9。使用程序生成的无害四包 PCAP 进行基础实验：三个 IPv4/TCP 包端口依次为 443→443、50000→80、50000→8001，均未设置 SYN；第四个为 ARP。没有捕获实际网络数据，也没有在网卡上发送报文。12 条表达式均与预期相符：

| 表达式 | 命中原包序号 |
| --- | --- |
| `tcp.port == 443`、`tcp.port === 443` | 1 |
| `tcp.port != 443`、`tcp.port !== 443` | 2、3 |
| `not (tcp.port == 443)` | 2、3、4 |
| `tcp.port in {8000..8100}` | 3 |
| `tcp.port >= 8000 and tcp.port <= 8100` | 2、3；展示跨值比较的反例 |
| `tcp.flags.syn` | 1、2、3 |
| `tcp.flags.syn == true` | 无 |
| `ip.addr == 192.0.2.0/24` | 1、2、3 |
| `eth.src[0:3] == 02:00:00` | 1、2、3、4 |
| `tcp.payload contains 47:45:54` | 2；该包为合成 HTTP GET |

以上仅验证本机旧版本的少量原生语义，临时合成输入在实验后清理；不代表 StarBeacon 的 ES 编译器、原生隔离 Worker、4.6.9、复杂协议和性能已经验收。工程阶段必须提交可长期回放的固定 PCAP 及来源许可、表达式和预期包集合、事件映射对应集、完整版本/profile、字段字典摘要、异常样本结果、权限隔离测试和混合负载数据。

优先验证 `!=`／`not`、范围集合、多层同名字段、同会话多事务、未索引字段、双向时间、PCAPNG 混合接口、原始／派生字节映射，以及共享对象越权。产品支持列表以验收后的注册表发布，不能用“全部主流协议”一句话替代字段和证据覆盖。
