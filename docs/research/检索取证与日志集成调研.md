# 星烽 StarBeacon 检索取证与日志集成调研

调研日期：2026-09-28。本文补充高级检索、字节取证、日志转发、审计和监控设计，不实现应用代码。既有权威边界保持不变：告警事实在 ES，业务状态与审计在 PG，PCAP 在 S3；固定源事件 ID、固定逻辑分区、事务 outbox 和通知持久化后 ACK 继续遵循[架构设计](../架构设计.md)。搜索投影是派生数据，不构成第二套告警事实来源。统一实施规范以架构设计和[运营与集成设计](../运营与集成设计.md)为准。

## 2. 高级检索的字段语义

检索表单、专家查询框、REST 和 MCP 共同生成同一受限 AST。基本运算包括等于／不等于、集合、范围、存在／缺失、短语、前缀、受控包含和分组 AND／OR／NOT。界面显示字段类型、大小写规则和条件作用范围；不把用户输入直接拼成 `query_string`、脚本或任意 ES DSL。

| 查询对象 | 推荐索引与行为 |
| --- | --- |
| 事件 ID、规则 ID、探针 ID、租户、处理状态、研判枚举 | `keyword`；精确匹配、集合和聚合 |
| 规则名称、中文描述、调查摘要 | `text`，按需增加 `.exact` 的 `keyword` multi-field；短语与全文匹配分开 |
| `source.ip`、`destination.ip` | `ip`；IPv4/IPv6 精确值、CIDR、地址范围，不对 IP 做中文分词 |
| 端口、状态码、字节数、包数、严重度 | 明确的数值类型；范围和排序 |
| `network.transport` | `tcp`、`udp` 等传输层 `keyword` |
| `network.protocol`、`http.version` | 应用协议与版本分开；HTTP 不与 TCP/UDP 共用互斥枚举 |
| HTTP method | 大小写语义明确的 `keyword`，保留原始 token；常见方法提供 GET/POST 等选项 |
| `url.original`、`url.path` | 原始观测值与路径分别保存；采用 ECS 对应的 `wildcard` 或经压测确定的专用模式字段 |
| 原始 EVE、完整原始载荷 | 原文保存与展示；不默认展开全部索引，也不把 Base64 当全文搜索内容 |

`text` 适合分词检索，`keyword` 适合精确值、排序和聚合；同一字段可有多个索引视图。不要为了聚合对大文本开启 fielddata。添加 multi-field 不会自动回填已有文档，映射／分词变化需要重建或显式回填。[多字段](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/multi-fields)、[text 类型](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/text)

长字符串超过 `ignore_above` 时仍可能出现在 `_source`，却无法通过对应 keyword 字段检索。为长 URL 设置明确上限和 `indexing_truncated`／`unindexed_fields`，需要完整相等匹配时可增加原值 SHA-256 检索键；不能把“查不到”解释为原文不存在。[ignore_above](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/ignore-above)

ECS 将 `network.transport` 与应用层 `network.protocol` 分开，当前 URL 规范将 `url.original`、`url.full`、`url.path` 定义为 wildcard。平台固定 ECS schema 版本，保留 Suricata 原始 `proto` 和 `app_proto`，由适配器明确映射。端口 443 不自动等于 HTTP；HTTP/3 可以基于 UDP，但不能据此宣称当前探针已解析加密 HTTP/3 请求内容。[ECS 网络字段](https://www.elastic.co/docs/reference/ecs/ecs-network)、[ECS URL 字段](https://www.elastic.co/docs/reference/ecs/ecs-url)

源／目的地址指明“报文观测端点”，另设客户端／服务端、内部／外部与受影响资产语义。可信代理头、NAT 映射和镜像方向作为额外证据，不覆盖原始地址。`非某 IP` 是否包含缺失该字段的记录应作为明确选项，避免 NOT 的缺失值语义造成误解。

### 2.1 HTTP 路径与解码

同时保留 `url.original`、解析出的原始 path/query、一次百分号解码的派生显示字段、解码状态与转换版本；path 不统一转小写，保留重复参数、空值、参数顺序和异常编码。`+` 仅在明确的表单编码上下文中表示空格，不能对所有 URL 无条件替换。保留字符的解码可能改变 URI 含义，原始值始终不可被派生值覆盖。[URI 编码规范](https://www.rfc-editor.org/rfc/rfc3986.html#section-2.4)

安全分析可提供“查看第二层解码”操作，但限定解码深度、输出长度与耗时，并记录转换链。查询界面让用户选择“原始路径”“解码路径”“完整 URL”，不要用一个模糊的 URL 输入框暗中查询不同含义的字段。

### 2.2 数组与关联条件

HTTP headers、query 参数或文件列表如果需要“同一个元素内同时满足多个条件”，使用有界 `nested`。例如 `[{name: "a", value: "1"}, {name: "b", value: "2"}]` 不应命中 `name=a AND value=2`。普通 object 数组会丢失元素配对关系；flattened 也不替代同元素约束。高频固定 header 单独提取，未知扩展受数量与长度限制，不把每个 header 名生成新 mapping。[Nested](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/nested)

跨告警、HTTP 事务和会话的关联不是 nested 查询。若 UI 支持按任意 HTTP 事务筛选告警，必须先按 `tenant + sensor + engine_run_id + flow_id + tx_id` 等有范围的关系生成投影，或明确启动有预算的关联任务；不能无界跨索引 Join。

## 3. 中文分词的选择

| 方案 | 已核实能力 | StarBeacon 采用建议 |
| --- | --- | --- |
| 内置 CJK analyzer | 可处理 CJK 文本，无需另装 SmartCN | 首期默认方案和评测基线；用真实安全词语评测召回与噪声 |
| 官方 Smart Chinese | 官方插件，适合简体中文与中英文混合；不是默认已安装；每节点安装并重启；其核心 analyzer/tokenizer 不提供可配置词典 | 中文自然语言字段的可选方案，评测后采用，固定 ES 配套版本 |
| IK | 第三方插件，Apache-2.0；支持 `ik_smart`、`ik_max_word` 与本地／远程词典 | 专业词典评测证明增益且有兼容 ES 9.5.4 的受控制品后采用；纳入供应链和词典发布管理 |

官方依据：[CJK analyzer](https://www.elastic.co/docs/reference/text-analysis/analysis-lang-analyzer)、[Smart Chinese](https://www.elastic.co/docs/reference/elasticsearch/plugins/analysis-smartcn)、[IK 仓库](https://github.com/infinilabs/analysis-ik)、[IK 许可证](https://github.com/infinilabs/analysis-ik/blob/master/LICENSE.txt)。

中文分词只作用于规则说明、中文名称、研判描述等自然语言。IP、CVE、SHA、规则 SID、HTTP method、URL 原始值、协议枚举和二进制内容保留精确语义。避免全字段 `ik_max_word` 带来的索引膨胀与误匹配。

IK 词典热加载依据远程资源的 ETag／Last-Modified 变化，词典为 UTF-8 文本；但词典更新不会重写已经存下的倒排索引。[IK 词典说明](https://github.com/infinilabs/analysis-ik#hot-reload-dictionary) 设计上将词典视作版本化制品：审核词条、计算摘要、内网白名单分发、校验全节点一致性、灰度与回滚。索引期词典变化需建立新索引代次并重建，不能只更新查询期词典后宣称历史召回一致。不同租户的私有术语不得无审核加入所有租户共用词典。

## 4. 通配符、正则与海量检索成本

默认检索顺序为精确字段 → 时间／租户／探针范围 → 前缀／短语 → 有条件的包含／正则。支持正则不等于开放任意模式：服务端限制字段、模式长度、自动机状态预算、查询窗口、并发与返回量；无足够约束的大范围扫描转异步作业或拒绝，并解释可缩小的条件。

ES 正则使用 Lucene 语法，不是 PCRE；匹配整个 term，不支持常见的行首行尾锚点 `^`、`$`。在 text 字段上它匹配分词后的 term，并非完整原始字符串。前导 `*`／`.*` 容易形成高成本查询。`search.allow_expensive_queries` 可作为部署防线，具体允许的查询与字段组合须按锁定版本验收，不能为单次用户查询临时改变全局开关。[正则语法](https://www.elastic.co/docs/reference/query-languages/query-dsl/regexp-syntax)、[regexp 查询](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-regexp-query)、[wildcard 查询](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-wildcard-query)

统一设计起点为 AST 深度 5、条件数 50；模式长度可从 256 字符、同步查询 5 秒、每租户同时 2 个重查询开始压测。这些是待压测参数，不是 ES 硬限制。服务端取消超时任务、限制分片扇出、记录拒绝原因；导出与交互查询使用独立预算。限制输出行数不能替代计算成本控制。

查询响应返回 `total_relation`、是否超时／截断、实际时间范围、投影水位和字段索引完整性。只有 `eq` 才展示精确总数；`gte` 显示“至少”。查询缓存绑定租户、权限版本、AST、索引代次与水位，Redis 命中也不绕过授权。

## 5. 完整告警搜索投影与分页一致性

`alerts` 事实与 PG 业务状态具有独立权威，但直接先取一页事实，再从 PG／状态索引合并并过滤，会造成漏项、页长变化、错误总数和错误排序。平台采用**完整的 `alert-search` 投影**：每条告警一份可检索文档，包含筛选／排序所需事实字段、当前流程状态、当前选中研判、资产维度和原始事实定位；不复制完整 PCAP 或大载荷，也不再维护功能重复的 `alert-state` 索引。

投影构建顺序为：事实入库 → 事实通知；业务变更 → PG outbox；模型结果 → 研判通知；三类通知由投影 Worker 汇合后更新 ES。事实未就绪时暂存待构建状态，不把不完整骨架计入可搜索告警。原有“原始事实入 ES → 后续通知持久化 → ACK”的顺序保持不变。

一个 ES 版本号不能直接代表多个异步权威来源的先后。为投影保存 `fact_revision`、`enrichment_revision`、`workflow_revision`、`assessment_selection_revision` 和 `projection_schema_version`；各业务组件版本由相应权威来源单调推进，schema 版本由投影制品控制，不用墙上时钟或模型名称大小判断新旧。乱序事件触发重读当前权威状态；旧版本不得覆盖新组件。ES 更新再使用 `_seq_no + _primary_term` 进行并发保护，冲突时重读并合并，不能盲目全量覆盖。`external_gte` 也不能替代多来源版本约束。[ES 并发控制](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/optimistic-concurrency-control)

PG 仍只为实际业务操作和任务保存稀疏记录，不为每条告警建立 PG 镜像行。读模型与原告警绑定相同逻辑时间桶和事件 ID，各自保存物理定位，更新不得使用当前写入日期。投影可以从事实、状态和研判历史重建；重建采用新索引代次、记录源水位、增量追赶、校验和原子切换读别名。事实固定分区与事件 ID 不因投影重建改变。索引空间预算必须另计搜索投影、中文倒排和重建临时空间。

告警列表、筛选总数、当前状态聚合、排序及导出统一查询这份投影。操作成功返回新的业务版本，界面可暂时显示单项更新和“检索同步中”；达到投影水位后刷新列表。这样既不把最终一致性伪装成同步事务，也不让状态筛选依赖浏览器拼接。

PIT + `search_after` 固定搜索视图；保留完整排序值及 tie-breaker，并按返回值更新 PIT ID。游标签名绑定租户、权限版本、AST、排序、PIT、投影代次与过期时间。状态在翻页期间变化不会改写该 PIT；用户点击刷新才打开新视图。详情可显示当前状态，但须区分列表快照时间；批量操作重新检查当前权限和业务版本。PIT 不是 PG 与 ES 的跨库快照，也不是长期备份。[分页规范](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results)

## 6. HEX、UTF-8 与字节证据

### 6.1 先确定正在查看什么

界面提供“原始捕获文件”“单个报文”“告警载荷”“重组方向流”“解码后的应用内容”等明确视图。Suricata EVE 的 `packet`、`payload`、HTTP body 是不同来源；`payload-printable` 明确属于有损展示，不能用于恢复原始字节。载荷可能受 buffer 上限限制，报文输出不等于完整重组流，也不是一个包含文件头的 PCAP 文件。[Suricata EVE 配置](https://docs.suricata.io/en/suricata-8.0.7/output/eve/eve-json-output.html)

每个字节制品记录 `artifact_id`、类型、来源事件／对象版本、完整大小、实际捕获大小、SHA-256、linktype、方向、截断与缺口、转换链、保留期。解密、解压、去分块或流重组结果作为派生制品，不覆盖原始字节，不把其 offset 当作原 PCAP 文件 offset。

### 6.2 展示和 API 契约

HEX 每行 16 字节，左侧为十六进制字节偏移，中间为字节值，右侧为 ASCII 或 UTF-8 尝试解码。偏移明确从当前制品第 0 字节起算：PCAP 文件偏移、报文帧偏移、传输层 payload 偏移、重组流逻辑偏移各自独立。协议树选择字段时返回对应的原始 byte range；跨包重组用一个或多个 range 映射，存在缺口时明确展示。

只以“证据 ID + 视图 + offset + length”申请窗口；服务器解析对象位置，不接受任意 bucket/key。每次读取重新授权、固定对象版本、限制长度并返回实际范围、总长度、截断和校验信息。默认窗口为 64 KiB，受控网络可压测更小窗口，长文件按需加载；不要把数百 MiB Base64 一次塞进浏览器。

UTF-8 解码先严格校验；无效序列保留字节并显示转义／错误标记，不能让替换字符掩盖实际内容。分块解码须保留跨块状态或读取必要边界上下文，处理多字节字符跨页。JavaScript 字符串下标不是原始字节 offset；选择、高亮、复制和导出依赖 byte-to-text span 映射。UTF-8 不成功只说明该视图不能完整按 UTF-8 解码，不等于原始证据损坏。[WHATWG TextDecoder](https://encoding.spec.whatwg.org/#interface-textdecoder)

默认按纯文本渲染，禁止把载荷当 HTML、执行脚本、自动打开 URL 或自动加载外部资源。控制字符、双向文本控制符和不可见字符可切换为显式标记；保留原始字节下载能力。内容下载使用附件和明确类型，禁止 MIME 嗅探。模型读取须经过额外数据策略，不能因界面能查看载荷就自动发送给外部模型。

大二进制放 S3，ES 保存摘要、长度、内容类型、来源和受限检索文本。ES `binary` 接受 Base64，但不可搜索，不是字节索引方案；也不为每字节生成 HEX 字符串进入全文索引。少量 EVE 内联 payload 可随原文保留但关闭索引。字节序列搜索限定当前制品或授权异步扫描任务，拥有独立字节量与时间预算。[ES binary 类型](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/binary)

### 7.1 协议与交付含义

| 模式 | 使用定位 | 可对用户承诺的状态 |
| --- | --- | --- |
| RFC 5424 + RFC 5425 TLS | 默认生产模式，验证服务端证书，按目标支持配置 mTLS | 连接建立、写入传输成功；无应用回执时不能称为远端入库成功 |
| RFC 5424 over TCP | 兼容可信专网目标；优先长度计数分帧 | 可重连重发，但不证明远端应用持久化 |
| RFC 5424 over UDP | 明确选择的兼容模式 | 已发出数据报；不保证到达、顺序或去重 |

RFC 5425 明确没有应用层 ACK，连接中断时发送方无法总是知道对端应用收到哪些消息；默认 TLS 端口是 6514。TCP 应优先采用 `MSG-LEN SP SYSLOG-MSG` 的 octet-counting；长度是字节数，不是中文字符数。基于换行的旧分帧会被 MSG 中的换行干扰。[RFC 5425](https://datatracker.ietf.org/doc/html/rfc5425#section-6.3)、[RFC 6587](https://datatracker.ietf.org/doc/html/rfc6587#section-3.4.1)、[UDP 边界](https://datatracker.ietf.org/doc/html/rfc5426#section-5.4)

因此“至少一次”应限定为平台内部任务投递与发送尝试。断线后的不确定消息可能重发，接收方按稳定 message ID 去重；普通 Syslog 无法保证远端应用至少一次持久化。若客户必须取得入库确认，需接收方提供支持回执的协议／接口，由对应连接器单独验收，不能给 TCP 写成功套一个虚构 ACK。

### 7.2 格式、长度与超限

格式使用 RFC 5424 HEADER + STRUCTURED-DATA + MSG；severity 与平台风险级别采用有版本映射，不直接把 Suricata 数字 severity 当成 Syslog severity。`MSGID` 用短消息类型，完整事件 ID 放结构化字段或 JSON MSG，避免超过头字段限制。自定义 SD-ID 使用实际取得的企业 PEN；未取得时可用 `-` 和版本化 JSON MSG，不编造企业编号。[RFC 5424 格式](https://datatracker.ietf.org/doc/html/rfc5424#section-6)

输出字段至少含 schema、源事件 ID、转发消息 ID、目标与模板版本、租户可公开标识、探针、事件时间、平台时间、严重度、规则、源／目的、协议、摘要及授权链接。MSG 采用接收方验收的 UTF-8 JSON 编码档；若声明 RFC 的 MSG-UTF8 则按标准加 BOM，无 BOM 的 JSON 按 MSG-ANY 承载，不能混淆编码声明。结构化参数转义与 JSON 转义分别实现。

按目标配置 `max_message_bytes` 并测试完整传输链。RFC 5424 的通用最低接收能力为 480 字节、建议 2048；TLS 映射要求至少 2048、建议 8192。这不是所有服务器统一的 8 KiB 上限。默认模板采用短摘要；经目标确认后可提高长度。[RFC 5424 消息长度](https://datatracker.ietf.org/doc/html/rfc5424#section-6.1)、[RFC 5425 消息长度](https://datatracker.ietf.org/doc/html/rfc5425#section-4.3)

超限时不能直接截断整个 JSON 或结构化头。按照字段优先级先移除非必需大字段，再按 UTF-8 字节边界裁剪摘要，保留 ID、原始大小、摘要和 `truncated_fields`；原始事实仍在平台。客户要求完整字段时，超限进入失败／待处理状态，不假装完整转发。标准 Syslog 没有通用应用层分片重组约定，默认不拆成多条日志；只有接收方明确支持约定时才启用带 `part_index/part_count/message_hash` 的连接器分片。

### 7.3 队列与目标隔离

目标配置在 PG，包含允许租户、事件类型、筛选条件、模板、协议、地址、证书引用、限速、最大长度、重试与保留期。告警转发消费已索引通知；操作／登录日志转发来自审计 outbox。转发和 AI 使用独立持久消费者与资源预算，目标故障不阻塞告警入 ES。

转发任务 ID 由目标、源事件、触发类型、模板版本确定；渲染后的消息及其摘要在入队时固定。每目标有独立积压、速率限制和熔断；暂时故障指数退避，永久配置错误进入隔离，人工重放留记录。对不确定写入可重发，但仍用同一个消息 ID。更换模板需创建新的转发版本，不冒充原始重试。

状态使用 `queued`、`sending`、`transport_written`、`retrying`、`failed`、`outcome_unknown`；只有连接器取得真实应用回执时使用 `receipt_confirmed`。不要把无回执的普通 Syslog 标记为“接收端已确认”。证书失败不得自动降级明文或关闭验证；目的地址遵守租户出站策略。

高频发送尝试日志写 ES 独立 `delivery-logs`，PG 保存目标配置、手动重放任务、批次／序列段结果水位和低频业务记录，避免每条转发复制成 PG 日志流。记录每次尝试的耗时、字节数、错误分类和结果，不记录密钥或完整敏感 payload。对转发日志自身设置路由隔离与循环检测，避免失败日志再次触发同一路由形成递归。

## 8. 日志中心与探针／平台监控

### 8.1 日志分类

| 日志 | 权威与检索 | 关键字段 |
| --- | --- | --- |
| 操作日志 | PG 追加审计为权威，ES 为检索投影 | 操作者、租户／授权范围、资源、动作、前后版本、原因、请求 ID、结果、时间 |
| 登录日志 | 身份域审计，PG 分区保存，ES 检索 | 主体或脱敏声明账号、登录方式、MFA、成功／失败、可信来源 IP、设备、会话引用、失败分类 |
| 推送／转发日志 | ES 高频记录，任务队列保证重试；PG 管配置与人工操作 | 目标、消息 ID、模板、尝试序号、协议、传输／回执状态、错误、字节数、耗时 |
| 平台运行日志 | ES 短期运行日志；与业务审计分开 | 服务、实例、版本、级别、trace ID、错误码；不默认保存完整请求体 |

失败登录不能直接信任客户端提交的 tenant ID 或 X-Forwarded-For；仅解析受信代理链，未知租户事件进入受限平台安全域。密码、验证码、Cookie、access token、API key 和私钥不进入日志；配置差异展示密钥引用变化，不能保存密钥明文前后值。登录拒绝、权限失败、导出、PCAP 下载、规则／模型／目标配置变更均有明确审计事件。

日志筛选统一时间、操作者／主体、租户、动作、资源、来源 IP、结果和请求 ID；推送日志另有目标、协议、消息 ID、尝试与错误分类。各类日志独立保留期、访问权限和导出预算。审计链路失效时显示降级并按业务风险限制敏感操作，不把“日志写不进去”静默忽略。

### 8.2 探针监控

| 范围 | 最少采集项 |
| --- | --- |
| 身份与版本 | agent ID、boot ID、平台接收时间、agent／Suricata／规则包／配置版本与摘要、操作系统和内核 |
| CPU | 主机和 Suricata／代理进程 CPU 时间、利用率、可用核心数或容器配额、负载；明确利用率是否按总核归一化 |
| 内存 | 总量、available、进程 RSS、Go heap、swap、OOM；不把 free 内存直接当作 available |
| 磁盘 | 分挂载点容量、可用空间、inode、读写字节与延迟；WAL、PCAP、系统盘分别告警 |
| 网络 | 每观测接口 rx/tx 字节、包、错误和 drop 累计量与速率；与管理网卡区分 |
| 捕获与检测 | Suricata 捕获／内核丢包、重组缺口、流表与内存上限、EVE 速率和实际规则版本 |
| 上报健康 | 心跳间隔、WAL 字节及最老年龄、确认延迟、队列缺口、上传任务积压、时钟偏差 |

采样可从 15–30 秒起步；计数器按 boot ID 和重置情况计算速率，重启不能出现负流量。网卡 drop、内核抓包 drop 和 Suricata 流重组缺口分别展示；不同捕获后端的丢包分母需要适配器明确，不随意拼一个统一比率。CPU 分母与采样窗口保存在元数据；缺失或过期数据标记未知，不能显示成 0%。

探针已有出站 gRPC 通道可传健康摘要，平台生成授权的当前状态与历史曲线。避免为探针监控额外开放客户网络入站端口。版本、接口和能力在变更时更新，指标只保留低基数标签；不得将 URL、源目的 IP、告警 ID、用户 ID 放入每条监控时间序列标签。

### 8.3 平台自身监控

覆盖平台节点 CPU／内存／磁盘／网络，以及 Go 进程、API 错误率与 P95/P99、PG 连接与复制延迟、outbox 最老年龄、ES 分片与拒绝写入／查询延迟、JetStream quorum／副本滞后／积压年龄、S3 失败率、Redis 内存／淘汰／连接、模型预算和响应撤销失败。平台异常与业务安全告警分开通知，防止监控故障淹没安全分析队列。

接口按 Prometheus/OpenMetrics 暴露，平台基础设施可复用现有 Prometheus 与告警路由；如作为标准生产组件交付，必须列入整体 BOM、容量与备份边界。它承担运行监控，不改变 PG+ES 的业务数据权威划分。小部署也可将受控健康样本存 ES 指标 data stream，最新视图用 Redis 加速；不能两套高频样本无预算重复存储。[指标命名和标签](https://prometheus.io/docs/practices/naming/)、[Exporter 指导](https://prometheus.io/docs/instrumenting/writing_exporters/)

监控规则带持续时间、恢复阈值、维护窗口和通知去重。探针掉线时同时显示最后心跳和最后安全事件时间；“服务可连接”不等于“检测与上报链路正常”。容量趋势要提供预计磁盘耗尽时间、MaxAge 剩余窗口及补偿速度，不能只显示当前百分比。

## 9. 验收与容量补充

1. 中文自然语言能按预期分词；IP、URL、CVE、SID 不被误分词。词典升级后通过历史与新数据一致性测试。
2. 同一数据集验证精确、CIDR、范围、短语、前缀、包含、正则及 NOT 缺失语义；nested 不跨元素误匹配。
3. 超长 URL、畸形编码、重复参数、大小写敏感路径保持原值；未索引字段不伪装成“没有该值”。
4. 状态更新乱序、重复消息、先状态后事实、投影重建和 ES 冲突不会回退新状态；列表总数和状态筛选一致。
5. PIT 翻页期间关闭告警、更新研判和新增告警，原视图稳定；权限撤销使旧游标失效，批量操作重新鉴权。
6. HEX 验证 UTF-8 跨页、多字节与非法序列、NUL、控制字符、二进制、压缩、重组缺口；字节 offset 与下载内容一致。
7. Syslog 验证中文长度、结构化转义、JSON 超限、TLS 证书、连接中断与部分写入；不把 transport_written 展示为远端入库。
8. 外部目标离线和慢接收时仅积压该目标；恢复可重放，接收方可按 message ID 去重；UDP 丢包不会生成虚假确认。
9. 操作与登录日志不包含凭据；推送日志能关联原始事件和每次尝试，不递归触发自己。
10. 探针重启、网卡更名、磁盘满、队列积压、时钟漂移、平台组件故障均可观察；离线数据不会画成零负载。

海量规模需要在原容量公式外增加：`搜索投影字节/日 × 留存 × 副本`、`转发匹配 EPS × 目标数 × 消息字节 × 故障缓冲时间`、`发送尝试数 × 平均尝试日志字节` 和 `探针数 × 接口／指标组合 × 采样频率 × 留存`。长 URL wildcard、nested 文档和中文多粒度分词的放大系数必须实测。按租户和数据单元分配查询、导出、转发与监控预算，避免只扩写入 Worker 却忽略查询和恢复能力。
