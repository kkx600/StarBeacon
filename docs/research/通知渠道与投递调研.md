# 星烽 StarBeacon 通知渠道与投递调研

调研基准日：2026-09-28。范围为邮件、企业微信、钉钉、飞书及通用 Webhook；Syslog 作为独立日志转发链路设计。外部协议事实附官方来源，其余流程、阈值和表结构为 StarBeacon 设计建议。本次未登录客户账号、创建机器人或发送真实消息，租户权限、付费额度及实际到达情况仍需接入验收。

## 1. 渠道选型与协议约束

保留“群消息推送”和“企业应用”两种接入类型。群推送适合值班群快速接入；应用适合指定人员、交互卡片、身份绑定和有条件的状态追踪。两者不能共用权限假设、额度或回执能力。

| 渠道 | 鉴权、内容与限流 | StarBeacon 接入方式 |
| --- | --- | --- |
| 邮件 | SMTP AUTH 与 TLS；大小由服务器能力及服务商限制决定，没有通用的“每分钟邮件额度”。`465` 隐式 TLS 或强制成功升级的 `587 STARTTLS` 均可，校验证书。 | 每租户 SMTP 配置，支持供应商允许的授权码或 OAuth 认证；默认发送摘要与平台链接，正文提供纯文本和 HTML。参考 [邮件 TLS 标准](https://www.rfc-editor.org/rfc/rfc8314)、[SMTP AUTH](https://www.rfc-editor.org/rfc/rfc4954)。 |
| 企业微信群推送 | Webhook URL 中的 `key` 是凭证；文本最多 2048 UTF-8 字节，Markdown 最多 4096 字节；每个推送入口最多 20 条/分钟。支持模板卡片等消息格式。 | 独立限流器与专用渲染器，超长摘要裁剪并附详情链接；不向其他渠道套用企业微信 Markdown 语法。[消息推送配置](https://developer.work.weixin.qq.com/document/path/91770) |
| 企业微信应用 | 自建应用通过企业及应用凭证取得 `access_token`，按返回有效期缓存；文本超过 2048 字节会截断。同一应用对同一成员有 30 次/分钟、1000 次/小时约束，并有按企业账号上限计算的日人次限制。 | 保存企业、应用及接收对象映射；发送前校验应用可见范围，主动按字节裁剪，避免服务端截断业务结论。[应用消息](https://developer.work.weixin.qq.com/document/path/90236)、[访问凭证](https://developer.work.weixin.qq.com/document/path/91039) |
| 钉钉自定义机器人 | Webhook 携带 `access_token`；可配置关键词、加签及 IP 限制。每机器人最多 20 条/分钟，超额会限流 10 分钟。当前官方文档仍说明群接入，不以历史下线转载判断现状。 | 群通知专用适配器；当前发送文档未给出统一正文硬上限，平台先设正文 4 KiB 的保守上限，按所选消息类型验收，不宣称这是厂商上限。[创建机器人](https://open.dingtalk.com/document/orgapp/custom-bot-creation-and-installation)、[发送群消息](https://open.dingtalk.com/document/orgapp/custom-robots-send-group-messages) |
| 钉钉企业机器人 | 应用凭证换取 `accessToken`；消息按 `robotCode`、接收对象、`msgKey` 和模板参数发送。批量单聊结果可含 `processQueryKey`、无效人员及被限流人员列表。额度和字段长度按实际接口、模板及企业配置管理。 | 与自定义机器人分开配置。需要人员通知、状态查询或交互能力时选用；对部分失败仅补投未成功人员。[应用凭证](https://open.dingtalk.com/document/orgapp/obtain-the-access_token-of-an-internal-app)、[批量单聊](https://open.dingtalk.com/document/development/chatbots-send-one-on-one-chat-messages-in-batches) |
| 飞书自定义机器人 | Webhook 仅作用于所在群；可使用关键词、IP 白名单及签名。单租户单机器人 100 次/分钟、5 次/秒，请求体不超过 20 KB。 | 预算按整个 JSON 编码后的字节数计算，卡片也受请求体限制；自定义机器人没有用户数据访问权限。[使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot) |
| 飞书应用机器人 | `Bearer tenant_access_token`，启用机器人及发送权限，收件人须在可用范围内或机器人已入群。当前发送接口为 1000 次/分钟、50 次/秒；文本 150 KB，卡片及富文本 30 KB。`uuid` 最长 50 字符，同值请求在 1 小时内至多成功发送一条。 | 保持同一次逻辑投递的 `uuid` 不变；不同内容另建投递。上述为接口限制，仍需叠加租户套餐及具体会话限制，不能推断持续吞吐保证。[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create) |
| 通用 Webhook | 平台定义 HTTPS JSON 契约、HMAC 签名、幂等键、超时与确认语义。 | 默认最大 64 KiB、10 秒请求期限，可配置更低额度；接收方持久化后返回 2xx，业务完成通过另行约定的回执表达。采用密钥、TLS 校验和稳定投递 ID 的做法可参考 [GitHub Webhook 实践](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks)。 |

所有限额均保存为可版本化的适配器能力参数，配合平台、租户、渠道、接收对象四层预算。默认留出余量，不能靠增加机器人或出口地址绕过厂商限流。消息模板必须记录长度计量单位，区分字符数、UTF-8 字节数、编码后请求体与展开后卡片体积。

### 签名不能混用

- 钉钉自定义机器人：毫秒时间戳；以 `secret` 为 HMAC-SHA256 密钥，输入为 `timestamp + "\n" + secret`，结果 Base64 后 URL 编码，放入请求参数；允许的时间误差不超过一小时。[安全设置](https://open.dingtalk.com/document/orgapp/customize-robot-security-settings)
- 飞书自定义机器人：秒时间戳；官方样例以 `timestamp + "\n" + secret` 为 HMAC-SHA256 密钥，对空消息计算后 Base64，放入 JSON 的 `sign`；时间戳与请求时间相差不超过一小时。[签名说明](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)
- StarBeacon 通用 Webhook：自有协议采用 `HMAC-SHA256(secret, timestamp + "\n" + delivery_id + "\n" + raw_body)`；约定时间戳单位为秒，默认接收窗口五分钟。签名覆盖实际传输字节，携带密钥版本，支持轮换重叠期；每次重试重新签名，但 `delivery_id` 不变。

## 2. 成功、送达、已读与响应

投递结果拆成两条状态轴：发送轴 `queued → sending → accepted / retry_wait / delivery_unknown / failed / expired / cancelled`；回执轴 `unsupported / pending / delivered / read / rejected`。业务“已确认处理”单独记录 `acknowledged_by/at`，不能由已读事件代替。HTTP 200 仍须检查渠道业务码，SMTP 也必须检查会话阶段和每个接收人的响应。

| 证据 | 可以证明 | 不可以推导 |
| --- | --- | --- |
| SMTP 在 DATA 后返回成功 | 当前邮件服务器接管消息责任 | 已进入最终收件箱、未进垃圾箱、用户已阅读 |
| 群机器人成功响应 | 渠道接口受理本次请求 | 每个群成员实际收到或看到 |
| 应用返回消息标识 | 消息创建或任务受理，具体依渠道定义 | 全部接收人成功、已读或已响应 |
| 经验证的送达／已读回执 | 回执覆盖的消息及人员达到对应状态 | 其他人员状态或安全事件已完成处置 |

SMTP 支持 DSN 时，按信封事务和接收人关联退信、延迟与交付通知；不把像素加载等行为当作可靠已读证明。[SMTP 责任与重试](https://www.rfc-editor.org/rfc/rfc5321)、[DSN](https://datatracker.ietf.org/doc/html/rfc3461)

企业微信 `errcode=0` 仍可能带 `invaliduser`、`invalidparty`、`invalidtag` 或 `unlicenseduser`；批量结果必须展开为部分失败。飞书 `im.message.message_read_v1` 明确对应用户阅读机器人发送的**单聊**消息，不能据此承诺群机器人已读统计。[企业微信响应](https://developer.work.weixin.qq.com/document/path/90236)、[飞书已读事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/message_read)

回调入口按厂商规则验签、解密、校验应用与租户绑定，先持久化再确认，按供应商事件 ID 去重。保留回执原始时间与接收时间，允许乱序到达；重复或迟到的“已发送”不得覆盖“已读”。没有回执能力时展示“渠道已受理，送达状态不可查询”。

## 3. 可靠投递链路

业务事件／定时摘要 → 订阅匹配与权限过滤 → 去重、聚合、静默判断 → PG 通知意图及 Outbox → 队列 → 渠道 Worker → 投递尝试 → 回执与业务确认。PG 只保存通知业务状态、受控摘要及 ES 告警引用，不复制全量告警、载荷或 PCAP。高频告警先聚合，再生成实际通知任务。

Worker 通过租约领取任务，发送前再次检查渠道启用、租户权限、策略有效期和消息过期时间。网络超时、5xx、限流可重试；尊重 `Retry-After`，同时处理 HTTP 400 内的厂商限流业务码。采用带抖动的指数退避，初始建议 5 秒、30 秒、2 分钟、10 分钟，并受通知时效与总次数上限约束；厂商更长禁发期优先。[HTTP Retry-After](https://datatracker.ietf.org/doc/html/rfc9110#section-10.2.3)

认证失败先允许一次受控刷新；权限不足、接收对象无效、内容违规及模板不合法转为需修复。不能把所有失败无限重试。超过期限进入失败队列，向备用渠道发独立故障通知，防止在故障渠道中递归通知自身故障。

请求发出后超时、或者外部已接收但本地提交结果前崩溃，状态必须是“结果未知”。有厂商去重键或查询能力时先复用／查询；没有时按策略补发并标记可能重复，不承诺端到端恰好一次。稳定 `Message-ID` 也不代表邮件服务器必然去重。已处理的告警在恢复投递时不再发送过期的“立即处置”提示，必要时生成当前状态摘要。

## 4. 订阅、聚合与生命周期

订阅条件覆盖组织、资产组、网段、风险等级、规则、威胁类型、研判结论、处置状态、探针故障及报告发布。配置接收组、渠道顺序、模板、时区、值班表、聚合窗、提醒间隔、静默例外、升级链及有效期。去重、分组、静默和依赖抑制分别建模，可借鉴 [Alertmanager 的独立概念](https://prometheus.io/docs/alerting/latest/alertmanager/)，但通知抑制不删除告警事实。

| 语义 | 落地规则 |
| --- | --- |
| 重复投递去重 | 相同业务事件 ID、订阅、接收目标、通知阶段和模板版本只创建一个通知意图；不同渠道属于不同投递。 |
| 聚合 | 在同一租户、组织与接收权限范围内，按事件／规则族、资产和时间窗合并；保留首次、末次、总量、最高等级和详情查询引用。 |
| 静默／依赖抑制 | 留存命中策略、理由、责任人和截止时间；紧急事件能否越过静默由租户显式配置。 |
| 升级 | 风险等级上升或超过响应时限产生独立阶段事件；已读不停止升级，具有权限的确认、认领或处置状态才按策略停止。 |
| 重复提醒 | 同一未解决事件按间隔提醒，带当前累计量；不是重新创建安全事件。 |
| 恢复与复发 | 恢复通知包含处理结果；事件关闭后再次发生创建新的 `episode_id`，重新触发首次通知，避免被旧去重键压制。 |
| 报告 | 日、周、月报仅在满足发布策略后推送；生成完成不等于自动外发，消息带统计区间、时区、版本与授权链接。 |

首期建议普通告警聚合 60 秒，高风险事件即时首报；后续按 5 分钟聚合变化。所有值是可调整的产品默认值，不是安全事件严重性的固定判断标准。

## 5. 内容、卡片与租户边界

模板只读取字段白名单。默认包含事件编号、等级、受影响资产摘要、时间、研判状态、处置进度与平台链接；LLM 结论标明证据不足等状态。原始 HTTP 正文、Cookie、Authorization、口令、完整载荷和 PCAP 不进入办公群；手机号、人员邮箱、内部地址按租户数据策略脱敏。HTML、Markdown、链接和提及语法由渠道渲染器转义，告警载荷中的 `@all` 或链接不能改变通知行为。

卡片跳转只携带资源定位符，不在 URL 嵌入 API Key、会话票据或长期对象签名。用户进入平台后重新登录并校验租户、资产及证据权限；转发卡片不会转发权限。按钮回调须映射已绑定身份、校验一次性 nonce 和当前版本。卡片上的封禁入口只能进入同一响应策略与审批服务，不能形成第二条绕过授权的动作通道。

每租户渠道保存 `secret_ref`，密钥加密上下文绑定租户、渠道及版本；访问令牌缓存键也包含这些边界。凭证只写入和轮换、不明文回显，Webhook URL 的敏感路径和查询参数从日志中去除。普通平台运维身份不自动取得客户渠道密钥。

通用 Webhook 防止 SSRF：校验 HTTPS、解析目标和连接 IP，禁止未授权管理网／云元数据地址、自动跳转及 DNS 重绑定；私有化内部目标使用显式允许策略。配置测试使用合成告警，发送前展示目标及脱敏预览，不带真实告警证据。

## 6. 数据模型、日志页面与回放

所有实体必须有 `tenant_id`，关联键包含租户边界；只有实际通知产生明细。数据库表按保留策略分区，不以每条原始告警一行的方式扩张控制面。

| 实体 | 关键字段 |
| --- | --- |
| `notification_channels` | 类型、接入模式、目标别名、`secret_ref`、能力版本、健康状态、额度、失效时间 |
| `notification_subscriptions` | 过滤 AST、组织／资产范围、接收组、模板版本、日历、聚合、静默、升级策略 |
| `notification_templates` | 渠道类型、字段白名单、敏感级别、长度预算、不可变版本 |
| `notification_intents` | 业务事件／告警组／报告引用、`episode_id`、通知阶段、去重键、策略版本、抑制理由 |
| `notification_deliveries` | 意图、渠道、目标快照、发送与回执状态、供应商消息 ID、正文摘要 hash、有效期、幂等键 |
| `notification_attempts` | 投递 ID、尝试序号、开始／结束、耗时、HTTP／SMTP／业务码、错误分类、下次时间、trace ID |
| `notification_receipts` | 供应商事件 ID、接收人员、回执类型、源时间、验签结果、受控回执摘要 |
| `notification_replays` | 原投递、操作者、原因、回放方式、当前授权校验、生成的新投递及审计 ID |

推送日志列表支持按时间、组织、渠道、目标、通知阶段、事件编号、状态、错误类型、模板及重试次数筛选。详情展示脱敏内容、聚合数量、抑制依据、逐接收人结果、完整尝试时间线、供应商标识、回执与关联审计；凭证和原始敏感报文不可通过“查看详情”泄露。

“自动重试”保持同一投递与幂等键；“人工重新发送”创建新投递并关联原记录，明确可能重复；“策略回放”默认只计算命中、内容和数量，不发外部消息。对历史内容重新发送时再次检查当前订阅、目标授权、数据出域策略和有效期，不能因历史成功而绕过现有禁用状态。

## 7. 验收边界

至少验证多租户密钥与收件人隔离、中文／Emoji 字节边界、模板转义、批量部分失败、限流与长期积压、发送后崩溃、重复及乱序回执、证书错误、目标撤权、静默到期、事件复发及已解决告警补投。回放测试默认使用本地模拟接收端；真实渠道测试使用专用测试群和合成事件。

运行指标分别报告意图数量、被抑制数量、渠道受理率、可观测送达率、响应确认率、最老待投年龄、限流时长、失败队列和回调验签失败。送达率的分母只纳入具备相应回执能力的投递，并显示覆盖率，不能将“接口返回成功率”命名为“通知送达率”。
