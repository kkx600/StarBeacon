# 星烽 StarBeacon 态势感知系统

StarBeacon — stellar early-warning for security posture.

星烽 StarBeacon 面向单组织私有化、集团安全运营和多租户 SaaS，建立从网络检测、告警研判、流量取证到响应复盘的安全运营闭环。

本仓库当前交付为产品与工程设计方案，尚未实现运行中的平台。调研基准日：2026-09-30。方案中的容量、性能、模型准确率门槛和工期均为待验证的设计目标；基础组件与检索语义的局部核验不代表平台已经通过验收。

## 建议采用的主线

业务后端使用 Go，前端使用 Vue 3、TypeScript 与 Ant Design Vue；以 Go 编写的探针代理管理 Suricata，通过 gRPC 上报事件、同步规则和执行受控任务。PostgreSQL 保存平台配置及业务流程状态，Elasticsearch 保存全部告警及分析数据，PCAP 保存到 MinIO/S3 对象存储。NATS JetStream 负责持久缓冲与重放，Redis 负责有界缓存与短期协调。

所有已启用并产生的业务数据默认保留 **180 天**，包括全量 PCAP、告警、协议明细、操作与登录日志、通知记录、统计历史、文件样本和分析报告；用户可按租户及数据类别自定义期限。冷热迁移不缩短期限，缓存／传输缓冲的运行 TTL 与业务留存分开；当前有效配置和活动业务对象不因创建满 180 天自动删除。容量按无压缩基准估算，完整预算见[实施与容量规划](docs/实施与容量规划.md)。

旁路采集分别记录原包获取、实际检测覆盖和事件交付质量。完整会话导出验证真实握手、双向字节与结束证据，缺包或中途开始采集时明确给出限制；保存密文不等于能够解密。协议能力按识别、事务、规则、文件、原生取证和外部补充逐项验收，文件静态分析及动态沙箱结果异步回填，不阻塞实时告警推送。

首期采用有明确模块边界的单体业务服务与独立接入、分析进程。单组织部署默认只有一个租户，集团和 SaaS 使用同一套租户隔离与资源配额机制；规模扩大时迁移到多个独立数据单元。

AI 采用“确定性规则 → 小型决策模型 → 通用大模型 → 人工复核”的分层路由，支持策略选择与组合。概率输出与最终处置权限分开，所有封禁经过策略引擎并具备有效期、执行回执和撤销机制。Jev、Laya 和通用 LLM 都是可替换的模型适配器。

自动化策略正式支持影子、审批和自动模式。主平台下发任务，采集器上的受限连接器通过官方 API 或经授权的控制台认证插件执行防火墙／EDR 联动，并核对生效与到期撤销。规则中心将 AI 一键生成连接到实际引擎验证、正负样本回放和签名灰度发布。

高级检索提供事件索引与原生数据包两种模式，明确多值比较、未知字段、正则、切片和协议层的支持边界。通信详情保留 MAC 的实际观测来源、精确包时间及可验证的收发时间；单臂镜像不会产生虚构的出站时间。生产范围还包含多源日志接入、基础关联与狩猎、情报生命周期、漏洞修复、案件协作和受限自动化剧本。

截至调研日，MinIO 社区仓库已归档；生产部署必须落实受支持的 MinIO 产品或经过验收的 S3 兼容存储，不把历史社区镜像作为长期维护承诺。[官方仓库](https://github.com/minio/minio)
