## 当前工程

当前可运行子流程包括身份会话与租户用户管理、探针登记、分组管理与心跳、持久事件上报、告警可视／高级筛选、协议事件与会话摘要检索、事件调查与协作任务及笔记、Syslog 接收与日志检索、关联规则与窗口回测、保护与观察名单、资产／资产组／网段修订与有界被动地址发现、签名任务、规则验证、单探针固定修订同步及多探针分批发布、PCAP 离线重放、连续原包归档与压缩、逐包协议与原文查看、受限 TCP 会话导出、运行与审计、通知渠道与推送日志、模型配置与连接验证、统计型智能助手、日报／周报／月报及持久报告计划、态势统计及全屏展示、分类留存策略发布、MCP 有界只读工具与元数据资源。完整需求的实现与验收状态见[功能实现与验收状态](docs/功能实现与验收状态.md)。真实事件链路为：

```text
网卡 → Suricata AF_PACKET → EVE → bbolt WAL → mTLS gRPC → NATS JetStream → Elasticsearch → 平台检索
                                                        ↓
                                                  通知摘要 → PG outbox → 渠道回执
```

107 项正式复合需求中，68 项已有真实子流程，39 项待实现。当前的逐项状态和验收缺口见[功能实现与验收状态](docs/功能实现与验收状态.md)。2026-11-20 之前的核对报告与验收记录保存在[归档目录](docs/archive/)。

2026-10-23 的历史源码、部署及页面核对结果见[保护名单与调查协作验收摘要](docs/验收证据/2026-10-23-保护名单与调查协作.json)。当前图库使用原型的合成数据。

[Syslog 接收与日志检索](docs/Syslog接收与日志检索.md)支持采集器 TLS／TCP／UDP 来源、严格分帧、持久缓冲、独立日志索引、中文正文筛选及原文审计；安全日志默认保留 180 天。来源由采集器私有文件管理，日志不自动转为安全告警或阻断依据。

资产管理支持按当前探针注册、网段修订和不超过 24 小时的窗口查询已有流记录，源、目的方向独立计数，单次最多 512 个地址；人工核对后可登记资产。观测 IP／MAC 不证明设备身份或归属，详见[资产被动发现](docs/资产被动发现.md)。

主控平台可管理本租户用户、探针、规则包、重放样本和任务。探针列表支持稳定分页、分组、站点和连接状态筛选；管理弹窗使用独立修订与注册代次核对，任务选择器读取完整分页目录，详见[探针分组与管理信息](docs/探针分组与管理信息.md)。用户管理提供公开目录、创建、角色和使用状态，以及自身密码修改和管理员成员重置；权限变更原子撤销旧会话，并核对修订、幂等请求及当前管理员保护，详见[用户管理与权限](docs/用户管理与权限.md)。Linux 采集器在托管模式下可选择实际 Ethernet 网卡、线程、BPF 和混杂模式，启动专属 Suricata 进程；原生捕获轮询确认后才显示采集中，配置失败保留原进程。平台也可通过签名任务配置采集或停止采集，提交时冻结探针注册代次、配置修订及摘要，设备执行前再次核验；任务受理不代表配置生效，成功回执须包含实际参数与进程状态。设备和平台详情展示期望／生效修订、实际计数及观察时间；外部 EVE 模式仅保存待应用目标。两端均可独立导入样本执行重放。规则使用共享 CodeMirror 编辑器提供语法高亮和基础结构诊断，引擎兼容性由选定探针的原生 Suricata `-T` 检查确定。规则发布要求同设备、同修订、同检测配置的一天内装载与独立正反样本回执，支持手动逐探针部署、历史修订回滚和中断后的原生核实；受理与实际生效分开显示。固定计划修订的分批推进、逐目标验证和观察水位见[规则分批发布](docs/规则分批发布.md)；生产规模效果门禁和自动故障回退仍待验收。

两端提供[协议能力目录](docs/协议能力与检测验证.md)，记录原生引擎与配置摘要，分别展示识别、事务日志、在线规则、文件提取、报文取证及外部补充。配置核对在后台隔离执行，健康读取不等待原生命令；未知、禁用与待验收分开显示，目录本身不证明检测效果。

[检测质量](docs/检测质量观测.md)读取当前托管引擎持久化后的原生统计，保留运行身份、配置摘要和采样时间，展示 25 项累计或瞬时指标及有效连续区间增量。[质量事件](docs/检测质量事件.md)提供变化留存、历史检索与显式订阅通知，通过累计值和原生复位水位核对相邻心跳区间。捕获限制、检查覆盖、队列溢出和策略抑制分别呈现；缺测、复位、过期与离线保持未知，不推断单流完整性或流量安全。

离线重放使用 `suricata -r`，支持 PCAP／PCAPNG、本地执行及平台选择探针执行，结果保留包数、命中、摘要、日志和限制。本机已验证真实 Suricata 8.0.7 的命中、未命中及非法规则拒绝；重放不向网卡发包，也不发布线上告警或执行阻断。

Linux 托管采集器另有独立 AF_PACKET 原包捕获流，按真实网卡保存带 MAC、纳秒时间与实际丢包统计的 PCAPNG，分帧 Zstandard 压缩，经 mTLS 上传至平台的本地／挂载磁盘或带版本的 S3 兼容对象存储。平台和采集器提供原包目录、完整摘要核验、下载及按包序号查看协议字段与原始字节；默认最长留存 180 天，可配置。平台原包存储由全部租户共享，不设租户额度，剩余空间低于阈值（默认 5%）时按全局最早归档回收，可回溯时长取决于部署磁盘和流量。平台会话导出固定双方 IP／端口／MAC／VLAN，严格模式要求实际握手、连续载荷和双向 FIN 确认，缺口返回原因；快照须明确选择，不补造报文或 TLS 明文。当前导出限 16 个同源切片、256 MiB 输入、1 小时窗口及 64 MiB 输出；详见[原包归档与会话导出](docs/原包归档与会话导出.md)。

常驻验收实例目前未启用持久托管采集。独立真实网卡用例证明相应工程链路可以运行，不能据此认定该实例正在持续捕获、保留生产流量或满足 180 天实际容量。

态势总览和大屏读取实际告警聚合、登记资产与探针状态，采用共享窗口、有界缓存和租户统计预算；统计失败不显示为零。告警下钻保留原统计窗口，图形及数值不推断攻击成功。

告警与协议记录支持[检索元数据导出](docs/检索快照与元数据导出.md)：沿用已提交条件，以固定 PIT 输出有界 CSV，核验完整分片、当前会话和文件摘要；超限不提供截断结果。列表持久快照、异步海量导出和原生包统一查询仍待实现。

流量检索提供独立协议列表、实际会话时间与双向计数、MAC 集合及 TLS／DNS 可见元数据；按探针和流标识调查，容量保留 uint64 精度并自动换算。记录数不等于独立会话数或原包数，字段缺失不补造，细节见[流量检索与会话观测](docs/流量检索与会话观测.md)。

应用识别规则支持产品与类别配置、HTTP Host／SNI／DNS 条件、附加与排除依据、不可变修订、输入验证和单探针签名部署。采集器按完整快照匹配真实可见协议元数据，平台按原部署来源复算，告警和流量详情展示未知、规则候选或证据冲突；原始 EVE 保持不变，分类不授予阻断权限。应用字节计量、排行和真实产品样本效果仍待交付，见[应用识别规则与采集器分类](docs/应用识别规则与输入验证.md)。

AI 规则生成支持自然语言、PCAP 与原字节 HTTP Raw 材料，提供模型修订、来源引用、SID 防冲突和人工采纳。候选通过原生装载检查及独立正反样本回放后进入发布流程，见[AI 规则生成与样本验证](docs/AI规则生成与样本验证.md)。

管理员可在告警详情中记录人工研判、攻击结果、依据与认领，查看独立修订历史。来源校验、并发修订、幂等保存、审计和默认 180 天留存共同保护记录；人工结论不改写原始告警，也不自动执行封禁。具体流程与边界见[告警研判与协作](docs/告警研判与协作.md)。

[事件调查](docs/事件调查与结案.md)关联人工线索和检测事实，支持责任分派、调查时间线、结案与重开。协作任务记录负责人、截止时间、进展和完成依据，保留独立修订；未完成任务阻止结案，已结案事件的任务只读。调查笔记支持作者维护、撤回、恢复及不可变历史，结案后只读；修订冲突与未知提交分别处理。截止时间用于人工协作，不触发设备动作或 SLA。

告警详情还提供[模型研判](docs/告警模型研判.md)：冻结实际白名单字段与模型修订，生成带事实引用、反证和补充信息的待复核建议，支持历史、取消和未知提交确认。模型自评分未经校准，不构成设备处置授权。

决策策略支持按需影子评估、持续评估与人工确认、持续评估与限时自动授权。持续模式绑定模型修订，处理策略维护者在当前修订启用后创建并完成的本人研判。自动执行模式可单独启用新告警自动研判，固定探针、注册代次、告警等级和每日额度，并明确确认字段提交与调用费用；默认关闭。平台保留本人固定策略修订的触发记录，队列发送前重新核对许可。自动模式固定执行探针注册与设备配置，核对评分阈值、攻击尝试结论、事实引用、保护网段、目标冷却、告警去重与任务预算，再由采集器执行签名任务。模型自报分数未经校准，任务受理不代表真实流量已阻断。判断、独立授权和任务档案默认保留 180 天；详见[决策策略与影子评估](docs/决策策略与影子评估.md)、[持续决策与自动授权](docs/持续决策与自动授权.md)及[研判处置确认](docs/研判处置确认.md)。

管理员可在[联动设备目录](docs/联动设备目录与本地配置核对.md)按执行探针查询设备、核对运行配置并关联历史动作；采集器提供固定本地文件与运行绑定的配置核对。管理员可在探针详情中提交[HTTP 联动与限时封禁](docs/HTTP联动与限时封禁.md)，由指定采集器访问固定受信接口，保存独立租约并回读设备配置。请求超时使用原键确认，重启只核对历史状态，原执行回执保持不可变；任务与本地历史默认保留 180 天。采集器任务详情通过原编号独立读取，分别显示执行、留存及清理保护；`SB_TASK_RETENTION_DAYS` 只调整后续本地任务期限。启动及每分钟独立清理已到期且可回收的档案，续点持久保存，未确认及结果待核实的记录继续受保护；bbolt 回收页可复用，文件不保证立即收缩。详见[PCAP 重放与规则验证](docs/PCAP重放与规则验证.md)。通用协议使用隔离 Docker 端点验证，真实防火墙／EDR 和流量阻断效果另行验收，影子模型不授予执行权限。

高级筛选使用受限 Wireshark 风格语法，作用于已索引的告警或协议元数据；告警 HEX／UTF-8 视图展示 EVE 实际包含的载荷副本；原包归档的协议查看展示经过完整归档核验的实际捕获帧，两种来源分别标识。通知已具备邮件、企业微信、钉钉、飞书、Webhook 和出站 Syslog TLS 的真实协议适配，Syslog 可配置订阅租户操作和登录审计，并持久记录投递结果；模型页面具备加密配置及有限连接验证。智能助手和日报／周报／月报基于冻结的租户统计快照，提供逐项来源和 HTML 导出；模型失败仍可复核统计报告。对话按租户和创建人隔离，不向模型传递原始 EVE、PCAP 或凭据，不执行安全动作。报告计划按固定时区和时间持久调度，模型计划需要固定修订和持续授权；停机恢复只生成最近完整周期并记录错过范围。调度实际验收、审批发布、PDF 和领域效果验收尚未完成，业务边界见[报告计划与调度](docs/报告计划与调度.md)。

MCP 服务使用官方 Go SDK，提供告警／协议流量检索、两个数据集的字段目录与过滤表达式校验、态势统计、资产详情和探针列表，共九个只读工具；另支持按授权范围发现与读取字段目录、能力目录及字段模板资源。管理员在“智能助手 → MCP 服务”登记 OAuth 授权方的主体与客户端；告警与协议流量分别授权，工具与资源共用当前租户、主体预算及审计，不返回原始通信载荷或探针注册标识。界面的资源说明不代表当前身份已获得访问权。部署及协议边界见[MCP 服务接入](docs/MCP服务接入.md)。

[保护与观察名单](docs/保护与观察名单.md)提供固定探针注册范围、有效期、IP／CIDR／精确域名及不可变修订。有效 IP／CIDR 保护项在手动、模型确认和持续自动封禁的新授权事务中核对，原检查摘要随任务不可变保存；域名不自动解析为封禁保护，名单变化不追溯撤回已有任务。观察名单目前用于目录与有界材料预览，不自动标记全部历史告警。

生产探针的 CSR 注册、固定指纹登记、到期前自动续签及平台和 CA 独立吊销记录见[探针注册与证书](docs/探针注册与证书.md)。使用独立 step-ca，平台不持有根私钥，采集器本机生成私钥；官方固定镜像已有单节点工程验证和受控离线分发，生产高可用、迁移与轮换资格分别记录。

大规模会话索引与长连接导出、规则来源、生产规模灰度效果与自动故障回退、自动响应的完整设备适配与认证插件、应用会话计量与产品样本效果、风险与处置大屏、MCP 资源下载与收费分析工具、案件／情报／风险治理、文件与沙箱仍存在工程缺口。Linux 原生隔离与现有后端链路已在独立远程 Docker 开发环境运行。历史来源的两个 Linux UPX ZIP 已通过两次独立构建的字节一致性、依赖许可／SBOM 绑定和有界离线／实时网卡链路；当前源码与前端仍须形成同源发行包并独立验收。真实外部产品、生产 TLS／HA、海量数据容量及 PC 全路由完整交互仍未验收，当前 **不能正式发布**。具体边界见[工程实现与开发](docs/工程实现与开发.md)和[PCAP 重放与规则验证](docs/PCAP重放与规则验证.md)。

推送 `v*` 标签即触发[版本发布](.github/workflows/release.yml)：同一运行内复用工程检查，构建平台与采集器两个 Linux amd64 UPX ZIP，核对结构、许可与 SBOM 后创建 GitHub Release；`v0.2.0-rc.1` 等带后缀的标签发布为 Prerelease。标签须指向已合入 `main` 的提交，已发布的版本不覆盖。流水线只证明工程检查与发行包结构，不代表完整产品或生产环境验收，完整步骤见[测试与发布流程](docs/测试与发布流程.md)。

## 开发启动

需要 Go **1.26.8**、Node.js **24.19.0**、pnpm **12.6.0**、主机编排用 Python **3.12 或更高**、Docker 与 Compose plugin。Go 构建与检查由 Makefile 设置 `GOTOOLCHAIN=local`，并核对精确补丁版本；PATH 中的 `go` 必须为 1.26.8，或在相关命令后加 `GO=/绝对路径/go`。仅依赖 `go.mod` 的自动工具链选择不能满足 Makefile 检查。

在仓库根目录执行：

```sh
make dev-setup
pnpm --dir web install --frozen-lockfile
```

`dev-setup` 编译五个 Go 入口、启动 PostgreSQL／Redis／NATS／Elasticsearch 开发依赖、迁移和初始化身份，并生成开发证书与命令签名密钥。Compose 只包含上述依赖；Go 进程和前端分别启动。随机凭据保存在 Git 忽略的 `.local/`，重跑初始化保留已有身份。

分别在六个终端运行：

```sh
make platform
make ingest
make worker
make collector
make web
make collector-web
```

平台页面为 `http://127.0.0.1:5174/`，采集器页面为 `http://127.0.0.1:5175/`；两端使用独立登录。以上启动命令使用已经编译的二进制，不需要再次指定 Go 路径。`make sample` 追加带明确标记的工程验收 EVE，用于验证传递与索引，不代表真实抓包或攻击检测。

两端使用 History 路由。Go API 不提供静态页面；生产静态文件与 `/api/` 应经同源入口发布。[Nginx 平台示例](deploy/nginx/platform.conf)与[采集器示例](deploy/nginx/collector.conf)包含 SPA 回退及 API 代理，两份模板默认均为 `listen 80`、`server_name _`，须配置不同的主机名／监听入口及 TLS。Go 的 `SB_ALLOWED_ORIGIN` 须设为实际外部来源（不含路径，生产使用 HTTPS），代理保留请求的原始 `Origin`。采用同机代理时，配置 `SB_TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128`，与模板覆盖的 `X-Real-IP` 配合，按客户端执行限流和审计；默认不信任转发头。完整端口、环境变量及镜像限制见[开发说明](docs/工程实现与开发.md)。

运行原生规则验证、重放或协议观测的采集器容器须启用进程回收：Compose 配置 `init: true`，直接运行 Docker 时配置 `--init`，并保留既有隔离与资源限制。具体约束见[主机与容器交付](docs/依赖版本与部署清单.md#5-主机与容器交付)。

## 页面原型

原型提供 **44 个主导航工作区、130 个主控功能视图**，采集器按 **5 个工作区、9 个工程对应视图**组织，映射 **107 项需求**。2026-11-27 在 `home_dev` 重拍了 **195 张 1440×900 JPEG**。图库包含 130 张主控有数据状态、九类代表页面的 45 张其他状态、9 张采集器规范视图和 11 张登录与访问边界。[截图清单](prototype/public/screenshots/manifest.json)

图片目录可按模块、关键词和状态筛选。交互原型使用合成数据，操作只更新浏览器内存。[打开图库](prototype/public/screenshots/index.html)

安装锁定依赖后即可启动交互原型。

```sh
pnpm --dir web install --frozen-lockfile
pnpm --dir prototype install --frozen-lockfile
pnpm --dir prototype dev
```

打开 `http://127.0.0.1:4173/`。原型直接复用 `web/packages/shared` 的规则编辑器及工具源，因此需要先安装 `web` 依赖；原型运行本身无需启动 Go 服务或两个工程前端。详情见[原型说明](prototype/README.md)。

主控平台、采集器和原型共用主题、表格、分页、状态标签、指标和控件。12 个代表页已通过人工评审，图库脚本逐张核对渲染状态、文件与尺寸。[界面设计规范](DESIGN.md) [开发任务](docs/开发任务.md)

工程平台登记 **51 个业务视图**，覆盖 **30 个工作区**。其余 14 个工作区可在系统设置的功能目录查看交付状态。采集器提供 **9 个规范视图**。平台自动化编排可从告警启动已发布修订，操作员逐步确认并核对原设备回执。[功能实现与验收状态](docs/功能实现与验收状态.md) [AI 自动化处置设计](docs/AI自动化处置设计.md)

```sh
make build test vet

pnpm --dir web build
python3 scripts/check_alignment.py --check
pnpm --dir prototype check:coverage

```

Go 命令沿用前述精确工具链要求；集成测试需先完成 `dev-setup` 并保持开发依赖运行。截图检查核对图库清单、文件和 1440×900 JPEG 尺寸。安装锁定依赖和 Chrome 后，可在验收机执行 `pnpm --dir prototype screenshots:capture` 重拍图库。[重拍说明](prototype/README.md#重拍图库)

上面是全部检查命令的清单。什么时候跑哪一组、在哪里跑、怎样才算通过，以[测试与发布流程](docs/测试与发布流程.md)为准：本机只做编译、静态检查和类型检查，测试在远程主机或 CI 执行。代码覆盖率不等于功能完成率；当前逐项状态见[功能实现与验收状态](docs/功能实现与验收状态.md)。
