# 星烽 StarBeacon 态势感知系统

StarBeacon — stellar early-warning for security posture.

星烽 StarBeacon 面向单组织、集团与多租户安全运营，将网络检测、告警调查、流量证据和受控响应连接起来。本仓库提供产品设计、Vue 交互原型及可运行的 Go 与 Vue 工程。

## 当前工程

当前可运行子流程包括身份会话与租户用户管理、探针登记、分组管理与心跳、持久事件上报、告警可视／高级筛选、协议事件与会话摘要检索、资产／资产组／网段修订、签名任务、规则验证与单探针发布、PCAP 离线重放、连续原包归档与压缩、逐包协议与原文查看、受限 TCP 会话导出、运行与审计、通知渠道与推送日志、模型配置与连接验证、统计型智能助手、日报／周报／月报及持久报告计划、态势统计及全屏展示、分类留存策略发布、MCP 有界只读接入。完整需求的实现与验收状态见[功能实现与验收状态](docs/功能实现与验收状态.md)。真实事件链路为：

```text
网卡 → Suricata AF_PACKET → EVE → bbolt WAL → mTLS gRPC → NATS JetStream → Elasticsearch → 平台检索
                                                        ↓
                                                  通知摘要 → PG outbox → 渠道回执
```

主控平台可管理本租户用户、探针、规则包、重放样本和任务。探针列表支持稳定分页、分组、站点和连接状态筛选；管理弹窗使用独立修订与注册代次核对，任务选择器读取完整分页目录，详见[探针分组与管理信息](docs/探针分组与管理信息.md)。用户管理提供公开目录、创建、角色和使用状态，以及自身密码修改和管理员成员重置；权限变更原子撤销旧会话，并核对修订、幂等请求及当前管理员保护，详见[用户管理与权限](docs/用户管理与权限.md)。Linux 采集器在托管模式下可选择实际 Ethernet 网卡、线程、BPF 和混杂模式，启动专属 Suricata 进程；原生捕获轮询确认后才显示采集中，配置失败保留原进程。平台也可通过签名任务配置采集或停止采集，提交时冻结探针注册代次、配置修订及摘要，设备执行前再次核验；任务受理不代表配置生效，成功回执须包含实际参数与进程状态。设备和平台详情展示期望／生效修订、实际计数及观察时间；外部 EVE 模式仅保存待应用目标。两端均可独立导入样本执行重放。规则使用共享 CodeMirror 编辑器提供语法高亮和基础结构诊断，引擎兼容性由选定探针的原生 Suricata `-T` 检查确定。规则发布要求同设备、同修订、同检测配置的一天内装载与独立正反样本回执，支持手动逐探针部署、历史修订回滚和中断后的原生核实；受理与实际生效分开显示，自动灰度编排尚未交付。

离线重放使用 `suricata -r`，支持 PCAP／PCAPNG、本地执行及平台选择探针执行，结果保留包数、命中、摘要、日志和限制。本机已验证真实 Suricata 8.0.7 的命中、未命中及非法规则拒绝；重放不向网卡发包，也不发布线上告警或执行阻断。

Linux 托管采集器另有独立 AF_PACKET 原包捕获流，按真实网卡保存带 MAC、纳秒时间与实际丢包统计的 PCAPNG，分帧 Zstandard 压缩，经 mTLS 上传至指定版本对象存储。平台和采集器提供原包目录、完整摘要核验、下载及按包序号查看协议字段与原始字节；默认留存 180 天，可配置。平台会话导出固定双方 IP／端口／MAC／VLAN，严格模式要求实际握手、连续载荷和双向 FIN 确认，缺口返回原因；快照须明确选择，不补造报文或 TLS 明文。当前导出限 16 个同源切片、256 MiB 输入、1 小时窗口及 64 MiB 输出；详见[原包归档与会话导出](docs/原包归档与会话导出.md)。

态势总览和大屏读取实际告警聚合、登记资产与探针状态，采用共享窗口、有界缓存和租户统计预算；统计失败不显示为零。告警下钻保留原统计窗口，图形及数值不推断攻击成功。

告警与协议记录支持[检索元数据导出](docs/检索快照与元数据导出.md)：沿用已提交条件，以固定 PIT 输出有界 CSV，核验完整分片、当前会话和文件摘要；超限不提供截断结果。列表持久快照、异步海量导出和原生包统一查询仍待实现。

流量检索提供独立协议列表、实际会话时间与双向计数、MAC 集合及 TLS／DNS 可见元数据；按探针和流标识调查，容量保留 uint64 精度并自动换算。记录数不等于独立会话数或原包数，字段缺失不补造，细节见[流量检索与会话观测](docs/流量检索与会话观测.md)。

应用识别规则支持产品与类别配置、HTTP Host／SNI／DNS 条件、附加与排除依据、不可变修订以及输入验证。结果区分未知、规则候选和证据冲突；不会把名称匹配直接用于真实流量归因或阻断，见[应用识别规则与输入验证](docs/应用识别规则与输入验证.md)。

AI 规则生成支持自然语言、PCAP 与原字节 HTTP Raw 材料，提供模型修订、来源引用、SID 防冲突和人工采纳。候选通过原生装载检查及独立正反样本回放后进入发布流程，见[AI 规则生成与样本验证](docs/AI规则生成与样本验证.md)。

管理员可在告警详情中记录人工研判、攻击结果、依据与认领，查看独立修订历史。来源校验、并发修订、幂等保存、审计和默认 180 天留存共同保护记录；人工结论不改写原始告警，也不自动执行封禁。具体流程与边界见[告警研判与协作](docs/告警研判与协作.md)。

告警详情还提供[模型研判](docs/告警模型研判.md)：冻结实际白名单字段与模型修订，生成带事实引用、反证和补充信息的待复核建议，支持历史、取消和未知提交确认。模型自评分未经校准，不构成设备处置授权。

决策策略支持表达式校验、分数阈值、材料时限、保护网段及按需影子评估，复用本人已完成的模型研判材料。评估档案独立保存原判断、策略修订、来源标识及摘要，默认保留 180 天；本人历史查询与原提交确认不会重新读取后来改变的配置。管理员可通过[研判处置确认](docs/研判处置确认.md)独立授权匹配候选的限时任务，当前不连续自动执行。配置、档案与结果边界见[决策策略与影子评估](docs/决策策略与影子评估.md)。

管理员可在探针详情中提交[HTTP 联动与限时封禁](docs/HTTP联动与限时封禁.md)，由指定采集器访问固定受信接口，保存独立租约并回读设备配置。请求超时使用原键确认，重启只核对历史状态，原执行回执保持不可变；任务与本地历史默认保留 180 天。采集器任务详情通过原编号独立读取，分别显示执行、留存及清理保护；`SB_TASK_RETENTION_DAYS` 只调整后续本地任务期限。启动及每分钟独立清理已到期且可回收的档案，续点持久保存，未确认及结果待核实的记录继续受保护；bbolt 回收页可复用，文件不保证立即收缩。详见[PCAP 重放与规则验证](docs/PCAP重放与规则验证.md)。通用协议使用隔离 Docker 端点验证，真实防火墙／EDR 和流量阻断效果另行验收，影子模型不授予执行权限。

高级筛选使用受限 Wireshark 风格语法，作用于已索引的告警或协议元数据；告警 HEX／UTF-8 视图展示 EVE 实际包含的载荷副本；原包归档的协议查看展示经过完整归档核验的实际捕获帧，两种来源分别标识。通知已具备邮件、企业微信、钉钉、飞书、Webhook 和出站 Syslog TLS 的真实协议适配，Syslog 可配置订阅租户操作和登录审计，并持久记录投递结果；模型页面具备加密配置及有限连接验证。智能助手和日报／周报／月报基于冻结的租户统计快照，提供逐项来源和 HTML 导出；模型失败仍可复核统计报告。对话按租户和创建人隔离，不向模型传递原始 EVE、PCAP 或凭据，不执行安全动作。报告计划按固定时区和时间持久调度，模型计划需要固定修订和持续授权；停机恢复只生成最近完整周期并记录错过范围。调度实际验收、审批发布、PDF 和领域效果验收尚未完成，业务边界见[报告计划与调度](docs/报告计划与调度.md)。

MCP 服务使用官方 Go SDK，提供告警／协议流量检索、两个数据集的字段目录与过滤表达式校验、态势统计、资产详情和探针列表，共九个只读工具。管理员在“模型配置 → MCP 服务”登记 OAuth 授权方的主体与客户端；告警与协议流量分别授权，调用范围绑定当前租户，支持停用、到期及调用预算，不返回原始通信载荷或探针注册标识。字段目录与校验工具帮助 Agent 构造有效查询，校验通过不表示存在匹配数据。部署及协议边界见[MCP 服务接入](docs/MCP服务接入.md)。

大规模会话索引与长连接导出、规则来源与自动灰度编排、自动封禁与设备认证插件、应用品牌识别、风险与处置大屏、MCP 资源下载与收费分析工具、案件／情报／风险治理、文件与沙箱仍存在工程缺口。Linux 原生隔离与现有后端链路已在独立远程 Docker 开发环境运行。两个实际 Linux UPX ZIP 已通过两次独立构建的字节一致性、依赖许可／SBOM 绑定和有界离线／实时网卡链路；真实外部产品、生产 TLS／HA、海量数据容量及 PC 全路由完整交互仍未验收。当前 **不能正式发布**。具体边界见[工程实现与开发](docs/工程实现与开发.md)和[PCAP 重放与规则验证](docs/PCAP重放与规则验证.md)。

## 开发启动

需要 Go **1.26.8**、Node.js **24.19.0**、pnpm **12.6.0**、Python 3、Docker 与 Compose plugin。Go 构建与检查由 Makefile 设置 `GOTOOLCHAIN=local`，并核对精确补丁版本；PATH 中的 `go` 必须为 1.26.8，或在相关命令后加 `GO=/绝对路径/go`。仅依赖 `go.mod` 的自动工具链选择不能满足 Makefile 检查。

在仓库根目录执行：

```sh
make dev-setup
pnpm --dir web install --frozen-lockfile
```

`dev-setup` 编译五个 Go 入口、启动 PostgreSQL／Redis／NATS／Elasticsearch 开发依赖、迁移和初始化身份，并生成开发证书与命令签名密钥。Compose 只包含上述依赖；Go 进程和前端分别启动。随机凭据保存在 Git 忽略的 `.local/`，重跑初始化保留已有身份。

分别在六个终端运行：

```sh
make platform
make ingest
make worker
make collector
make web
make collector-web
```

平台页面为 `http://127.0.0.1:5174/`，采集器页面为 `http://127.0.0.1:5175/`；两端使用独立登录。以上启动命令使用已经编译的二进制，不需要再次指定 Go 路径。`make sample` 追加带明确标记的工程验收 EVE，用于验证传递与索引，不代表真实抓包或攻击检测。

两端使用 History 路由。Go API 不提供静态页面；生产静态文件与 `/api/` 应经同源入口发布。[Nginx 平台示例](deploy/nginx/platform.conf)与[采集器示例](deploy/nginx/collector.conf)包含 SPA 回退及 API 代理，两份模板默认均为 `listen 80`、`server_name _`，须配置不同的主机名／监听入口及 TLS。Go 的 `SB_ALLOWED_ORIGIN` 须设为实际外部来源（不含路径，生产使用 HTTPS），代理保留请求的原始 `Origin`。采用同机代理时，配置 `SB_TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128`，与模板覆盖的 `X-Real-IP` 配合，按客户端执行限流和审计；默认不信任转发头。完整端口、环境变量及镜像限制见[开发说明](docs/工程实现与开发.md)。

## 页面原型

原型提供 **42 个主导航工作区、119 个主控功能视图**、**5 个采集器工作区**，映射 **107 项需求**。当前页面清单定义 744 个业务状态与 11 个登录／访问边界；现有图库仍为先前的 737 张基础图和 43 张补充图，共 **780 张**，不包含原包归档与探针分组的十二张状态图，也不包含独立评估档案页面。

可直接打开[图片目录](prototype/public/screenshots/index.html)查看图库。原型全部使用合成数据，操作只改变浏览器内存，不调用模型、设备或后端。交互页面启动顺序为：

```sh
pnpm --dir web install --frozen-lockfile
pnpm --dir prototype install --frozen-lockfile
pnpm --dir prototype dev
```

打开 `http://127.0.0.1:4173/`。原型直接复用 `web/packages/shared` 的规则编辑器及工具源，因此需要先安装 `web` 依赖；原型运行本身无需启动 Go 服务或两个工程前端。详情见[原型说明](prototype/README.md)。

图库保留历史截图；决策策略、应用识别规则及共用表单的当前内容以交互原型为准，历史图片不作为当前来源的视觉验收记录。
